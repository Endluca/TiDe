# 教师端积分与课程读取对照表

状态：唯一当前契约（DTS v2 参与粒度）
日期：2026-08-21

## 1. 读取原则

教师端后端只需要三个入口：

1. `teacher_scorecard_current`：一位教师一行，直接返回总分、资格、五维及子项；
2. `teacher_lesson_score_current`：一条教师参与一行，直接返回源课程事实、该参与证据和冻结完课参与的具体加分项；
3. `task_assignments + task_templates`：任务内容和执行状态。

教师浏览器不得直连 PostgreSQL。教师端后端使用受限账号，并且每次查询必须带当前登录教师的 `teacher_id`。教师端不从原始表自行计算积分、出营或金牌结论。

## 2. 教师积分首页

查询入口：`teacher_scorecard_current`，过滤条件：

```sql
WHERE teacher_id = :current_teacher_id
```

| 教师端要展示的数 | 视图字段 | 含义 |
|---|---|---|
| 教师 ID | `teacher_id` | 当前登录教师 |
| 当前入营标识 | `camp_enrollment_id` | 当前教师培养关联键 |
| 教师在线状态 | `online_status` | `on+入职 0–29 天→NEW`、`on+入职满 30 天→EXISTING`、`off→LEFT`、`hei→BLOCKED`；与在营状态和资格分开 |
| 累计总分 | `raw_total_score` | 五维积分之和，不封顶 |
| 教师端展示总分 | `public_total_score` | 对外展示分，当前最高显示 200 |
| 当前在营状态 | `graduation_state` | 仅 `IN_CAMP / GRADUATED`；入职满 30 天未出营仍为 `IN_CAMP` |
| 是否已获得出营资格 | `graduation_qualified` | 历史上是否已经获得；获得后不因重算撤回 |
| 出营时间 | `graduation_qualified_at` | 首次获得出营资格的时间，写入后不可改 |
| 固定出营分数 | `graduation_score_locked` | 首次出营时冻结的出营分数，当前为 100 |
| 是否已获得金牌资格 | `gold_qualified` | 历史上是否已经获得；获得后不因重算撤回 |
| 金牌状态 | `gold_status` | 由 `gold_qualified` 派生为 `NOT_GOLD / GOLD` |
| 金牌时间 | `gold_qualified_at` | 首次获得金牌资格的时间，写入后不可改 |
| 出营分数线 | `graduation_threshold` | 当前积分版本的出营线，现为 100 |
| 金牌分数线 | `gold_threshold` | 当前积分版本的金牌线，现为 200 |
| 已完成必修数 | `mandatory_task_completed_count` | 当前 9 项必修任务中 `COMPLETED` 的数量 |
| 必修总数 | `mandatory_task_total_count` | 当前固定必修任务数量，正常为 9 |
| 当前积分版本 | `score_rule_version` | 当前结果使用的规则版本 |
| 最后重算时间 | `calculated_at` | 当前积分读取模型更新时间 |
| 五维及子项 | `dimensions` | 已按教师端展示顺序组织好的 JSON 数组 |

服务层响应的 `source.teacher_source_status` 用来区分 `CONFIRMED` 与
`SOURCE_MISSING`。教师身份存在但 `teacher_source_wide` 当前源行缺失时，不能把现有 0 分解释为
“已确认没有积分”。

出营分数和金牌进度分分开：`graduation_score_locked` 为教师的固定出营分数 100；
`raw_total_score` 为不封顶的实际累计分。例如 100 分出营后又获得 100 分，实际分为 200
并获得金牌；之后累计到 250，教师端 `public_total_score` 仍显示 200，出营分数仍为 100。
`LEFT/BLOCKED` 不停止实际分继续累计。

`dimensions` 中每个维度直接包含：

| JSON 字段 | 含义 |
|---|---|
| `code` | 五维稳定编码 |
| `score` | 该维度当前总分 |
| `score_rule_version` | 该维度使用的积分规则版本 |
| `projection_revision` | 该维度当前修订序号 |
| `calculated_at` | 该维度最后重算时间 |
| `components` | 该维度下的积分子项数组 |

新积分规则发布成功时，视图中的分数已经完成全量重算。两个资格字段是不可逆获得事实，
不等同于“按当前规则重新计算后是否仍满足”。教师端只展示资格字段，不自行根据当前分数
撤销徽章或资格状态。

`components` 中每个子项直接包含：

| JSON 字段 | 含义 |
|---|---|
| `code` | 稳定子项编码 |
| `unit_count` | 计分数量，如好评课数、Peak 完课数、必修完成状态 |
| `points_per_unit` | 每单位分值；供给里程碑可为空 |
| `score` | 本子项当前总分 |
| `source_scope` | 来源粒度：`LESSON / TEACHER / TASK` |
| `source_metric` | 直接计分指标名 |
| `lesson_attributed_count` | 已定位到具体课程的计分次数 |
| `lesson_attributed_score` | 已定位到具体课程的分数 |
| `unattributed_score` | 尚不能准确定位到课程的分数 |
| `reconciliation_status` | 教师汇总与逐课归因是否一致 |

## 3. 五维与子项编码

| 教师端卡片 | `dimensions.code` | 子项 `components.code` | `unit_count` 的业务含义 |
|---|---|---|---|
| 用户反馈 | `USER_FEEDBACK` | `FEEDBACK_PRAISE` | 获得好评的完课数量 |
| 用户反馈 | `USER_FEEDBACK` | `FEEDBACK_FAVORITE` | 课程 end+24h 时锁定、按师生去重且只归因一课的收藏数量 |
| 上课稳定度 | `RELIABILITY` | `PERFECT_COMPLETED` | 课程明细中 `is_perfect = true` 的去重 `(source_region,source_appoint_id)` 复合课程数 |
| 上课稳定度 | `RELIABILITY` | `PEAK_COMPLETED` | Peak 时段完课数量 |
| 课堂质量 | `CLASS_QUALITY` | `CLASS_QUALITY_HARDWARE` | 三项硬件异常字段均明确为 0 的课程数量 |
| 可上课情况 | `CAPACITY` | `CAPACITY_PEAK_SLOT_40` | 当前 `peak_slot_cnt` |
| 必修任务 | `NEW_TEACHER_TASK` | `G01`–`G09` | `1` 表示已完成，`0` 表示未完成 |

注意：

- 可靠性分为 `perfect_cnt × 4 + peak_completed_cnt × 2`。
- 课堂质量分为硬件质量达标课程数 × 2。未开摄像头、CPU 占用过高、网络延迟过高三个字段必须都明确为 0；任一字段为空时该课不加分并标记 `SOURCE_MISSING`。CPU、网络来源已取消且替换来源尚未接入，过渡期两字段必须为 `NULL`，不得产生新的硬件质量加分。
- 收藏关系当前态不要求已有完成课程，`feedback_favorite_cnt` 只表示当前关系中的去重学员数。
  收藏积分从 `course_favorite_attributions` 读取：`status=AWARDED` 与
  `AWARDED_PENDING_EVIDENCE` 都是当前唯一奖励态，unit_count=1且保留同一+5；后者只表示历史证据暂缺，
  不新增/冲正流水。明确为假、VOID或TRANSFER后才转REVERSED并扣除。持续收藏或取消后再收藏不能让后续课程重复加分。
  学生标识、完课时间或关系历史缺失时不猜测。
- 课程事实不以入职 30 天为准入上限；30 天只用于教师 `NEW→EXISTING` 和被明确定义为新师观察窗口的指标。
- 15 日复约不是积分子项；目标 22 列课程源不提供逐课复约事实，教师端不得从旧 `is_rebooked` 兼容列或积分账户伪造该结论。
- 收藏总分汇总上述两个当前奖励态，不直接读取当前关系人数。同一师生及同一课程都只能有一个当前奖励归因；
  读取模型应同时返回evidence status，不能把held态显示成新奖励、0分或已冲正。
- 供给分在 `peak_slot_cnt` 证据 CONFIRMED 且首次达到 40 后为 10 分；稳定流水键为
  `CAPACITY_MILESTONE:CAPACITY_PEAK_SLOT_40:{teacher_id}`。首次获得后即使当前槽位下降、scope 失效或
  再次达到也不冲正、不重复奖励；教师端按该里程碑流水/组件账户读取，不从当前计数重新猜测。
- 当前 9 项必修任务的 `score` 为各任务当前已获得的分数；任务执行状态仍以 `task_assignments.status` 为准。G01–G09 分值依次为 `3 / 2 / 2 / 3 / 3 / 4 / 3 / 5 / 5`，合计 30 分。G04 为“首课准备”，分值 3；课件准备确认和授课环境照片 AI 审核是两个任意顺序、分别保存进度的模块，只有两项全部通过才可写入 `COMPLETED` 并获得该 3 分。设备网络检测不再参与 G04 完成判定。

## 4. 课程列表与单课详情

查询入口：`teacher_lesson_score_current`。v2 一条教师参与一行：同一源课程代课后，缺席教师和完课
教师各看到自己的参与；课程积分只显示在首次 end 冻结参与上。

```sql
WHERE teacher_id = :current_teacher_id
  AND participation_role IN ('NORMAL','COMPLETION')
  AND visible_to_teacher = true
ORDER BY scheduled_start_at NULLS LAST,
         lesson_local_date NULLS LAST,
         lesson_local_time NULLS LAST,
         source_region, source_appoint_id, participation_seq
LIMIT :page_size OFFSET :offset
```

| 教师端要展示的数 | 视图字段 | 含义 |
|---|---|---|
| 课程 ID | `source_appoint_id` | 外部源课程 ID；需与 `source_region` 联合唯一 |
| 教师参与序号 | `participation_seq` | 同一源课程内第几次教师指派 |
| 第几节课 | `lesson_sequence` | 按预约开始时间、源课程 ID、参与序号稳定排序生成 |
| 课程总数 | `lesson_count` | 当前教师参与行总数，供分页使用 |
| 来源地区 | `source_region` | `dom/ovs` |
| 预约开始时间 | `scheduled_start_at` | 带时区的预约时间 |
| 本地日期/时间 | `lesson_local_date / lesson_local_time` | 页面日期与时间展示 |
| 课程状态 | `lesson_lifecycle_status` | 完课、缺席等当前课程状态 |
| 是否完美完课 | `is_perfect` | 冻结完课且迟到/早退都明确为 false 时 true；任一来源未知时 NULL |
| 是否参与计分 | `valid_for_scoring` | 是否进入当前课程计分 |
| 课程证据状态 | `evidence_status` | 课程事实证据是否完整 |
| 本课总加分 | `lesson_total_score` | 本课可归因的课程加分之和，包含完美完课的 4 分和硬件质量达标的 2 分 |
| 积分版本 | `score_rule_version` | 本课结果使用的规则版本 |
| 最后重算时间 | `updated_at` | 本课积分结果更新时间 |
| 课程业务事实 | `business_facts` | 出席、反馈、课堂质量、Peak、投诉事实 |
| 本课三个维度 | `dimensions` | 用户反馈、可靠性、课堂质量及各自加分项 |

行的稳定身份是 `source_region + source_appoint_id + participation_seq`；API 游标、缓存和前端 key 必须
使用三者，不能拼接成伪源课程 ID。课程级评价/标签/投诉/QA 可在同课所有可见参与行展示，缺席和处罚
只显示对应参与；只有冻结完课参与 `valid_for_scoring=true` 并返回本课积分，其余参与返回 0 分。

`business_facts` 已直接按页面分组：

| JSON 分组 | 主要字段 |
|---|---|
| `attendance` | `is_late / is_early / absence_reason_detail` |
| `user_feedback` | 好评、差评标签、评价详情、课程收藏归因、拉黑关系摘要 |
| `classroom_quality` | 摄像头、CPU、网络延迟、`hardware_quality_passed`、`is_perfect` |
| `capacity` | `is_peak` |
| `complaint` | 投诉一/二/三级分类、级别、处理路由 |

假早退已从业务契约移除，教师端 API 和页面不得继续返回 `is_false_early_leave`。CPU、网络字段暂时
保留，但新来源接入前必须返回 `NULL`，不能沿用旧 `qa_ac_classroom_record` 结果。

`dimensions` 中每个元素包含：

| JSON 字段 | 含义 |
|---|---|
| `code` | `USER_FEEDBACK / RELIABILITY / CLASS_QUALITY` |
| `score` | 本课在该维度获得的分数 |
| `evidence_status` | 本维度证据状态 |
| `evidence_coverage` | 本维度证据覆盖程度 |
| `components` | 本课具体在哪些子项获得了多少分 |

`is_perfect` 是系统根据当前课程事实实时派生的逐课业务结果，
`business_facts.classroom_quality.is_perfect` 返回同一个值。它不是新增上游字段，也不重复
落入已删除的旧 `lesson_facts` 或任何源表。逐课 `is_perfect = true` 时，`PERFECT_COMPLETED` 加 4 分并标记
`CONFIRMED`；教师维度 `perfect_cnt` 是这些课程按 `(source_region,source_appoint_id)` 复合键去重后的数量。
课堂质量的
`CLASS_QUALITY_HARDWARE` 根据 `is_camera_off / is_cpu_usage_high /
is_network_delay_high` 三个字段逐课结算；三项都明确为 `false` 时本课加 2 分，
任一字段为空时本课为 0 分并标记 `SOURCE_MISSING`。

## 5. 任务读取与状态更新

积分读取视图不替代任务表。

| 教师端用途 | 表/字段 |
|---|---|
| 我的任务列表 | `task_assignments`，按 `teacher_id` 查询 |
| 任务标题 | 优先 `task_assignments.display_title`，为空时读取 `task_templates.payload.title` |
| 为什么产生 | `task_assignments.why`；个性化任务已包含 `Evidence:` 最小英文证据摘要，可直接展示 |
| 怎么做 | `task_templates.payload.how_summary` |
| 完成标准 | `task_templates.payload.completion_standard` |
| 完成后获得 | `task_templates.payload.benefit`；不另设重复的 `gain` 字段 |
| 内容状态 | `task_templates.payload.content_status`；当前 G01–G09 均为 `READY` |
| 当前状态 | `task_assignments.status` |
| 优先级/截止时间 | `priority / due_at` |
| 任务类型与执行路由 | `task_code + task_assignments.teacher_execution_variant`；通过 `template_version_id = task_templates.row_id` 读取冻结模板，禁止从 evidence JSON 推断照片/通用变体 |
| 完成时间 | `completed_at` |
| 并发更新版本 | `row_version` |

教师端数据库账号按最终角色文档获得表级 CRUD；数据库 Trigger 拒绝创建、删除，并只接受以下状态字段发生业务变化：

`status, status_reason_code, status_changed_at, completed_at, updated_by`

状态更新后，本系统会自动更新当前 9 项必修子项、成长任务维度和教师总分。教师端不写任何积分字段。

## 6. 最小查询示例

```sql
-- 积分首页：一行即可直接渲染
SELECT *
FROM teacher_scorecard_current
WHERE teacher_id = :current_teacher_id;

-- 课程页：一条可见教师参与一行，直接分页
SELECT *
FROM teacher_lesson_score_current
WHERE teacher_id = :current_teacher_id
  AND participation_role IN ('NORMAL','COMPLETION')
  AND visible_to_teacher = true
ORDER BY scheduled_start_at NULLS LAST,
         lesson_local_date NULLS LAST,
         lesson_local_time NULLS LAST,
         source_region, source_appoint_id, participation_seq
LIMIT :page_size OFFSET :offset;

-- 任务页
SELECT
    a.*,
    t.payload AS template_payload
FROM task_assignments AS a
JOIN task_templates AS t
  ON t.row_id = a.template_version_id
WHERE a.teacher_id = :current_teacher_id
  AND EXISTS (
      SELECT 1
      FROM task_templates AS current_t
      WHERE current_t.template_id = a.task_code
        AND current_t.status = 'PUBLISHED'
  )
ORDER BY a.priority, a.assigned_at;
```

`t` 是 assignment 创建时冻结的版本，换版后可以是 RETIRED，查询不得按 `t.status` 过滤；上面的 EXISTS
只判断 task_code 是否仍属于当前目录，因此旧版本 assignment 内容不漂移，G00/已退出目录编码仍隐藏。
