# 教师端共享工单表契约

## 1. 单一事实源

教师端和运营端共用：

`public.teacher_support_tickets`

该表由教师端负责建表和结构变更。TiDe 不复制工单表，也不通过接口同步整张工单。

## 2. 双方分别做什么

| 动作 | 教师端 | TiDe 运营端 |
|---|---|---|
| 创建工单 | 写入共享表 | 读取 |
| 教师追加消息 | 更新共享表 | 读取 |
| 运营回复 | 读取 | 只调用 `public.append_teacher_support_ticket_operator_message(...)` 追加消息 |
| 关闭、超时和图片清理 | 按教师端规则执行 | 读取结果 |

TiDe 不直接改工单状态、教师消息或历史消息。

## 3. TiDe 读取的必要字段

| 字段 | 用途 |
|---|---|
| `ticket_id` | 工单唯一标识 |
| `teacher_id` | 关联教师 |
| `primary_category`、`secondary_category` | 问题分类与筛选 |
| `problem_location`、`problem_context` | 定位问题发生位置及相关业务对象 |
| `messages` | 展示对话，并判断当前轮到谁回复 |
| `status` | 判断是否已关闭 |
| `row_version` | 运营回复时做并发校验，防止覆盖新消息 |
| `created_at`、`updated_at` | 排序和展示时间 |
| `last_operator_reply_at`、`teacher_reply_deadline_at` | 教师端超时关闭规则所需时间 |
| `close_reason`、`closed_at` | 展示关闭结果 |
| `image_cleanup_status`、`images_deleted_at` | 展示附件是否已清理 |

教师姓名不重复保存，通过 `teacher_id` 关联 `public.teachers` 读取。

## 4. 当前状态口径

- `status = CLOSED`：已关闭。
- 未关闭且最后一条消息由教师发送：待运营回复。
- 未关闭且最后一条消息由运营发送：待教师回复。

运营回复成功后，TiDe 立即按最后一条消息更新页面状态，不等待另一端刷新。

## 5. 运营回复

TiDe 只调用：

```sql
public.append_teacher_support_ticket_operator_message(
  ticket_id uuid,
  expected_row_version bigint,
  message jsonb
)
```

`message` 当前只写：

```json
{
  "message_id": "UUID",
  "sender": "OPERATOR",
  "content": "回复正文",
  "images": []
}
```

`expected_row_version` 必须等于读取工单时的 `row_version`。不一致时提示运营刷新后重试。

## 6. 上线前必须完成

1. 上述数据库函数在追加运营消息时同步写入 `last_operator_reply_at`，否则教师端基于该时间的 48 小时规则可能失效。
2. 运行账号只保留共享表 `SELECT` 和运营回复函数 `EXECUTE` 权限，不保留对工单表的直接增删改权限。
3. 教师端确认能读取运营回复、正确更新 `row_version`，并共同完成并发回复和关闭流程验收。

图片回复不是当前上线范围。后续开放时再补上传、鉴权预览和清理契约。
