# 教师端共享任务表契约

状态：唯一当前契约
日期：2026-08-21

## 1. 怎么交换

任务触发中心与教师端共用同一个 PostgreSQL：

- `task_templates` 是唯一任务目录：新建只用当前 PUBLISHED，既有 assignment 继续读取其冻结的
  PUBLISHED 后已 RETIRED 版本；
- `task_assignments` 是唯一任务实例与当前状态事实；
- 不建任务发布 HTTP 接口、状态回传 HTTP 接口或第二份任务副本。

共库不等于共用超级账号。教师浏览器不直连数据库；教师端后端使用 `tit_teacher_crud`，任务触发中心使用独立账号。

## 2. 谁创建、谁更新

| 方向 | 写入内容 | 所有权 |
|---|---|---|
| 任务触发中心 → 共享库 | 新教师出现时初始化当前 9 项固定成长 assignment | `FIXED_GROWTH + TRIGGER_CENTER` |
| 任务触发中心 → 共享库 | 按确定性规则创建 5 类个性化 assignment | `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER` |
| 教师端 → 共享库 | 更新已有 G/P 任务的执行状态 | 表级 `UPDATE`，数据库 Trigger 只接受状态五字段语义 |
| 任务触发中心 ← 共享库 | 读取当前 G01–G09 assignment 的合法 `COMPLETED` 及其冻结模板版本并幂等结分 | 不修改教师完成结论 |

固定任务不是人工发布：教师首次进入试用期教师集合时，由任务触发中心自动建立 9 条共享任务事实。初始化本身不创建通知、提醒或投递意图。个性化任务由触发中心按已确认规则创建。教师端直接读取当前目录中 G/P assignment 及其冻结模板版本并负责“接收→完成”，不再创建任务。

教师端读取当前任务时必须用 `task_assignments.template_version_id = task_templates.row_id`
关联冻结模板，不得对该冻结行增加 `status='PUBLISHED'` 条件。目录可见性另以同一 task_code 是否存在当前
唯一 PUBLISHED 模板判断；因此模板换版后既有 assignment 仍显示 RETIRED 冻结内容并可推进状态，G00 或
真正退出当前目录的编码仍隐藏。不能只按 `teacher_id` 全表读取，也不能用冻结模板 status 代替目录策略。

## 3. 当前任务目录

### 3.1 固定成长任务

| 编码 | 任务 | 分值 |
|---|---|---:|
| G01 | 资料与资质完善 | 3 |
| G02 | 平台政策学习 | 2 |
| G03 | 不同类型学员应对 | 2 |
| G04 | 首课准备 | 3 |
| G05 | TTP 入门 | 3 |
| G06 | ME 文化与 PARSNIP | 4 |
| G07 | 可靠性培训 | 3 |
| G08 | Global Communicator 培训 | 5 |
| G09 | SET 教学基础 | 5 |

合计 30 分。G04 是“首课准备”；教师执行页包含两个相互独立的模块：课件准备确认、授课环境照片 AI 审核（摄像头角度、光线、背景、着装四项）。两个模块可任意顺序执行并分别保存进度，不得相互覆盖或重置；只有两项全部通过时，G04 才是 `COMPLETED`。设备网络检测不再是 G04 的执行步骤或完成条件；既有设备检测进度只保留为历史审计事实。重排前的退役任务以隐藏技术编码 `G00` 只读保留，不进入当前任务列表、积分和资格判断。已确认不存在复营或跨营期回补，同一教师同一当前 G 任务只能有一条 assignment。

G03 的教师端标题为 `How to handle different types of students`，G04 的教师端标题为 `Lesson Preparation`。G01–G09 同时是教师端执行流程路由码，不是单纯展示顺序；教师端必须按本表同步执行定义。

### 3.2 个性化改善任务

| 编码 | 教师动作 | 分值 |
|---|---|---:|
| `P-REL-MEMO` | 阅读内嵌 Lesson Memo 规则文档 | 0 |
| `P-REL-ATTENDANCE` | 完成阔知课程 595 Reliability | 0 |
| `P-FB-NEGATIVE` | 完成差评标签对应的配置化改善活动；已确认的授课环境标签使用拍照 AI 检测 | 0 |
| `P-FB-COMPLAINT` | 完成一般投诉对应学习 | 0 |
| `P-FB-BLACKLIST` | 完成拉黑改善学习 | 0 |

`personalized_trigger_matches` 保存的是“一个稳定 `dedupe_key` 的当前生命周期”，不是每次复命中
都新建一条证据行。同一 `dedupe_key` 在 `MATCHED/MATERIALIZED → SUPPRESSED` 或
`SUPPRESSED → MATCHED/MATERIALIZED` 时更新原行，`match_revision += 1`，并更新
`last_transition_at`；每次转换只向 `audit_events` 追加旧/新状态、必要证据摘要和来源位置。
禁止因“恢复命中”另建同键 match 或覆盖已有审计历史。

assignment 的 `why/evidence_snapshot/display_title` 只冻结首次物化证据。之后同一任务键新增、抑制或
恢复的课程/参与/地区 match 只进入 `personalized_trigger_matches + audit_events`，不能改写 assignment；
需要当前贡献时聚合 active match，不从首次快照倒推。

首次物化必须由独立 Task Planner 对 assignment `dedupe_key` 加事务锁后，从同一一致性快照的全部 active
match 选择 canonical seed，禁止把最先到达的事件或并发 INSERT 胜者当 seed。排序固定为
`seed_rule_rank → source_region(dom<ovs) → canonical source_appoint_id → participation_seq → canonical evidence id → match.dedupe_key`
逐项 ASC NULLS LAST；P-REL-ATTENDANCE 中缺席 match rank=10、投诉出席 match rank=20，其余每种 assignment
的 match rank=10。已存在 assignment 永不重选；真正晚于 Planner 快照出现的 match 只增加当前贡献。
完整字段、负面标签空名/执行变体冲突的失败关闭规则及 shadow/cutover 要求以冻结实施规格 §3.1、§6.3 为准。

P-REL 缺席任务只按 `dom_teacher_absent_reason.reason_type` 精确触发：

- `reason_type='Unfilled Lesson Memo'`：幂等创建 `P-REL-MEMO`；
- 其他任意非空 `reason_type`（包括 `No Notification`）：幂等创建 `P-REL-ATTENDANCE`；
- `reason_type` 为空：不创建缺席任务。

`No Notification` 是 `no_notice_cnt` 的独立精确判定值，不等于 `Unfilled Lesson Memo`。任务行写入只能证明任务事实已创建，不能证明通知、提醒或外部动作已送达。

“缺席原因触发 P-REL”只使用上面三条；投诉分类为“出席问题”时也可以复用同一
`personalized:P-REL-ATTENDANCE:{teacher_id}` assignment，但它的证据 match 必须使用投诉键
`complaint:TR-REL-ATTENDANCE:{source_region}:{source_appoint_id}:{completion_participation_seq}:{complaint_type_grandson}`，不得伪装成
absence match。投诉分流、Case/提醒键与生命周期以冻结实施规格 §6.4 为准。

缺席原因必须先按 `source_region + source_appoint_id + teacher_id` 映射到唯一、已经是
`t_absent` 的教师参与；原因早到时只保留来源事实，参与形成后再重算。命中证据和任务实例使用两层键：

```text
personalized_trigger_matches.dedupe_key =
  absence:{rule_code}:{source_region}:{source_appoint_id}:{participation_seq}

task_assignments.dedupe_key =
  personalized:{task_code}:{teacher_id}
```

原因 UPDATE/DELETE 或改型后，旧 match 改为 `SUPPRESSED` 并保留审计；若新原因命中另一规则，
按该规则的稳定键 UPSERT match：该键从未出现才新建，已有 `SUPPRESSED` 行则重新激活原行并
`match_revision += 1`。已经创建的 assignment 不删除、不取消、不回退，未完成状态继续保留，
已完成终态保持不变；以后再次命中同键原因时复用教师级 assignment 和原 match，不新建证据行。

`P-FB-NEGATIVE` 按标签 ID 形成任务实例：只读取 DOM 当前评价明确为差评的课程，并从
`source_course_labels` 读取当前 `label_id + label_name` 集合；`label_id` 是身份，`label_name` 只用于
创建时的展示快照。按冻结完课教师统计，同一 `label_id` 至少出现在 2 个不同
`(source_region, source_appoint_id)` 时才具备创建资格；display_title必须从已发布
`teacher_personalized_copy` 读取，精确命中时为 `Negative Feedback - {mapped English}`，未命中固定为
`Negative Feedback - Feedback Pattern`。原标签名只留evidence，禁止创建中文标题。键固定为：

```text
每课标签命中 = negative-label:{teacher_id}:{label_id}:{source_region}:{source_appoint_id}
任务实例     = personalized:P-FB-NEGATIVE:{teacher_id}:{label_id}
```

评价、标签或完课纠错使阈值不再成立时，受影响 match 改为 `SUPPRESSED`；同一课程标签以后恢复时，
重新激活原 match 并 `match_revision += 1`，不新建证据行。已经创建的 assignment 仍不删除、
不取消、不回退。标签字典改名不改变 `label_id` 身份，也不改写既有 assignment 的冻结标题。

阈值已达但 `grading_label_log` 当前 `label_name` 为空时，只建
`negative-label-name-missing:{teacher_id}:{label_id}` 的 PENDING_DATA match，不读 `grading_label` 字典、
不建 assignment。名称补齐后才按正常键物化；非空名称无批准英文映射时使用固定英文通用标题，原名只
留 evidence。这样两个授课环境照片变体仍只能由已确认精确原名选择。

`P-FB-COMPLAINT` 只在课程已有冻结完课教师、`complaint_type_grandson` 非空，且该三级分类 ID
精确命中 `complaint_category_rules` 的 P2/P3/P4 时创建。键固定为：

```text
每课分类命中 = complaint:{rule_code}:{source_region}:{source_appoint_id}:{completion_participation_seq}:{complaint_type_grandson}
任务实例     = personalized:P-FB-COMPLAINT:{teacher_id}:{complaint_type_grandson}
```

`complaint_type_grandson IS NULL` 仍计入有效投诉指标，但因无法选择具体改善分类，只在 typed complaint/
course current 写 `PENDING_DATA:COMPLAINT_CATEGORY_MISSING`，不建 trigger match 或 assignment。投诉失效、分类/严重度变化或完课归属纠错时，
旧 match 改为 `SUPPRESSED`；同键恢复时重新激活原行并 `match_revision += 1`。分类名称变化不改变 ID 身份和既有任务标题。

教师端动态英文文案只认已发布高影响配置 `config_key=teacher_personalized_copy`。v2 首个 Seed 固定为
`version_id=cfg-teacher-personalized-copy-v1, version_number=1, schema_version=1`；assignment evidence 必须冻结
该 `version_id`、规范化 lookup key、mapping_hit 和原始中文快照。配置更新只影响以后首次创建的 assignment，
不得改写既有 why/title/variant；cutover revision vector 必须包含该配置。
新copy发布时，触发中心先按新版本重评全部有active match但尚无assignment的标题、执行变体、evidence/hash及
负面标签blocker，再按assignment key合并为一次TASK_PLAN revision；禁止旧match与新plan混用。

`P-FB-BLACKLIST` 按当前师生拉黑关系中不同 `student_token` 计数，不要求存在完课；同一教师在同一
`source_region` 达到 2 人时命中。键固定为：

```text
阈值命中 = blacklist-threshold:{source_region}:{teacher_id}
任务实例 = personalized:P-FB-BLACKLIST:{teacher_id}
```

DOM/OVS 同教师 ID 的拉黑关系不跨 `source_region` 合并计阈值；任一地区首次达阈值时，按全局
`teacher_id` 复用同一 assignment。assignment 的 `evidence_snapshot` 只冻结首次物化时的地区贡献，
后续地区贡献只写对应 match/audit；读取当前贡献时聚合 active match，不修改 assignment 证据。该地区降到 2 人以下时把对应 match 改为
`SUPPRESSED`；同地区再次达阈值时重新激活原行并 `match_revision += 1`，不开启新的阈值周期。

上述五类个性化 assignment 只在对应任务键首次物化时 INSERT 一次。任何 match 的抑制或恢复都不删除、
不取消、不回退也不重建 assignment；已完成任务保持终态，未完成任务保持当前进度。
`dom_user_complaint/ovs_user_complaint` 只保留 source version/current 审计，不生成业务脏键、v2 Outbox、指标、任务或积分。

触发中心对“灯光过暗/亮”“环境乱/灯光差”两个已确认标签，在冻结证据中写入稳定的
assignment 类型化列写入
`teacher_execution_variant = TEACHING_ENVIRONMENT_PHOTO`；教师端只据此列开放与 G04 相同四项标准的
单步拍照 AI 检测。该个性化变体仅借用 G04 的当前标准：每次提交都独立检测，只以本次四项结果
判定完成，不保留照片或审核明细，也不查询或复用历史 PASS。G04 本身的独立模块进度、照片审核保存
和既有 PASS 复用逻辑不变。其他标签不得因同属 `P-FB-NEGATIVE` 而统一开放拍照流程。上线前已冻结的
同标签 assignment 可按上述两枚精确原始标签兼容识别，不做模糊匹配，也不自行重算触发条件。

### 3.3 固定成长积分与出营资格

- 当前 9 项必修任务的完成状态只认共享 `task_assignments.status`。除 `COMPLETED` 外，其他状态均不加该任务分。
- 每个 assignment 通过 `template_version_id` 固定引用一条模板记录；合法完成后按该记录的 `payload.score_value` 累加。已经完成的任务立即进入当前成长任务分，不必等待 9 项全部完成。
- 当前成长任务分为已完成 9 项必修任务的模板分值之和，最高 30 分。教师端不能写 `score_value`、积分流水、总分或资格结论。
- 出营资格中的“必修成长任务全部完成”要求同一教师当前 9 条 assignment 全部存在且全部为 `COMPLETED`。初始 `ASSIGNED` 明确表示“任务已建立、尚未完成”；少于 9 条属于内部 `TASK_BASELINE_INCOMPLETE`，不能解释为教师未完成，也不能标为外部 `SOURCE_MISSING`。
- 当前出营另外两项硬门槛为 L0 投诉 0 次、raw 总分不低于 100。金牌资格包含五项硬门槛：满足当前出营条件、raw 总分不低于 200、迟到不超过 1 次、早退 0 次、缺席 0 次。
- G01 唯一读取的外部状态是 `teacher_source_wide.is_cpl_tesol`。`true` 表示完成，
  `false` 表示明确未完成，`NULL` 表示上游尚未提供；缺值不得用 Mock 或默认值补成完成。
  `teacher_source_wide.is_self_introduce` 继续作为教师资料事实保留，但不是 G01 的展示项或
  完成条件。TESOL 通过仍不足以完成 G01，还必须同时满足教师端持有的 61 题通过、Essay
  完成确认和完成证明提交。

## 4. `task_templates` 共享字段

| 字段 | 含义 | 为什么必须有 |
|---|---|---|
| `row_id` | 模板记录 ID | assignment 冻结引用的外键 |
| `template_id` | G/P 稳定任务编码 | 两端使用同一业务类型 |
| `template_version` | 模板序号 | 识别 assignment 创建时所用内容 |
| `status` | `DRAFT / PUBLISHED / RETIRED` | 只允许已发布模板创建任务 |
| `revision` | 编辑乐观锁 | 防止配置页并发覆盖 |
| `output_type` | 输出类型，当前为 `TEACHER_TASK` | 避免把 Case/提醒当成教师任务 |
| `execution_owner` | 任务执行方，当前为 `TEACHER_APP` | 明确“收到→完成”归教师端 |
| `integration_mode` | `INBOUND_STATUS_ONLY / OUTBOUND_MANAGED` | G 只接收教师端状态更新；P 由触发中心按规则管理 |
| `external_task_template_code` | 教师端执行页路由码 | 让教师端稳定打开对应流程 |
| `source_mode` | 模板来源性质 | 区分真实配置与测试种子 |
| `payload` | 静态标题、Why、How、完成标准、`benefit`、内容状态、分值、截止规则 | 静态内容只存一份 |
| `created_by / updated_by` | 创建与更新主体 | 审计追溯 |
| `created_at / updated_at` | 创建与更新时间 | 判断内容的时间边界 |

数据库对 `(template_id,template_version)` 和 `(row_id,template_id)` 唯一，并对
`(template_id) WHERE status='PUBLISHED'` 建部分唯一索引。唯一发布入口为受限
`publish_task_template_v2`：无current时DRAFT→PUBLISHED，换版时旧PUBLISHED→RETIRED+新DRAFT→PUBLISHED+
audit；RETIRED终态，direct status写、单独退役/复活及PUBLISHED原地修改/删除均拒绝。单模板发布只fan-out
`target_task_code=该template_id` 的active无assignment TASK_PLAN；copy发布才fan-out全部此类键，任一失败
整事务回滚。首次发布和换版还必须逐编码校验本节目录的精确分值，G01–G09 不得只校验合计30分，五个P任务
必须为0；异值拒绝发布。新建 assignment 在 catalog shared lock 内校验当前 PUBLISHED，并用
`(template_version_id,task_code)→(row_id,template_id)` 复合外键防止 G01 引用 G02/P 模板。既有 assignment
状态更新和显示只要求冻结复合 FK 存在，允许引用 RETIRED 历史行。

教师端展示字段直接读取：

| 教师端文案 | `task_templates.payload` 字段 |
|---|---|
| Why | `task_assignments.why`；模板 `why_template` 只作为创建种子/默认文案，不在读取时覆盖实例 Why |
| How | `how_summary` |
| Completion standard | `completion_standard` |
| What you’ll gain | `benefit` |

不新增 `gain` 字段：它与 `benefit` 语义相同，重复存储会产生两个内容真相源。当前
G03 的 `content_status = READY`。它使用阔知课程 655，三段视频均完成到
`percent=100` 且三份配套考试均完成后，教师端才可将 assignment 更新为 `COMPLETED`。
当前其余必修任务同样为 `READY`。

## 5. `task_assignments` 共享字段

| 字段 | 含义 | 为什么必须有 |
|---|---|---|
| `assignment_id` | 任务实例 ID | 两端定位同一条任务 |
| `teacher_id` | 任务所属教师 | 决定谁能看到和执行 |
| `task_code` | G/P 稳定任务编码 | 选择正确的教师端执行流程 |
| `template_version_id` | `task_templates.row_id` | 冻结本实例使用的静态内容 |
| `task_kind` | `FIXED_GROWTH / PERSONALIZED_IMPROVEMENT` | 区分加分的固定成长与不加分的改善任务 |
| `creator_system` | 当前为 `TRIGGER_CENTER` | 强制任务创建所有权；教师端不能创建 assignment |
| `status` | 当前执行状态 | 两端共享的核心事实 |
| `priority` | `P0 / P1 / P2 / P3` | 教师端和运营端一致排序 |
| `why` | 该教师为什么收到本任务；教师端外显，必须为英文；应用写入后不可修改，受控目录迁移除外 | 必须让外教直接理解触发原因，不依赖教师端二次翻译 |

| `materialization_seed_key` | 个性化任务必填且不可改 | MATCH为match key；FROZEN/COMPAT分别用`legacy-assignment:`/`legacy-compat:`+ID |
| `materialization_seed_revision` | MATCH为match_revision；两种LEGACY为0 | 冻结首次选择时的证据版本 |
| `materialization_seed_payload_hash` | 个性化任务必填且不可改 | 校验重放、并发和 cutover 没有产生另一套首次 payload |
| `materialization_template_revision` | 个性化任务必填且不可改 | 模板 RETIRED 后仍能重建首次 payload hash |
| `materialization_plan_revision` | MATCH 对应 TASK_PLAN revision，legacy=0 | 证明冻结列来自哪一份不可变请求快照 |
| `eligibility_generation` | MATCH>=1、两种LEGACY=0、固定为空 | 不拿当前generation重解释旧assignment |

| `teacher_copy_config_key` | MATCH/COMPAT固定小写copy key，FROZEN/fixed为空 | 与version_id组成复合FK，禁止跨域 |
| `teacher_execution_variant` | MATCH/COMPAT为GENERAL/照片，FROZEN为LEGACY_FROZEN | 冻结执行路由 |
| `plan_evidence_hash` | 个性化任务必填且不可改 | 冻结 canonical 业务证据；审计 JSON 键序/时间不影响 hash |
| `eligible_since_at` | MATCH取plan；FROZEN回填旧assigned_at；COMPAT等于新INSERT assigned_at | 消费延迟不能推迟截止 |
| `due_at` | 截止时间 | 排期和超时判定 |
| `timezone_used` | 截止时间所用时区 | 避免跨时区任务歧义 |
| `timezone_source` | 时区来源 | 追溯时区是教师资料、人工或默认值 |
| `timezone_verified_at` | 时区核验时间 | 证明截止时间计算依据 |
| `status_reason_code` | 失败、过期、豁免或取消的稳定原因码 | 让异常状态可统计，不只留自由文本 |
| `source_mode` | 本实例的数据性质 | 不把 Mock 当真实任务 |
| `dedupe_key` | 任务幂等键 | 防止重试或重复批次创建同一任务 |
| `created_by` | 创建服务/账号 | 创建审计 |
| `updated_by` | 最后状态更新服务/账号 | 更新审计 |
| `row_version` | 乐观锁序号 | 防止旧状态覆盖新状态 |
| `assigned_at` | 任务成为可读事实的时间 | 不用教师首次看到时间代替发布时间 |
| `status_changed_at` | 当前状态生效时间 | 状态时效和审计 |
| `completed_at` | 可信完成时间 | 只有 `COMPLETED` 可非空，用于结分/效果分析 |
| `created_at` | 数据库建行时间 | 技术追溯 |
| `updated_at` | 最后合法更新时间 | 同步与排错 |

`due_at` 为空时三个时区证据字段必须同时为空；有截止时间时必须同时完整。MATCH/LEGACY_COMPAT必须同时
具有 eligible_since_at、due_at 和三项时区证据，P-REL 的 due_at=eligible_since_at+48 小时，P-FB 为
+72 小时；assigned_at 只是实际建行/可读时间。LEGACY_FROZEN 的 eligible_since_at 回填原 assigned_at，
原 due/timezone 可成组为空且不重算；固定任务 eligible_since_at 和四个 seed 字段为空。
MATCH/LEGACY_COMPAT的copy两列必须成组非空，复合引用 `config_versions(version_id,config_key)`；创建时必须指向唯一
PUBLISHED且schema/hash合法的版本，后续可继续引用不可变RETIRED。教师端只读这两列，不参与选版。
LEGACY_COMPAT只允许compatibility窗口受限函数创建：seed=`legacy-compat:{assignment_id}`、revision/plan/
generation=0、eligible_since_at=assigned_at，英文copy/variant/template/timezone/due/evidence/hash完整；cutover
原样保留。LEGACY_FROZEN仅指expand前存量，copy两列为空。

受限函数精确为
`create_legacy_compat_assignment_v2(assignment_dedupe_key,teacher_id,task_code,
expected_legacy_compat_match_set_hash)`；新请求在 `V1_COMPAT_DUAL_CAPTURE/ROLLED_BACK` 可用，V2_PRIMARY
拒绝；已成功同request跨mode重放仍REPLAYED。assignment ID 由
`legacy-compat-assignment:v2\u0000+dedupe_key` 的 SHA-256 确定生成，不能使用随机默认值；四参数 request hash
写入永不过期的 `idempotency_records`。锁序为 cutover shared→完整
`CONFIG:teacher_personalized_copy/TEMPLATE:{task_code}` catalog key 集合按 UTF-8 bytes 升序（当前 CONFIG 先）→
assignment key→idempotency→teacher→canonical active matches。同请求响应丢失后返回同 assignment/同payload的
`REPLAYED`，同幂等key异请求拒绝；已有同教师/任务 assignment只关联match并返回
`EXISTING_ASSIGNMENT`，不改冻结列。只有match-set hash、当前template/copy、英文文案、时区和due全部完整时
才可原子 `CREATED`；稳定错误和hash字段以冻结实施规格§3.1为准。
compat候选只认LEGACY_REUSED、generation=0、is_serving=false、无serving generation的TEACHER_TASK active
状态；其`legacy_compat_match_set_hash_v1`独立于v2 serving active-set hash。

## 6. 具体写法

### 6.1 任务触发中心初始化当前 9 项必修任务

触发条件只有一个：新教师首次写入 `teachers`，即系统首次识别到该教师进入试用期培养范围。同一教师重复同步、接口重试或补数不能重复创建。

初始化必须满足：

- 一次事务内引用当前已发布的 9 项必修任务，恰好创建 9 条；
- `task_kind = FIXED_GROWTH`；
- `creator_system = TRIGGER_CENTER`；
- `dedupe_key = fixed:{teacher_id}:{task_code}`；
- 初始 `status = ASSIGNED`，业务含义是“已生成、未完成”；
- 不写 `notifications`，不创建提醒或投递意图；
- 目录不是恰好 9 项、模板引用无效或最终少于 9 条时失败关闭，并记录内部异常 `TASK_BASELINE_INCOMPLETE`。

固定任务初始化必须幂等。事务先按 template_id UTF-8 bytes 顺序取得 G01–G09 九个 catalog shared locks，
在同一 snapshot 校验恰好九个 current PUBLISHED，再创建/补齐；模板换版使用 exclusive lock，不能在查询与
INSERT 之间退役模板。已有合法 assignment 保留原状态，只补缺失项，不覆盖教师端已经写入的进度或完成事实。

### 6.2 任务触发中心创建个性化任务

来源 handler 只写/更新类型化 match，并在同一事务递增对应 TASK_PLAN revision、冻结 eligibility/模板/copy/
时区依据并写 plan Outbox；不得直接以事件到达顺序 INSERT assignment。Task Planner 按 canonical typed seed
元组选首次证据。assignment 已存在时，后到或恢复的 canonical 更小 match 只关联原 assignment，不重选
seed、模板、Why、截止时间或 hash。

触发中心只能引用当前唯一 PUBLISHED 的 5 个 P 模板，并写入：

- `task_kind = PERSONALIZED_IMPROVEMENT`；
- `creator_system = TRIGGER_CENTER`；
- 可读的英文 `why`，以及对应的 `display_title`；
- 只含必要证据的 `evidence_snapshot`；
- canonical seed kind/key/revision 及冻结 payload hash；
- TASK_PLAN 冻结的 `eligible_since_at`、模板 revision/copy version、时区证据；
- 实际 INSERT 时间 `assigned_at`；due_at 仍按 eligibility 起点计算，不按 Planner 消费时间顺延；
- 与触发范围一致的 `dedupe_key`。

五类个性化任务的 assignment 键必须严格使用 3.2 已冻结口径：P-REL 为
`personalized:{task_code}:{teacher_id}`，`P-FB-NEGATIVE` 为
`personalized:P-FB-NEGATIVE:{teacher_id}:{label_id}`，`P-FB-COMPLAINT` 为
`personalized:P-FB-COMPLAINT:{teacher_id}:{complaint_type_grandson}`，`P-FB-BLACKLIST` 为
`personalized:P-FB-BLACKLIST:{teacher_id}`。不得把单次课程或地区阈值 match 的键当 assignment 键，
也不得仅用可变的 `label_name` 或分类名称去重。

match 转为 `SUPPRESSED` 不触发 assignment 删除、取消或状态回退；同键 match 恢复时更新原
`personalized_trigger_matches` 行并增加 `match_revision`，复用原 assignment，不新建证据行或任务行。

Planner 必须先完成同一键当前 match 集合重算，再按本契约 §3.2 的 canonical seed 排序创建 assignment；
同一事务写 assignment、seed match 关联及其他 active match 的 output 关联。唯一键冲突后只允许读取并校验
本次两个首次创建竞争者的同一 seed/payload hash。若 assignment 在加锁前已经存在，只校验其冻结字段
自洽并关联新 active match，不用当前最小 match 对比历史 seed。`P-FB-NEGATIVE` 阈值已达但任一贡献课程名称为空时不得跳过该课程；名称对应的
执行变体发生照片/通用冲突时以 `TASK_SEED_VARIANT_CONFLICT` 失败关闭。只有全部名称非空且执行变体一致
时，canonical 最小课程才提供冻结 payload。

教师端只消费共享行，不改 Why、标题、证据、优先级、截止时间或模板引用。

对需要特定教师端执行流程的个性化 assignment，触发中心必须把批准值写入类型化
`task_assignments.teacher_execution_variant`；evidence_snapshot 可保留同值作审计镜像，但不得成为路由
真值。该字段只选择已发布的执行变体，不代表教师端拥有触发规则：教师端不得根据课程次数、阈值或相似标签自行创建任务，也不得用模糊匹配推断变体。

`why` 只写面向教师的英文解释，并在数据库原值中包含最小必要证据摘要，例如课程 ID、迟到/早退、未填写 Lesson Memo、投诉等级、重复差评次数、不同学员拉黑人数或课堂设备异常。教师端、运营端和 API 均直接读取该字段，不在读取时二次拼接。可能为中文的上游标签、投诉分类或缺席原因不直接写入 `why`，原始值保留在 `evidence_snapshot`，供追溯和按需展开。任务实例创建后 `why` 仍不可修改；历史实例通过受控迁移一次性回填完整英文原因。

### 6.3 教师端更新所有已有任务

为简化运维，教师端数据库账号对 assignment 统一授予表级 CRUD；这不改变业务所有权。
Trigger 会拒绝教师端 `INSERT / DELETE`，并且只接受已有 assignment 的以下状态字段发生业务变化：

`status, status_reason_code, status_changed_at, completed_at, updated_by`

更新必须在 `WHERE` 中带旧 `row_version`：

```sql
UPDATE task_assignments
SET status = :new_status,
    status_reason_code = :reason_code,
    status_changed_at = :changed_at,
    completed_at = :completed_at,
    updated_by = :service_name
WHERE assignment_id = :assignment_id
  AND row_version = :expected_row_version;
```

影响行数为 0 时先重读，不盲目重试覆盖。数据库会自动递增 `row_version`、更新 `updated_at`、写审计，并在状态变化时写 Outbox。

## 7. 状态机

状态集：

`ASSIGNED / VIEWED / IN_PROGRESS / SUBMITTED / UNDER_REVIEW / COMPLETED / FAILED / EXPIRED / WAIVED / CANCELLED`

- `VIEWED / IN_PROGRESS / SUBMITTED` 来自教师真实动作，不由时间推断。
- `COMPLETED / FAILED / EXPIRED` 由教师端可信服务按模板完成标准产生。
- `WAIVED / CANCELLED` 只由有权运营或系统流程产生，教师端受限角色不能写。
- 合法边固定为：
  `ASSIGNED→VIEWED|IN_PROGRESS|SUBMITTED|UNDER_REVIEW|COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `VIEWED→IN_PROGRESS|SUBMITTED|UNDER_REVIEW|COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `IN_PROGRESS→SUBMITTED|UNDER_REVIEW|COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `SUBMITTED→UNDER_REVIEW|COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `UNDER_REVIEW→COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `FAILED→IN_PROGRESS|SUBMITTED|UNDER_REVIEW|COMPLETED`。
- `COMPLETED / EXPIRED / WAIVED / CANCELLED` 无出边。同状态更新不是状态转移，不能修改
  status_changed_at，只能按字段所有权更新允许的状态字段。
- `FAILED / EXPIRED / WAIVED / CANCELLED` 必须有 `status_reason_code`；`COMPLETED` 必须有 `completed_at`。
- 非法边、目标状态权限、原因/完成时间和旧版本分别返回
  `TASK_STATUS_TRANSITION_INVALID / TASK_STATUS_AUTHORITY_DENIED / TASK_STATUS_REASON_REQUIRED /
  TASK_STATUS_COMPLETED_AT_INVALID / TASK_ASSIGNMENT_VERSION_CONFLICT`，调用方不得盲重试。
- assignment 不允许删除。误报完成不能直接回退，必须走受控修正与审计。
- 阔知正式课程查询、逐任务进度、原始分数和判定快照只保存在教师端 `tide` Schema；全部必修条件由教师端可信后端判定后，仍只按本契约更新 assignment 状态字段。
- `P-FB-NEGATIVE` 的授课环境照片变体只对上述两枚精确标签开放，使用独立步骤键但复用 G04 的 `TEACHING_ENVIRONMENT_V1` 四项标准、置信度门槛、背景否决和安全提示。每次拍照均为一次性检测：检测后不保留照片和 `image_reviews / image_review_items`，不复用历史 PASS；AI 返回 RETRY 或技术性 ERROR 时保留 assignment 为 `IN_PROGRESS`，老师可重新拍照；本次四项全部 PASS 就更新为 `COMPLETED`，且始终不加固定成长积分。G04 不适用该一次性约束。
- G01、G05–G09 的考试／培训执行只使用阔知 iframe；G09 使用阔知课程 658，必修任务为视频 `3826 / 3831 / 3836` 与考试 `3829 / 3832 / 3834`（试卷 `589 / 590 / 591`），六项均以阔知返回的 `percent=100` 判定完成。课程中的三份 Job Aid 文档保留在阔知学习顺序中，但不单独作为 TIDE 完成条件。不得恢复 TIDE 本地 Mock 视频或小测。
- G02 使用 TIDE 原生版本化 `Overseas NT Policies` 文档；后端按 execution 的 `contentVersion / contentHash` 提供精确正文，读到末尾后在同一事务冻结 submission 阅读证据并完成 assignment，不写阔知同步记录。

## 8. 生产接入门

当前共享表、表级权限和数据库约束已在本地实现。生产还必须完成：

1. 教师端生产后端使用独立受限账号，不使用表所有者或超级用户。
2. 验证新教师写入后自动出现恰好 9 条 `ASSIGNED` 固定任务，重复同步不重复创建，且初始化不产生通知。
3. 逐边验证状态矩阵、同状态字段所有权、教师端不可写 WAIVED/CANCELLED、终态拒绝及旧 `row_version` 错误码。
4. 验证教师端不能改 `priority / why / display_title / evidence_snapshot / materialization_seed_* /
   materialization_template_revision / eligibility_generation / teacher_copy_version_id / teacher_copy_config_key /
   teacher_execution_variant / plan_evidence_hash / eligible_since_at / due_at / timezone_* /
   template_version_id / task_code`。
5. 验证每次创建/更新均有 `audit_events`，状态变化均有 `outbox_events`；固定任务初始化不得创建 `notifications`。
6. 验证同一 G assignment 重复完成不会重复加分。
7. 监控每位教师当前固定任务数量必须等于 9；偏差统一记为 `TASK_BASELINE_INCOMPLETE`，不得归为外部数据缺失。
8. 模板换版后，既有 assignment 仍按 row_id 显示 RETIRED 冻结内容并可合法更新状态；新建只能引用新
   PUBLISHED；task_code/template_id 错配被复合 FK 拒绝，G00 仍因无当前目录项而隐藏。
9. MATCH 个性化任务缺 eligible/due/timezone、due 等式错误、消费延迟或后到更小 seed 时分别验证失败关闭、
   截止时间不漂移且原 assignment seed/Why/模板不变。

通过以上验收前，只能称为“本地共享表契约可运行”，不能称为“教师端生产已打通”。
