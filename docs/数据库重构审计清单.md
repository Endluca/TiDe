# TiDe 数据库重构审计清单

状态：本轮结构清理已完成；当前 head 为 public rev49、tide 0029
范围：`public` 与 `tide` Schema
原则：每张表只保存一种不可替代的事实；可稳定派生的数据使用视图；源表只保留已确认的
业务字段，不增加同步控制字段。

数据库切换边界：在已选定的 TiDe 测试 PostgreSQL 实例中新建
`tit_growth_test_v2`；现有测试库保持不变，作为切换失败时的只读回退点。
旧源数据不迁移，验收只使用显式测试 Seed。建库和迁移必须同时通过连接串库名与
`current_database()` 双重校验，任何一个不是 `tit_growth_test_v2` 都停止。

当前实存核验（2026-08-07）：`public` head 为 `20260807_49_unused_columns`，`tide` head 为
`0029_remove_unused_columns_and_orphan_function`。rev48 将投诉规则来源合并为一张专用表，保留并原位瘦身
10 行 `score_accounts` 与 30 行 `score_component_accounts`，删除 4 张空置 public 表；0028
删除 6 张空置 tide 表和 5 个已被当前实现替代的分析视图。rev49 删除 3 个已有完整来源或从未独立更新的 public 冗余列；0029 删除固定为私有的文件可见性列和无消费者的孤儿函数。两张源表及其业务数据未被清理。
正式迁移前已在同实例克隆库完成 upgrade → downgrade → upgrade 往返；正式库迁移前后 72 张
非迁移物理表、197 行数据的逐表规范化哈希一致，临时克隆和备份库均已删除。0029 同时兼容
PostgreSQL 16 的 `attnotnull` 表示和 PostgreSQL 18 的独立 NOT NULL 约束依赖，其他列依赖仍失败关闭。

## 1. 目标边界

### 1.1 两张源表

| 表 | 内容 | 写方 | 读方 | 决定 |
|---|---|---|---|---|
| `public.teacher_source_wide` | CSV“教师维度”61 个字段 + 2 个 G01 外部状态字段 | 外部监控服务 | TiDe 增量 Worker、运营查询、教师端 G01 | `KEEP`，新增 |
| `public.lesson_source_wide` | CSV“课程维度”23 个字段 | 外部监控服务 | TiDe 增量 Worker、课程查询 | `KEEP`，新增 |

硬约束：

- 教师源表只在 CSV 61 列后追加 `is_cpl_tesol`、`is_self_introduce` 两个确认的业务字段；
  两张源表都不增加 `updated_at`、`source_version`、`row_hash`、`sync_run_id` 等同步字段。
- 外部监控服务只写这两张表，不能写任务、积分、资格、通知或运营表。
- 教师表以 `tchr_id` 唯一，课程表以 `课程id` 唯一；主键约束不算新增业务字段。
- CSV 课程表没有“是否复约”，数据库不得补造该源字段，也不得默认成 `0`。
- 同步批次、重试和水位由监控服务自行负责，不写入两张源表。

### 1.2 字段级更新

源表 Trigger 只比较 `OLD` 与 `NEW`，并在同一事务写入
`public.outbox_events`。当前链路已经实现：

```text
源表 INSERT / UPDATE / DELETE
→ Trigger 记录 source_table、source_id、operation、changed_fields、旧/新 teacher_id
→ 增量 Worker 消费 Outbox
→ 只定位受影响教师并幂等更新课程结果、积分组件、任务触发和资格
```

Trigger 不计算积分、不创建任务、不遍历课程。源表提交与派生更新是两个事务，Worker 默认
每 3 秒轮询；失败保留事件并退避重试。日常变化不扫描其他教师；为避免复杂易错的增量差分，
涉及聚合的课程字段会重算该教师的课程集合。只有积分规则发布执行全量重算，并与发布同事务。

当前已实现的边界从“两张宽表已提交变化”开始。国内/海外两个业务库到宽表每个字段的查询 SQL、来源字段与影响映射尚未提供；在这些契约到位前，Otter 监听、MQ 消费与宽表更新逻辑仍是待实现部分。

## 5. 保留对象及不可替代理由

- `complaint_rule_imports`：保存一份审核文件及其无损 43 行来源，不能由类型化规则替代。
- `teachers`：是 public 与 tide 的共同身份锚点，保留内部身份、首次识别和来源快照语义。
- `score_accounts`：保存维度当前值、规则版本和乐观锁；是当前写模型，不是可直接替换的视图。
- `score_component_accounts`：保存可解释子项、归因核对和投影修订，是字段级重算最小单元。
- `task_assignments`：是两端唯一任务实例及当前状态事实。
- `score_entries`：保存不可变奖励、冲正和人工调整流水，不能由当前总分替代。
- `outbox_events` 与 `audit_events`：分别承担可靠异步和不可变审计，不能互相合并。

## 6. 验收标准

### 6.1 结构

- 教师源表恰为 61 个 CSV 字段加 2 个 G01 业务字段，课程源表与 23 列 CSV 完全一致；
  两表均无额外同步控制字段。
- 每个业务事实只有一个物理写入位置。
- 所有 FK、视图、ORM、权限脚本和文档指向新结构。
- rev47–rev49 与 tide 0027–0029 标记删除的物理表、列、旧视图和孤儿函数不再存在，也没有运行代码引用。
- `public` 与 `tide` 不保存同一任务、积分、课程或通知事实副本。

### 6.2 增量更新

- 修改一个课程字段，Outbox 的 `changed_fields` 只包含真实变化字段。
- 修改一个课程字段，只重算该课程和所属教师相关组件，不扫描其他教师。
- 修改一个教师字段，只重算该教师受影响组件和门槛。
- 同一 Outbox 事件重复消费，结果不变且不产生重复流水或任务。
- 失败事件可重试；源表事务不执行重型业务计算。
- 新建 `tit_source_monitor` 权限组在全库仅有必要的 Schema 访问和两张源表 CRUD，无 Outbox 或其他业务表写权；真实 LOGIN 服务账号加入该组后必须再做实际连接验收。

### 6.3 业务一致性

- 新教师恰好出现 9 条 G01–G09 `ASSIGNED` assignment，重复更新不重复创建。
- 固定任务完成只结算一次；终态、乐观锁和字段写权限继续由数据库保护。
- 五维总分等于积分组件之和，教师视图与运营视图一致。
- 已获得的出营和金牌资格不会因重算撤销。
- 缺失值保持 `NULL/SOURCE_MISSING`，不得转换为业务零值。
- 课程源 CSV 没有“是否复约”时，页面和积分不得伪造该事实。
