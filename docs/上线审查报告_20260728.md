# TiDe 新师成长运营台上线审查

审查日期：2026-07-28
审查范围：运营 WebApp、后端 API、共享任务与积分链路、PostgreSQL 结构与数据、
权限和运行配置、外部依赖与发布条件。

## 结论

当前状态是：**公司共享测试环境可试跑、核心业务链路可继续联调，但不满足正式生产上线条件。**

| 判断 | 结果 | 依据 |
|---|---|---|
| 可开工 | 是 | 当前产品范围、任务事实、积分口径和读取契约均已落到代码与数据库 |
| 可联调 | 有条件可 | 共享测试库、运营端和教师端只读视图已具备；尚需教师端生产账号和真实外部数据接口 |
| 可上线 | 否 | 外部日更、真实投递、教师端生产验收、生产基础设施与数据差异仍未关闭 |

不能把“页面可打开、自动化测试通过、测试库有真实数据”表述成生产完成。

## 本轮已关闭的问题

### 前端

- 所有业务页面首次进入保持空态，只在运营主动点击更新时请求数据。
- 教师档案、课程证据、任务进展、触达记录和操作审计均使用分页结果，不再把全量明细
  一次塞进浏览器。
- 操作审计共享库现有 45,203 条记录；接口已改为每页 20 条，支持教师和关键词服务端
  筛选，不再把全部记录塞入浏览器。
- 修复历史审计 payload 不完整时页面只显示“系统 / —”的问题；事件类型、教师、
  任务、时间以审计表权威列为准。
- 修复积分 `v1` 草稿不可编辑的问题。草稿的业务分值和门槛可修改；任务数量、指标标识、
  结算方式、对外显示锚点等跨端结构字段继续锁定。
- 经营总览已用共享测试库复验：1,065 位培养教师、797 位有课程记录教师、
  37,317 节课程、当前运营待办 0、开放个性化任务 829。
- 首次进入仍保持显式空态；点击更新后经营总览、教师列表、教师详情、任务统计、
  任务明细和审计分页均已在真实浏览器回归，无页面崩溃。

### 后端

- API 统一鉴权和角色校验；会话 token 只存哈希，Cookie 为 HttpOnly、SameSite=Strict，
  生产环境自动启用 Secure。
- 生产环境缺少 Allowed Hosts、PostgreSQL 或数据库证书校验时启动失败；生产环境关闭
  OpenAPI 文档并返回最小健康信息。
- 生产环境示例已与 Nginx 同域 `/api` 代理对齐：API 信任 Web App 域名，同域部署不再
  错配 CORS；该契约已有自动化测试防止回归。
- API 增加安全响应头；业务响应禁止缓存。
- 任务、输出、待办和审计明细改为服务端分页；经营总览、教师、输出和审计均直接查询
  PostgreSQL，不再在 API 启动时装载完整业务工作集。
- 经营总览由读取完整教师 JSON 和 8 次数据库查询改为 4 次数据库聚合；共享测试库
  服务内实测约 2.6 秒降至 0.43 秒，HTTP 连续三次为 261–327 ms。
- 单任务教师明细不再读取该任务全部 ORM 对象后于内存分页；共享库 G01 首页服务内
  实测约 1.1 秒降至 0.39 秒，HTTP 连续三次为 368–425 ms。
- 输出重试已迁为数据库事务：输出、关联通知、审计事件和 Outbox 原子提交；共享测试库
  两个并行 Worker 同时重试只接受一次。
- 积分规则发布在同一事务内重算当前投影；失败则发布与重算一并回滚；已获得的出营、
  金牌资格不收回。
- 模拟 cohort 已通过受控脚本从共享测试库移除，不再作为启动时隐式数据。

## 正式上线阻塞

### P0：两个外部数据源的日更接口尚未接入

当前数据来自一次性教师宽表和课程明细导入。正式运行需要：

- 教师日更进入时幂等 upsert 教师，并初始化 G01–G09；
- 课程增量按稳定业务键幂等写入；
- 保存 source batch、游标、水位、原始记录、成功/失败数量和对账摘要；
- 支持断点续跑、重复投递、迟到数据和修正数据；
- 连续两个业务日完成自动同步、重跑和对账验收。

### P0：教师端生产消费尚未端到端通过

数据库已存在教师端只读视图和受限角色，但仍需教师端在生产候选环境证明：

1. 新教师出现后能读取自己的 9 项必修任务；
2. 教师端只能修改本人已有 assignment 的允许状态字段；
3. 状态更新后，成长任务分、五维总分、出营/金牌当前条件在两端一致；
4. 越权、重复请求、旧 `row_version`、并发更新均被拒绝或幂等处理。

接口或 SQL 单点成功不等于这条链路完成。

### P0：真实触达和回执尚未接入

当前站内通知、提醒、运营审批和外部动作只有可追溯记录，没有正式投递 Worker 和消费方回执。
上线条件：具备实际投递、送达/失败回执、重试、死信、人工补偿和监控告警，并用至少一条
成功与一条失败样例完成端到端验证。

### P0：生产运行基础设施尚未落到公司环境

仓库已有非 root 后端镜像、静态 Web/Nginx 同源代理、双 API Worker 与积分结算进程的
生产编排示例、一次性运营账号初始化命令，以及 fail-closed 的生产环境清单。但公司
HTTPS 域名、运行平台、数据库、证书、监控和发布流水线尚未实际创建，因此仍不是生产部署。

上线前必须完成：

- HTTPS 域名、反向代理、证书和可信 Host/Origin；
- PostgreSQL `sslmode=verify-full` 和 CA；
- 密钥托管与轮换，禁止 `.env` 进入镜像或仓库；
- 结构化日志、错误率/延迟/队列积压/同步失败告警；
- 备份、恢复演练、迁移前快照和回滚方案；
- 可追溯构建产物、版本号、发布审批和灰度/回退步骤。

### P0：当前源数据仍有两类未对齐

- 268 位培养教师没有课程明细；
- 295 位教师的教师宽表 `perfect_cnt` 与课程明细按 `is_perfect` 推导的数量不一致。

系统已把教师汇总分和逐课归因状态分开保存，不会自行平均拆分。但生产前需要数据方明确：

- 268 位是尚未上课，还是课程事实漏数；
- 295 位差异来自时间窗口、状态口径、迟到/早退口径，还是源表修正延迟；
- 以哪个来源作为教师总分权威值，何时允许标记 `MATCHED`。

### P1：权限和安全需要生产收口

- 测试库连接未启用 TLS，只能作为测试环境；
- `tit_growth_app` 不是超级用户，也无建库/建角色/建 schema 权限，但当前仍对
  32 个 public 关系（29 张业务表、2 个教师端视图和迁移元数据）拥有 DELETE；
  生产应按实际命令进一步收窄到确有写入需要的表；
- 登录缺少生产级限流、失败锁定或公司 SSO 接入；
- 生产入口应在网关增加请求体限制、速率限制和 Origin/CSRF 防护；
- 教师端角色与运营角色需要做逐表、逐视图、逐动作权限回归。

### P1：发布版本不可追溯

当前工作目录没有 Git remote，且存在 195 个未提交/新增/删除项。即使本机运行正常，
也无法把当前代码映射到一个不可变发布版本。

上线条件：清理并确认变更范围，完整提交，绑定远程仓库，生成 tag/commit SHA 和构建产物，
在干净工作区复跑测试。

## 建议的上线顺序

1. 接入教师/课程日更，关闭 268/295 两类数据差异。
2. 完成教师端共享任务与积分读取/回写端到端验收。
3. 接入真实通知和回执 Worker。
4. 将现有生产镜像部署到公司候选环境，完成权限、安全、备份恢复、迁移回滚和监控演练。
5. 在生产候选环境做一次 24 小时以上试跑，再决定灰度上线。

在上述 P0 项关闭前，最准确的对外状态仍是：**共享测试环境内部试跑，可继续联调，不可正式上线。**
