# 教师端任务语义迁移与联合部署验收

日期：2026-07-30

状态：**发布前验收口径。本文不是生产完成证明。**

## 1. 目标与边界

教师端生产迁移必须完整到
`0025_fixed_task_semantic_alignment`，使教师端执行事实与 TiDe 唯一当前固定任务目录
一致。迁移只调整教师端持有的 `tide.task_execution_versions` 业务编码和启停状态，
不能重建 execution、步骤、规则或教师进度，也不能改写 TiDe 持有的共享任务、积分和资格
事实。

联合部署只有在静态预检、数据库迁移、只读契约探针和业务冒烟全部通过后才允许切流。
任一技术门禁通过，只能证明该门禁范围内的条件成立，不能单独写成“已上线”“已送达”或
“业务验收完成”。

## 2. 唯一当前固定任务目录

| 编码 | 英文标题 | 分值 |
|---|---|---:|
| G01 | Profile & Credentials Completion | 3 |
| G02 | Platform Policies | 2 |
| G03 | How to handle different types of students | 2 |
| G04 | Lesson Preparation&Device Network Check | 3 |
| G05 | TTP Orientation | 3 |
| G06 | ME Culture & PARSNIP | 4 |
| G07 | Reliability Training | 3 |
| G08 | Cocos Course Training | 5 |
| G09 | SET Teaching Fundamentals | 5 |

目录必须精确为以上 9 项，总分 30。不能缺项、增加 G10、调整标题空格或标点、替换标题，
也不能只保持总分相同而改变单项分值。

## 3. 0025 迁移映射

0025 通过稳定的共享模板 `row_id` 识别业务语义，执行以下向前映射：

| 迁移前教师执行编码 | 迁移后编码 | 迁移后状态 |
|---|---|---|
| G01 | G01 | ACTIVE |
| G03 | G02 | ACTIVE |
| G04 | G03 | ACTIVE |
| G02 | G04 | ACTIVE |
| G06 | G05 | ACTIVE |
| G07 | G06 | ACTIVE |
| G08 | G07 | ACTIVE |
| G09 | G08 | ACTIVE |
| G10 | G09 | ACTIVE |
| G05 | G00 | RETIRED |

迁移在任何目录或 execution 计数校验前锁定稳定模板、assignment、execution 和待发布通知。
教师固定 execution 必须是全新库的 0 条或升级库的精确 10 条；9/10、未知稳定行、额外 G 编码
或目标编码冲突都会整笔失败。历史埋点不回写，分析 v2 只通过
`assignment -> stable template row` 解析当前编码，并单独保留 raw code；无稳定身份时标记
`UNRESOLVED`，不能用旧 code 猜测当前任务。

迁移必须在单一事务内完成。`0025` 是教师端生产迁移账本中的正式 head；生产链必须严格为：

```text
0001, 0002, 0003, 0004, 0005, 0006, 0007, 0008, 0009, 0010,
0011, 0012, 0013, 0014, 0015, 0016, 0019, 0020, 0021, 0022,
0023, 0024, 0025
```

`0017/0018` 曾越过所有权边界修改 `public.task_assignments`，不得进入生产链。数据库回退依赖
发布前一致性备份或向前修复，不执行破坏性 down migration 恢复旧任务语义。

## 4. 发布前证据

执行前冻结并留存：

1. 两个仓库已评审、干净且固定的 40 位提交 SHA。
2. TiDe Alembic head、教师端 `tide.schema_migrations` 全量有序账本。
3. 当前 `public.task_templates`、`public.task_assignments`、
   `tide.task_execution_versions`、执行步骤/规则和教师进度快照。
4. `public.score_entries` 及已获得出营/金牌资格事实快照。
5. 一致性数据库备份、恢复命令与隔离环境恢复演练结果。
6. 五套独立受保护环境文件及对应角色核验结果；凭据不得写入本文或仓库。
7. 所有尚未发布的固定任务通知配置：按标题、受众条件和目标任务的实际语义重新核对，
   不能只按编码替换。`G00/G10` 可直接判定为退役编码；其余旧编码与当前编码重叠，
   数据库无法仅凭 code 还原原始意图，必须由配置责任人确认后重新生成。

快照需包含稳定主键、外键、业务编码、状态、版本与必要内容摘要。表行数或页面截图不能代替
主键级前后对照。

## 5. 发布与验收顺序

### 5.1 静态预检

```bash
set -a
. /安全路径/combined.env
set +a

bash deploy/combined/preflight.sh
docker compose -f deploy/combined/docker-compose.yml config --quiet
```

预检必须正向确认：

- 教师端工作树干净，HEAD 等于已评审固定 SHA；
- 0025 迁移文件存在；
- 生产迁移器是上节列出的完整有序链，默认 head 为 0025；
- 源码目录中的 G01–G09 编码、英文标题和分值逐项精确匹配；
- 教师端不隐藏 G02、不包含 G10，生产链不包含 0017/0018。

只有 0024、缺少任一 G 任务、包含 G10、标题或分值错误，都必须失败关闭。

### 5.2 数据库迁移

停止两端写流量、教师后台任务和积分结算 Worker，完成一致性备份后依次执行：

```bash
docker compose -f deploy/combined/docker-compose.yml \
  --profile migration run --rm migrate

docker compose -f deploy/combined/docker-compose.yml \
  --profile migration run --rm teacher-migrate
```

TiDe 必须先到 `20260729_38_catalog_scores`，教师端随后完整执行到
`0025_fixed_task_semantic_alignment`。不得通过手工 SQL、部署脚本或目录同步器绕过
正式迁移账本改编码。0025 会拒绝仍引用 `G00/G10` 的待发布系统通知；命中时先取消旧配置，
按当前任务语义重新创建并复核，再重跑迁移。

### 5.3 最小权限与数据库契约

0024 会调整工单函数 owner，因此必须在完整教师端迁移之后，由 DBA 重放教师运行角色的
最小授权，再应用独立只读探针角色授权。随后执行：

```bash
docker compose -f deploy/combined/docker-compose.yml \
  --profile migration run --rm contract-probe
```

探针通过必须同时证明：

- TiDe Alembic head 精确为 38；
- 教师迁移账本精确、完整、有序且以 0025 结束；
- 数据库中的 G01–G09 编码、标题和分值精确匹配，总分为 30；
- 每位教师恰有 9 条当前固定 assignment；
- ACTIVE execution 通过稳定模板行对应当前 G01–G09；
- 探针使用独立只读角色、目标数据库与真实 TLS 会话；
- 教师端不能创建或删除共享 assignment，只能更新契约允许的状态字段；
- 共享工单函数 owner 与最小权限仍符合契约。

### 5.4 主键级前后对照

数据库迁移后，将第 4 节快照逐项回读并比较：

| 验收对象 | 必须变化 | 必须不变 |
|---|---|---|
| `tide.task_execution_versions` | 固定任务业务编码按映射调整；旧 G05 对应 execution 变为 G00/RETIRED | execution ID、共享模板行引用、教师关联 |
| 执行步骤、规则、教师进度 | 无 | 行 ID、execution 引用、已完成状态、结果与版本 |
| `public.task_templates` | 无 | `row_id`、当前编码、标题、分值、状态 |
| `public.task_assignments` | 无 | assignment ID、教师、模板行引用、当前状态与版本 |
| `public.score_entries` | 无 | 积分事实、幂等键、关联 assignment |
| 资格事实 | 无 | 已获得的出营或金牌资格 |

出现主键重建、进度减少、共享表额外写入、积分变化或资格撤销时，立即停止切流。不要用
“最终行数相同”放行。

### 5.5 运行时冒烟

先启动并观察积分 Worker，再启动运营 API、单副本教师 API 和两端 Web，最后启动 Edge
灰度。至少验证：

1. 教师登录后只看到精确 G01–G09；G04 是合并的备课与设备网络检测任务。
2. Foundation、Integration、Advance 分阶段分别为 4、3、2 项，路由到正确 execution。
3. 已有教师的完成进度未丢失，终态不能回退，重复写入符合 `row_version` 与幂等契约。
4. 教师端只更新已有任务状态；不会新建固定任务，也不会写分值、总分或资格。
5. 合法完成状态触发一次且仅一次积分结算，重复事件不重复加分。
6. 运营登录、课程/积分读取、工单教师回复与运营回复往返正常。
7. 两个域名、真实客户端 IP、限流、TLS、数据库连接池和后台任务租约符合部署配置。

## 6. 停止与放行

以下任一情况必须停止发布并保留现场证据：

- 静态预检或契约探针失败；
- 教师迁移账本只到 0024、缺项、乱序或出现 0017/0018；
- 源码或数据库任务目录与第 2 节不完全一致；
- 0025 无法通过稳定模板行唯一映射 execution；
- 任何 execution、步骤、规则、进度、assignment、积分或资格事实被意外重建或改变；
- 备份不可恢复、最小权限不成立、探针不是独立只读 TLS 会话；
- 冒烟出现任务错路由、进度丢失、重复计分或写权限越界。

放行记录必须写明两个提交 SHA、数据库目标、两端 migration head、快照对比结果、探针结果、
冒烟样本和遗留风险。只有这些证据齐全且有明确发布责任人确认，才可灰度切流；仍不得把灰度
技术通过扩大为业务效果或全量生产完成。
