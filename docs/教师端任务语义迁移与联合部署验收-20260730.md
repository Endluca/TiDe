## 1. 目标与边界

原位加入授课环境拍照步骤与四项 AI 审核。这些迁移均不得重建 execution、替换保留步骤／
规则主键、改写 assignment 或教师进度原始行；0037 还必须保留历史设备进度和检测证据。

任一技术门禁通过，只能证明该门禁范围内的条件成立，不能单独写成“已上线”“已送达”或
“业务验收完成”。

## 5. 发布与验收顺序

### 5.1 静态预检

```bash
set -a
. /安全路径/combined.env
set +a

bash deploy/combined/preflight.sh
docker compose -f deploy/combined/docker-compose.yml config --quiet
```

预检必须正向确认：

- 教师端工作树干净，HEAD 等于已评审固定 SHA；
- 0025–0032 历史迁移与 0033、0037、0038 文件均存在且没有重复编号；
- 生产迁移器是上节列出的完整有序链，默认 head 为 0038；
- canonical 账本精确为 33 条，0033、0037、0038 顺序固定；
- 源码目录中的 G01–G09 编码、英文标题和分值逐项精确匹配；
- 教师端不隐藏 G02、不包含 G10，生产链不包含 0017/0018。

只到 0037、缺少任一 G 任务、G04 仍含当前设备步骤、包含 G10、标题或分值错误，都必须失败关闭。

### 5.2 数据库迁移

停止两端写流量、教师后台任务和积分结算 Worker，完成一致性备份后依次执行：

```bash
docker compose -f deploy/combined/docker-compose.yml \
  --profile migration run --rm migrate

docker compose -f deploy/combined/docker-compose.yml \
  --profile migration run --rm teacher-migrate
```

联合迁移必须保持九阶段兼容顺序：TiDe 先到 revision 46，教师端到 0028；TiDe 再到
`20260810_50_g04_sections`，教师端到 `0032_first_login_onboarding`；然后 TiDe 到
`20260811_54_g04_remove_device_check`，教师端到 `0037_g04_remove_device_check`；最后 TiDe 到
`20260811_55_source_wide_v12`，再到 `20260811_56_p_fb_negative_copy`，教师端最后到
`0038_personalized_environment_photo`。public 54 阶段包含 rev51 G01 TESOL-only，teacher 37
阶段包含 0033 G01 规则迁移。不得在教师端 0031 之前先执行 public 54，也不得在 teacher 0037
之前执行 public 55，更不得跳过 public 55 直接执行 public 56；不得通过手工 SQL、部署脚本或目录同步器绕过
正式迁移账本改编码。0025 会拒绝仍引用 `G00/G10` 的待发布系统通知；命中时先取消旧配置，
按当前任务语义重新创建并复核，再重跑迁移。

### 5.3 最小权限与数据库契约

最小授权，再应用独立只读探针角色授权。随后执行：

```bash
docker compose -f deploy/combined/docker-compose.yml \
  --profile migration run --rm contract-probe
```

探针通过必须同时证明：

- TiDe Alembic head 精确为 `20260811_56_p_fb_negative_copy`；
- 教师迁移账本精确为 33 条、完整、有序且以 0038 结束，0033、0037、0038 顺序固定；
- `tide.account_onboarding_states` 的主键、账号级幂等键与终态约束完整；
- 数据库中的 G01–G09 编码、标题和分值精确匹配，总分为 30；
- 每位教师恰有 9 条当前固定 assignment；
- ACTIVE execution 通过稳定模板行对应当前 G01–G09；
- G01 共享模板和外部状态规则只包含 TESOL，教师运行角色不能读取 `is_self_introduce`；
- G04 execution 精确只包含照片 AI 审核与课件准备两个独立模块，当前步骤不存在设备检测，completion rule 只要求这两项；历史设备进度和检测证据仍存在；
- `P-FB-NEGATIVE:v1` 精确包含一个环境拍照步骤、四项 AI 审核和默认 PENDING 执行配置；
- `P-FB-NEGATIVE:v1` 的 How、完成标准、`score_type=ZERO` 与 `score_value=0` 精确匹配 rev55；
- 探针使用独立只读角色、目标数据库与真实 TLS 会话；
- 教师端不能创建或删除共享 assignment，只能更新契约允许的状态字段；
- 共享工单函数 owner 与最小权限仍符合契约。

### 5.5 运行时冒烟

先启动并观察积分 Worker，再启动运营 API、单副本教师 API 和两端 Web，最后启动 Edge
灰度。至少验证：

1. 教师登录后只看到精确 G01–G09；G04 是 `Lesson Preparation`，只显示照片 AI 审核和课件准备两张卡片。
2. Foundation、Integration、Advance 分阶段分别为 4、3、2 项，路由到正确 execution。
3. 已有教师的完成进度未丢失，终态不能回退，重复写入符合 `row_version` 与幂等契约。
4. 教师端只更新已有任务状态；不会新建固定任务，也不会写分值、总分或资格。
5. 合法完成状态触发一次且仅一次积分结算，重复事件不重复加分。
6. 运营登录、课程/积分读取、工单教师回复与运营回复往返正常。
7. 两个域名、真实客户端 IP、限流、TLS、数据库连接池和后台任务租约符合部署配置。

## 6. 停止与放行

以下任一情况必须停止发布并保留现场证据：

- 静态预检或契约探针失败；
- 教师迁移账本只到 0032、缺项、乱序或出现 0017/0018；
- 源码或数据库任务目录与第 2 节不完全一致；
- 0025 无法通过稳定模板行唯一映射 execution；
- 0031 或 0037 发现未知 G04 step/rule、0037 无法保留历史进度/设备证据或既有终态；
- 任何 execution、步骤、规则、进度、assignment、积分或资格事实被意外重建或改变；
- 备份不可恢复、最小权限不成立、探针不是独立只读 TLS 会话；
- 冒烟出现任务错路由、进度丢失、重复计分或写权限越界。

放行记录必须写明两个提交 SHA、数据库目标、两端 migration head、快照对比结果、探针结果、
冒烟样本和遗留风险。只有这些证据齐全且有明确发布责任人确认，才可灰度切流；仍不得把灰度
技术通过扩大为业务效果或全量生产完成。
