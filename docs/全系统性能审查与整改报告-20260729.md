# TIT Growth System 全系统性能审查与整改报告

日期：2026-07-30  
范围：运营端 FastAPI/PostgreSQL、积分结算 Worker、React 前端、生产运行参数，以及教师端
`new-teacher-training-camp-prototype/version2` 当前工作树的任务语义和同机部署边界。

## 总体结论

本轮最值得关注的风险不是某一条“慢 SQL”，而是同一种放大模式反复出现：
**请求或 Worker 先读取远大于页面/批次所需的事实，再在应用内关联、分组、重算或重试**。
数据量、并发和失败率一同上升时，它会同时放大数据库连接等待、Python 内存、CPU、响应体、
前端竞态和后台积压。

运营端的主要代码级放大点已整改并通过回归；隔离 PostgreSQL 已验证迁移和 generic prepared
plan 能使用新索引。教师端生产运行封装、正式迁移器、上传内存并发门、精确 readiness 和联合
契约探针也已落地。教师端旧任务已按稳定模板行原位映射到当前 `G01–G09`，旧 `G05` 以隐藏
`G00` 保留；真实 PostgreSQL 已验证 execution、步骤、assignment 和教师进度身份不变。
当前共享测试库仍停留在 revision 36，目标库尚未应用 37／38 和教师端 0025，生产 APM、
真实流量压测、备份恢复、灰度也尚未完成，因此结论是“代码级性能与语义门已收敛”，不是
“线上性能或发布已证明”。

## 背景和证据边界

- 业务场景：1065 位教师、约 3.7 万课程基线、共享任务状态、积分投影、运营检索与证据查看。
- 当前现象：没有提供生产 P95/P99、APM Trace、慢 SQL、GC 或 OOM 事件；风险起点主要来自
  静态代码、查询形态与本地 PostgreSQL 基准。
- 本轮本地对照值用于判断放大方向，不代表生产 SLA：

| 路径 | 整改前 | 整改后 | 变化 |
|---|---:|---:|---:|
| 干预中心列表 | 约 324 ms | 约 51 ms | SQL 端聚合与分页 |
| 教师选项 | 约 309 ms | 约 1.5 ms | 去除逐教师读取 |
| 经营总览 | 约 233 ms | 约 114 ms | 聚合查询替代全量对象投影 |
| 任务进展 | 约 60 ms | 约 40 ms | 摘要与明细拆分、服务端分页 |
| 干预中心峰值 Python 分配 | 约 45 MiB | 约 1.18 MiB | 不再保留全量 match/输出对象 |
| 教师选项峰值 Python 分配 | 约 75.6 MiB | 约 0.11 MiB | 仅投影选项所需列 |

这些数字来自本轮同机、同数据集的定向测量，只说明实现方向有效；生产仍需以相同请求集合、
固定并发和真实数据分布重测。

## 风险明细与处理结果

### 1. 运营读取路径全量加载和应用层关联

- 原风险等级：高
- 触发场景：干预、任务、教师、输出、课程或审计记录持续增长，运营人员并发刷新。
- 可能表现：请求 RT 和 RSS 随历史总量增长；数据库传输大量最终不会展示的行；页面第一页
  也要等待全表扫描和 Python 分组。
- 已处理：
  - 干预总览、干预分页、风险聚合、教师列表/选项、任务进展、输出和课程证据改为数据库过滤、
    聚合、排序和分页。
  - 干预证据按输出最多返回 20 条并显式标记 `evidence_sampled`，避免单个输出历史击穿页大小。
  - 已压制的 match 不再进入风险列表、signals 或开放输出统计。
  - 教师详情与列表只读取当前页面需要的列和关联统计。
- 代码依据：`backend/app/operations_service.py`、`backend/app/teacher_read_service.py`、
  `backend/app/task_service.py`、`backend/app/output_service.py`。

### 2. 积分重算与 Outbox 消费的 N+1 / 失败 O(N²)

- 原风险等级：高
- 触发场景：同一教师积累多条 assignment 状态事件，或投影/配置出现系统性异常。
- 可能表现：逐事件 assignment 锁查询；失败后每轮只排除一条再重做剩余组，最坏形成
  `N + (N-1) + ... + 1` 次准备和锁等待。
- 已处理：
  - 同一批事件一次性锁定相关 assignment，按教师分组结算。
  - 事件自身格式错误只失败该事件；配置/投影等组级错误一次标记该教师的全部合格事件。
  - 失败状态批量锁定、批量更新；未知异常只保存异常类名，不把潜在敏感文本放入 Outbox。
  - Worker claim 使用固定 SQL literal 以匹配 `PENDING` partial index；空批次前的系统错误直接上抛，
    不空转 100 次。
  - 启动即写 heartbeat，批次和 statement timeout 有界。
- 代码依据：`backend/app/shared_task_score_settlement.py`、
  `backend/scripts/settle_shared_task_scores.py`。

### 3. 审计搜索、活跃输出和待结算事件缺少可用索引

- 原风险等级：高
- 触发场景：模糊搜索审计、按输出聚合 match、Worker 持续领取 PENDING 事件。
- 可能表现：JSON 全量转文本、顺序扫描、排序放大；psycopg 切换 generic prepared plan 后，
  参数化常量导致表达式/partial predicate 与索引不再可证明等价。
- 已处理：
  - 审计搜索范围收敛到稳定结构化字段，增加 `pg_trgm` GIN 表达式索引。
  - 增加活跃输出、待结算 claim、逐教师审计序列和教师课程积分索引。
  - 固定空字符串、分隔符、`SUPPRESSED` 和 `PENDING` 使用 SQL literal。
  - 隔离 PostgreSQL 在 `plan_cache_mode=force_generic_plan` 下验证：
    - 审计搜索使用 `ix_audit_events_structured_search_trgm`；
    - Worker claim 使用 `ix_outbox_pending_settlement_claim` 的 Index Only Scan；
    - 活跃输出使用 `ix_personalized_trigger_match_active_output`。
- 代码依据：`backend/app/audit_service.py`、
  `backend/migrations/versions/20260729_37_read_path_indexes.py`。

### 4. 数据库连接、事务占用和密码哈希缺少容量边界

- 原风险等级：高
- 触发场景：登录突发、慢 SQL、数据库不可用或多个 API Worker 同时扩容。
- 可能表现：Argon2 抢占 CPU/内存；认证依赖在整个业务响应期间占住连接；连接创建或取池无限等待；
  请求堆积后形成级联超时。
- 已处理：
  - 明确配置每进程 pool size、overflow、取池超时、连接超时、回收和 LIFO。
  - PostgreSQL 会话设置 lock timeout、idle transaction timeout、statement timeout 和
    `application_name`。
  - 认证会话、账号和角色合并为一次 JOIN；生成身份后立即结束只读事务并释放连接。
  - Argon2 使用非阻塞并发闸门，登录按 IP+用户名做有界进程内速率保护；公司网关仍需承担
    全局限流。
  - 取池超时统一返回可识别 503；慢 API 只记录路由模板、状态、耗时和无凭据池指标。
- 代码依据：`backend/app/database.py`、`backend/app/auth.py`、`backend/app/main.py`、
  `backend/app/runtime_settings.py`。

### 5. 前端启动负载、重复读取和过期响应覆盖

- 原风险等级：中高
- 触发场景：用户快速切页、连续搜索/分页/刷新，慢请求晚于新请求返回。
- 可能表现：初始包过大；已取消页面仍更新状态；旧分页覆盖新筛选；刷新错误导致整棵已访问页面
  卸载并丢失状态。
- 已处理：
  - 登录区和工作区分包，工作区页面按访问惰性加载；生产构建已形成独立页面 chunk。
  - 所有主要读取使用 AbortController “latest request wins”；全量刷新会取消仍在运行的分页和
    详情请求。
  - 已访问页面保留挂载，切页不自动重读；全局错误展示不再卸载页面树。
  - 页面只在用户明确点击更新、搜索或分页时读取，并使用服务端分页。
- 代码依据：`frontend/src/App.tsx`、`frontend/src/WorkspaceApp.tsx`、
  `frontend/src/useLatestRequest.ts`、`frontend/src/pages/`。

### 6. 无消费方重试造成虚假积压和架构放大

- 原风险等级：中高
- 触发场景：运营点击输出重试，但真实外部投递 Worker 尚未部署。
- 可能表现：PENDING Outbox 持续增长，监控把“投递意图”误报成可消费 backlog；重试无法产生
  业务回执。
- 已处理：
  - 没有真实消费方的 retry intent 明确进入 `PARKED`，不冒充待处理事件。
  - revision 37 保存迁移前状态和错误摘要；隔离库已验证 upgrade → downgrade 可精确恢复。
  - 输出语义仍保持“已创建投递意图”，没有回执时不写成已送达或已执行。

### 7. 同机反向代理会放大错误限流、请求体复制和假健康

- 原风险等级：高
- 触发场景：公司网关、Edge 与教师 API 串联；多人同时登录或上传工单截图；数据库连接正常
  但教师身份表或积分视图缺失。
- 可能表现：全体教师被识别为同一个 Edge IP 并共享限流桶；合法的三张截图请求在 Nginx
  被 413；Edge tmpfs 重复缓存完整请求体；readiness 变绿但 My TIDE 核心读取失败；运营
  健康检查因 Host 不在 allowlist 永久返回 400。
- 已处理：
  - Edge 的 real-ip 链只信任显式公司网关 `/24`–`/32` 源范围，忽略直连请求自带的 XFF，
    再把上游 XFF 覆盖为单个规范客户端 IP；教师 API 只信任 Edge 一跳，运营 API 只信任
    Edge 固定容器 IP，不再把公司网关或整个私网段作为全体用户的限流键。
  - Edge 只允许绑定 loopback/RFC1918 规范 IPv4；公网、`0.0.0.0`、链路本地和 IPv6 均在
    预检失败关闭。运营健康检查使用 allowlist 内业务 Host。
  - Edge 与教师 Web 请求上限统一为 26 MiB，关闭请求体预缓冲；应用仍逐文件限制 8 MiB，
    1 GiB 教师 API 在 Multer 读取 Buffer 前默认最多接受 4 个 multipart 请求；超量返回带
    `Retry-After` 的可重试 429，只有完整下游处理结束才释放并发槽。
  - 教师生产默认联合模式固定为 `DIRECT_TABLES`；VIEWS 模式缺身份视图时拒绝启动，
    readiness 除身份来源和两张积分视图外，还核对完整正式迁移链、唯一最新 `0024`、
    当前工单/租约对象、索引、函数 owner 与运行账号权限，旧库不再假绿。
- 代码依据：`deploy/combined/docker-compose.yml`、`deploy/combined/edge-nginx.conf.template`、
  教师端 `src/main.ts`、`multipart-upload-concurrency.interceptor.ts`、
  `database.service.ts` 与 `frontend/nginx.conf`。

### 8. 迁移账号和工单 CAS 缺少失败关闭

- 原风险等级：高
- 触发场景：用 DBA/superuser 或错误数据库运行迁移；调用工单函数时传 NULL 行版本或消息。
- 可能表现：`SECURITY DEFINER` 函数继承超级权限；迁错库；NULL 三值逻辑绕过乐观锁；
  消息、状态和 48 小时窗口出现无版本并发写。
- 已处理：
  - 两端正式迁移器分别核对固定迁移账号、非 superuser、目标库和严格 TLS；运行与迁移环境
    文件分离。
  - 联合契约探针改用独立 `tit_contract_probe` 只读 LOGIN 角色和第五份受保护环境文件，
    不再借用 `tit_growth_migrator`；探针核对直接登录身份、目标库、实际 TLS、只读事务、
    无角色继承、无 Schema/表/序列写权限及无变更函数执行权。
  - 教师端 revision 0024 同时拒绝 NULL 版本和 NULL 消息，四个工单函数归属固定
    NOLOGIN 最小权限 owner；安全 downgrade 不恢复漏洞。
  - 联合探针断言 revision 38、教师 0022–0024、函数 owner、CAS 代码、双方函数执行权限和
    教师共享读取权限。
- 代码依据：`backend/migrations/env.py`、教师端
  `database/migrations/0024_support_ticket_cas_and_function_owner.up.sql`、
  `database/scripts/apply-production.sh`、`deploy/combined/run-contract-probe.sh`、
  `grant-contract-probe.sql` 和 `contract-probe.sql`。

### 9. 独立生产编排与新运行守卫不一致

- 原风险等级：高
- 触发场景：不采用联合部署、单独启动运营端生产 Compose。
- 可能表现：Alembic 因缺少迁移模式直接拒绝；迁移/API 共用数据库凭据；健康检查被 Host
  allowlist 拒绝；API 信任整个 Docker 私网，发布端口意外监听公网。
- 已处理：
  - 运行与迁移环境文件、数据库角色完全分离，Compose 显式注入迁移模式和目标数据库。
  - Web Nginx 使用固定容器 IP，API 只信任该精确地址；原点覆盖而不是继承入站转发头。
  - 健康检查发送允许的业务 Host；宿主端口默认只绑定 loopback。
  - 新增生产预检，失败关闭校验环境文件不复用、账号、私网绑定、容器子网及固定代理 IP。
- 代码依据：`docker-compose.production.yml`、`scripts/preflight_production.py`、
  `frontend/nginx.conf`。

### 10. 教师任务换码导致进度、通知和分析口径错位

- 触发场景：运营端已使用当前 `G01–G09`，教师端、历史事件或待发布通知仍按旧编码理解任务。
- 可能表现：相同 code 指向不同业务；错误搬迁或清空教师进度；阶段、积分和报表把不同任务
  混在一起；仅改标题后实际仍进入旧流程。
- 已处理：
  - 教师端按实际语义完成旧 `G01–G04,G06–G10` 到当前 `G01–G09` 的路由、阶段、内容、
    通知和前端适配，旧 `G05` 以不可见 `G00` 保留历史。
  - 0025 通过稳定模板 `row_id` 做两阶段原位换码；在计数前锁定模板、assignment、execution

    一律失败关闭。

    步骤、规则和进度主键；不重建 assignment，不清空教师状态。

    `assignment -> stable template row` 解析当前任务语义，同时暴露 raw code 和解析状态。

  - 明确出现 G00／G10 的待发布通知由迁移拒绝；G02–G09 新旧编码重叠，必须按真实受众和

## 其余审查维度

- CPU：主要风险来自 Argon2 和重复对象投影，已做并发限制和 SQL 下推；生产仍需 CPU profile。
- 内存：列表全量对象和前端全量响应已收敛；未发现长期无界应用缓存。
- 磁盘 IO/日志：应用不在请求热路径同步写业务文件；容器日志设置 10 MiB × 5 轮转。慢日志不
  包含 payload、SQL 参数或凭据。
- 网络 IO：运营核心路径当前以 PostgreSQL 为主，没有新增串行第三方链路；教师端 OSS、邮件和
  AI 依赖须分别设置超时并在生产 Trace 中验证。
- 并发/锁：共享写命令保留事务、行锁、CAS、幂等键和单实例积分 Worker；没有为追求吞吐取消
  终态保护或跨服务字段所有权。
- 缓存：当前没有引入 Redis 或进程缓存。对 1065 教师规模，先把查询有界和建立正确索引比增加
  缓存更可控；若后续确有读热点，必须先定义失效、版本和事实一致性。
- 架构放大：API、积分 Worker、迁移任务隔离；教师端后台任务仍嵌在 API，是联合部署的已知
  单副本限制。

- 教师 readiness：PostgreSQL 16 实测完整 `0024` 链返回可用；事务内移除 `0024` 后立即失败，

  拆为逐项 `AND` 后仅有 SELECT 返回 `false`、补齐必需写权限返回 `true`，临时库和角色已删除。
- generic plan：三条关键路径均命中新索引。
- 共享测试库：只读确认仍为 `20260729_36_perfect_score`，本轮未擅自应用 migration 37/38。
