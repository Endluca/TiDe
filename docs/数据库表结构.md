# TIT 成长系统数据库表结构

状态：唯一当前文档
数据库：PostgreSQL
核验日期：2026-08-07

## 1. 当前边界

本文档描述当前 ORM / Alembic head 的结构，并标注远程测试库实存验收结果。

- 当前 ORM 与 Alembic head 为 `20260807_49_unused_columns`，teacher 迁移代码 head 为
  `0030_remove_unused_columns_and_orphan_function`。远程 `tit_growth_test_v2` 的 public 已到 rev49，
  但 tide 仍是合并前旧编号的 `0029_remove_unused_columns_and_orphan_function`，尚未包含 release
  新增的 0027 本地 Quiz 清理；部署当前代码前必须受控重建或完成账本与实存结构对账。旧库 `tit_growth_test` 保持在
  `20260729_38_catalog_scores`，没有新增两张源表，也未原地改造。
- revision 39 新增 `teacher_source_wide` 与 `lesson_source_wide` 的 CSV 61/23 列基线；
  revision 46 在教师表末尾追加 `is_cpl_tesol`、`is_self_introduce` 两个可空 G01
  状态字段。两表都没有更新时间、版本、哈希或同步批次字段。
- revision 47 在确认数据为空、跨 Schema 分析视图已由其 owner 退役、且不存在外部依赖后，
  无 `CASCADE` 删除 `teacher_metric_snapshots`、`lesson_facts`、
  `lesson_dimension_scores`。这三张表已退出当前 ORM 和运行路径。
- revision 40–42 将 `tit_growth_app` 收紧为逐表、逐操作/列和最终有效权限；它只读两张源表，不能创建
  Schema 对象，也不能创建任务实例或运营账号。`tit_source_monitor` 只读写两张源表，不能直接写 Outbox。
- revision 43–45 新增逐课结果、不可逆资格事实、新读取视图和运行时列级权限；
  `tit_growth_app` 与 `tit_source_worker` 都不能写两张源表或删除资格。
- 任务域物理表只有 `task_templates` 和 `task_assignments`。`task_assignments` 是两端共用的任务实例及当前状态事实。
- 当前已发布目录是连续编号的 G01–G09 固定必修成长任务（合计 30 分）和 5 个个性化改善任务（不加分）；G00 是隐藏的退役历史记录。
- `complaint_rule_imports` 只保留一份已审核投诉规则文件及其无损原始行；教师、课程源数据
  只存在两张宽表。个性化规则命中及物化结果由 `personalized_trigger_matches` 追溯。
- 任务写入会由数据库校验所有权、状态流转、终态、固定任务唯一性和乐观锁，并写入 `audit_events`；状态变化同时产生 `outbox_events`。
- `complaint_rule_imports` 不承担两张宽表的同步水位，也不向运行服务开放。
- 站内通知和运营 Case 已可供调试，但真实投递 Worker 尚未接入，不能把通知意图解读为已送达。

### 1.1 外部数据日更

新的当前源事实入口已经建模为 `teacher_source_wide` 与
`lesson_source_wide`。外部监控服务未来只写这两张表；数据库 Trigger 只把真实变化字段写入
`outbox_events`，不在源表事务中计算积分或创建任务。SourceWide Worker 已实现事件消费、
字段路由、受影响教师重算、重试和死信；国内/海外两个业务库到宽表的查询 SQL 与字段影响映射尚未提供，因此 Otter、MQ 消费和宽表写入逻辑仍未接入。

旧教师快照、旧课程事实和旧逐课三行积分表已退役。投诉规则导入仍独立保留文件身份与原始行，
但它们不是新监控服务的写入目标。

生产形态需要每天从外部接口获取教师、课程和相关证据，然后完成拉取、完整性校验、标准化、幂等落库和受影响教师重算。以下内容尚未实现，不是当前表：

- 外部接口鉴权、分页/游标、水位和迟到修正规则；
- 每日调度、重试、失败告警和补数/重放；
- 接口原始响应的页级追溯、完整性水位和修正链。

SourceWide Worker 处理新增教师时会复用当前教师初始化入口：`teachers` 首次出现一位教师时
幂等补齐当前 9 项必修任务，统一为 `ASSIGNED`；已有教师的日更不重复生成任务，也不创建通知。

### 1.2 通用口径

- `timestamptz` 为带时区时间；`date` 只保留日粒度。
- `jsonb` 保存已有复合输入或快照；稳定查询字段仍使用类型化列。
- `NULL` 表示来源未提供或尚不确定；`0` 只表示明确的零值。
- `REAL / DERIVED_REAL / MOCK / MOCK_SIMULATION / MOCK_PROXY` 用于区分真实、真实派生和测试/代理数据。
- 当前积分列使用 `double precision`，本文按实际 Schema 记录，不写成尚未落库的精确小数类型。

## 3. 数据底座

### 3.1 `complaint_rule_imports`

一份已审核投诉分类规则文件的不可变来源记录。原来的通用批次头与逐行来源表已合并；该表
不记录两张宽表的同步批次、水位或版本，也不向运营运行角色开放。

| 字段 | 类型/必填 | 存在理由 |
|---|---|---|
| `source_sha256` | varchar(64)，PK，必填 | 文件内容身份，也是规则版本与幂等键 |
| `source_filename` | varchar(512)，必填 | 人可识别的原始文件名 |
| `raw_rows` | jsonb，必填 | 43 行无损原文；每行附 `source_row_number` 供精确追溯 |
| `imported_at` | timestamptz，必填 | 该审核文件被导入的时间 |

### 3.2 `teacher_source_wide`

教师维度当前源事实，一位教师一行。表中有 CSV 61 个字段，以及两个经确认的 G01
外部状态字段，共 63 列；`tchr_id` 是主键，不增加更新时间、版本、哈希或同步批次字段。

| 字段 | 类型/必填 | 存在理由 |
|---|---|---|
| `tchr_id` | varchar，PK，必填 | CSV 教师稳定业务键 |
| `real_name`, `tchr_group`, `tchr_group_desc`, `center_type_id`, `center_type_desc`, `bu`, `based_type`, `status`, `teach_area_type` | text，可空 | CSV 教师身份、组织和状态原值 |
| `status_on_date`, `status_off_date`, `last_on_date`, `onboard_date`, `onboard_30d_end_date`, `first_open_slot_dt`, `first_booked_dt`, `first_completed_dt` | date，可空 | CSV 日粒度状态与首次行为日期 |
| `is_ft_hbt`, `is_fte` | boolean，可空 | CSV 明确的 0/1/空标志 |
| `job_days`, `total_booked_cnt`, `peak_booked_cnt`, `total_completed_cnt`, `peak_completed_cnt`, `absent_cnt`, `late_cnt`, `early_cnt`, `anomaly_cnt`, `perfect_cnt`, `no_notice_cnt`, `first_completed_student_cnt`, `completed_again_student_15d_cnt`, `feedback_total_eval_cnt`, `feedback_praise_cnt`, `feedback_negative_cnt`, `feedback_complaint_cnt`, `feedback_valid_complaint_cnt`, `feedback_favorite_cnt`, `feedback_block_cnt`, `total_slot_cnt`, `reg_slot_cnt`, `peak_slot_cnt`, `slot_days`, `peak_slot_days` | integer，可空 | CSV 计数原值；`perfect_cnt` 只对账，不直接驱动计分 |
| `job_month`, `tchr_score`, `reliability_absent_rate`, `reliability_late_rate`, `reliability_early_leave_rate`, `reliability_late_early_rate`, `feedback_praise_rate`, `feedback_negative_rate`, `feedback_complaint_rate`, `feedback_rebook_rate`, `feedback_favorite_rate`, `feedback_block_rate`, `feedback_eval_rate`, `capacity_avg_completed_per_day`, `capacity_peak_slot_rate`, `capacity_key_slot_day_rate` | double precision，可空 | CSV 小数与比率原值；上游 `tchr_score` 不覆盖 TiDe 积分 |
| `is_cpl_tesol` | boolean，可空 | G01 的 TESOL 外部状态；`true` 完成，`false` 明确未完成，`NULL` 上游尚未提供 |
| `is_self_introduce` | boolean，可空 | G01 的 Self-intro 外部状态；三值语义同上 |

每个字段是否触发下游及最小重算范围由
`backend/app/source_contracts.py` 唯一登记。两个 G01 字段只刷新教师资料投影，不触发
积分、资格或课程重算，也不能单独完成 G01；当前规则不消费的 CSV 字段不会触发无意义计算。

### 3.3 `lesson_source_wide`

课程维度当前源事实，一节课一行。表中只有 CSV 23 个字段；没有“是否复约”，也没有额外同步字段。课程不对教师源表建 FK，避免两个上游资源因到达顺序互相阻塞；但 `老师id` 本身必填。

| 字段 | 类型/必填 | 存在理由 |
|---|---|---|
| `课程id` | varchar，PK，必填 | CSV 课程稳定业务键；禁止原地修改 |
| `老师id` | varchar，必填 | 确定受影响教师和下游归属 |
| `学员id` | varchar，可空 | 收藏和拉黑去重所需源事实；仅受限服务可读 |
| `上课日期` | date，可空 | CSV 本地日期，不猜时区 |
| `上课时间` | time，可空 | CSV 本地时间，不猜时区 |
| `课程状态`, `缺席原因明细`, `投诉一级分类`, `投诉二级分类`, `投诉三级分类`, `评价详情` | text，可空 | CSV 状态、投诉和评价原值 |
| `差评分` | double precision，可空 | CSV 数值原值；当前规则只保存，不计分或触发 |
| `是否高峰`, `迟到`, `早退`, `差评标签`, `是否拉黑`, `收藏`, `好评标签`, `未开摄像头`, `cpu占用过高`, `网络延迟过高`, `假早退` | boolean，可空 | CSV 0/1/空事实；空值保持未知 |

仅有两个读取索引：教师+课程时间用于逐课计分，教师+学员+课程时间用于收藏归因和拉黑去重。行级 Trigger 比较 `OLD/NEW` 后写一条紧凑
`source_wide.changed.v1` Outbox 事件；无变化 UPDATE 不发事件，Trigger 不做业务计算。

### 3.5 已删除的旧结构

revision 47 已删除以下三个空表：

- `teacher_metric_snapshots`：教师指标、计算输入、分数和原始 JSON 混合快照；当前权威来源分别是教师宽表、积分账户、任务事实和资格事实。
- `lesson_facts`：课程源数据的旧类型化副本；当前课程事实只来自 `lesson_source_wide`。
- `lesson_dimension_scores`：一课三行的旧积分结果；当前由 `lesson_score_results` 一课一行保存。

revision 48 又删除以下四张 public 表：

- `source_records`：43 行投诉规则原文已无损折叠进 `complaint_rule_imports.raw_rows`。
- `agent_decisions`、`provider_calls`：空置调试存储，无当前 public 业务消费者。
- `outbound_outputs`：重复聚合任务、通知和 Case；输出页现直接读取各自权威事实。

删除前由 `tide` Schema owner 先通过迁移 0028 退役唯一依赖旧教师快照的分析视图；
public 迁移随后锁表、确认三表为空并检查视图、外键、继承/分区和发布依赖，最后按依赖顺序
无 `CASCADE` 删除。downgrade 只用于结构回退，不恢复历史数据。
rev48 在删积分冗余列前会验证其确实等于自然键、教师营期或零值，并验证来源批次为空；
任何不一致都会停止迁移。`complaint_rule_imports` 已有新导入后，rev48 downgrade 会拒绝
编造旧 `source_records` 哈希、路径和批次标签，需先导出并走受控回退。

teacher 迁移 0029 继续用空表、G00 当前路由和外部依赖门禁，无 `CASCADE` 删除
`outcome_projections`、`camp_enrollment_projections`、`tide.audit_events`、
`task_template_files`、`file_migrations`、`teacher_photo_runs`，以及 5 个已被 analytics v2
替代的视图；`analytics_technical_quality_v1` 和 `analytics_help_usage_v1` 仍保留。

revision 49 在锁表并逐行核对可还原性后，无 `CASCADE` 删除
`complaint_category_rules.learning_title`、`complaint_category_rules.learning_url` 和
`operator_sessions.last_seen_at`。前两列的完整来源值仍保留在
`complaint_rule_imports.raw_rows`；会话活跃时间没有独立更新，与 `created_at` 完全相同。
teacher 0030 在确认所有文件均为 `PRIVATE`、没有外部列依赖、孤儿函数没有消费者后，
无 `CASCADE` 删除 `tide.file_objects.visibility` 和 `tide.enforce_outbox_target()`。

### 3.6 `complaint_category_rules`

投诉三级分类到处理级别的可追溯映射。每个来源文件内标准化三级分类唯一。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `rule_id` | varchar，PK，必填 | 投诉分类规则 ID |
| `source_sha256` | varchar(64)，FK，必填 | 对应 `complaint_rule_imports` 的审核文件 |
| `source_row_number` | integer，必填 | 来源行号 |
| `category_l1` | varchar，可空 | 一级分类 |
| `category_l2` | varchar，可空 | 二级分类 |
| `category_l3` | varchar，必填 | 三级分类原值 |
| `category_l3_normalized` | varchar，必填 | 用于精确匹配的规范化三级分类 |
| `source_level` | varchar，必填 | 来源表原始 P0–P4，保留原样 |
| `severity_rank` | integer，必填 | 严重度排序值 `0–4`，数字越小越严重 |
| `default_route` | varchar，必填 | 默认路由域 |
| `created_at` | timestamptz，必填 | 规则落库时间 |

学习任务标题和地址是投诉导入文件的原始属性，已保留在
`complaint_rule_imports.raw_rows` 的 `Course Title in the Learning Hub` 与 `link`，
不再在类型化规则表中重复存储。

### 3.7 `personalized_trigger_matches`

个性化规则的命中事实。它将“什么证据命中了哪条规则”与最终产生的教师任务、运营 Case、通知或数据待补记录连起来。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `trigger_match_id` | varchar，PK，必填 | 规则命中 ID |
| `trigger_code` | varchar，必填 | 稳定触发规则编码 |
| `rule_version` | varchar，必填 | 命中时的规则标识 |
| `teacher_id` | varchar，FK，必填 | 受影响教师 |
| `lesson_id` | varchar，FK，可空 | 相关课程；教师聚合规则也保留达阈值的课程 |
| `complaint_rule_id` | varchar，FK，可空 | 投诉匹配所依据的分类规则 |
| `dedupe_key` | varchar，唯一，必填 | 防止同一证据重复触发 |
| `output_type` | varchar，必填 | `TEACHER_TASK / OPS_CASE / NOTIFICATION / PENDING_DATA` |
| `output_title` | varchar，必填 | 运营可读的命中结果标题 |
| `output_id` | varchar，可空 | 物化后的任务、Case 或通知 ID |
| `match_status` | varchar，必填 | `MATCHED / MATERIALIZED / SUPPRESSED / FAILED / PENDING_DATA` |
| `evidence_snapshot` | jsonb，必填 | 命中当时所用的最小证据快照 |
| `matched_at` | timestamptz，必填 | 命中时间 |
| `materialized_at` | timestamptz，可空 | 产生对外输出的时间 |
| `updated_at` | timestamptz，必填 | 物化状态最后更新时间 |

## 4. 积分

### 4.1 `lesson_score_results`

当前课程源的一课一行积分结果，取代新链路中“一课三个物理行”的旧结构。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `lesson_id` | varchar，PK、FK，必填 | 对应 `lesson_source_wide.课程id`；源课删除时级联删除结果 |
| `user_feedback_score` | double precision，必填 | 本课好评与去重收藏分 |
| `reliability_score` | double precision，必填 | 本课完美完课与 Peak 完课分 |
| `class_quality_score` | double precision，必填 | 本课三项硬件质量分 |
| `lesson_total_score` | double precision，必填 | 上述三个维度之和，由数据库约束校验 |
| `dimensions` | jsonb，必填 | 三个维度的组件、证据状态和归因细节 |
| `score_rule_version` | varchar，必填 | 本次计算使用的规则版本 |
| `projection_revision` | integer，必填 | 内容实际变化时才递增的投影版本 |
| `calculated_at` | timestamptz，必填 | 最后一次实际重算时间 |

### 4.2 `score_accounts`

每位教师每个维度的当前积分写模型。复合主键为 `teacher_id + dimension`；保留物理表是因为
Worker 与规则发布事务需要原位更新分数、规则版本和乐观锁版本。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `teacher_id` | varchar，联合 PK、FK，必填 | 教师 ID |
| `dimension` | varchar，联合 PK，必填 | 五大积分维度之一 |
| `current_score` | double precision，必填 | 该维度当前累计分 |
| `score_rule_version` | varchar，必填 | 当前计分规则标识 |
| `version` | integer，必填 | 账户乐观锁序号 |
| `updated_at` | timestamptz，必填 | 账户最后重算时间 |

### 4.3 `score_component_accounts`

### 4.6 读取与更新语义

- 新的教师/课程源表更新：源表事务只写 `source_wide.changed.v1` Outbox；SourceWide
  Worker 默认每 3 秒轮询，在独立事务中按 `payload.changed_fields` 异步、幂等地更新派生结果。
- 课程重算语义：不扫描其他教师；为保证聚合和去重正确，会读取受影响教师的课程集合，
  更新一课一行结果，并按去重课程 ID 重算 `perfect` 与 `RELIABILITY`，按硬件质量规则重算
  `CLASS_QUALITY`；收藏按 `teacher_id + student_id_hash` 仅归因到上课时间最早的
  有效完课收藏，后续收藏课保留事实但该项为 0 分；
- 与积分无关的资料字段不触发积分重算；固定任务完成只更新任务组件、总分和资格，不扫描课程；
- 新积分版本发布：在发布事务内按新版本全量重算当前教师投影；任一重算失败则版本发布回滚。

源表更新与派生计算是两个事务：派生计算失败不回滚已提交的源事实，而是保留/重试 Outbox 事件。只有积分规则发布与对应全量重算必须同事务。现有教师端读取视图为：

- `teacher_scorecard_current`：一位教师一行，直接包含总分、资格、五维及全部子项；
- `teacher_lesson_score_current`：一节课一行，直接包含课程事实、三个课程维度及具体加分项；
  其中 `is_perfect` 为派生布尔值，仅在课程状态为 `end`、迟到为 `false`、早退为
  `false` 时为 `true`。该字段直接由 `lesson_source_wide` 派生；达标课程的
  4 分进入 `lesson_total_score`。课堂质量硬件项直接读取逐课三项异常字段，满足条件的
  2 分也进入 `lesson_total_score`。收藏总分读取教师源表 `feedback_favorite_cnt`；逐课
  `FEEDBACK_FAVORITE` 只做首次收藏归因，无法定位的差额保留为未归因分。

教师端任务仍读取 `task_assignments + task_templates`。完整字段对应见
`contracts/教师端积分与课程读取对照表.md`。

### 5.2 `task_assignments`

当前数据库硬约束：

- 当前 G01–G09 必须为 `FIXED_GROWTH + TRIGGER_CENTER`；5 个 P 任务必须是 `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER`。G00 历史行只读保留。
- 同一教师同一 G 任务只能有一条。已确认不存在复营或跨营期回补。
- 当前 9 项必修任务从 `ASSIGNED` 开始；该状态表示“任务已建立、尚未完成”。固定任务初始化不创建 `notifications`、提醒或投递意图。
- 教师端受限角色没有 assignment 的 `INSERT / DELETE` 权限，只能按状态机更新已有行的状态五字段。
- 有 `due_at` 时，三个时区证据字段必须同时存在；无截止时间时必须同时为空。
- `FAILED / EXPIRED / WAIVED / CANCELLED` 必须有 `status_reason_code`。
- `COMPLETED / EXPIRED / WAIVED / CANCELLED` 为不可回退终态；`FAILED` 可按状态机进入重试或完成。
- assignment 禁止删除；标识、教师、任务编码、模板引用、Why、展示标题、证据快照、来源和幂等键在创建后不可修改。
- `display_title` 和 `why` 不拼接中文上游值；投诉分类、差评标签、缺席原因等原始证据保留在 `evidence_snapshot`。个性化任务的数据库 `display_title` 必须是非空英文，`why` 必须包含 `Evidence:` 最小英文证据摘要；教师端、运营端和 API 均直接读取，不在读取时转换或二次拼接。数据库和应用在新建时拒绝含中文字符的教师端文案。
