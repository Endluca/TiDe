### 1.1 外部数据日更

目标 v2 的 DTS 当前事实入口是 `dts_source_rows`，领域权威写模型是
`source_courses + source_course_participations + teacher_student_relationship_*`；
`teacher_source_wide` 保留教师聚合，`lesson_source_wide` 降为切换期只读兼容投影。DTS 接入事务只做
账本、来源当前态/tombstone、脏键和 checkpoint，领域投影与积分在后续幂等重算事务完成。截至 2026-08-19，系统库已由
现场读回确认为 public `20260818_62_dts_claim_idx`；启用 direct 前还必须执行
`20260819_63_dts_direct_privacy`。
应用发布、direct 模式切换与执行计划/吞吐复验仍是独立门禁。DTS 仍须以 `projection=false`
完成真实连通性、readiness/heartbeat、双流 checkpoint 与账本验收。
DTS 最新部署边界要求海外消费者在
新加坡、国内消费者通过独立 Gaea 项目 `tida-camp-dts-dom` 在中国大陆集群运行；新 Pod 仍须读回
平台地域和 `TIT_DTS_EXECUTION_REGION=cn`。国内消息在构造海外 SQL 参数前只保留 `dom:v1:`
HMAC token，海外库不得保存原始国内学生 ID。数据库连接默认及正式环境使用 `verify-full`；当前
固定 `tide_system_test` PRE 专线端点可通过既有两项 DTS 门禁临时明文连接，但专线本身不提供
传输加密，数据库启用 TLS 后必须恢复 `verify-full`。当前仍
没有国内新 Pod 的成功
readiness/heartbeat、双流 checkpoint、目标写入和业务字段对账证据。

2026-08-19 源码新增尚未发布的显式 `direct` v1 替代路径。该路径在同一个 checkpoint 事务内
按 offset 逐条执行：字段白名单/HMAC 后，使用 before 撤销旧课程贡献、after 写入新课程
贡献，并以“新贡献减旧贡献”直接加减教师宽表字段；不写业务事件账本、通用业务源镜像或
脏键，只保留 `dom_complaint_cate` 参考字典和国内 HMAC 指纹契约，也不扫描整位教师课程重算。
教师/课程 INSERT，或当前完整镜像满足 cohort/课程范围的 UPDATE，可以创建主行；缺失主行的
DELETE、范围外 UPDATE 和子事件记为 ignored，不修改宽表但正常推进
`dts_ingest_checkpoints`。
这里的现行“课程范围”代码仍包含 `appoint.use_point='buy'` 和
`status NOT IN ('cancel','on')`。已确版目标要求从课程宽表准入中同时删除这两个条件：所有
`use_point`、所有 `status`（包括 `cancel/on/NULL`）都保留课程事实，派生指标再独立判断状态。
该路径只作为现行差异说明，不得发布为目标业务实现。目标 v2 中 direct/queued 复用同一持久化与
领域服务，不能清空数据后依赖七天增量重建，也不能永久忽略缺字典投诉。完整规则见
`DTS_direct开发冻结实施规格.md`。

旧教师快照、旧课程事实和旧逐课三行积分表已退役。投诉规则导入仍独立保留文件身份与原始行，
但它们不是新监控服务的写入目标。

生产形态需要每天从外部接口获取教师、课程和相关证据，然后完成拉取、完整性校验、标准化、幂等落库和受影响教师重算。以下内容尚未实现，不是当前表：

- 外部接口鉴权、分页/游标、水位和迟到修正规则；
- 每日调度、重试、失败告警和补数/重放；
- 接口原始响应的页级追溯、完整性水位和修正链。

SourceWide Worker 处理新增教师时会复用当前教师初始化入口：`teachers` 首次出现一位教师时
幂等补齐当前 9 项必修任务，统一为 `ASSIGNED`；已有教师的日更不重复生成任务，也不创建通知。

### 1.2 通用口径

- `timestamptz` 为带时区时间；`date` 只保留日粒度。
- `jsonb` 保存已有复合输入或快照；稳定查询字段仍使用类型化列。
- `NULL` 表示来源未提供或尚不确定；`0` 只表示明确的零值。
- `REAL / DERIVED_REAL / MOCK / MOCK_SIMULATION / MOCK_PROXY` 用于区分真实、真实派生和测试/代理数据。
- 当前积分列使用 `double precision`，本文按实际 Schema 记录，不写成尚未落库的精确小数类型。

## 3. 数据底座

### 3.1 `complaint_rule_imports`

一份已审核投诉分类规则文件的不可变来源记录。原来的通用批次头与逐行来源表已合并；该表
不记录两张宽表的同步批次、水位或版本，也不向运营运行角色开放。

| 字段 | 类型/必填 | 存在理由 |
|---|---|---|
| `source_sha256` | varchar(64)，PK，必填 | 文件内容身份，也是规则版本与幂等键 |
| `source_filename` | varchar(512)，必填 | 人可识别的原始文件名 |
| `raw_rows` | jsonb，必填 | 43 行无损原文；每行附 `source_row_number` 供精确追溯 |
| `imported_at` | timestamptz，必填 | 该审核文件被导入的时间 |
| `status` | varchar，必填 | `DRAFT/PUBLISHED/RETIRED`；全表最多一条 PUBLISHED |
| `publication_revision` | bigint，必填 | 发布生命周期乐观锁；状态改变严格递增 |
| `activation_generation` | bigint，条件必填 | DRAFT为NULL；曾PUBLISHED版本唯一且全局单调，首版1、每次换版+1 |
| `row_count/content_hash` | integer/varchar(64)，必填 | raw_rows 与解析规则行发布前一致性证据 |
| `published_at/retired_at` | timestamptz，可空 | 受控发布/退役时间 |

数据库对 `status='PUBLISHED'` 建全表唯一部分索引。发布事务取得 cutover shared mutex 与
complaint-rule-catalog exclusive advisory lock，校验 raw_rows↔规则行 count/hash、原子 RETIRE 旧 SHA并
PUBLISH 新 SHA、写审计并唤醒两区在 L1/L2/L3 引用受影响分类的课程。Worker 读取规则时取 catalog shared
lock并在提交前 CAS active SHA；禁止按 created_at 或无 ORDER BY 选择规则。PUBLISHED/RETIRED import 的
raw_rows及其 `complaint_category_rules` 由 Trigger 禁止 UPDATE/DELETE；修正只能导入新 SHA。
唯一发布入口为
`publish_complaint_rule_import_v2(source_sha256,expected_revision,idempotency_key)`，其中 source_sha256就是本表
PK。无旧 current时 DRAFT→PUBLISHED；有旧时同事务旧 PUBLISHED→RETIRED、新 DRAFT→PUBLISHED、audit和
差异 fan-out。RETIRED终态，current PUBLISHED不得单独退役/删除或原地修改，普通角色无 status写权限；
expected revision冲突、异参重放或半发布返回冻结规格的稳定错误。同 key/hash成功响应丢失后幂等返回原结果。
发布 fan-out 的dirty catalog identity固定为`COMPLAINT_RULE_SET/ACTIVE_COMPLAINT_RULE_SET`，revision使用新版本
activation_generation，version_id使用source_sha256，payload_hash使用content_hash；不得比较不同SHA各自的
publication_revision。

### 3.2 `teacher_source_wide`

教师维度当前源事实，一位教师一行。表中有确认映射的 53 个字段，以及两个教师资料状态字段，
共 55 列；G01 只消费 TESOL。`tchr_id` 是主键，不增加更新时间、版本、哈希或同步批次字段。

| 字段 | 类型/必填 | 存在理由 |
|---|---|---|
| `tchr_id` | varchar，PK，必填 | CSV 教师稳定业务键 |
| `real_name`, `center_type_id`, `bu`, `status` | text，可空 | 教师身份、组织和状态原值 |
| `center_type_desc` | text，可空 | 已确版目标映射：`center_type_id=1`→`CBT`、`5`→`TBT`，其他所有值（含源 `NULL`）→`HBT`；当前代码对未列出值仍会写 `NULL`，待后续修复 |
| `teach_area_type` | text，可空 | 已确版目标枚举为 `dom/ovs`；当前存量及投影中的国内旧值 `dmo` 必须在后续代码/数据迁移批次统一为 `dom` |
| `status_on_date`, `status_off_date`, `last_on_date`, `onboard_date`, `onboard_30d_end_date`, `first_open_slot_dt`, `first_booked_dt`, `first_completed_dt` | date，可空 | CSV 日粒度状态与首次行为日期 |
| `first_open_slot_evidence_status`, `first_booked_evidence_status`, `first_completed_evidence_status` | varchar，目标新增 | `CONFIRMED/CONFIRMED_EMPTY/LEGACY_FROZEN/SOURCE_MISSING`；解释三项历史首次日期 |
| `job_days`, `total_booked_cnt`, `peak_booked_cnt`, `total_completed_cnt`, `peak_completed_cnt`, `absent_cnt`, `late_cnt`, `early_cnt`, `anomaly_cnt`, `perfect_cnt`, `no_notice_cnt`, `first_completed_student_cnt`, `feedback_total_eval_cnt`, `feedback_praise_cnt`, `feedback_negative_cnt`, `feedback_complaint_cnt`, `feedback_valid_complaint_cnt`, `feedback_favorite_cnt`, `feedback_block_cnt`, `total_slot_cnt`, `reg_slot_cnt`, `peak_slot_cnt`, `slot_days`, `peak_slot_days` | integer，可空 | 计数原值；`perfect_cnt` 只对账，不直接驱动计分 |
| `job_month`, `reliability_absent_rate`, `reliability_late_rate`, `reliability_early_leave_rate`, `reliability_late_early_rate`, `feedback_praise_rate`, `feedback_negative_rate`, `feedback_complaint_rate`, `feedback_favorite_rate`, `feedback_block_rate`, `feedback_eval_rate`, `capacity_avg_completed_per_day`, `capacity_peak_slot_rate`, `capacity_key_slot_day_rate` | double precision，可空 | 小数与比率原值 |
| `is_cpl_tesol` | boolean，可空 | G01 的 TESOL 外部状态；教师当前证书集存在 `certification_code='16' AND certification_status=1` 时为 `true`，已完整观测且不存在时为 `false`，增量期从未触达为 `NULL` |
| `is_self_introduce` | boolean，可空 | 保留的 Self-intro 教师资料状态；三值语义同上，不参与 G01 展示或完成判断 |

每个字段是否触发下游及最小重算范围由
`backend/app/source_contracts.py` 唯一登记。两个教师资料字段只刷新教师资料投影，不触发
积分、资格或课程重算；G01 只读取 `is_cpl_tesol`，且该字段也不能单独完成 G01。当前规则
不消费的 CSV 字段不会触发无意义计算。

v2 三项首次日期不是当前集合 min：分别从 schedule 曾经 on 的版本历史、普通参与历史、initial/已批准
completion 快照历史取最小日期，普通 UPDATE/DELETE、source_deleted 或完课纠错不能清空或移晚。cutover
与同 fence 的 v1 旧值取 LEAST；旧值更早而 v2 历史无法证明时保留并标 LEGACY_FROZEN。双空只有对应
HISTORY 从 onboard_date 覆盖到 fence 时为 CONFIRMED_EMPTY，否则为 SOURCE_MISSING。普通运行角色只能
写入更早日期；修正错误历史值需受限纠错和审计。

### 3.3 `lesson_source_wide`（现行 v1 兼容表）

该表是现行一课一师兼容结构，不再是 v2 权威写模型。代码 head 已由 rev73 从 CSV 23 列基线物理删除“假早退”，现有 22 个业务字段加内部 `source_region`，共 23 个物理列；v2 启用前必须按
expand-contract 两阶段迁移：先暂停唯一 consumer 并冻结 checkpoint H0，只加可空 `source_region`、候选
复合索引和仅接受显式地区/合法事务 GUC 的临时 Trigger；发布全部 CRUD/ON CONFLICT/查询携带地区的
`V1_COMPAT_DUAL_CAPTURE` binary，但 consumer/旧 Worker继续暂停。存量回填无 NULL/冲突、全部复合 FK 可
唯一证明后，在同一暂停窗口完成第二次 NOT NULL、复合 PK/FK并移除单键依赖；两次 DDL、新 binary smoke
和复合关联全部通过后才从 H0 恢复。旧 binary 不允许穿过第一阶段 Trigger继续写，也不存在恢复后仍由单列
PK 承载 DOM/OVS 同号课程的窗口。
业务取消
“假早退”后兼容字段为 22 个。v2 权威事实使用 3.3.2 的 `source_courses` 与
`source_course_participations`；切换后本表只读，禁止 direct/queued 继续把当前 t_id 覆盖为唯一教师。

课程行准入不以 `appoint.use_point` 或 `appoint.status` 为条件。`课程状态` 保存源值，不得因为状态是
`cancel`、`on`、未知值或 `NULL` 删除/忽略课程行。状态是否参与完课、计分、预约等聚合由对应派生

归因。国内学生键继续只能使用 `dom:v1:` token。`appoint.end_time` 已确认为业务权威完课时间，
也是收藏 24 小时观察起点；不得改用 DTS 到达时间。关系历史修正影响观察时刻真值时，
必须标记归因变脏并按业务生效时间重算：应加未加时补 5 分，只有证据完整且明确应扣才扣 5 分；证据暂缺
时归因转 `AWARDED_PENDING_EVIDENCE` 并继续保留原分，
再按规则重选唯一获分课程。完课 TRANSFER/VOID 不原地改观察：旧当前观察分别转
`INVALIDATED/VOIDED`，需要重评时插入 `observation_revision+1`。同一候选被冲正后再次获奖时
`award_generation+1`，新奖励幂等键包含观察修订和 generation；冲正只引用原奖励流水，不能被旧奖励键吞掉。

favorite INSERT 缺 `add_time` 时，source_timestamp 只允许用于确定性排序和当前关系更新，必须写
`effective_time_evidence_status=SOURCE_MISSING`。这类记录不能证明观察点历史真值；观察写
`WAITING_EVIDENCE/FAVORITE_EFFECTIVE_TIME_MISSING` 且不加分。后续补齐权威 add_time 后重新排队重评。

favorite UPDATE 的 after.add_time 或 DELETE 的 source_timestamp 为空时同样为未知关系边界：可能跨越该
边界的观察进入 WAITING_EVIDENCE，已有奖励进入 held态且不按到达时间扣分；权威时间补齐后再重评。唯一归因候选按
observed_at ASC，再按 appoint topic 固定 ID 类型的 numeric/UTF-8 bytes ASC；禁止 varchar 或到达顺序决胜。

deferred trigger 要求 AWARDED 的 teacher/participation等于当前 completion且观察仍 CONFIRMED_TRUE；
AWARDED_PENDING_EVIDENCE 仍计分并与 AWARDED共同占用师生/课程当前奖励唯一约束，只可引用同教师/参与的
PENDING/EVALUATING/RETRY/DEAD/WAITING_HISTORY/WAITING_EVIDENCE，hold_reason对应
REVALIDATION_PENDING/WAITING_HISTORY/WAITING_EVIDENCE且不新加流水。证据真则原 generation回 AWARDED，
明确假/VOID/TRANSFER才唯一冲正为 REVERSED。REVERSED 历史豁免当前指针约束。

观察状态、owner函数和字段组合约束按冻结规格 §4.6：claim把到期 PENDING/RETRY原子转 EVALUATING并
attempt+1；expired EVALUATING由 reaper转 RETRY或第8次 DEAD+Case；完成可转两种 CONFIRMED/WAITING，技术
失败转 RETRY/DEAD；evidence变化经受限 requeue，DEAD只能受限恢复，INVALIDATED/VOIDED终态。只有
EVALUATING可有 lease，PENDING/RETRY必须有 next_attempt_at，DEAD attempt=8；Trigger拒绝直接状态写和旧
lease/row_version。origin/created generation不可改，rollback/再次cutover只改 is_serving与serving generation。
正常claim/reaper签名不接收now：各自在数据库函数入口只读一次clock_timestamp作为领取/过期边界，Worker
主机时间不能使未来观察提前获分或提前回收租约；cutover reducer仍只用run冻结evaluation_as_of。
`favorite_observation_evidence_fingerprint_v1` 对completion revision、关系current/history、有效HISTORY scope
epoch/vector和rule version做canonical JSON v1 SHA-256；受限requeue在fingerprint变化时把observation-local
required_evidence_revision+1。同fingerprint重放no-op。EVALUATING期间只提高required、不抢lease；claim冻结
claimed=required，完成/失败/reaper发现required>claimed时不得提交旧结论或计失败，只清lease回PENDING立即重评。
确定/等待状态completed=required，EVALUATING独有claimed；deferred CHECK锁定组合，消除证据变化lost wakeup。
DEAD恢复函数精确为
`recover_favorite_observation_v2(command_id,source_region,source_appoint_id,expected_observation_revision,
expected_dead_generation,expected_row_version,reason)`；永不过期command幂等记录先于状态校验，同request返回

成功转PENDING、attempt=0、next=transaction_timestamp()且保留dead_generation。响应丢失后即使再次DEAD，

#### 3.3.3 `dts_source_scope_states` / `dts_source_scope_snapshots`

`dts_source_table_publish_generations` 以 `(source_region,source_table)` 为 PK，字段固定为
`current_generation>=0`、current_snapshot_id、active_candidate_snapshot_id、candidate_owner/
lease_token/lease_expires_at、row_version/updated_at。expand 对每个白名单 region/table Seed generation=0；
generation=0 时 current snapshot为空，>0 时必须复合 FK 到同表 COMPLETE且 published_generation相等的
snapshot。candidate ID与三枚 lease字段全空或全非空，同表 GLOBAL/TEACHER 共用一枚 head，禁止并发 candidate。

唯一 begin/heartbeat/abort/expired-takeover/publish函数、lease token防 ABA、成功响应丢失 no-op与
`SNAPSHOT_PUBLISH_STATE_CONFLICT` 规则按冻结规格 §4.7。publish同事务把 snapshot
published_generation=base+1、head generation/current snapshot更新并清 candidate；失败/取消/超时必须经受限
函数把 candidate置 FAILED并清 head，普通角色不能手工释放或推进 generation。

`dts_source_scope_states` 证明某张来源表在全表或某教师 scope 下是否已经完成权威快照/对账。复合主键为
`source_region + source_table + scope_kind + scope_level + scope_key`，其中 `scope_kind=CURRENT/HISTORY`，
`scope_level=GLOBAL/TEACHER`；GLOBAL 的 `scope_key='*'`，TEACHER 的 key 为规范化教师 ID。字段固定为：

- `state=INCOMPLETE/LOADING/VERIFYING/COMPLETE/FAILED/STALE`；
- `active_snapshot_id` 可空 FK，始终指向最后一次成功原子发布的 epoch；非 COMPLETE 时只可作为旧 current
  与 diff 基线，不能提供集合完整性；
- `candidate_snapshot_id` 可空 FK，指向本轮装载尝试；失败时保留，下一轮以新 ID 原子替换；
- `completed_at/invalidated_at/row_version`，每次状态转换按旧 row_version 乐观锁并递增。

`dts_source_scope_snapshots` 以全局唯一 `snapshot_id` 为 PK，同时保存完整 scope 复合键，并对
`snapshot_id + scope 复合键` 建唯一约束供双指针和 staging 使用复合 FK。至少包含
`epoch_state=LOADING/VERIFYING/COMPLETE/FAILED/STALE/SUPERSEDED`、`snapshot_as_of`、上游
`snapshot_consistency_token/snapshot_fence_vector`、逐 epoch/topic/partition 的
start_next_offset/end_next_offset向量、row_count/content_hash、base_publish_generation、条件非空且按
region/table唯一的 published_generation、generation_diff_count/hash、HISTORY 的 history_from/through、错误码
和生命周期。staging每 key冻结 base_source_row_revision/base_row_hash。
`dts_source_snapshot_rows(snapshot_id+scope+source_key)` 必须 FK 到该 epoch；发布后的 epoch staging 禁止
UPDATE/DELETE。即使 active 是合法空集，也由 scope 指针和 epoch 证据证明，不能用 membership 无行反推。

状态机固定为：首次 `INCOMPLETE→LOADING(candidate 新建、active NULL)→VERIFYING→COMPLETE`；刷新或
订阅重置/offset 回退先把 scope 与旧 active epoch 标 STALE，但保留 active/current，再新建 candidate 并走
`STALE→LOADING→VERIFYING`。失败时 candidate epoch 与 scope 同时 FAILED，active 不变；恢复必须新建
snapshot_id，旧失败 epoch/staging 保留。发布事务锁定 scope 并校验
`row_version + candidate_snapshot_id + candidate epoch=VERIFYING`，同一事务完成 replacement diff、
current/membership 切换、candidate→COMPLETE、旧 active→SUPERSEDED、active=candidate、candidate=NULL、
scope→COMPLETE；任何一步失败全部回滚。新 candidate 发布前不得提前移动 active 或混读两个 epoch。

同一 region/table跨 scope一次只装载一个 candidate；publisher要求 head generation仍等于 candidate base，
重放 snapshot token fence后的 CDC至锁内 end_next_offset并逐键核对 live revision/hash。GLOBAL缺 key写
tombstone，TEACHER缺 key只清该 scope membership。每个 SNAPSHOT_DIFF 保存同一
source_table_publish_generation并以 `(region,table,generation,snapshot_id)` 复合 FK到 COMPLETE snapshot；
旧 generation不可回退 current。token/fence、candidate owner/lease、revision barrier任一不符整次失败。

同表同 kind 存在 TEACHER scope 时始终优先于 GLOBAL，即使教师 scope 非 COMPLETE 也不得回退使用 GLOBAL。
只有 scope state 与 active epoch 同时 COMPLETE 时，空集合才可推导 TESOL=false、处罚异常=false 或数量 0；
收藏在观察时刻还必须有对应 HISTORY 覆盖，否则返回 NULL/`SOURCE_MISSING` 或 `WAITING_HISTORY`。

四张 scope 表的 epoch/snapshot baseline、BASELINE/SNAPSHOT_DIFF source 版本和发布切换只允许 Scope
Coordinator 角色写；普通 Ingestor 只写 CDC 版本/checkpoint，并只可通过 SECURITY DEFINER
`scope_membership_apply_cdc()` 更新 active membership overlay。Domain/Worker/应用角色只读 scope 证据。
Trigger 拒绝跨角色改 active/candidate/epoch/staging/baseline/overlay，并拒绝发布后改写 staging。

#### 3.3.4 `dts_source_row_versions` 与地区化脏键

v2 新增 `dts_source_partition_epochs`，PK 为
`(source_region,source_partition_epoch_id,topic,partition_id)`，`epoch_kind=BROKER/SNAPSHOT_BASELINE/
SNAPSHOT_DIFF`。BROKER 行保存已验证 `stream_generation_id/epoch_opening_id`、
`status=BARRIER_PENDING/ACTIVE/SUPERSEDED`、start_offset、reason、`epoch_sequence>=1`、predecessor、
`v2_epoch_bootstrap_floor`、`activation_mode=H0_BOOTSTRAP/SNAPSHOT_MANIFEST`、activation manifest count/hash、
bootstrap/cutover run 与生命周期。epoch id 由 region/topic/partition/两 ID 的 canonical hash 生成；同
region/topic/partition/sequence 唯一且最多一个 ACTIVE。synthetic 行必须有 snapshot_id/source_table、无
broker 两 ID，按 `region+kind+snapshot_id+source_table` 确定 epoch id，topic 为保留 baseline/diff topic、
partition=0、status=SEALED，并以四元组唯一/FK 到 scope snapshot；它们没有 checkpoint，也不参与 broker
lineage。

全部 configured partition 的首个 epoch 只能由一次整向量
`bootstrap_initial_broker_epoch_v2(bootstrap_run_id,consumer_group,h0_vector,expected_vector_hash)` 创建，
禁止逐 partition提交。函数锁完整route集合，要求全部BROKER epoch/current checkpoint/control H0不存在、
vector与route一一相等且每项generation/opening/H0均已回读验证；同一事务为全部条目写sequence=1 ACTIVE、
start=floor=H0、predecessor=NULL、activation_mode=H0_BOOTSTRAP、manifest hash=NULL和current checkpoint，
最后写完整typed H0 vector/hash、唯一pipeline control/audit。同run/vector响应丢失重放no-op，任何半状态/
漏多route/异值/未验证identity报 `INITIAL_EPOCH_BOOTSTRAP_CONFLICT`。后续 reset/
repartition/recreate 一律创建 sequence=前驱+1 的 BARRIER_PENDING epoch，同事务把旧 checkpoint current=false、
新 checkpoint current=true并令相关 scope STALE；普通重启只续同一 epoch。同 generation start 不得低于
bootstrap floor；新验证 generation 可从自己的新 floor（包括 0）开始。

`dts_broker_epoch_activation_requirements` PK 固定为
`(source_region,source_partition_epoch_id,topic,partition_id,source_table,scope_kind)`，字段至少含
`requirement_kind=SOURCE_SCOPE/ROUTE_EMPTY`、scope_level/key、条件可空 required_next_offset/
satisfying_snapshot_id、route_config_version/hash、status 与 row_version，并复合 FK 到该 BROKER epoch。
SOURCE_SCOPE要求真实source_table、scope_kind=CURRENT/HISTORY、GLOBAL/*、非空barrier/snapshot并复合FK到
满足项；ROUTE_EMPTY固定source_table为 `__route_empty__`、scope_kind为ROUTE_EMPTY、scope_level为GLOBAL、
scope_key为 `*`，且barrier/snapshot为空。manifest
矩阵固定为 routed 有效白名单表全部 `GLOBAL/CURRENT`；`dom_appoint/ovs_appoint/`
`dom_teacher_class_schedule/dom_teacher_favorite/ovs_teacher_favorite/dom_teacher_blacklist/`
`ovs_teacher_blacklist` 另需 `GLOBAL/HISTORY`；无有效业务表必须写唯一哨兵，TEACHER scope 不阻断
激活。只有受限 `activate_broker_epoch_v2` 能在SOURCE_SCOPE逐项COMPLETE/fence/checkpoint barrier、
ROUTE_EMPTY回读仍为空、count/hash和route
回读全部一致时把 epoch ACTIVE；漏一项即保持 BARRIER_PENDING。

`dts_ingest_checkpoints` v2 PK 固定为
`(source_region,source_partition_epoch_id,topic,partition_id)`，字段为 consumer_group、`next_offset bigint`、
`is_current`、row_version/updated_at并复合 FK 到 BROKER epoch。next_offset 表示所有更小 offset 已在
ledger/source/current/dirty 同事务耐久并可 ACK，CAS 只增不减；旧 SUPERSEDED epoch checkpoint永久只读。
同 `(region,topic,partition)` 恰有一个 current 行，它必须指向最大 sequence 的 BARRIER_PENDING/ACTIVE epoch。
实时 vector只取 current；lineage函数返回 DOMINATES/PENDING_BARRIER/INCOMPARABLE，Ingestor可在前两者续跑，
final shadow/cutover只接受全部 ACTIVE 的 DOMINATES。所有 fence 使用半开 `[start_next_offset,end_next_offset)`；
checkpoint next>=end 即覆盖，普通增量从 offset>=end 继续。

无法通过 envelope/epoch 校验的 delivery 不写 ingest ledger，而写 `dts_ingest_issues`：PK
`ingest_issue_id=SHA-256(canonical(delivery_identity_hash,payload_hmac,hmac_key_version))`，并对这三列唯一。
保存可取得的 region/epoch/topic/partition/offset、canonical current_error_codes、issue_revision、
status OPEN/RESOLVED、first/last seen、attempt、case_id 与安全摘要；禁止 raw payload、学生原 ID和密钥。
A错误修复后暴露B错误更新同一 issue/error set并 revision+1；只有原 delivery 全部校验通过且合法
event/version/current/checkpoint提交的同一事务才能 RESOLVE并 ACK。普通角色不能改 identity/HMAC、直接
RESOLVE或 DELETE。

append-only `dts_source_row_versions` 的复合主键为
`(source_region,source_partition_epoch_id,topic,partition_id,offset_value)`，保存白名单化 before/after、
version kind、source table/key、operation、source time、typed record identity/position、条件可空
source_row_revision、snapshot证据和 covered-through vector。CDC 使用真实位点；BASELINE 与 SNAPSHOT_DIFF
分别复合 FK 到对应 synthetic epoch且不写 checkpoint。BASELINE 只作证据、revision=NULL，并按
`(snapshot_id,source_table,source_key)` 唯一。

SNAPSHOT_DIFF 的 ordinal 在每个 `(snapshot_id,source_table)` 内，只对最终实际会写 diff 的 distinct canonical
source_key 排名；不变、BASELINE-only、TEACHER仅移membership的key不参与。NUMERIC按任意精度升序在前，TEXT按
UTF-8 bytes升序在后，同表key类型不得漂移，使用1-based row_number，故ordinal>=1。单步或 bootstrap step1 使用 offset=2*ordinal-1；legacy
bootstrap 后仍有正常 diff 时 step2 使用 offset=2*ordinal。每行显式保存 `diff_step=1/2` 与
`source_table_publish_generation`，唯一键为 `(snapshot_id,source_table,source_key,diff_step)`；operation/step
组合由 CHECK 限定。CDC/SNAPSHOT_DIFF 真正推进 current 时在 source行锁内取 revision+1，并对
`(source_region,source_table,source_key,source_row_revision)` 条件唯一。appoint A→B→A、首次 end 瞬态和
关系历史只按版本重建；Trigger拒绝版本改写、物理删除和原始国内学生 ID。

目标 v2 的 `source_position` 统一为服务从 envelope 生成的 JSONB，不接受来源 opaque 字符串充当排序键：
`{v:1,source_timestamp:UTC RFC3339 microseconds|null,record_id_type:none|numeric|text,
record_id:canonical string|null,source_partition_epoch_id,topic,partition_id,offset_value}`。数据库提供不可变
`dts_source_position_is_valid(jsonb)` CHECK 和 `dts_source_position_cmp(jsonb,jsonb)`；后者按 timestamp
NULLS FIRST、record 类型固定序、typed record ID、topic UTF-8、integer partition、bigint offset 逐项 ASC
形成真实 CDC envelope 的诊断/同 partition epoch 顺序；epoch不同直接拒绝，禁止比较
BASELINE/SNAPSHOT_DIFF 与 CDC。
跨 version kind、所有 typed selector 末位、source current、参与状态机和完课纠错 expected/resolved 边界只
比较整数 source_row_revision；所有 position 列均用该 JSONB 契约但只作审计。非法时间、
record 类型不符、空 topic 或缺 partition/offset 时整批写稳定错误
`SOURCE_CONFLICT:SOURCE_POSITION_INVALID`，不写版本、不推进 checkpoint、不 ACK。

同一 immutable stream generation reset 后重读旧 offset：payload hash相同记 EPOCH_REPLAY并推进新 epoch
checkpoint，但 source_row_revision=NULL且不写 current/dirty/Outbox；hash不同为 SOURCE_CONFLICT。只有新的、
已验证 stream_generation_id才允许同名 topic/partition/offset表示新事件。source key跨 partition/topic报
SOURCE_KEY_PARTITION_DRIFT并等待新 snapshot manifest。

同一 source key 在一个 `source_partition_epoch_id` 内只允许来自同一真实 topic/partition 且 offset 严格
推进；漂移报 `SOURCE_KEY_PARTITION_DRIFT` 且 offending checkpoint 不前进。重分区/reset 必须新
BARRIER_PENDING epoch并令 scope STALE；该 epoch仍可耐久 CDC/current/dirty/checkpoint并 ACK，但 manifest
激活前不能提供 completeness/dominance。SNAPSHOT_DIFF position 只审计；candidate replay 只改 staging，
发布在 source-table exclusive lock 内与 live current 做剩余 diff并分配后续 source_row_revision，普通 CDC
取同锁 shared 模式。

deferred trigger 要求 current 的 source key/revision/复合来源位点与所指 version 完全一致。接入事务锁本行，

替换快照先写 candidate 的 `dts_source_snapshot_rows(snapshot_id+scope+source_key)` staging；

`snapshot_is_present/snapshot_row_hash`、CDC overlay
`cdc_overlay_is_present/cdc_overlay_row_hash/last_cdc_source_revision`、生成的 effective_is_present 和
membership_revision。校验通过

vector；发布时 snapshot baseline 吸收该 barrier 并清除已覆盖 overlay。STALE/FAILED overlay 可追 current，
但不能提供集合完整性。

现行 `dts_dirty_keys` 身份不含地区，v2 必须把 `source_region` 纳入主键/唯一约束：

身份替代；claim、重试、完成和 upsert SQL 都必须带地区，避免 DOM/OVS 同 ID 相互覆盖。
四列均NOT NULL，单ID key的key_part_2固定空字符串。数据库CHECK矩阵固定为：COURSE=(dom/ovs,appoint_id,'')、

(dom,teacher_id,北京业务日YYYY-MM-DD)。前五类只由Domain Projector领取，TIME_RECHECK只由SourceWide Worker
领取。canonical dirty key/hash、技术Case和dependency FK统一使用四列canonical JSON；NULL、`*`、`-`或handler

目标 `dts_dirty_keys` 的运行列固定为：

| 字段 | 约束/含义 |
|---|---|
| `status` | `PENDING/PROCESSING/WAITING_DEPENDENCY/RETRY/DEAD/COMPLETED` |

append-only `dts_dirty_key_inputs` 的 PK 为 dirty 复合键加
`input_kind,input_identity_hash,input_revision`，并对 `(dirty key,dirty_work_revision)` 唯一。保存canonical identity、

业务日、revision=1、fingerprint含`teacher-time-recheck-v1`；catchup/00:05同日重放no-op，跨日使用不同dirty key。
相同identity/revision/fingerprint重放no-op，异fingerprint
冲突，更旧identity revision no-op；不同identity无论其source revision数值大小都分配下一dirty work revision。
因此appoint r10后grading r1仍是新工作，不作跨表比较。

`dts_dirty_key_dependencies` 的 PK 为上述 dirty 复合键加
`dependency_type,dependency_region,dependency_key`，另存 `observed_dependency_source_revision/hash`，并以后三列

分别只有固定wrapper和角色，DEPENDENCY/OPERATOR只能由wake/recover内部常量调用，且全部锁内回读引用事实，
不能传任意kind/hash复活DEAD。claim/renew/complete/wait/fail/reaper的底层
`_*` SECURITY DEFINER函数全部REVOKE PUBLIC/runtime EXECUTE。对外只提供两套常量owner wrapper：domain族只
GRANT NOINHERIT login `tit_dts_domain_projector_runtime`并覆盖前五类，time-recheck族只GRANT
`tit_source_wide_runtime`并覆盖TEACHER_TIME_RECHECK；time族无wait-dependency入口。不得在SECURITY DEFINER内
用current_user识别invoker。精确函数名、状态边、token/CAS、15–300秒租约、
5秒指数退避且30分钟封顶、第8次DEAD+Case、响应丢失和 required_work>claimed_work 的重排语义以冻结实施规格 §4.1
为准。complete 必须和领域事实/aggregate/Outbox 同事务；reaper 接管过期 PROCESSING 并计一次
`DIRTY_LEASE_EXPIRED`。所有转PENDING入口都写`next_attempt_at=transaction_timestamp()`；claim固定用
`status IN (PENDING,RETRY) AND next_attempt_at<=transaction_timestamp()`，不得用COALESCE猜NULL。依赖事件只有
同identity的revision/hash真实变化才经input表唤醒，普通重放不能复活DEAD。cutover只接受
全部相关 dirty 行 COMPLETED。
claim wrapper分别为`claim_domain_dirty_keys_v2`和`claim_teacher_time_rechecks_v2`；后续wrapper同样按owner分族，
内部常量kind并校验lease_owner_kind/key_type，防止跨owner接管。ACL测试必须证明两login各自可领/完成本类、
互相无EXECUTE且不能直调内部函数。

#### 3.3.5 `domain_aggregate_revisions` 与 v2 影子对账

`domain_aggregate_revisions` 为 `source_wide.changed.v2` 提供统一语义修订号，PK 为
`aggregate_type + aggregate_id`；保存规范化 `canonical_key`、`revision>=1`、last source revision、审计
source position、`aggregate_state jsonb NOT NULL DEFAULT '{}'` 和更新时间。aggregate_type CHECK 包含
`COURSE/PARTICIPATION/TEACHER/TEACHER_STUDENT/LABEL/COMPLAINT_CATEGORY/COMPLETION_CONFLICT/SOURCE_SCOPE/
TASK_PLAN`；前八类只发 `source_wide.changed.v2`，TASK_PLAN 只发 `task.materialization.requested.v2`。
TASK_PLAN state 必须通过固定 schema CHECK，至少包含 materializable、eligibility generation/since、冻结
时区/教师 row version/模板 revision/copy version number、match-set、blocker-set 与 plan-state hash；不能存教师文案、原始学生 ID，
也不复制 assignment_exists/id/hash。assignment 是否存在只按 task_assignments.dedupe_key 唯一行判断，
避免首次物化在不递增 revision 时改写 same-revision plan hash。
精确schema为additionalProperties=false的`task_plan_state_v1`：protocol、assignment key、teacher、target task、
materializable、generation、eligible/timezone、teacher row version、template id/revision、copy id/config key/
`teacher_copy_version_number=config_versions.version_number`、active match set hash、blocker code/set hash、plan state hash。
唯一数据库`task_plan_state_hash_v1`对除hash自身外全集做canonical JSON v1
SHA-256（UTC微秒、JSON null、整数十进制、UTF-8 key排序）。MATCH true时generation>=1且basis完整；关联的
LEGACY_COMPAT/FROZEN generation=0并按assignment冻结字段条件可空。false保留最近generation/basis，只有从未
成立且无legacy assignment时basis全null；teacher/task/set/blocker hash始终保留。assignment存在/ID/hash和
技术时间禁止进入。
blocker code固定为`NONE/NO_ACTIVE_MATCH/NEGATIVE_LABEL_NAME_MISSING/NEGATIVE_LABEL_VARIANT_CONFLICT/
NEGATIVE_LABEL_MULTIPLE/TASK_COPY_CONFIG_MISSING/TASK_COPY_CONFIG_CONFLICT`；blocker set由negative PENDING match的
kind/dedupe/revision/evidence hash与copy missing/conflict的config key/排序候选version IDs组成并做canonical hash，
summary优先级和空集规则以冻结实施规格§3.1为准。
已有assignment遇到blocker只改变当前贡献和plan hash；恢复复用原generation/basis，不重选任务冻结内容。
`aggregate_id=v2:{aggregate_type}:{SHA-256(canonical JSON key)}`，只有规范化事实语义真实变化时才
`revision+1`；同一事务用该 revision 生成唯一 `event_id`。aggregate type、canonical key 和写入所有权
以 `DTS_direct开发冻结实施规格.md` §3.1/§4.1 为准，不允许各 handler 自造 revision。

切换前的 shadow 完全独立于生产 Outbox：

| 表 | 主键 | 用途 |
|---|---|---|
| `source_wide_v2_reconciliation_runs` | `run_id` | 记录规则版本、完整 source fence、domain/TASK_PLAN/task/output/score/qualification revision、scope epoch/fence、14 项 active template、active complaint SHA/copy/config vector、唯一 `evaluation_as_of/evaluation_business_date_beijing`、`technical_work_readiness_count/hash/vector`、是否在 cutover mutex 内、`RUNNING/COMPLETE/FAILED`、各结果类型 count/hash 与起止时间 |
| `source_wide_v2_shadow_cursors` | `run_id + result_type` | 按 canonical key 全量扫描的独立断点、last_key、row_count/hash 和状态 |
| `source_wide_v2_shadow_results` | `run_id + result_type + result_key_hash` | 保存规范化结果键、预期 payload、payload_hash 和计算时间 |

shadow 只计算
`TEACHER_WIDE/LESSON_SCORE/LESSON_COMPONENT_SETTLEMENT/FAVORITE_OBSERVATION/FAVORITE_ATTRIBUTION/TRIGGER_MATCH/TASK_PLAN/CASE_PLAN/NOTIFICATION_PLAN/SCORE_ACCOUNT/SCORE_COMPONENT_ACCOUNT/SCORE_ENTRY_PLAN/QUALIFICATION/OUTBOX_COVERAGE`
预期结果，不领取或修改生产 `outbox_events`，不写任务、积分、资格、通知或生产 ID。同一 fence 全部
cursor COMPLETE 且 count/hash 校验通过的 run 才可作为 cutover 输入。

14 类 canonical key/action 以冻结实施规格 §4.9 注册表为准。每条结果带精确旧行/ABSENT前置条件；cutover
锁行校验后才 MERGE/REBUILD/CREATE。积分流水计划只允许 REUSE/ALIAS/AWARD/REVERSE：REUSE不写、ALIAS只建
供给里程碑alias、AWARD/REVERSE只追加流水；固定任务分只REUSE。未登记type/key/action直接拒绝。
LESSON_SCORE 另允许 DELETE_CURRENT，但仅当 v2 无当前completion且对应可逆流水已冲正；不得保留陈旧分或
写无completion的零分行。
CASE_PLAN/NOTIFICATION_PLAN 还必须覆盖自动取消、仅恢复系统自动取消原行和保留已处理/已读状态；不能只做
REUSE/CREATE，也不能让来源恢复回退人工处理或阅读事实。

run input/evaluation/vector 创建后不可变，状态只允许 RUNNING→COMPLETE|FAILED。RUNNING result 只能
INSERT；同 run/type/key 同 payload hash 重放 no-op，异 payload 报 SHADOW_RESULT_CONFLICT，禁止 UPDATE/
DELETE。cursor 只可单调推进，COMPLETE 后不可回退；run 终态后 run/cursor/result/count/hash/vector 全部
不可改删，重算使用新 run_id。cutover 锁 COMPLETE run 后必须从 results 独立重算每类 count/hash，与冻结
摘要不一致报 CUTOVER_SHADOW_EVIDENCE_CHANGED。
cursor 只能经 `complete_shadow_cursor_v2` 锁定并重算该 type terminal key/count/hash后置 COMPLETE；完成后
该 type 禁止再插 result或修改任何 cursor列。run 只能经 `complete_shadow_run_v2` 校验固定 result_type 全集、
所有 cursor终态、逐型摘要和 technical readiness 后置 COMPLETE；普通角色无直接终态 UPDATE 权限。

cutover 首次任务只能经 `materialize_cutover_task_plan_v2(run_id,result_key_hash)`。shadow TASK_PLAN 结果
必须冻结 `EXISTING_EVENT/CUTOVER_PLANNED` 分支、base/planned revision、deterministic event_id、matches、
plan/assignment hash及 OUTBOX_COVERAGE。production aggregate 不存在时 base固定0、planned固定1；包括
absent aggregate 首次 0→1，不得把不存在解释为 revision 1。若当前 state/hash相同且有合法 PENDING current
event，必须走 EXISTING_EVENT并保持 revision；只有语义不同或无可沿用 event才走 CUTOVER_PLANNED，要求
planned=base+1。

函数锁内复核后调用普通 Planner 共用 checker：EXISTING_EVENT锁原 event并物化/关联后settle；
CUTOVER_PLANNED原子写 matches、aggregate、PENDING event、assignment/link后settle。响应丢失重试只在
aggregate/current event/payload/link/assignment全部相同且 `settled_by_run_id=同run` 时走 ALREADY_APPLIED
no-op；半应用、异 run、异 payload/关联一律回滚并报 CUTOVER_INPUT_CHANGED。planned base event晚到只能以
`CUTOVER_PLANNED_BASE_SUPERSEDED` 留审计，不覆盖 current。不得直接 INSERT assignment 绕过 checker。

`technical_work_readiness_vector` 必须逐类冻结 captured fence 内的 dirty/source conflict、到期 favorite
DEAD、Outbox DEAD_LETTER 与其 generation/revision/source_ref；count/hash 由 canonical key 排序结果计算。
dirty/source conflict/Outbox DEAD_LETTER 必须为零才可 COMPLETE。favorite DEAD 分为
`TAKEOVER_ELIGIBLE/BLOCKING`：只有 final shadow 同时存在该 observation 及其完整 attribution/明确空结果、
result ref/payload hash 可逐键复核时才是 TAKEOVER_ELIGIBLE 并允许 run COMPLETE；缺任一结果均为 BLOCKING。
TAKEOVER_ELIGIBLE 的业务状态重建和技术 Case恢复证据只在 cutover 接管事务原子写入，不能要求 shadow
预先修改生产 Case。vector 与锁内重算不一致或任一阻断项非零时不得 COMPLETE；不能只凭业务结果 hash
宣称可切换。

维护窗前 run 只作预检。最终 cutover run 必须在专用连接持有
`pg_advisory_lock(hashtextextended('tit:dts-v2-cutover',0))` 期间重跑；所有 DTS、Domain/Worker、纠错、
收藏观察、任务/Case/提醒、教师日更和规则发布事务都必须先取对应 xact shared lock。锁丢失或完整 revision
vector 任一变化时 run 失效并报 `CUTOVER_INPUT_CHANGED`，不得只凭相同 source fence 切读。

每个 run 创建时冻结一次数据库时间；全部 cursor、断点恢复、favorite 到期判断、北京业务日状态、任务
due_at 和最终 cutover materialization 必须显式复用该 `evaluation_as_of`，业务判断内禁止再次取 now。
技术 created_at 可用实际提交时间但不进入计划 hash。全量主事务把 mode/read route 与
`time_catchup_status=PENDING,run_id,from=evaluation_as_of` 同时提交；协调器仍持 intake gate+cutover
exclusive锁，另起事务把未来 observation保持可领取PENDING，并按跨过的每个北京业务日/教师 UPSERT
`dts_dirty_keys(dom,TEACHER_TIME_RECHECK,teacher_id,YYYY-MM-DD)`。事务用自己的 clock写 through，独立回读
teacher/date与observation expected count/hash后才置 COMPLETE；崩溃恢复必须重新取得两把锁幂等补齐。
COMPLETE及through当前业务日二次校验前 API维护、Worker/assignment/DTS均不恢复，也不释放锁。

`OUTBOX_COVERAGE` 的 key 为 event_id，payload 固定 manifest_version、event payload/vector hash、aggregate
revision/state、由 `expand_impact_closure_v1` 独立展开并 canonical 排序的逐键
`result_type/result_key_hash/PRESENT|EXPLICIT_EMPTY/payload_hash`、count/hash。closure registry 与 event 白
名单、SUPERSEDED 仅限 event revision<caught revision、SOURCE_SCOPE epoch/fence 与 TASK_PLAN plan-state
附加校验完全以冻结实施规格 §9 为准。cutover 只能 settle 原状态 PENDING 且 coverage 逐键一致的白名单
v2 event；未知/缺失/错误 hash 或任何 captured DEAD_LETTER 全事务失败，不能把 DEAD 自动改 PUBLISHED。
普通 coverage 标 `EXISTING_EVENT` 并要求 event revision<=run captured revision。cutover 首次补缺 TASK_PLAN
按上文两分支冻结；CUTOVER_PLANNED锁内要求 production仍为base且 event不存在，写后精确为planned再settle，
不适用普通<=captured判断。跳号、current/event/payload/link占用或缺计划结果均失败关闭。

#### 3.3.6 `dts_pipeline_control`

单例 `control_id='PRIMARY'`，字段为 `mode=V1_COMPAT_DUAL_CAPTURE/V2_PRIMARY/ROLLED_BACK`、row_version、
`projection_generation>=0`、固定 consumer_group、不可变 initial H0 epoch-aware next-offset vector/hash、
最近 handoff H vector/hash/run_id、`time_catchup_status=NOT_REQUIRED/PENDING/COMPLETE`、catchup run/from/
through/expected count/hash、changed_at/by。初始化 generation=0；每次进入 V2_PRIMARY（含再次cutover）
恰好+1，rollback不回退。control 不复制运行中的 current checkpoint；实时 vector始终从同一快照读取
`dts_ingest_checkpoints` current行并 canonical hash。

`dts_projection_read_routes` 是受保护单例表，PK/CHECK固定 `route_id='PRIMARY'`，字段为
`active_projection=V1_COMPAT/V2`、route_contract_version、row_version、switched_by_run_id/switched_at。
deferred constraint要求 V1_COMPAT_DUAL_CAPTURE或ROLLED_BACK只能配V1_COMPAT，V2_PRIMARY只能配V2；
mode、route、projection_generation、全量物化audit和cutover/rollback run同事务。部署期预建不变的
v1/v2查询分支，稳定教师/课程视图只按route表选择分支，运行时禁止CREATE OR REPLACE VIEW；两侧课程分支都
输出 participation-shaped契约。`time_catchup_status=PENDING` 时无论哪条route都返回维护错误。
只有 cutover/rollback 专用角色可在 exclusive mutex 内 CAS mode；普通服务只读且启动时 fail closed 校验模式：

- V1_COMPAT_DUAL_CAPTURE：同一 consumer/同一 checkpoint 同事务写 v2 source facts并继续 v1 direct 投影；
  Domain 为 SHADOW_BUILD，v1 Worker 唯一写生产结果，v2 SourceWide/Planner/score关闭；
- V2_PRIMARY：同一 consumer 从 H 续读且不再 direct 写 v1；Domain与v2 SourceWide启用，v2→v1 compatibility
  启用，旧 Worker关闭；
- ROLLED_BACK：consumer/v2 Ingestor/Domain/compatibility继续，v2 SourceWide/Planner/favorite生产物化关闭，
  v1 Worker只消费兼容投影并唯一写生产结果，不做反向 broker handoff。此模式下 Domain 对新完课冲突使用
  SHADOW_BUILD 语义，只写 conflict/COMPLETION_CONFLICT Outbox/CASE_PLAN，不创建生产 Case或回填 case
  pointer；既有 Case 保留可见。再次 cutover 才按 canonical source_ref 原子复用/物化 Case并回填指针。

Fixed Task Score Settler 在三种 mode 都运行，并且是 `FIXED_TASK_AWARD` 的唯一 writer；它只读取合法 fixed
assignment完成状态，用 canonical assignment幂等键并通过共享教师账户锁/账户重建函数结算。v1/v2
SourceWide、全量materialization和rollback都只能对账/复用这类流水，不创建、冲正或复制固定任务分。

mode、生产读route和全量物化必须同一 cutover/rollback 主事务提交。提交后若 time catchup仍PENDING，所有
服务保持维护且协调器继续持锁完成补跑；只有COMPLETE才恢复新mode。进程在主事务提交前崩溃沿旧mode/
checkpoint恢复，提交后崩溃则先恢复catchup而不是开放服务；禁止第二 consumer group、双 ACK、回退
checkpoint或两套 projector同写。
该表和唯一 V1_COMPAT_DUAL_CAPTURE 初始行必须在 expand 阶段、恢复 consumer 和发布任何会读取 mode 的
binary 之前创建并写初始化 audit；服务启动遇到缺行/重复行/group-vector 不一致一律 fail closed。后续迁移
阶段只能校验该行，不能以“尚未建 control”为兼容分支。这里的 vector 校验是：consumer group 必须相等，
当前 checkpoint必须由唯一lineage函数对initial H0/该mode最近handoff H返回DOMINATES；
PENDING_BARRIER/INCOMPARABLE均失败关闭，不要求运行中的current vector与control完全相等。只有
cutover/rollback/catchup受限角色可写mode/route/generation/time字段；Ingestor只写checkpoints。

`dts_pipeline_reset_audits` 记录 rev101 的破坏性重置事实，包括版本化事件字段契约 identity、
`NEW_EVENTS_ONLY/NO_BACKFILL`、执行人和执行时间。rev101 在确认相关运行进程已停止后，以显式根表和外键闭包
一次性清空旧消费事实，保留任务目录、积分规则等静态配置；随后固定唯一运行态为 `V2_PRIMARY` / generation 1，
但不伪造 DOM/OVS offset。每个真实 DTS partition 的第一条不早于 `TIT_DTS_START_AT` 的事件通过
`initialize_dts_event_stream_v1(...)` 原子建立 checkpoint 和 epoch，之后只按数据库 checkpoint 续跑。
`dom_appoint/ovs_appoint` UPDATE 若不存在课程当前态，只写 `IGNORED` 账本并推进 checkpoint，不创建课程事实。

数据库 CHECK 保证 discriminator type/value 一致，并对
`(assignment_dedupe_key_sort_bytes,is_serving,match_status,seed_rule_rank,source_region_rank,
source_appoint_id_type_rank,source_appoint_id_numeric,source_appoint_id_sort_bytes,participation_seq,

dedupe_key_sort_bytes)` 建 active seed 领取索引。Planner 只读取
`is_serving=true AND match_status IN ('MATCHED','MATERIALIZED')`，禁止解析 dedupe_key/evidence_snapshot 排序。
数据库 CHECK 对 `output_type IN ('TEACHER_TASK','PENDING_DATA')` 要求 assignment key/sort bytes、rule rank、
source appoint type-rank与互斥 numeric/text列、evidence type-rank与互斥列、dedupe sort bytes全部结构完整；
source_region 还必须与生成 rank 一致。NONE 只允许两种值列都空。进入 Planner 的 TEACHER_TASK active行任何一项缺失必须拒绝写入，不能靠
NULLS LAST 容忍。OPS_CASE/NOTIFICATION按各自 schema，不进入 seed索引。
origin/created generation由CHECK和Trigger冻结；rollback只允许把CUTOVER_CREATED/V2_LIVE的is_serving=false并
清serving generation，不改match_status/evidence。再次cutover复用同一match时只写新的serving generation。
旧projection_epoch列必须迁走，不能用字符串ROLLED_BACK表达来源或服务态。
投诉证据 match 的 `complaint_rule_id/complaint_source_sha256` 必须同时为空或通过
`(rule_id,source_sha256)` 复合外键；`rule_version` 仍表示触发规则版本，不能代替投诉导入 SHA。
match_kind、target_task_code、typed appoint/participation/evidence 和 variant 的完整映射以冻结实施规格
§3.1 seed 表为 CHECK 真值；两个 NEGATIVE PENDING kind 固定 region=dom、appoint=NONE、seq=NULL、
evidence=label_id。TEACHER_TASK/PENDING_DATA 的 plan_evidence_hash 与 variant 必须完整；JSON 键序、审计
时间或 source_position 变化不得改变 hash。
输出 CHECK 固定为：MATERIALIZED 时按 output_type 恰有一个对应 typed FK 非空且 materialized_at 非空；
MATCHED/PENDING_DATA/FAILED 三个 typed FK 与 materialized_at 均为空；SUPPRESSED 可保留曾物化的 typed link
及原 materialized_at，也可在从未物化时全空，但非空 link 不得清除/换 ID。TEACHER_TASK link 由 deferred
trigger 校验 assignment.dedupe_key=assignment_dedupe_key、teacher_id/target_task_code 一致；Case/通知同样
校验所属 source_ref/teacher。错表 ID、错教师或孤儿均拒绝。
match 集合或尚未物化 plan basis 变化时，统一 TASK_PLAN 重算命令锁 `domain_aggregate_revisions`、更新
aggregate_state并同事务写 plan Outbox；模板/copy publication 按冻结规格的 catalog RW lock 和 canonical
fan-out 与普通 match 事务串行。

`personalized_trigger_matches` 是稳定 `dedupe_key` 的当前生命周期，不是每次复命中都 INSERT。
证据失效时同一行转 `SUPPRESSED`；同键恢复时重新激活该行并 `match_revision+1`，每次转换追加审计。
同状态的 plan_evidence_hash/typed seed/target task/variant 语义变化同样 revision+1并追加审计；
MATERIALIZED 保持状态和 output link，MATCHED 保持状态。仅 JSON 键序、审计时间/position 变化不增 revision。
任务 assignment 一经创建不删除、不取消、不回退。四类任务的键固定为：

NEGATIVE_LABEL_NAME_MISSING/VARIANT_CONFLICT 是 assignment key 的原子 blocker：激活任一 PENDING_DATA
行时，同事务必须 SUPPRESS 该 key 全部正常 NEGATIVE_LABEL_COURSE match、递增 TASK_PLAN revision并使
materializable=false；恢复时反向抑制 blocker并按当前集合重新激活正常 match。deferred trigger 禁止同一
assignment_dedupe_key 在提交时同时存在 active blocker 与 active normal match，旧 plan event 由新 revision
supersede，不能绕过 blocker物化任务。

```text
P-REL match       = absence:{rule_code}:{source_region}:{source_appoint_id}:{participation_seq}
P-REL assignment  = personalized:{task_code}:{teacher_id}
差评 match        = negative-label:{teacher_id}:{label_id}:{source_region}:{source_appoint_id}
差评 assignment   = personalized:P-FB-NEGATIVE:{teacher_id}:{label_id}
一般投诉 match    = complaint:{rule_code}:{source_region}:{source_appoint_id}:{completion_participation_seq}:{complaint_type_grandson}
一般投诉 assignment = personalized:P-FB-COMPLAINT:{teacher_id}:{complaint_type_grandson}
拉黑阈值 match    = blacklist-threshold:{source_region}:{teacher_id}
拉黑 assignment   = personalized:P-FB-BLACKLIST:{teacher_id}
```

三级投诉分类为空仍可计有效投诉指标，但只在 typed complaint/course current 写
`PENDING_DATA:COMPLAINT_CATEGORY_MISSING`，不创建 trigger match 或任何输出。拉黑按地区内当前不同 student token 达到 2 人触发，不要求完课；地区证据不合并，教师级
assignment 按全局 teacher_id 复用。

## 4. 积分

### 4.1 `lesson_score_results`

一节源课程一行的当前积分结果。现行 code head 以 `lesson_source_wide.课程id` 为单键；v2 迁移必须
改为源课程复合键并显式保存冻结完课参与。未首次 end 的课程不创建可计分结果；A 缺席、B 完课时
只产生归 B 的一行结果，不给 A 复制同课积分。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `source_region` | varchar(8)，联合 PK/FK，必填 | `dom/ovs` |
| `source_appoint_id` | varchar，联合 PK/FK，必填 | 对应 `source_courses` |
| `completion_participation_seq` | integer，复合 FK，必填 | 对应冻结完课参与 |
| `teacher_id` | varchar，必填 | 冻结完课教师；普通 DTS 不得静默改写 |
| `user_feedback_score` | double precision，必填 | 本课好评与去重收藏分 |
| `reliability_score` | double precision，必填 | 本课完美完课与 Peak 完课分 |
| `class_quality_score` | double precision，必填 | 本课三项硬件质量分 |
| `lesson_total_score` | double precision，必填 | 上述三个维度之和，由数据库约束校验 |
| `dimensions` | jsonb，必填 | 三个维度的组件、证据状态和归因细节 |
| `score_rule_version` | varchar，必填 | 本次计算使用的规则版本 |
| `projection_revision` | integer，必填 | 内容实际变化时才递增的投影版本 |
| `calculated_at` | timestamptz，必填 | 最后一次实际重算时间 |

同一 deferred constraint trigger 要求任何已存在的 `lesson_score_results` 行，其
`completion_participation_seq/teacher_id` 必须同时等于 `source_courses` 当前冻结指针，并指向
`participation_role='COMPLETION'` 的参与；不能只依赖“FK 指向任意 participation”。TRANSFER 必须先把旧
COMPLETION 降为 SUPERSEDED，再升目标并更新课程/积分指针，全部在一个锁定课程行的事务内完成。

首次 end 后 source 教师/状态/完课时间变化或 DELETE 时，本表保持原结果并等待
`COURSE_COMPLETION_CORRECTION` 决定；批准 transfer/void 时以一个受限事务写冲正流水和新结果。
rev78 只允许 `PENDING` 保留仍与冻结 completion 完全匹配的既有 v2 结果；此状态下禁止结果
新增、更新或删除，必须在同一事务先决议为 KEEP/TRANSFER/VOID，再按最终决议保持、迁移或清空。
旧 `lesson_id` 外键只在兼容窗口保留，v2 切读后删除，不能继续级联删除已结分历史。

| `reversal_score_entry_id` | varchar，可空 | 最近冲正流水 |
| `points` | double precision，必填 | 本 generation 的分值 |
| `score_rule_version` | varchar，必填 | 计分规则版本 |

`reversal_of_score_entry_id` 非空时必须有唯一约束，保证一条原奖励最多冲正一次。逐课非收藏组件和
收藏的奖励/冲正键分别以冻结实施规格 §7.4.1/§4.6 为准；任务奖励继续以 assignment 身份幂等。
writer矩阵固定：迁移前存量=LEGACY_EXISTING；expand后v1语义Worker=V1_COMPAT_LIVE；唯一Fixed Task Score
Settler=FIXED_TASK_LIVE；cutover新建=CUTOVER_CREATED；V2_PRIMARY SourceWide=V2_LIVE；rollback冲正=
ROLLBACK_CREATED。FIXED_TASK_LIVE只允许FIXED_TASK_AWARD且task_assignment_id非空；ROLLBACK_CREATED只允许
reversal且run非空。逐课settlement/收藏attribution的LEGACY_REUSED可引用LEGACY_EXISTING或V1_COMPAT_LIVE；
其他origin/run/generation必须精确相等，Trigger拒绝writer自选或错配。

供给里程碑恰有一条不可逆 +10 流水，canonical `idempotency_key` 为
`CAPACITY_MILESTONE:CAPACITY_PEAK_SLOT_40:{teacher_id}`，`score_entry_id` 为
`CAPM-{SHA-256(key) 前32位}`，dimension=`CAPACITY`、entry_type=`MILESTONE_ACHIEVEMENT`、
reason_code=`CAPACITY_PEAK_SLOT_40_ACHIEVED`。首次确认 peak_slot_cnt>=40 后不因下降、scope 失效或删除
冲正。cutover 可为唯一同教师/营期、同 reason、delta=10、未冲正 legacy 流水建立 canonical alias 并保留
原 idempotency_key/score_entry_id；多候选、金额/营期不一致、被冲正、账户已有 10 却无唯一流水均停线，
不补造、合并或 UPDATE append-only 流水。

### 4.6 读取与更新语义

- v2 DTS 接入事务写账本、来源当前态/tombstone、脏键和 checkpoint；领域投影完成后写
  `source_wide.changed.v2` Outbox。SourceWide Worker 在独立事务中异步、幂等更新派生结果。
- 课程重算语义：不扫描其他教师；为保证聚合和去重正确，会读取受影响教师的课程集合，
  更新一课一行结果，并按去重课程 ID 重算 `perfect` 与 `RELIABILITY`，按硬件质量规则重算
  `CLASS_QUALITY`；收藏按 `source_region + teacher_id + student_token` 终身只保留一个当前获分归因，
  从 `CONFIRMED_TRUE` 观察中按 `observed_at, source_appoint_id` 选择最早课程；历史纠错通过冲正流水
  补扣并重选，后续普通关系变化不重复加分；
- 与积分无关的资料字段不触发积分重算；固定任务完成只更新任务组件、总分和资格，不扫描课程；
- 新积分版本发布：在发布事务内按新版本全量重算当前教师投影；任一重算失败则版本发布回滚。

源表更新与派生计算是两个事务：派生计算失败不回滚已提交的源事实，而是保留/重试 Outbox 事件。只有积分规则发布与对应全量重算必须同事务。现有教师端读取视图为：

- `teacher_scorecard_current`：一位教师一行，直接包含总分、资格、五维及全部子项；
- `teacher_lesson_score_current`：一条教师参与一行，源课程通过 `source_appoint_id` 对账；缺席教师
  可见自己的 `t_absent` 参与，只有冻结完课参与显示本课积分。`is_perfect` 仅在冻结完课且迟到、早退
  都有完整证据并明确为 `false` 时为 `true`；任一未知则为 NULL/SOURCE_MISSING。该字段由 v2 参与和处罚集合派生；达标课程的
  4 分进入 `lesson_total_score`。课堂质量硬件项直接读取逐课三项异常字段，满足条件的
  2 分也进入 `lesson_total_score`。收藏总分目标读取课程 end+24h 锁定的唯一归因，不再直接读取
  当前关系人数 `feedback_favorite_cnt`；无法取得关系历史的课程标记为 `SOURCE_MISSING`。

教师端任务仍读取 `task_assignments + task_templates`。完整字段对应见
`contracts/教师端积分与课程读取对照表.md`。

## 5. 任务

### 5.1 `task_templates`

当前唯一任务目录表。当前 catalog 的唯一 PUBLISHED 内容包含 G01–G09 和 5 个个性化改善任务；G00 以
`RETIRED` 保留历史引用且因同 template_id 不存在当前 PUBLISHED 而隐藏。assignment 始终按 row_id 读取其
冻结版本，即使该历史行后来 RETIRED；status=PUBLISHED 的限制只用于新建 assignment 和“该 task_code 是否
仍属当前 catalog”的 EXISTS 判断。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `row_id` | varchar，PK，必填 | 一条模板记录的稳定 ID，供 assignment 冻结引用 |
| `template_id` | varchar，必填 | 任务稳定编码；当前发布 9 个 G 编码及 5 个 P 编码 |
| `template_version` | integer，必填 | 模板记录序号；assignment 通过 `row_id` 冻结引用 |
| `status` | varchar，必填 | `DRAFT / PUBLISHED / RETIRED`；只有新建 assignment 必须引用当前 PUBLISHED，既有 FK 可继续指向 RETIRED |
| `revision` | integer，必填 | 草稿编辑并发乐观锁 |
| `output_type` | varchar，必填 | 输出类型；当前为 `TEACHER_TASK` |
| `execution_owner` | varchar，必填 | 任务执行方；数据库限制为 `TEACHER_APP` |
| `external_task_template_code` | varchar，必填 | 教师端识别任务类型的稳定编码 |
| `source_mode` | varchar，必填 | 模板内容的来源性质 |
| `payload` | jsonb，必填 | 标题、Why、How、完成标准、`benefit`、`content_status`、阶段、`score_value` 和截止规则等静态内容；assignment 通过模板引用固定结算分值 |
| `created_by` | varchar，必填 | 创建人/服务 |
| `updated_by` | varchar，必填 | 最后更新人/服务 |
| `created_at` | timestamptz，必填 | 模板记录创建时间 |
| `updated_at` | timestamptz，必填 | 模板记录最后更新时间 |
| `integration_mode` | varchar，必填 | 固定成长任务为 `INBOUND_STATUS_ONLY`，表示教师端只回写执行状态；个性化改善任务为 `OUTBOUND_MANAGED` |

数据库对 `(template_id,template_version)` 唯一，并对
`(template_id) WHERE status='PUBLISHED'` 建部分唯一索引。唯一发布入口为受限
`publish_task_template_v2(...)`：无current时DRAFT→PUBLISHED；换版时同事务旧PUBLISHED→RETIRED、新
DRAFT→PUBLISHED、audit与fan-out。RETIRED终态，current PUBLISHED不能被单独退役/删除；直接status UPDATE、
复活RETIRED、原地修改PUBLISHED identity/payload/score/截止/路由均由Trigger拒绝。首次发布和换版都逐
`template_id` 校验固定分值：`G01..G09=3,2,2,3,3,4,3,5,5`，五个 `P-*` 均为 `0`；异值整笔拒绝，不能只校验
G任务合计30分。函数在cutover shared mutex
和该template catalog exclusive lock下，只选择 `target_task_code=本template_id` 且active match、无assignment
的键按canonical顺序重算TASK_PLAN；禁止模板A换版fan-out模板B。teacher_personalized_copy发布才fan-out全部
active无assignment键。普通 plan/Planner/固定 G 初始化分别取得所需 catalog shared locks；固定初始化一次性按
canonical 顺序锁定九个 G template_id、在同一 snapshot 校验恰好九项再插入。发布事务预计算全部目标/依赖
catalog locks并排序取得，禁止边扫描边加锁。既有 assignment 的状态 UPDATE 只校验冻结 FK 存在，不要求
该历史 row 仍 PUBLISHED。发布事务任一plan/event失败则模板/copy状态、fan-out与audit全部回滚。
模板表还必须提供 `UNIQUE(row_id,template_id)`，供 assignment 用
`(template_version_id,task_code) REFERENCES task_templates(row_id,template_id)` 复合外键保证编码与冻结模板
语义一致。新建 assignment 在 catalog shared lock 内另校验所引 row 为该 task_code 当前唯一 PUBLISHED；
既有状态更新只要求复合 FK 仍存在，可继续引用 RETIRED row。

### 5.2 `task_assignments`

任务实例及当前状态的唯一事实表。两端不再通过任务发布/状态回传 HTTP 接口复制数据。

在当前 v1 中，当前 9 项必修任务的每条合法 `COMPLETED` assignment 按 `template_version_id`

当前数据库硬约束：

- 当前 G01–G09 必须为 `FIXED_GROWTH + TRIGGER_CENTER`；5 个 P 任务必须是 `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER`。G00 历史行只读保留。
- 同一教师同一 G 任务只能有一条。已确认不存在复营或跨营期回补。
- 当前 9 项必修任务从 `ASSIGNED` 开始；该状态表示“任务已建立、尚未完成”。固定任务初始化不创建 `notifications`、提醒或投递意图。
- 教师端角色对 assignment 使用表级 CRUD；数据库 Trigger 仍拒绝教师端创建、删除，并只接受已有行的状态五字段语义，拒绝内容、身份、模板、优先级和截止时间变更。
- 有 `due_at` 时，三个时区证据字段必须同时存在；无截止时间时必须同时为空。
- 个性化任务 `eligible_since_at` 必填且不可变，固定任务必须为空。MATCH due_at 以该值+模板 48/72 小时
  绝对时长计算，assigned_at 仍是实际建行可读时间。MATCH与LEGACY_COMPAT必须同时具有非空due_at和三项时区证据，
  并由 deferred trigger 复核 due_at 等式；LEGACY_FROZEN 保留原 due/timezone（可成组为空），
  eligible_since_at 回填原 assigned_at 并在 evidence 标 `LEGACY_ASSIGNED_AT`，禁止重算。
- MATCH/LEGACY_COMPAT 的 `(teacher_copy_version_id,teacher_copy_config_key)` 必须成组非空并复合引用
  `config_versions(version_id,config_key)`；key固定小写值且创建时所指版本必须是唯一PUBLISHED。既有assignment
  换版后可继续引用RETIRED不可变行；LEGACY_FROZEN/fixed两列必须同时为空。
- LEGACY_COMPAT只能由受限 `create_legacy_compat_assignment_v2` 在V1_COMPAT_DUAL_CAPTURE或ROLLED_BACK创建；seed为
  `legacy-compat:{assignment_id}`、revision/plan/generation均0，eligible_since_at=assigned_at，英文copy、
  variant、模板、时区、due与evidence/hash必须完整。cutover保留该行且不得改写为MATCH。
- 函数精确签名为
  `create_legacy_compat_assignment_v2(assignment_dedupe_key text,teacher_id text,task_code text,
  expected_legacy_compat_match_set_hash char(64)) RETURNS (assignment_id,outcome,payload_hash)`。确定 ID 为 `TAS-LC-`+
  `SHA-256(UTF8('legacy-compat-assignment:v2\u0000'||dedupe_key))` 前40位小写hex；幂等 key 为
  `create-legacy-compat-assignment:v2:{SHA-256(UTF8 dedupe_key)}`，`idempotency_records` 永不过期并保存四参数
  canonical request hash与完整响应。锁序固定 cutover shared→把
  `CONFIG:teacher_personalized_copy`/`TEMPLATE:{task_code}` 完整集合按UTF-8 bytes一次性升序取得shared catalog锁
  （当前为CONFIG先、TEMPLATE后）→assignment advisory→
  idempotency row→teacher→canonical active matches。同request返回REPLAYED且不重读当前目录；异request同key
  报REQUEST_CONFLICT；既有同teacher/task assignment返回EXISTING_ASSIGNMENT且不改冻结列；否则按当前唯一
  PUBLISHED template/copy和canonical seed原子创建、关联全部active match、audit与幂等响应。模式关闭、match
  hash漂移、依赖缺失、身份冲突的稳定错误及payload构造以冻结规格§3.1为准。候选只认
  LEGACY_REUSED/generation0/not-serving/no-serving-generation的TEACHER_TASK MATCHED/MATERIALIZED；独立
  `legacy_compat_match_set_hash_v1`包含typed seed/evidence/variant/origin而不复用v2 serving set hash。函数先
  命中成功幂等响应再做mode gate；新请求在DUAL_CAPTURE/ROLLED_BACK合法，V2_PRIMARY拒绝。
- 合法状态边固定为：
  `ASSIGNED→VIEWED|IN_PROGRESS|SUBMITTED|UNDER_REVIEW|COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `VIEWED→IN_PROGRESS|SUBMITTED|UNDER_REVIEW|COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `IN_PROGRESS→SUBMITTED|UNDER_REVIEW|COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `SUBMITTED→UNDER_REVIEW|COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `UNDER_REVIEW→COMPLETED|FAILED|EXPIRED|WAIVED|CANCELLED`；
  `FAILED→IN_PROGRESS|SUBMITTED|UNDER_REVIEW|COMPLETED`。
  `COMPLETED/EXPIRED/WAIVED/CANCELLED` 无出边。同状态更新不属于状态转移：status_changed_at 必须保持不变，
  只允许按字段所有权更新 status_reason_code/updated_by 等已授权状态字段并递增 row_version。
- `FAILED / EXPIRED / WAIVED / CANCELLED` 必须有 `status_reason_code`；只有 `COMPLETED` 的 completed_at
  非空。教师端可信服务可按上述边进入 VIEWED/IN_PROGRESS/SUBMITTED/UNDER_REVIEW/COMPLETED/FAILED/
  EXPIRED；有权运营/系统才可进入 WAIVED/CANCELLED。Trigger 分别
  返回 `TASK_STATUS_TRANSITION_INVALID/TASK_STATUS_AUTHORITY_DENIED/TASK_STATUS_REASON_REQUIRED/
  TASK_STATUS_COMPLETED_AT_INVALID`；旧 row_version 返回 `TASK_ASSIGNMENT_VERSION_CONFLICT`。
- assignment 禁止删除；标识、教师、任务编码、模板引用、Why、展示标题、证据快照、四个 materialization
  seed 字段、materialization template revision、eligibility generation、copy version、execution variant、
  plan evidence hash、eligible_since_at、due/timezone、来源和幂等键在创建后不可修改。个性化任务的冻结
  字段按 kind 成组完整，固定任务必须同时为空；
  `MATCH` revision 必须大于等于 1；两种 LEGACY revision/plan revision/generation 必须为0。
  `LEGACY_FROZEN` key必须等于`legacy-assignment:{assignment_id}`、copy两列为NULL、variant=LEGACY_FROZEN；
  `LEGACY_COMPAT` key必须等于`legacy-compat:{assignment_id}`、copy两列和template/timezone/due/evidence完整、
  variant为GENERAL或批准照片变体。MATCH 的 eligibility_generation/template revision>=1、copy两列必填且
  materialization_plan_revision>=1。payload hash 必须能仅由 assignment
  冻结列确定性重建，不读取当前 plan/template/copy。

MATCH 行只能由 SECURITY DEFINER `materialize_task_plan_v2(event_id)` 插入，Planner 无直接 INSERT 权限。
函数按 catalog→TASK_PLAN→assignment→match 锁序校验 event/plan revision+hash、当前 PUBLISHED 模板及其
revision、copy version、generation/eligible/due/timezone、canonical seed match 的 key/revision/
plan_evidence_hash/variant/target_task_code，并重算 assignment payload hash；防绕过 Trigger复核复合 FK。
任一不一致报 `TASK_PLAN_MATERIALIZATION_MISMATCH`，整事务无写入。固定 G 初始化和 LEGACY 回填使用不同
受限函数/迁移角色，不能绕用 MATCH 路径。
- `display_title` 和 `why` 不拼接中文上游值；投诉分类、差评标签、缺席原因等原始证据保留在 `evidence_snapshot`。个性化任务的数据库 `display_title` 必须是非空英文，`why` 必须包含 `Evidence:` 最小英文证据摘要；教师端、运营端和 API 均直接读取，不在读取时转换或二次拼接。数据库和应用在新建时拒绝含中文字符的教师端文案。

### 6.5 `outbox_events`

数据库事务内产生的内部待消费事件。`task_assignments` 状态变化会自动写入；两张源表还会写
`source_wide.changed.v1`，payload 只含源表、源 ID、操作、真实变化字段和旧/新教师 ID，
不含整行或学员原值。事件只有在同一 Worker 事务完成所有派生更新后才变为 `PUBLISHED`；
失败会保留为可退避重试的 `PENDING`，达到上限后进入 `DEAD_LETTER`。

v2 使用 `domain_aggregate_revisions` 生成 aggregate identity 和 revision；Worker 以
`FOR UPDATE SKIP LOCKED` 在持有 Outbox 行锁的同一事务内完成幂等业务写并发布。进程崩溃时事务回滚、
行锁释放、状态仍为 `PENDING`；Outbox 不增加 lease 或 `COMPLETED` 状态。领取后先建 handler SAVEPOINT：
失败只回滚 savepoint，继续持 Outbox 锁并在同一外层事务更新 attempt/available/error，第8次原子写
DEAD_LETTER+技术 Case；成功则业务+PUBLISHED提交。禁止释放锁后另起失败事务，也禁止 handler 做不可回滚
外部副作用。

完课纠错决定函数先锁并校验 `dts_pipeline_control.mode=V2_PRIMARY`；DUAL_CAPTURE/ROLLED_BACK 返回
`CORRECTION_PROJECTION_MAINTENANCE` 且不落任何业务写。合法决定事务必须递增 COURSE 和所有受影响 PARTICIPATION aggregate revision，并原子写对应 v2
Outbox；COURSE 是投诉、摄像头、差评、课程展示和教师聚合的 fan-out 根。Correction Service 不直接写
这些 match/output；Worker 复用正常重算函数抑制旧 completion 键并物化新键。全部关联事件 PUBLISHED
后才把决定的 downstream_projection_status 置 PUBLISHED；DEAD_LETTER 可告警和原 event_id 重放，但不
回滚已提交决定或复制输出。

cutover 只允许把冻结规格 §9 白名单中原状态 PENDING、event/revision/vector 与 OUTBOX_COVERAGE impact
manifest 逐键一致的 v2 event 写为 PUBLISHED/settled。任何 captured DEAD_LETTER、未知类型、缺 ref 或错误
hash 均使整次 cutover 回滚；必须先把原 event 审计恢复到 PENDING并重跑锁内 final shadow，不能在切换
事务把 DEAD“治愈”。settle 后同事务锁相关 `ops_decisions` 并按 projection_event_ids 全量重算：全部存在且
PUBLISHED 才为 PUBLISHED，缺失/未覆盖 PENDING 仍为 PENDING。若本次 settle 的 event 曾从 DEAD 恢复，
对应技术 Case 同事务按 §6.6 OPEN→RESOLVED或 IN_REVIEW 追加 recovery evidence；任一步失败全部回滚。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `outbox_id` | varchar，PK，必填 | Outbox 记录 ID |
| `event_id` | varchar，唯一，必填 | 事件全局 ID |
| `aggregate_type` | varchar，必填 | 聚合类型 |
| `aggregate_id` | varchar，必填 | 聚合 ID |
| `event_type` | varchar，必填 | 稳定事件类型 |
| `payload` | jsonb，必填 | 事件快照 |
| `status` | varchar，必填 | 仅 `PENDING/PUBLISHED/DEAD_LETTER` |
| `available_at` | timestamptz，必填 | 最早可消费时间 |
| `attempt_count` | integer，必填 | 已消费尝试次数 |
| `recovery_count` | integer，必填，默认 0 | 受控 DEAD→PENDING 恢复次数；每次+1 |
| `last_error` | text，可空 | 最近失败摘要 |
| `settled_by_run_id` | varchar，可空，v2 新增 | cutover 全量事务覆盖该事件时记录 materialization run；普通 Worker 消费为空 |

INSERT 后 `outbox_id/event_id/aggregate_type/aggregate_id/event_type/payload/created_at` 永不可 UPDATE，整行
禁止 DELETE；普通角色列权限只允许技术状态列。初始必须 PENDING、attempt=0、recovery=0、published/
settled为空。每次 handler 失败在持锁外层事务把 attempt+1；1–7 保持 PENDING 并更新 available/error，第8次
原子转 DEAD_LETTER+技术 Case。DEAD_LETTER 只能由受限
`recover_outbox_event_v2(command_id,event_id,expected_payload_hash,expected_recovery_count,reason)` 恢复。
永不过期幂等key为`recover-outbox:v2:{command_id}`，request hash按protocol/五参数固定顺序canonical计算；函数
先锁command/idempotency，同request已有成功响应直接校验resource/payload后返回REPLAYED，不重读当前status；
同command异request拒绝。首次命令再锁event，要求DEAD/payload/recovery_count精确一致，成功写PENDING、
attempt=0、available_at=transaction_timestamp()、recovery+1、audit和响应。响应丢失后即使event再次DEAD，
同command不恢复下一代；下一次必须新command并传当前recovery_count。普通直接UPDATE拒绝。

PENDING→PUBLISHED 必须写 published_at；普通 Worker settled_by_run_id 为空，只有 cutover 角色可同时写
合法 COMPLETE run_id。PUBLISHED 无出边；DEAD/PENDING 的 published_at/settled必须为空。Trigger 返回稳定
`OUTBOX_IMMUTABLE/OUTBOX_STATUS_TRANSITION_INVALID/OUTBOX_RECOVERY_DENIED`。恢复后再次第8次失败仍更新同
event_id/source_ref 技术 Case revision，不另造事件；最终真正 PUBLISHED 才按 §6.6 恢复 Case。

#### 6.5.1 `outbox_events_legacy_archive`

仅承载三态约束启用前可证明不是真实待消费工作的旧行。`event_id`为PK、原`outbox_id`唯一；保存原
aggregate/event identity、通过敏感字段检查的payload及hash、原status/attempt/error/created/published时间、

`archive_reason=PROVEN_NON_REAL_MOCK_CANCELLED/PROVEN_RETIRED_CONTROL_PARKED`、proof_type/proof_hash、

aggregate_type/aggregate_id/event_type/payload_hash/status/available_at/attempt_count/recovery_count/
last_error/settled_by_run_id/created_at/published_at；timestamp为UTC微秒、NULL保留、整数十进制、字符串不trim。
proof_type只允许 `MOCK_SEED_CANCELLED/MIGRATION_20260729_37_RETRY_PARKED`。前者必须逐列证明CANCELLED
TASK_ASSIGNMENT未发布、mock payload七枚固定标志、linked assignment为MOCK*且created_by=MOCK_SEED并无
FIXED_TASK_AWARD；后者必须逐列证明PARKED、event_type=outbound_output.retry_requested.v1、
NO_OUTPUT_CONSUMER_CONFIGURED、未发布及payload迁移marker previous_status=PENDING。proof_hash由这些typed
值和引用行PK/关键列canonical计算；自由文本、悬空引用、未知proof或任一谓词不符均拒绝。

敏感检查唯一入口为不可变数据库函数
`legacy_outbox_payload_safety_issues_v1(payload jsonb,proof_type text) RETURNS text[]`，结果按错误码UTF-8 bytes
排序去重，空数组才安全。object/canonical JSON上限16384 bytes/深度2；额外key一律拒绝。MOCK proof顶层只
允许 `assignment_id,teacher_id,task_code,task_kind,from_status,to_status,status_reason_code,result_code,
completed_at,row_version,scenario,origin,source,source_mode,mock_only,delivery_disabled,execution_allowed`，全部为
标量并按proof枚举、正整数、安全ID `[A-Za-z0-9._:-]{1,128}`、RFC3339 UTC微秒或null校验。MIGRATION proof
顶层只允许 `output_id,attempt_count,display_type,actor_id,_migration_20260729_37`；marker是唯一嵌套object且只
允许previous_status=PENDING、previous_last_error为null或安全code。递归字符串另拒绝Bearer/password=/数据库
连接串/JDBC/私钥特征和任意dom:v1:/ovs:v1: student token。固定错误码与RFC6901 pointer以冻结规格§3.1为准。

`preview_legacy_outbox_archive_v2(event_id,proof_type)` 返回row hash、payload hash、proof hash、issues和eligible，
是迁移取得expected hash的唯一入口。两类proof canonical字段顺序分别固定为：MOCK 使用
`proof_type,event_id,outbox_id,aggregate_type,aggregate_id,event_type,status,published_at,settled_by_run_id,
last_error,payload_hash,scenario,origin,source,source_mode,mock_only,delivery_disabled,execution_allowed,

last_error,payload_hash,output_id,attempt_count,display_type,actor_id,marker_previous_status,
marker_previous_last_error`。共用canonical JSON v1编码；mock的payload/aggregate/linked assignment ID必须相等。
唯一受限 `archive_legacy_outbox_event_v2(event_id,expected_row_hash,proof_type,expected_proof_hash,
migration_run_id)` 锁active
与archive键，锁内重新调用同版本checker/row/proof hash，校验证明后同事务插archive+audit并以专属权限删除active；这是Outbox禁止DELETE的唯一迁移例外。
