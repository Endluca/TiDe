# 数据与积分规则

日期：2026-08-11
状态：唯一当前口径

## 1. 事实分层

- `teacher_source_wide` 是确认映射的教师聚合投影；现行 `lesson_source_wide` 是一课一师兼容表，
  不能承载代课历史。v2 权威写模型为 `source_courses + source_course_participations`，来源当前态和
  tombstone 在 `dts_source_rows`；同步控制不混入领域表。
- `teacher_metric_snapshots`、`lesson_facts` 和 `lesson_dimension_scores` 已由 revision 47 物理删除；旧课程离线导入器及唯一历史分析视图已先退役。投诉规则文件的导入批次、原始行、摘要和发布证据统一保存在 `complaint_rule_imports` 及其类型化 `raw_rows`，不存在第二套 `data_import_batches/source_records` 事实源。
- `complaint_category_rules` 保存投诉三级分类精确匹配规则。原始 P0–P4 不改写，同时保存 `severity_rank=0–4`。
- `personalized_trigger_matches` 保存一个稳定 `dedupe_key` 的当前生命周期、最小证据和最终输出关联。
  `SUPPRESSED` 后同键恢复必须重新激活原行并 `match_revision += 1`，不新建证据行；每次状态
  转换向 `audit_events` 追加旧/新状态、必要证据摘要和来源位置。
- `task_assignments` 保存固定成长与个性化改善任务的当前状态；只有当前目录 G01–G09 这 9 个 `task_code` 的合法固定成长 assignment 在 `COMPLETED` 时可产生成长积分。assignment 固定引用的模板后来可以进入 `RETIRED`，仍按该不可变历史模板的 `score_value` 结算；“当前目录”不要求冻结模板仍是 `PUBLISHED`。
- `score_entries` 是不可变积分流水和结算审计。固定成长任务的当前计分事实仍以共享 `task_assignments` 的状态及其固定引用的模板分值为准，教师端不直接写分。
- `score_accounts` 保存每位教师五维当前总分；`score_component_accounts` 保存维度内每个积分子项的当前总分；`lesson_score_results` 按 `(source_region,source_appoint_id)` 一课一行，并保存冻结完课参与与教师；缺席参与不复制同课积分。

教师源表中的 `peak_slot_cnt`、`first_booked_dt`、`is_cpl_tesol`、
`is_self_introduce` 均是类型化字段。G01 只把 `is_cpl_tesol` 作为外部证据；
`is_self_introduce` 继续作为教师资料事实保留，但不参与 G01 展示或完成判断。
两者为 `NULL` 时均表示上游尚未提供，不能当成明确未完成。

## 2. 数据状态

| 值 | 含义 |
|---|---|
| `REAL` | 上游直接提供的事实 |
| `DERIVED_REAL` | 只由真实字段和确定公式派生 |
| `MOCK` | 测试数据 |
| `MOCK_SIMULATION` | 基于真实规模的模拟结果 |
| `MOCK_PROXY` | 暂用相邻字段代替目标事实 |

没有证据时对应分数为 `0`，但必须另记 `SOURCE_MISSING`；`0` 不得伪装成“已确认没有问题”。

## 3. 积分与资格

五个维度独立累计，不使用权重、维度封顶或维度最低线：

```text
用户反馈分 = 好评次数 × 5 + 已锁定的课程收藏归因数 × 5
可靠性分 = 完美完课数 perfect_cnt × 4 + Peak 完课数 peak_completed_cnt × 2
课堂质量分 = 硬件质量达标课程数 × 2
供给分 = peak_slot_cnt 首次达到 40 时 +10，之后锁定
固定成长任务分 = Σ（task_code 为 G01–G09 且状态为 COMPLETED 的必修 assignment 所冻结模板的 score_value），最高 30
raw 总分 = 五个维度之和
显示分 = min(raw 总分, 200)
```

用户反馈比率的分子字段名固定为：

```text
feedback_praise_rate    = feedback_praise_cnt / feedback_total_eval_cnt
feedback_negative_rate  = feedback_negative_cnt / feedback_total_eval_cnt
feedback_complaint_rate = feedback_valid_complaint_cnt / total_completed_cnt
```

不得在实现、SQL 或契约中缩写为 `praise_cnt` / `negative_cnt` / `valid_complaint_course_cnt`。
分母为 0 或对应证据集合不完整时，比率为 `NULL`。

`feedback_favorite_cnt` 表示当前师生收藏关系中的去重学员数，不要求已有完成课程，也不再直接作为
收藏积分权威。收藏积分读取独立的课程归因事实：课程首次进入 `end` 时冻结教师和完课时间，在
`appoint.end_time + 24h` 查询该师生截至该时点的关系状态；为收藏时给该课创建幂等的
`FEEDBACK_FAVORITE` 归因。同一 `source_region + teacher_id + student_token` 只允许一节课获分，按最早达到
24 小时的课程决胜。相同时间按源主键的真实类型比较：NUMERIC 使用 PostgreSQL 任意精度数值升序，TEXT 使用
原始 UTF-8 bytes 字典序升序；两类之间 NUMERIC 先于 TEXT，禁止把数值主键转 varchar 排序。关系当前态仍持续更新，但不得把已锁定归因移动到后续
课程。取消后重新收藏只更新关系当前态和时间线，不开启新获分周期。如果延迟事件或源纠错改变了第 24 小时的真实关系，按业务生效时间
补/扣 5 分并重选唯一课程；任何时刻同一师生都只能保留一节收藏获分课程。
冻结教师、student_token 或完课时间缺失时不创建观察；favorite.add_time 缺失时到期观察进入
`WAITING_EVIDENCE/FAVORITE_EFFECTIVE_TIME_MISSING`；时间证据完整但 HISTORY scope 不足时进入
`WAITING_HISTORY`。新候选处于上述等待状态时不得新增积分。已经 `AWARDED` 的唯一归因若只是 HISTORY
scope 暂时 STALE，则转为 `AWARDED_PENDING_EVIDENCE`，保留原 +5、原 `award_generation` 和原流水；证据恢复且
候选仍为同课时原地回 `AWARDED`，不得冲正或新增流水。只有完整权威证据明确证明观察时刻为 false、或唯一
候选确实转移/作废时，才按专用归因状态机冲正并在以后真实恢复时开启新 generation。

供给分不是任务，不进 `task_assignments`。5 个个性化改善任务均为 0 分。
供给里程碑的稳定流水身份固定为
`CAPACITY_MILESTONE:CAPACITY_PEAK_SLOT_40:{teacher_id}`，分值 10、reason_code=
`CAPACITY_PEAK_SLOT_40_ACHIEVED`。只有 peak_slot_cnt 证据 CONFIRMED 且首次达到 40 时写一条；以后下降、
scope 失效或再次达到都不冲正、不重复奖励，供给组件账户以该流水是否存在为准。
`perfect_cnt` 是课程明细中满足完美完课口径的去重 `(source_region,source_appoint_id)` 复合课程数，
当前归入可靠性维度；新教师源表的 `perfect_cnt` 只用于对账，不直接驱动 TiDe 计分。原
`on_time_completed_cnt` 继续保留为来源字段，但不参与 v1 计分。课堂质量不读取
`perfect_cnt`、`class_quality_no_issue_rate`，也不使用模拟达成率；逐课同时满足
`is_camera_off = 0`、`is_cpu_usage_high = 0`、`is_network_delay_high = 0` 时，
`hardware_quality_passed = true` 并加 2 分。任一字段为 1 时明确不加分；任一字段
为空时不加分且标记 `SOURCE_MISSING`，不能把空值当作正常。
CPU、网络旧来源已经取消，替换来源尚未接入；过渡期两字段必须为 `NULL`，因此不得新增硬件质量分。

教师源表已经删除 `completed_again_student_15d_cnt` 与 `feedback_rebook_rate`；目标 22 列课程源也不提供 `is_rebooked`。当前 v1 不把复约作为积分子项，不生成 `FEEDBACK_REBOOK_15D` 当前积分账户，
也不进入用户反馈分或 raw 总分。旧配置和历史快照只保留原计分语义用于审计。

逐课 `is_perfect` 只对课程当前冻结 `COMPLETION participation` 计算，从该唯一参与的
`source_participation_fact_current` 读取三值 late/early；两者都明确为 false 才为 true，任一为 NULL 时
`is_perfect=NULL/SOURCE_MISSING`，任一为 true 时为 false。appoint 当前 status 离开 end 不得在纠错决定
前改变冻结参与或冲正完美分。每节 `is_perfect = true` 的课程在可靠性维度获得 4 分，`PERFECT_COMPLETED`
标记为 `CONFIRMED`，并进入 `lesson_total_score`；教师维度 `perfect_cnt`
按去重 `(source_region,source_appoint_id)` 汇总，因此教师子项与逐课加分可直接核对。课堂质量的
`CLASS_QUALITY_HARDWARE` 直接按三项逐课硬件事实结算，达标课程的 2 分进入
`lesson_total_score`，并可与教师课堂质量维度总分逐项核对。

固定成长任务不读取教师快照中的 `new_teacher_task_score` 作为当前结论。每个
当前 9 项必修 assignment 通过 `template_version_id` 固定所用模板；状态合法变为
`COMPLETED` 后，立即按该 `task_templates.payload.score_value` 计入当前成长任务分，
并同步更新当前教师积分组件、总分投影和资格，不必等待其余任务完成。任务状态与模板分值仍是
事实源，积分账户只是可查询投影。新教师首次进入系统时由本系统初始化当前 9 项必修任务，默认状态为
`ASSIGNED`（未完成）。少于 9 条 assignment 属于内部 `TASK_BASELINE_INCOMPLETE`，
不能解释为教师未完成，不能标为外部 `SOURCE_MISSING`，也不能用默认 30 分补齐。

出营必须同时满足：

- 当前 9 个固定成长 assignment 全部存在且状态均为 `COMPLETED`；
- L0 投诉次数为 `0`；
- `raw_total_score >= 100`。

L0 投诉次数按 `source_course_complaints` 的全部当前有效 typed 行与 `complaint_category_rules` 精确匹配后
聚合，不只读取课程最新展示分类。存在投诉但三级分类尚未
精确映射出级别时，投诉证据视为不完整，资格门禁失败关闭，不能当作 0 次 L0。
`complaint_type_grandson IS NULL` 仍满足有效投诉条件并计入 `feedback_valid_complaint_cnt`，
但因无法判定严重度或具体改善分类，必须保持 `PENDING_DATA:COMPLAINT_CATEGORY_MISSING`，
不得因此创建教师任务或把 L0 门槛推断为已通过。

当前金牌条件必须同时满足：

- 已满足上述出营资格；
- `raw_total_score >= 200`；
- `late_cnt <= 1`；
- `early_cnt = 0`；
- `absent_cnt = 0`。

`late_cnt / early_cnt / absent_cnt` 直接读取教师宽表；字段没有真实来源证据时门槛
失败关闭，不能把默认 0 当作“确认没有发生”。

新积分规则发布时，系统在同一数据库事务内按新版本全量重算当前教师积分、五维子项和
当前门槛命中情况；任一教师重算失败则新版本不生效。发布成功返回时，当前投影已经全部
使用新版本，不存在“新规则已发布、看板仍是旧分数”的中间状态。

出营和金牌资格采用“首次获得后锁定”：

- `graduation_criteria_met / gold_criteria_met` 表示按当前规则和当前数据重新判断的结果；
- `graduation_qualified / gold_qualified` 表示教师是否历史上已经获得对应资格；
- 当前条件后来不再满足时，当前分数和门槛命中情况照常更新，但已获得资格不撤回。

分数线命中、当前条件满足、历史资格获得、任务完成、积分结算和后续业务效果是不同事实，
不能互相代替。

### 3.1 教师在线、在营与资格状态

数据库必须分开三个维度，不能用一个“教师状态”字段混合表达：

| 维度 | 值 | 语义 |
|---|---|---|
| 在线状态 | `NEW / EXISTING / LEFT / BLOCKED` | 新师、旧师、离职、拉黑；与出营或金牌资格正交 |
| 在营状态 | `IN_CAMP / GRADUATED` | rev75 已将旧 `IN_PROGRESS / NOT_IN_CAMP` 迁为在营；`GRADUATED` 不可回退 |
| 金牌状态 | `NOT_GOLD / GOLD` | 由 `gold_qualified` 派生；`GOLD` 不可回退 |

在线状态映射为：`status='on'` 且入职日至入职日+29 天为 `NEW`；`status='on'`
且已达入职日+30 天为 `EXISTING`；`status='off'` 为 `LEFT`；`status='hei'` 为
`BLOCKED`。按北京业务日期计算；`NEW→EXISTING` 必须由日更或等价定时重算驱动，
不能仅依赖新 DTS 事件。其他 `status`，或 `on` 教师缺少/无效/未来入职日时，
`online_status=NULL` 并标记 `SOURCE_MISSING`。

教师进入培养范围后为 `IN_CAMP`。入职 30 天内首次满足出营条件时立即出营；
第 30 天仍未满足时继续保持 `IN_CAMP`，30 天以后首次满足仍可转为
`GRADUATED`。首次出营和首次达到金牌时，分别一次性写入 `graduation_qualified_at` 和
`gold_qualified_at`；两个时间都不得被后续重算覆盖。
课程事实不以入职 30 天为准入上限；30 天只限制 `NEW→EXISTING` 和明确指定的新师观察指标。

出营分数和金牌进度分分开存储：首次出营时写入不可变的
`graduation_score_locked=100`；`raw_total_score` 作为实际累计分，出营后、达到金牌后都继续计算且不封顶。
例如教师 100 分出营，后续再获得 100 分时 `raw_total_score=200` 并获得金牌，但
出营分数始终显示 100。实际分后续达到 250 时，教师端仍只显示
`public_total_score=min(250,200)=200`。`LEFT/BLOCKED` 只是在线状态，不停止新积分计算。

### 3.2 当前规则与旧快照兼容边界

- `v1` 是当前唯一生效口径：可靠性读取 `perfect_cnt × 4 + peak_completed_cnt × 2`；课堂质量按逐课硬件质量达标结果每节加 2 分；金牌包含迟到、早退、缺席三项门槛；必修硬门槛为当前 9 项。
- 旧格式 `v2`–`v10` 只用于读取旧快照；其中复约积分、旧可靠性口径、旧课堂质量分、`severe_redline_event`、旧任务数量和旧资格门槛均不得参与当前资格判断。
- 测试库积分配置历史已收敛为唯一 v1。当前页面、重算和新快照只使用 v1；历史已获得资格不随重算撤销。

## 4. 个性化触发口径

规则是确定性 Workflow，不由模型猜测。match 键和 assignment 键是两层不同的幂等身份：
课程/参与/地区证据变化只转换对应 `personalized_trigger_matches`，不改写已有教师任务的生命周期。
`MATCHED/MATERIALIZED → SUPPRESSED` 或 `SUPPRESSED → MATCHED/MATERIALIZED` 都更新同一稳定键行并
`match_revision += 1`；恢复时不新建证据行。

`absence_reason_detail` 只保存 `dom_teacher_absent_reason.reason_type`。以下缺席任务必须按
`reason_type` 精确值匹配，不得读取 `reason_desc` 或 `appoint.cancel_reason`：

1. **Lesson Memo**：`reason_type='Unfilled Lesson Memo'` 时幂等创建 `P-REL-MEMO`，任务动作为阅读内嵌 Lesson Memo 规则文档。教师端标题读取首次物化时冻结的已发布英文模板，不写中文动态标题。该值不增加 `no_notice_cnt`。
2. **出席问题**：其他任意非空 `reason_type`（包括 `No Notification`）时幂等创建 `P-REL-ATTENDANCE`，教师完成阔知课程 595 Reliability。仅 `No Notification` 另外增加 `no_notice_cnt`；空原因不创建缺席任务。
   原因必须先映射到唯一 `t_absent` 参与。证据 match 使用
   `absence:{rule_code}:{source_region}:{source_appoint_id}:{participation_seq}`，assignment 使用
   `personalized:{task_code}:{teacher_id}`。原因改型/删除抑制旧 match；同键以后恢复时重新激活原 match
   并 `match_revision += 1`，复用原 assignment，不新建证据行或任务行。
3. **投诉路由**：课程已有冻结完课教师、三级分类 ID 非空并精确命中规则后，按
   `出席问题→TR-REL-ATTENDANCE/P-REL-ATTENDANCE`、
   `网络设备问题→TR-QUALITY-NETWORK-EQUIPMENT/task-less 提醒`、其他 P0/P1→
   `TR-FB-SEVERE-COMPLAINT/Ops Case`、其他 P2/P3/P4→
   `TR-FB-GENERAL-COMPLAINT/P-FB-COMPLAINT` 顺序路由。每课 match 键统一为
   `complaint:{rule_code}:{source_region}:{source_appoint_id}:{completion_participation_seq}:{complaint_type_grandson}`，assignment 键为
   `personalized:P-FB-COMPLAINT:{teacher_id}:{complaint_type_grandson}`。投诉失效、分类/严重度变化或完课归属纠错时
   抑制旧 match；同键恢复时重新激活原 match 并 `match_revision += 1`。分类名称变化不改变 ID 身份或既有任务标题。
   `complaint_type_grandson IS NULL` 仍计入有效投诉指标，但只保留
   typed complaint/course current 的 `PENDING_DATA:COMPLAINT_CATEGORY_MISSING`，不创建 trigger match、
   assignment、Case 或提醒。出席任务复用
   `personalized:P-REL-ATTENDANCE:{teacher_id}`；严重 Case key 为
   `complaint-case:{rule_code}:{source_region}:{source_appoint_id}:{completion_participation_seq}:{complaint_type_grandson}`；网络提醒
   `source_ref=complaint-notification:{rule_code}:{source_region}:{source_appoint_id}:{completion_participation_seq}:{complaint_type_grandson}`。
   来源纠错时 assignment 保留；OPEN Case、STORED 提醒可转 CANCELLED，已处理/已读输出不回退；同键恢复
   只恢复由来源纠错自动取消的原行，不重复创建。精确状态以冻结实施规格 §6.4 为准。
4. **重复差评标签**：只读取 DOM 当前评价为差评的课程，并从 `source_course_labels` 按 `label_id`
   取当前标签集合；`label_name` 只用于展示。同一冻结完课教师的同一 `label_id` 出现在至少 2 个不同
   源课程时，创建一条 `P-FB-NEGATIVE`；教师端标题只从已发布 `teacher_personalized_copy` 生成：精确命中时为
   `Negative Feedback - {mapped English}`，未命中固定为 `Negative Feedback - Feedback Pattern`，原标签名只留
   evidence，不得写中文动态标题。命中次数按源课程复合键去重。
   每课 match 键为 `negative-label:{teacher_id}:{label_id}:{source_region}:{source_appoint_id}`，assignment
   键为 `personalized:P-FB-NEGATIVE:{teacher_id}:{label_id}`。评价、标签或完课归属纠错使阈值下降时
   抑制对应 match；同课程标签恢复时重新激活原 match 并 `match_revision += 1`，不新建证据行。
   标签改名不改变身份或既有任务标题。
5. **拉黑聚合**：`P-FB-BLACKLIST` 按当前拉黑关系中不同 `student_token` 数量计算，不要求师生已完课。
   DOM/OVS 同教师 ID 的关系分地区计阈值，不跨 `source_region` 合并；每个地区首次达到 2 人时命中
   `blacklist-threshold:{source_region}:{teacher_id}`。降到 2 人以下时抑制该地区 match，同地区恢复阈值时重新激活原行并
   `match_revision += 1`。任一地区命中都按全局 `teacher_id` 复用同一
   `personalized:P-FB-BLACKLIST:{teacher_id}` assignment；assignment 只冻结首次地区证据，后续贡献进入
   地区 match/audit，当前贡献从 active match 聚合，不改不可变 assignment evidence，也不开启新阈值周期。
6. **课中质量**：未开摄像头为 1 时创建 task-less 站内提醒，标题“课中质量问题”。来源事实不等待
   end，但 close-camera 表无教师字段，因此提醒等待冻结完课教师。match/source_ref 分别为
   `camera-off:TR-QUALITY-CAMERA-OFF:{source_region}:{source_appoint_id}:{completion_participation_seq}`、
   `camera-notification:TR-QUALITY-CAMERA-OFF:{source_region}:{source_appoint_id}:{completion_participation_seq}`。
   true→false 时抑制 match 并仅取消尚为 STORED 的提醒；恢复时复用原行。完课 TRANSFER 以新 participation
   产生新键，旧已读提醒只保留历史。CPU、网络字段在替换来源接入前保持 `NULL`，不得触发提醒；新来源
   确版后再补对应规则。

以上 P-REL、`P-FB-NEGATIVE`、`P-FB-COMPLAINT`、`P-FB-BLACKLIST` 任务首次物化后，不因任何
match 抑制或恢复而删除、取消、状态回退或重建。未完成 assignment 保留当前进度，已完成 assignment
保持终态。`dom_user_complaint/ovs_user_complaint` 只保留 source version/current 审计，不生成业务脏键、
`source_wide.changed.v2` Outbox、指标、任务或积分。

当前 2.0 基线共有 243 节差评课，均能从评价详情解析出标签；共形成 61 个“教师 × 重复标签”任务，涉及 33 位教师。没有评价详情缺口时，不再生成差评 `PENDING_DATA`。

严重投诉是运营 Case，课中质量是提醒，都不伪装成教师任务。每个命中用 `dedupe_key` 幂等，并在 `personalized_trigger_matches.evidence_snapshot` 保留当时证据。收藏 24 小时归因也必须使用独立幂等键，并保存当时关系状态和观察时间，不能只保存当前关系结果。

## 5. 导入与重算安全

- 旧文件导入路径在导入前校验 Sheet、字段顺序、行完整性、教师 ID、业务键和文件摘要；任一失败都不提交半批数据。
- DTS 接入事务只写事件账本、来源当前态/tombstone、脏键和 checkpoint；领域投影完成后写紧凑 v2 Outbox，Trigger 不做积分、任务或资格计算。
- `dom_user_complaint/ovs_user_complaint` 是上述通用脏键/Outbox 链路的明确例外：其 INSERT/UPDATE/DELETE
  只写 source version/current 审计并推进 checkpoint，不产生业务脏键或 v2 Outbox。
- SourceWide Worker 将异步、幂等重算受影响教师/课程；处理失败保留待重试事件，不回滚已提交的源行。该 Worker 尚未实现，当前不能声称源更新会自动更新派生结果。
- DTS 幂等、乱序与水位由数据库 epoch ledger、`source_row_revision` 当前态选择器和同事务 checkpoint CAS
  共同负责；外部监控只观测告警，不拥有业务顺序或提交水位。`source_position` 只作同 epoch 诊断审计，不能
  作为跨 partition 顺序或 current selector 末位。
- 历史原始行、快照、规则命中和积分流水不原地改写；纠错通过新批次、修正事实或冲正流水完成。
- 海外来源仍可在受限事实中保留海外源学员 ID；国内来源禁止把原始学员 ID 写入
  `complaint_rule_imports.raw_rows`、DTS 账本/Outbox payload 或任何其他海外事实，只能携带 `dom:v1:` 稳定伪名 token。前端只使用必要
  聚合，不返回海外原始 ID 或国内 token。
