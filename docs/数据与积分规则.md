# 数据与积分规则

日期：2026-08-11
状态：唯一当前口径

## 1. 事实分层

- `teacher_source_wide` 是确认映射的 53 个教师字段加 2 个可空教师资料状态字段的当前源事实；
  `lesson_source_wide` 是课程 CSV 23 列当前源事实。源表不增加同步控制字段。
- `teacher_metric_snapshots`、`lesson_facts` 和 `lesson_dimension_scores` 已由 revision 47 物理删除；旧课程离线导入器及唯一历史分析视图已先退役。`data_import_batches`、`source_records` 只服务投诉规则文件的来源追溯，不参与两张宽表同步。
- `complaint_category_rules` 保存投诉三级分类精确匹配规则。原始 P0–P4 不改写，同时保存 `severity_rank=0–4`。
- `personalized_trigger_matches` 保存规则命中、最小证据和最终输出的追溯关系。
- `task_assignments` 保存固定成长与个性化改善任务的当前状态；只有当前已发布的 9 项固定成长任务的合法 `COMPLETED` 可产生成长积分。
- `score_entries` 是不可变积分流水和结算审计。固定成长任务的当前计分事实仍以共享 `task_assignments` 的状态及其固定引用的模板分值为准，教师端不直接写分。
- `score_accounts` 保存每位教师五维当前总分；`score_component_accounts` 保存维度内每个积分子项的当前总分；`lesson_score_results` 保存一节课一行的三个课程维度、总分和证据状态，不再维护一课三行的重复积分投影。

教师源表中的 `peak_slot_cnt`、`first_booked_dt`、`is_cpl_tesol`、
`is_self_introduce` 均是类型化字段。G01 只把 `is_cpl_tesol` 作为外部证据；
`is_self_introduce` 继续作为教师资料事实保留，但不参与 G01 展示或完成判断。
两者为 `NULL` 时均表示上游尚未提供，不能当成明确未完成。

## 2. 数据状态

| 值 | 含义 |
|---|---|
| `REAL` | 上游直接提供的事实 |
| `DERIVED_REAL` | 只由真实字段和确定公式派生 |
| `MOCK` | 测试数据 |
| `MOCK_SIMULATION` | 基于真实规模的模拟结果 |
| `MOCK_PROXY` | 暂用相邻字段代替目标事实 |

没有证据时对应分数为 `0`，但必须另记 `SOURCE_MISSING`；`0` 不得伪装成“已确认没有问题”。

## 3. 积分与资格

五个维度独立累计，不使用权重、维度封顶或维度最低线：

```text
用户反馈分 = 好评次数 × 5 + 收藏人数 × 5
可靠性分 = 完美完课数 perfect_cnt × 4 + Peak 完课数 peak_completed_cnt × 2
课堂质量分 = 硬件质量达标课程数 × 2
供给分 = peak_slot_cnt 首次达到 40 时 +10，之后锁定
固定成长任务分 = Σ（状态为 COMPLETED 的当前 9 项必修 assignment 所固定模板的 score_value），最高 30
raw 总分 = 五个维度之和
显示分 = min(raw 总分, 200)
```

教师维度的收藏人数与收藏总分直接读取 `teacher_source_wide` 中的
`feedback_favorite_cnt`，不从课程明细反向覆盖。课程级只负责归因：同一
`teacher_id + student_id_hash` 下，在 `valid_for_scoring = true`、课程状态为
`end` 且 `is_favorited = true` 的课程中，按 `lesson_local_date +
lesson_local_time` 取最早一节计分；同一时间以 `lesson_id` 稳定决胜。后续收藏课
仍返回 `is_favorited = true`，但 `FEEDBACK_FAVORITE.awarded = false`、分数为 0。
学生标识或本地上课时间缺失时，不猜测首课，该师生组合不做课程级收藏归因并标记
`SOURCE_MISSING`。教师汇总与课程归因的差额进入未归因分和对账状态，不改写教师总分。

供给分不是任务，不进 `task_assignments`。5 个个性化改善任务均为 0 分。
`perfect_cnt` 是课程明细中满足完美完课口径的去重 `source_appoint_id` 数，当前归入可靠性维度；新教师源表的 `perfect_cnt` 只用于对账，不直接驱动 TiDe 计分。原
`on_time_completed_cnt` 继续保留为来源字段，但不参与 v1 计分。课堂质量不读取
`perfect_cnt`、`class_quality_no_issue_rate`，也不使用模拟达成率；逐课同时满足
`is_camera_off = 0`、`is_cpu_usage_high = 0`、`is_network_delay_high = 0` 时，
`hardware_quality_passed = true` 并加 2 分。任一字段为 1 时明确不加分；任一字段
为空时不加分且标记 `SOURCE_MISSING`，不能把空值当作正常。

教师源表已经删除 `completed_again_student_15d_cnt` 与 `feedback_rebook_rate`；当前 23 列课程源也不提供 `is_rebooked`。当前 v1 不把复约作为积分子项，不生成 `FEEDBACK_REBOOK_15D` 当前积分账户，
也不进入用户反馈分或 raw 总分。旧配置和历史快照只保留原计分语义用于审计。

逐课 `is_perfect` 由课程状态为 `end`、迟到为 0、早退为 0 三项事实派生。
每节 `is_perfect = true` 的课程在可靠性维度获得 4 分，`PERFECT_COMPLETED`
标记为 `CONFIRMED`，并进入 `lesson_total_score`；教师维度 `perfect_cnt`
按去重 `source_appoint_id` 汇总，因此教师子项与逐课加分可直接核对。课堂质量的
`CLASS_QUALITY_HARDWARE` 直接按三项逐课硬件事实结算，达标课程的 2 分进入
`lesson_total_score`，并可与教师课堂质量维度总分逐项核对。

固定成长任务不读取教师快照中的 `new_teacher_task_score` 作为当前结论。每个
当前 9 项必修 assignment 通过 `template_version_id` 固定所用模板；状态合法变为
`COMPLETED` 后，立即按该 `task_templates.payload.score_value` 计入当前成长任务分，
并同步更新当前教师积分组件、总分投影和资格，不必等待其余任务完成。任务状态与模板分值仍是
事实源，积分账户只是可查询投影。新教师首次进入系统时由本系统初始化当前 9 项必修任务，默认状态为
`ASSIGNED`（未完成）。少于 9 条 assignment 属于内部 `TASK_BASELINE_INCOMPLETE`，
不能解释为教师未完成，不能标为外部 `SOURCE_MISSING`，也不能用默认 30 分补齐。

出营必须同时满足：

- 当前 9 个固定成长 assignment 全部存在且状态均为 `COMPLETED`；
- L0 投诉次数为 `0`；
- `raw_total_score >= 100`。

L0 投诉次数按 `lesson_source_wide` 的三级投诉分类与当前 `complaint_category_rules` 精确匹配后聚合。存在投诉但三级分类尚未
精确映射出级别时，投诉证据视为不完整，资格门禁失败关闭，不能当作 0 次 L0。

当前金牌条件必须同时满足：

- 已满足上述出营资格；
- `raw_total_score >= 200`；
- `late_cnt <= 1`；
- `early_cnt = 0`；
- `absent_cnt = 0`。

`late_cnt / early_cnt / absent_cnt` 直接读取教师宽表；字段没有真实来源证据时门槛
失败关闭，不能把默认 0 当作“确认没有发生”。

新积分规则发布时，系统在同一数据库事务内按新版本全量重算当前教师积分、五维子项和
当前门槛命中情况；任一教师重算失败则新版本不生效。发布成功返回时，当前投影已经全部
使用新版本，不存在“新规则已发布、看板仍是旧分数”的中间状态。

出营和金牌资格采用“首次获得后锁定”：

- `graduation_criteria_met / gold_criteria_met` 表示按当前规则和当前数据重新判断的结果；
- `graduation_qualified / gold_qualified` 表示教师是否历史上已经获得对应资格；
- 当前条件后来不再满足时，当前分数和门槛命中情况照常更新，但已获得资格不撤回。

分数线命中、当前条件满足、历史资格获得、任务完成、积分结算和后续业务效果是不同事实，
不能互相代替。

### 3.1 当前规则与旧快照兼容边界

- `v1` 是当前唯一生效口径：可靠性读取 `perfect_cnt × 4 + peak_completed_cnt × 2`；课堂质量按逐课硬件质量达标结果每节加 2 分；金牌包含迟到、早退、缺席三项门槛；必修硬门槛为当前 9 项。
- 旧格式 `v2`–`v10` 只用于读取旧快照；其中复约积分、旧可靠性口径、旧课堂质量分、`severe_redline_event`、旧任务数量和旧资格门槛均不得参与当前资格判断。
- 测试库积分配置历史已收敛为唯一 v1。当前页面、重算和新快照只使用 v1；历史已获得资格不随重算撤销。

## 4. 个性化触发口径

规则是确定性 Workflow，不由模型猜测。同一课程按以下顺序评估：

1. **Lesson Memo 优先**：`absence_reason_detail = "Unfilled Lesson Memo"` 时创建 `P-REL-MEMO`，展示名“出席（未填写lesson-memo）问题”。同课的迟到/早退/假早退只放进证据说明，不再重复发出席任务。
2. **出席问题**：缺席原因非空且不是 Lesson Memo，或迟到/早退/假早退任一为 1，创建 `P-REL-ATTENDANCE`，教师完成培训和 quiz。
3. **投诉路由**：先用投诉三级分类精确匹配 `complaint_category_rules`。
   - 投诉二级分类为“出席问题”，改走可靠性出席任务；
   - 投诉二级分类为“网络设备问题”，改走课堂质量提醒；
   - 其他投诉的 P0/P1（`severity_rank 0/1`）创建运营 Case，标题“严重投诉-[投诉三级分类]问题”；
   - 其他投诉的 P2/P3/P4（`severity_rank 2/3/4`）创建 `P-FB-COMPLAINT`，标题“一般投诉-[投诉三级分类]问题”；
   - 三级分类无精确映射时记 `PENDING_DATA`，不自动输出。
4. **重复差评标签**：只读取 `差评标签 = 1` 的课程，将 `评价详情` 按英文逗号拆分、去除首尾空格并在单课内去重。同一教师的同一标签出现在至少 2 个不同课程 ID 时，创建一条 `P-FB-NEGATIVE`，标题“差评-[标签名称]问题”；命中次数按不同课程数计算。
5. **拉黑聚合**：同一教师被至少 2 个不同学员拉黑时，首次达阈值创建 `P-FB-BLACKLIST`，标题“拉黑问题”。
6. **课中质量**：未开摄像头、CPU 过高或网络延迟过高任一为 1，创建 task-less 站内提醒，标题“课中质量问题”，说明具体异常。

当前 2.0 基线共有 243 节差评课，均能从评价详情解析出标签；共形成 61 个“教师 × 重复标签”任务，涉及 33 位教师。没有评价详情缺口时，不再生成差评 `PENDING_DATA`。

严重投诉是运营 Case，课中质量是提醒，都不伪装成教师任务。每个命中用 `dedupe_key` 幂等，并在 `personalized_trigger_matches.evidence_snapshot` 保留当时证据。

## 5. 导入与重算安全

- 旧文件导入路径在导入前校验 Sheet、字段顺序、行完整性、教师 ID、业务键和文件摘要；任一失败都不提交半批数据。
- 新源表事务只写源行和紧凑 Outbox 事件；Trigger 不做积分、任务或资格计算。
- SourceWide Worker 将异步、幂等重算受影响教师/课程；处理失败保留待重试事件，不回滚已提交的源行。该 Worker 尚未实现，当前不能声称源更新会自动更新派生结果。
- 相同业务主键的幂等写入与乱序/批次水位由外部监控服务负责；两张源表不保存额外同步字段。
- 历史原始行、快照、规则命中和积分流水不原地改写；纠错通过新批次、修正事实或冲正流水完成。
- 海外来源仍可在受限事实中保留海外源学员 ID；国内来源禁止把原始学员 ID 写入海外
  `source_records.raw_payload` 或任何其他表，只能携带 `dom:v1:` 稳定伪名 token。前端只使用必要
  聚合，不返回海外原始 ID 或国内 token。
