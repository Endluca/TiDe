# TIT 成长系统数据库表结构

状态：唯一当前文档
数据库：PostgreSQL
核验日期：2026-07-30
联动口径版本：TIDE-SHARED-DB-20260730-14

## 1. 当前边界

本文档只描述当前 ORM 与已落库 Schema，不再保留另一套“目标表”。

- 当前在世文既有 24 张业务表之外，新增 1 张双方共用工单表，另有 1 张 Alembic 迁移元数据表。
- 任务域物理表只有 `task_templates` 和 `task_assignments`。`task_assignments` 是两端共用的任务实例及当前状态事实。
- 物理 Schema 已支持任务触发中心幂等初始化 `FIXED_GROWTH + TRIGGER_CENTER`，并按真实业务数据创建 `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER`。当前固定目录为连续编号的 G01–G09；G04 是合并后的“首课备课与设备网络检测”，教师端过滤隐藏 G00，按 9 个可见任务的 `camp_day` 或上一阶段完成状态开放，不创建第二套任务实例。
- 任务写入会由数据库校验所有权、状态流转、终态、固定任务唯一性和乐观锁，并写入 `audit_events`；状态变化同时产生 `outbox_events`。
- 教师端当前积分读取模型为 `teacher_scorecard_current` 和 `teacher_lesson_score_current`。前者一位教师一行，后者一节课一行；教师端不再从下述原始积分表重建页面结果。
- 公司测试库已有真实教师宽表、831 条个性化 assignment 和 527 条世文业务文字提醒；现有 `public.notifications` 均未携带 `task_id`。个性化任务分配与截止时间只以 assignment 为准，其他尚缺来源的指标继续明确标记为 Mock 或代理数据。
- 站内通知、提醒、运营 Case 和外部动作表已可供调试，但真实投递 Worker 尚未接入，不能把表中记录解读为已送达。

### 1.1 外部数据日更

当前已实现的是“手工导入文件 → `data_import_batches` → `teacher_metric_snapshots`”，不是生产日更。

生产形态需要每天从外部接口获取教师、课程和相关证据，然后完成拉取、完整性校验、标准化、幂等落库和受影响教师重算。以下内容尚未实现，不是当前表：

- 外部接口鉴权、分页/游标、水位和迟到修正规则；
- 每日调度、重试、失败告警和补数/重放；
- 接口原始响应的无损版本链和完整性水位。

待数据方确认接口合同后再做 Schema 迁移；在此之前不用假表名冒充已实现能力。

### 1.2 通用口径

- `timestamptz` 为带时区时间；`date` 只保留日粒度。
- `jsonb` 保存已有复合输入或快照；稳定查询字段仍使用类型化列。
- `NULL` 表示来源未提供或尚不确定；`0` 只表示明确的零值。
- `REAL / DERIVED_REAL / MOCK / MOCK_SIMULATION / MOCK_PROXY` 用于区分真实、真实派生和测试/代理数据。
- 当前积分列使用 `double precision`，本文按实际 Schema 记录，不写成尚未落库的精确小数类型。

## 4. 积分

本节三张表是世文内部积分事实与投影，用于源系统结分、审计和生成当前读取模型。教师端应用账号不直接读取，也不根据这些表自行计算页面积分。

### 4.1 `lesson_dimension_scores`

每节课在可靠性、用户反馈、课堂质量三个维度的当前分数状态。该表由世文持有：积分规则发布后，受控维护流程使用新规则重算所有老师的全部历史完课记录，并按 `camp_enrollment_id + lesson_id + dimension` 幂等更新本表。教师端应用账号只有只读权限，不参与写入。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `score_state_id` | varchar，PK，必填 | 课程维度分状态 ID |
| `camp_enrollment_id` | varchar，必填 | 当前入营关联键 |
| `lesson_id` | varchar，FK，必填 | 对应课程 |
| `teacher_id` | varchar，FK，必填 | 获得本课分的教师 |
| `dimension` | varchar，必填 | `RELIABILITY / USER_FEEDBACK / CLASS_QUALITY` |
| `current_score` | double precision，必填 | 该课该维度当前分数 |
| `evidence_status` | varchar，必填 | 证据状态 |
| `evidence_coverage` | varchar，可空 | 证据覆盖程度 |
| `score_rule_version` | varchar，必填 | 计分规则标识 |
| `current_revision` | integer，必填 | 该课该维度的当前修订序号 |
| `score_as_of` | timestamptz，可空 | 分数业务截止时间 |
| `last_score_entry_id` | varchar，可空 | 最后一条对应积分流水 ID |
| `payload` | jsonb，必填 | 当前计分输入和说明 |

| `minimum_score` | double precision，必填 | 该维度毕业最低门槛 |
| `weight` | double precision，必填 | 该维度当前配置权重 |
| `score_rule_version` | varchar，必填 | 当前计分规则标识 |

| `updated_at` | timestamptz，必填 | 账户最后重算时间 |
| `payload` | jsonb，必填 | 账户计算快照和说明 |

## 5. 任务

### 5.1 `task_templates`

唯一任务模板目录。物理表可同时保存固定任务和已发布的个性化模板；assignment 通过 `row_id` 冻结使用的具体版本。当前启用的 G01–G09 编码、阶段和分值以本节目录为准；隐藏 G00 仅作历史记录。

| 字段 | 类型/必填 | 含义 |
|---|---|---|
| `row_id` | varchar，PK，必填 | 一条模板记录的稳定 ID，供 assignment 冻结引用 |
| `template_id` | varchar，必填 | 任务稳定编码；当前固定任务为 G01–G09，隐藏历史任务为 G00，个性化任务使用已发布模板编码 |
| `template_version` | integer，必填 | 同一模板的版本序号；旧 assignment 继续引用原版本 |
| `status` | varchar，必填 | `DRAFT / PUBLISHED / RETIRED`；只有已发布模板可被 assignment 引用 |
| `revision` | integer，必填 | 草稿编辑并发乐观锁 |
| `output_type` | varchar，必填 | 输出类型；当前为 `TEACHER_TASK` |
| `execution_owner` | varchar，必填 | 任务执行方；数据库限制为 `TEACHER_APP` |

当前数据库硬约束：

- 当前启用的 G01–G09 必须为 `FIXED_GROWTH + TRIGGER_CENTER`；隐藏 G00 只保留历史记录，其他已发布模板编码只能是 `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER`。
- 同一教师同一 G 任务只能有一条。已确认不存在复营或跨营期回补。
- 新教师首次写入 `teachers` 时，任务触发中心在同一事务中幂等初始化恰好 9 条 `ASSIGNED` 固定 assignment；初始化本身不创建通知。少于 9 条统一记为内部 `TASK_BASELINE_INCOMPLETE`。
- 教师端可见固定任务按阶段开放：G01–G04 从第 1 天开放；G05–G07 在第 8 天自动开放，或在前述 4 项全部为 `COMPLETED` 后提前开放；G08–G09 在第 15 天自动开放，或在 G05–G07 全部为 `COMPLETED` 后提前开放。隐藏 G00 不参与教师端阶段判断。
- 教师端读取 assignment 时必须关联 `template_version_id = task_templates.row_id` 并限制模板 `status = PUBLISHED`。
- 固定任务不使用 `BEFORE_FIRST_LESSON / BEFORE_FIRST_PUSH` 事件截止时间；当前未配置截止时间时，`due_at` 与三个时区字段同时为空。
- 有 `due_at` 时，三个时区证据字段必须同时存在；无截止时间时必须同时为空。
- TIDE 提醒调度器只读 `assigned_at / due_at / timezone_used / timezone_source / timezone_verified_at` 等必要字段，不修改 assignment 的状态、截止时间或内容。
- `FAILED / EXPIRED / WAIVED / CANCELLED` 必须有 `status_reason_code`。
- `COMPLETED / EXPIRED / WAIVED / CANCELLED` 为不可回退终态；`FAILED` 可按状态机进入重试或完成。
- assignment 禁止删除；标识、教师、任务编码、模板引用、Why、来源和幂等键在创建后不可修改。

拉黑量达到 2 及以上时，世文先进入运营确认流程，不直接创建教师 assignment。运营确认教师确有问题并选择已发布任务后，才创建个性化 assignment；教师任务具体内容与完成规则待嘉荷后续配置。运营确认过程和教师原因说明不写入 `task_assignments`。

## 8. 配置

`config_versions` 的记录序号是配置审计机制，不是另一套产品或文档。每个 `config_key` 同时最多只有一条 `PUBLISHED`。

世文负责按当前规则生成积分结果并刷新两个教师端读取模型。教师端只读已落库结果，不读取配置，不执行规则，也不返回差额或对账字段。

### 8.2 教师端当前积分读取模型

`public.teacher_scorecard_current` 直接返回当前教师的 `raw_total_score / public_total_score`、出营与金牌资格、阈值、必修完成数、积分版本，以及五维 `dimensions[].components[]`。

`public.teacher_lesson_score_current` 直接返回分页所需的课程顺序与总数、课程事实、三维分、具体加分项、证据状态和积分版本。收藏按 `teacher_id + student_id_hash` 仅归因到上课时间最早的有效完课收藏；后续收藏课仍返回收藏事实，但收藏项为 0 分。当前无逐课 `perfect` 证据时，课堂质量课程项保持 0 分并标记 `SOURCE_MISSING`，不得平均拆分。

两张视图均由世文持有。教师端后端每次查询必须携带当前会话教师的 `teacher_id`，并只对白名单字段建模。详细字段见[教师端积分与课程读取对照表](教师端积分与课程读取对照表.md)。
