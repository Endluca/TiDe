# 教师端任务双向接口（精简版）

版本：V2.3-draft  
日期：2026-07-21  
用途：给任务触发中心和教师端研发直接对字段、接口和回传规则。

本文只回答两件事：双方传什么、怎么传。触发规则、数据来源、积分计算、运营 Case 和本地 Mock 验收不属于教师端接口。

> **实现状态：本文是双方准备冻结的精简外部合同，不是当前内部 `/api/v2` 调试接口的说明。现有内部接口字段更多，与本文请求体不兼容；教师端不要把下文占位地址直接替换成 `/api/v2` 调用。我方需要先按本文提供外部适配接口，再开始联调。**

| 链路 | 本文定义 | 当前实现 | 联调前由我方完成 |
|---|---|---|---|
| A 下发任务 | 精简任务 JSON | 只有内部 publication，没有真实教师端发送器 | 增加发送器、字段映射和最小 ACK |
| B1 回传状态 | 精简状态事件 | 内部接口仍要求旧结果契约字段 | 增加外部适配模型和最小响应 |
| B2 回传固定任务 | 精简完成事件 | 内部接口仍要求多项固定常量 | 增加完成事件适配模型和最小响应 |
| 鉴权与错误 | 机器鉴权、防重放、统一错误结构 | 仍为运营 Cookie 和本地占位签名 | 增加正式安全层和统一错误适配 |

## 1. 双方各自负责什么

| 方向 | 调用方 → 接收方 | 传递内容 |
|---|---|---|
| A | 任务触发中心 → 教师端 | 下发 28 类个性化改善任务 |
| B1 | 教师端 → 任务触发中心 | 回传上述任务的执行状态 |
| B2 | 教师端 → 任务触发中心 | 回传 `G01`–`G10` 固定成长任务的完成结果 |

边界：

- 方向 A、B1 只涉及 `S01`–`S05` 和 23 个 `P-*`，共 28 类任务，全部为 0 分。
- `G01`–`G10` 已存在于教师端。任务触发中心不重复下发，只通过 B2 接收完成结果，并在我方服务端计算积分。
- 教师端不传分数、总分、出营、金牌或试用期结论。
- `peak_slot_cnt >= 40` 的供给 10 分是我方内部规则，不经过教师端接口。
- 28 类任务编码和用途见 [教师端任务设计交接](../docs/教师端任务设计交接_v2_20260720.md)。

## 2. 共同传输方式

- 使用 HTTPS `POST`。
- 请求体使用 UTF-8 JSON，`Content-Type: application/json`。
- 时间使用 ISO 8601 且必须带时区，建议统一传 UTC，例如 `2026-07-21T08:00:00Z`。
- HTTP `2xx` 且响应 `accepted=true` 才算接收成功。
- 超时、`429` 或 `5xx` 可以重试；重试必须使用原业务 ID 和原请求内容，不能重新生成 ID。
- 相同幂等 ID、相同内容重复发送，应返回原成功结果；相同幂等 ID、不同内容应返回 `409`。

### 2.1 正式联调安全要求

| 能力 | 必要性 | 含义 | 为什么需要 |
|---|---|---|---|
| 机器身份鉴权 | 必须 | 识别请求来自任务触发中心还是教师端服务 | 防止普通用户或未授权系统调用机器接口 |
| 请求防重放 | 必须 | 拒绝超出有效窗口或已经消费的请求 | 防止旧请求被再次发送并重复改变任务状态 |
| 请求完整性校验 | 必须 | 确认请求内容在传输和转发过程中未被改变 | 防止 ID、状态或教师信息被篡改 |

具体采用网关 Token、HMAC 签名还是 mTLS 尚未确定，由双方联调前选定。因此业务 JSON 中不放 `signature`；认证信息由最终安全方案承载。

### 2.2 统一错误响应

```json
{
  "code": "INVALID_STATUS_TRANSITION",
  "message": "The task cannot move from COMPLETED to IN_PROGRESS."
}
```

| 字段 | 必要性 | 含义 | 为什么需要 |
|---|---|---|---|
| `code` | 必须 | 稳定的机器错误码 | 调用方据此决定修正请求、停止还是稍后重试 |
| `message` | 必须 | 便于研发阅读的错误说明 | 帮助联调和故障排查；程序逻辑不能只依赖文案 |

## 3. 方向 A：任务触发中心向教师端下发任务

教师端提供写入地址：

```text
POST {teacher_app_task_write_url}
```

请求示例：

```json
{
  "assignment_id": "TAS2-20260721-0001",
  "teacher_id": "7062537",
  "task_code": "TIT.P.REL.01",
  "title": "Reliability Rules Refresher",
  "why": "A confirmed lesson started late in the past 7 days.",
  "what_to_do": "Review the reliability rules and complete the knowledge check.",
  "completion_standard": "The knowledge check must be passed.",
  "outcome": "Completing this task records the corrective action. This task adds 0 points.",
  "priority": "P2",
  "due_at": "2026-07-23T10:00:00Z"
}
```

### 3.1 请求字段

| 字段 | 类型 | 必要性 | 含义 | 为什么需要 |
|---|---|---|---|---|
| `assignment_id` | string | 必须 | 我方为这一次任务生成的全局唯一 ID | 是双方共同识别任务、下发幂等和后续状态回传的主键 |
| `teacher_id` | string | 必须 | 接收任务的稳定教师 ID | 教师端必须知道任务属于谁，不能依赖姓名、邮箱或模糊匹配 |
| `task_code` | string | 必须 | 教师端执行模板编码，例如 `TIT.P.REL.01` | 决定打开哪一种任务页面和完成逻辑；标题不能用于程序匹配 |
| `title` | string | 必须 | 教师看到的任务标题 | 让老师快速识别任务是什么 |
| `why` | string | 必须 | 本次为什么收到任务，包含安全、可读的事实和时间范围 | 这是触发中心的核心解释责任，避免老师只看到要求却不知道原因 |
| `what_to_do` | string | 必须 | 老师需要完成的动作摘要 | 教师端据此展示清楚的下一步行动 |
| `completion_standard` | string | 必须 | 什么情况下可以认定任务完成 | 保证教师端和触发中心对“完成”使用同一口径 |
| `outcome` | string | 必须 | 完成后的作用以及是否产生积分 | 避免老师误以为完成改善任务会自动加分、消除历史事实或改变资格 |
| `priority` | enum | 必须 | `P0 / P1 / P2 / P3`，P0 最紧急 | 教师端据此排序并突出当前最需要处理的任务 |
| `due_at` | datetime | 必须 | 最晚完成时间 | 教师端需要展示截止时间并判断是否过期 |

V2 的教师可见文案统一使用英文。以后若需要多语言，应新增接口版本或明确增加语言字段，不能让教师端自行翻译 `why`。

### 3.2 教师端同步响应

教师端成功落库后返回：

```json
{
  "accepted": true,
  "assignment_id": "TAS2-20260721-0001",
  "external_task_id": "teacher-task-8899",
  "received_at": "2026-07-21T08:00:00Z"
}
```

| 字段 | 类型 | 必要性 | 含义 | 为什么需要 |
|---|---|---|---|---|
| `accepted` | boolean | 必须 | 教师端是否已成功、持久化地接收任务 | HTTP 已到达不代表业务已落库，需要明确业务接收结果 |
| `assignment_id` | string | 必须 | 原样返回我方任务 ID | 防止响应和请求串单，并方便双方日志对账 |
| `external_task_id` | string | 必须 | 教师端生成的任务实例 ID | 双方排查问题时可以同时定位我方任务和教师端任务 |
| `received_at` | datetime | 必须 | 教师端成功落库的时间 | 用于判断投递延迟和审计，不等于老师已经查看 |

幂等规则：

- 相同 `assignment_id` 和相同内容重复发送：返回同一个 `external_task_id`，不得创建第二条任务。
- 相同 `assignment_id` 但内容不同：返回 `409`。V2 不支持静默覆盖已下发任务。
- `external_task_id` 在第一次成功 ACK 后与 `assignment_id` 永久绑定，后续回传不得更换。
- 我方内部 `publication_id`、触发策略、来源表、SQL、学生信息和原始投诉内容不得发送给教师端。

## 4. 方向 B1：教师端回传个性化任务状态

我方提供接收地址：

```text
POST {trigger_center_task_status_url}
```

普通状态示例：

```json
{
  "provider_event_id": "TEVT-20260721-0001",
  "assignment_id": "TAS2-20260721-0001",
  "external_task_id": "teacher-task-8899",
  "status": "COMPLETED",
  "occurred_at": "2026-07-21T08:30:00Z",
  "sequence": 4
}
```

首课继续授课确认 `P-REL-03` 示例：

```json
{
  "provider_event_id": "TEVT-20260721-0002",
  "assignment_id": "TAS2-20260721-0002",
  "external_task_id": "teacher-task-8900",
  "status": "COMPLETED",
  "occurred_at": "2026-07-21T08:40:00Z",
  "sequence": 2,
  "result_code": "CANNOT_CONTINUE"
}
```

### 4.1 请求字段

| 字段 | 类型 | 必要性 | 含义 | 为什么需要 |
|---|---|---|---|---|
| `provider_event_id` | string | 必须 | 教师端为本次状态变化生成的全局唯一事件 ID | 是状态事件的幂等键，防止重试导致重复处理 |
| `assignment_id` | string | 必须 | 方向 A 中由我方下发的任务 ID | 精确找到需要更新的我方任务 |
| `external_task_id` | string | 必须 | 教师端的任务实例 ID | 用于验证该 assignment 没有被错误绑定，并支持双方排查 |
| `status` | enum | 必须 | 本次真实发生的任务状态 | 是我方任务台账和运营看板需要接收的核心结果 |
| `occurred_at` | datetime | 必须 | 该状态在教师端真实发生的时间 | 区分业务发生时间和接口接收时间，支持审计和时序判断 |
| `sequence` | integer | 必须 | 同一 assignment 从 1 开始递增的事件序号 | 网络可能乱序；它能防止迟到的旧事件覆盖新状态 |
| `reason_code` | string | 条件必填 | 失败、过期、豁免或取消的受控原因码 | 仅有状态无法说明为什么关闭或失败；正常状态不需要发送 |
| `result_code` | enum | 条件必填 | 状态之外的受控业务结果 | 当前仅 `P-REL-03 + COMPLETED` 必须传 `CAN_CONTINUE` 或 `CANNOT_CONTINUE` |

### 4.2 状态含义

| 状态 | 含义 |
|---|---|
| `RECEIVED` | 教师端已成功落库，不等于老师已经看到 |
| `VIEWED` | 老师已经查看任务 |
| `IN_PROGRESS` | 老师正在执行 |
| `SUBMITTED` | 老师已经提交，尚未完成校验 |
| `UNDER_REVIEW` | 教师端或运营正在审核 |
| `COMPLETED` | 教师端已经按完成标准确认任务完成 |
| `FAILED` | 当前尝试未通过，老师可以重新执行 |
| `EXPIRED` | 已超过截止时间并关闭 |
| `WAIVED` | 经授权后豁免 |
| `CANCELLED` | 任务已被取消 |

状态规则：

- 只回传真正发生的状态，不需要补发虚假的中间状态。
- 方向 A 已同步返回成功时，不要求教师端再异步回传 `RECEIVED`；保留该状态只用于“先接请求、后异步落库”的实现。
- `sequence` 必须大于该 assignment 上一次已接受的值，可以跳号。
- `COMPLETED / EXPIRED / WAIVED / CANCELLED` 是终态，进入后不能再修改。
- `FAILED` 不是终态，老师重新执行后可以继续回传后续状态。
- `reason_code` 至少由双方共同维护以下稳定值：`VERIFICATION_FAILED / EXPIRED_BY_POLICY / WAIVER_APPROVED / CANCELLED_BY_SOURCE`。
- 老师本人只能产生查看、执行和提交行为；`COMPLETED / FAILED / EXPIRED` 必须由教师端可信校验产生，`WAIVED / CANCELLED` 只能由有权限的运营或系统源产生，不能由老师按钮直接上报。
- 当前精简合同尚未定义“任务触发中心主动撤回已下发任务”的接口；该能力补齐前，我方不能把内部取消状态描述为教师端已取消。
- 除 `P-REL-03` 外，普通任务不传 `result_code`。
- `P-REL-03 + CANNOT_CONTINUE` 只会在我方生成待运营确认请求，不代表课程已经释放。
- 28 类任务的所有状态只更新任务闭环，不产生积分。

### 4.3 我方同步响应

```json
{
  "accepted": true,
  "provider_event_id": "TEVT-20260721-0001",
  "assignment_id": "TAS2-20260721-0001",
  "status": "COMPLETED",
  "latest_sequence": 4
}
```

| 字段 | 类型 | 必要性 | 含义 | 为什么需要 |
|---|---|---|---|---|
| `accepted` | boolean | 必须 | 我方是否已接受本次状态事件 | 调用方需要知道是否可以停止重试 |
| `provider_event_id` | string | 必须 | 原样返回事件 ID | 防止响应和事件串单 |
| `assignment_id` | string | 必须 | 被更新的我方任务 ID | 便于教师端记录和对账 |
| `status` | enum | 必须 | 我方接受后的任务状态 | 让教师端确认双方状态一致 |
| `latest_sequence` | integer | 必须 | 我方当前已接受的最大序号 | 教师端可据此处理乱序或重复事件 |

## 5. 方向 B2：教师端回传固定成长任务完成

我方提供接收地址：

```text
POST {trigger_center_fixed_task_completion_url}
```

请求示例：

```json
{
  "provider_event_id": "TEVT-G09-20260721-0001",
  "external_task_id": "teacher-fixed-task-8899",
  "teacher_id": "7062537",
  "task_code": "G09",
  "completed_at": "2026-07-21T08:00:00Z"
}
```

### 5.1 请求字段

| 字段 | 类型 | 必要性 | 含义 | 为什么需要 |
|---|---|---|---|---|
| `provider_event_id` | string | 必须 | 教师端生成的全局唯一完成事件 ID | 是完成事件的幂等键，防止重试造成重复记录或重复结分 |
| `external_task_id` | string | 必须 | 教师端已有固定任务的实例 ID | 固定任务不是我方创建，需要用教师端实例 ID 追溯来源 |
| `teacher_id` | string | 必须 | 完成任务的稳定教师 ID | 我方需要把完成事实写入正确教师账户 |
| `task_code` | enum | 必须 | 固定任务编码，只允许 `G01`–`G10` | 确定老师完成的是哪项任务，并读取我方对应积分配置 |
| `completed_at` | datetime | 必须 | 教师端可信确认完成的时间 | 用于任务镜像、积分流水和审计 |

本接口只表达“教师端已可信确认完成”，因此不重复传固定值 `status=COMPLETED`、`result_code=VERIFIED_COMPLETED` 或 `result_version=1`。教师端也不传分数，分值完全由我方根据 `task_code` 的版本化配置计算。

### 5.2 我方同步响应

```json
{
  "accepted": true,
  "provider_event_id": "TEVT-G09-20260721-0001"
}
```

| 字段 | 类型 | 必要性 | 含义 | 为什么需要 |
|---|---|---|---|---|
| `accepted` | boolean | 必须 | 我方是否已接受完成事件 | 教师端据此停止重试 |
| `provider_event_id` | string | 必须 | 原样返回教师端事件 ID | 防止响应和请求串单 |

幂等与结分规则：

- 相同 `provider_event_id`、相同内容重复发送：返回同一个成功结果。
- 相同 `provider_event_id`、不同内容：返回 `409`。
- 同一 `teacher_id + task_code` 最多结分一次。
- 教师端不得上传或修改固定成长任务分值。
- 已确认不存在复营或跨营期回补，因此 V2 不传 `camp_id`。

## 6. 双方都不能传的内容

- 分数、累计分、供给分、毕业或金牌结论。
- 用于我方内部计分的原始指标。
- 我方内部 `publication_id`、触发策略 ID、SQL、来源表和来源字段。
- 学生 ID、联系方式、投诉原文和运营内部备注。
- 可以直接触发处罚、课程释放或资格变化的自由文本。
