## 1. 总体结论

- 当前只有 `public` Schema，共 33 张表、0 个视图。
- 临时账号对全部表拥有 CRUD，所有表均未启用行级安全，权限远超教师端需要。
- 正式接入应改用只读白名单账号或教师安全视图；任务运行状态由本系统维护，不直接修改世文源表。
- 教师身份、五维和封顶总分已有批量数据；逐课归因、任务运行和消息数据尚不足以支撑真实闭环。
- 数据库没有邮箱列，`teachers.payload` 也没有 `email / company_email`。已确认邮箱与 `teacher_id` 的绑定由新师训练营系统自行保存，不要求世文补充邮箱字段。
- 已确认 `MIXED` 可按教师安全映射用于正式展示，`teacher_metric_snapshots.public_total_score` 是教师端唯一总分来源。
- 当前逐课能力只要求现有字段能映射教师端结构，不要求迁移、补齐或验证历史逐课数据。

## 3. 教师身份映射

### 3.1 `teachers`

| 字段 | 业务含义 | 使用规则 |
|---|---|---|
| `teacher_id` | 世文教师唯一标识 | 跨系统主键，不在前端路由直接暴露 |
| `camp_enrollment_id` | 当前训练营实例 | 关联任务、积分和课程；当前唯一且非空 |
| `name` | 教师姓名 | 只返回当前登录教师自己的姓名 |
| `country` | 国家／地区 | 是否展示待确认 |
| `timezone` | 教师时区 | 用于截止时间；可信来源仍待确认 |
| `camp_day` | 当前训练营天数 | 起算规则确认后再正式展示 |
| `graduation_state` | 出营状态 | 仅使用教师安全文案，不自行重算 |
| `total_score` | 未封顶原始总分 | 禁止教师端展示 |
| `data_mode` | `MIXED / MOCK` | Mock 不得冒充正式数据 |
| `source_batch_id / source_snapshot_label` | 来源批次／快照 | 内部追踪和对账 |
| `updated_at` | 更新时间 | 增量读取候选 |
| `payload` | 聚合 JSON | 禁止整包返回，只允许白名单映射 |

### 3.2 注册绑定口径

老师注册时填写公司邮箱、`teacher_id` 和密码。本系统后端只读 `teachers.teacher_id` 确认教师存在，再在本系统数据库保存 `company_email ↔ teacher_id` 双向唯一绑定；`camp_enrollment_id` 继续从世文读取。不能只凭姓名绑定账号，一期不增加邀请码或第二身份因子，并保留抢先绑定风险、审计和纠错记录。

## 4. My TIDE 总分与五维

### 4.1 `teacher_metric_snapshots`

推荐作为教师可见积分结果的主要来源。

| 字段 | 页面用途 | 规则 |
|---|---|---|
| `snapshot_id / batch_id` | 结果批次 | 同一页面只使用同批次结果 |
| `teacher_id` | 教师归属 | 必须与登录账号绑定 |
| `snapshot_label / updated_at` | 数据截至时间 | 可用于页面更新时间 |
| `data_mode` | 数据模式 | `MIXED` 可按教师安全映射正式展示；`MOCK` 必须明确标记 |
| `lessons_completed` | 已完成课程数 | 教师安全统计候选 |
| `feedback_praise_cnt / feedback_favorite_cnt` | 好评／收藏 | 用户反馈候选指标 |
| `completed_again_student_15d_cnt` | 15 天复约数 | 用户反馈候选指标 |
| `on_time_completed_cnt` | 准时完成数 | 可靠性候选指标 |
| `late_cnt / early_cnt / real_absent_cnt` | 履约事实 | 必须转换成教师安全表达 |
| `class_quality_no_issue_rate` | 无质量问题比例 | 课堂质量候选指标 |
| `user_feedback_score` | 用户反馈分 | 对应 `USER_FEEDBACK` |
| `reliability_score` | 可靠性分 | 对应 `RELIABILITY` |
| `class_quality_score` | 课堂质量分 | 对应 `CLASS_QUALITY` |
| `capacity_score` | 产能成长分 | 对应 `CAPACITY`，当前范围 0–10 |
| `new_teacher_task_score` | 固定必修成长任务分 | 当前全部为 30，暂不能证明任务已完成 |
| `raw_total_score` | 内部原始总分 | 禁止教师端展示 |
| `public_total_score` | 教师可见总分 | My TIDE 总分唯一来源，最高 200 |
| `score_rule_version` | 计分版本 | 必须与五维和总分一起保存 |

禁止教师端读取或返回：`real_name`、`severe_redline_event`、`raw_payload`、`metric_provenance`、`score_policy_snapshot`，以及其中的投诉、拉黑、风险、异常、阈值和内部组织信息。

### 4.3 `score_entries`

| 字段 | 用途 | 规则 |
|---|---|---|
| `score_entry_id` | 积分事件 ID | 列表稳定键 |

## 6. 任务映射

### 6.1 方向 A：28 类个性化改善任务

| 表 | 当前用途 |
|---|---|
| `task_publications_v2` | 世文内部发布事实来源；正式对接时由世文安全 assignment 视图提供教师可见字段，不暴露 `publication_id` 或内部触发快照 |
| `task_output_templates_v2` | 任务编码、公开文案和输出模板参考；安全视图不提供题目、表单、`completion_method` 或 V1 Action Schema |
| `task_status_callbacks_v2` | 原 V2.3 HTTP 回调落库设计；当前无数据，共享数据库方案不要求本系统直接写入 |

个性化任务字段和状态语义继续参考 V2.3；当前传输方式改为共享数据库安全视图。世文发布 assignment 安全视图，本系统按 `assignment_id + payload_hash` 幂等读取，不直接读取或修改上述世文业务表。

### 6.2 方向 B：`G01–G10` 固定成长任务

| 表 | 当前用途 |
|---|---|
| `fixed_task_instances_v2` | 世文消费本系统可信完成发布视图后形成的固定任务结算实例；当前无数据 |
| `fixed_task_status_events_v2` | 世文按 `provider_event_id` 幂等记录固定任务完成；当前无数据，本系统不直接写入 |

- `G01–G10` 由教师端系统持有、展示和校验，不由世文下发，也没有 assignment。
- 本系统发布 `provider_event_id / external_task_id / teacher_id / task_code / completed_at` 五个业务字段；完成语义由发布视图表达，不提供过程状态或分值。
- 世文按 `teacher_id + task_code` 终身最多结分一次；事件自身以 `provider_event_id` 幂等。

### 6.3 本系统任务运行状态

- 所有任务的查看、开始、提交、验证、重试和完成记录均写入本系统自己的表。
- 个性化任务按 V2.3 语义发布 `RECEIVED / VIEWED / IN_PROGRESS / SUBMITTED / UNDER_REVIEW / COMPLETED / FAILED / EXPIRED / WAIVED / CANCELLED`；当前无运营后台或世文撤回能力，`WAIVED / CANCELLED` 先作为预留状态。
- 固定任务只在可信完成后写入 V2.3 固定任务完成事件。
- 本系统不直接写世文上述 V2 表；世文从 `tide` 版本化只读视图消费事件，并在自身 Schema 记录结果。

### 6.4 V1／Sandbox 历史表

`task_assignments`、`task_executions`、`task_runtime_events` 和 `task_templates` 属于 V1／Sandbox／兼容观察范围。当前 `task_templates` 有 32 个已发布模板、1 个草稿，不能继续作为 V2 当前合同，也不得自动覆盖本系统任务级 PRD。

## 7. 消息映射

本节的“消息”指教师端通知，不是 AI 问答消息。

`notifications` 候选字段包括 `notification_id`、`task_id`、`teacher_id`、`channel`、`priority`、`status`、`requested_at`、`stored_at`、`read_at`、`clicked_at`、`response_due_at` 和 `payload`。

世文数据库已有 `notifications` 和 `notification_events` 表结构，但两张表当前都是 0 条数据。标题、正文、失效时间和训练营实例也没有独立列。取得一条真实教师安全通知样例前，不能冻结通知映射。

`notification_events` 只作为投递事件审计候选，不作为教师端消息主查询表。

## 8. 禁止教师端访问的表

- 账号安全：`operator_accounts`、`operator_role_grants`、`operator_sessions`；
- 运营与内部判断：`ops_cases`、`ops_decisions`、`agent_decisions`；
- 内部配置：`config_versions`、`config_publication_audits`、`trigger_policies_v2`；
- 内部投递：`outbox_events`、`outbound_outputs`、`provider_calls`、`idempotency_records`；
- 全量审计和导入源：`audit_events`、`data_import_batches`。

教师端也不得返回密码哈希、会话哈希、风险标签、内部信号、原始证据、策略快照、阈值和 JSON 原始载荷。

## 9. 实时读取与降级建议

一期不建定时全量同步：教师请求 My TIDE、逐课解释或通知数据时，后端实时只读世文安全表或视图。下表的键仍用于结果组装、最近成功投影和对账。

| 对象 | 主键／唯一键 | 增量字段 |
|---|---|---|
| 教师 | `teacher_id`；`camp_enrollment_id` 唯一 | `updated_at` |
| 指标快照 | `snapshot_id`；`batch_id + teacher_id` 唯一 | `updated_at / batch_id` |
| 五维账户 | `account_id`；`teacher_id + dimension` 唯一 | `version / updated_at` |
| 积分事件 | `score_entry_id`；`idempotency_key` 唯一 | `recorded_at` |
| 课程事实 | `lesson_id` | `updated_at` |
| 逐课维度 | 训练营+课程+维度唯一 | `current_revision / score_as_of` |
| V2 个性化发布 | `publication_id` | `updated_at`；仅用于对账，不作为教师端 assignment |
| V2 个性化回调 | 回调事件幂等键 | 回调时间／序列；具体以 V2.3 合同为准 |
| V2 固定任务事件 | `provider_event_id`；业务去重 `teacher_id + task_code` | `completed_at` |
| 消息 | `notification_id` | 当前缺少统一 `updated_at`，待确认 |

实时读取成功后可保存最近一次教师安全投影，记录 `source_updated_at`、`read_at`、`source_version` 和最近一次错误。Tunnel 中断时返回最近成功数据并标明时间；从未读取成功时返回暂时不可用，不使用 Mock 冒充。

## 10. 已确认与待补充

已确认：

1. `MIXED` 可按教师安全映射用于正式展示。
2. `teacher_metric_snapshots.public_total_score` 是教师端总分唯一来源。
