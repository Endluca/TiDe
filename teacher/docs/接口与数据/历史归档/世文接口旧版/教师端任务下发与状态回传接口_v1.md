# 教师端任务下发与状态回传接口 V1

> 用途：任务触发中心与雨熹负责的教师端任务运行域联调。  
> 状态：可交付开发；基础 URL、联调环境和密钥由双方按环境配置。  
> 本文只冻结两个跨系统接口，六类任务的完整 Action / Submission 结构继续以本目录 Schema 为准。

## 1. 责任边界

| 事项 | 唯一写入方 |
| --- | --- |
| 任务创建、内容、优先级、截止时间、修订与撤回 | 任务触发中心（我们） |
| 任务查看、开始、提交、验证和完成状态 | 教师端任务运行域（雨熹侧） |
| 运营看板中的执行状态 | 我们消费回传事件后生成的只读投影 |
| 积分、出营/毕业、下一任务 | 任务触发中心；教师端不回传这些结论 |

链路只有两步：

1. 我们调用雨熹侧「任务写入接口」；对方落库后同步返回 ACK。
2. 教师端每次成功变更执行状态后，调用我们的「状态回传接口」。

ACK 只表示任务已被对方持久化并接管，不表示老师已看到。

## 2. 通用约定

- 协议：HTTPS + UTF-8 JSON。
- 时间：RFC 3339 UTC，例如 `2026-07-17T08:30:00Z`。
- ID：不透明字符串，最长 128 位；`teacher_id` 必须是双方已对齐的稳定 ID。
- 投递语义：至少一次。双方都必须使用 Outbox / Inbox 或等价机制保存发送、消费和重试记录。
- 幂等：`event_id` 全局唯一；相同 `idempotency_key` + 相同 payload 重放返回首次结果，相同 key + 不同 payload 返回 `DUPLICATE_CONFLICT`。
- 鉴权：每个环境使用独立 HMAC-SHA256 密钥，密钥不进代码和文档。

请求头：

```http
Content-Type: application/json
Idempotency-Key: <与 body.idempotency_key 一致>
X-TIT-Key-Id: <key_id>
X-TIT-Timestamp: <RFC3339 UTC>
X-TIT-Nonce: <一次性随机串>
X-TIT-Signature: <lowercase hex HMAC-SHA256>
```

签名原文：

```text
HTTP_METHOD + "\n" + REQUEST_PATH + "\n" + X-TIT-Timestamp + "\n" + X-TIT-Nonce + "\n" + SHA256_HEX(raw_body)
```

接收方拒绝超过 5 分钟的时间偏差，并在 10 分钟内拒绝重复 nonce。

## 3. 接口 A：任务写入教师端

**接口归属**：雨熹侧提供，我们调用。  
**Method / Path**：`POST /integration/v1/task-assignment-events`

### 3.1 支持的事件

| `event_type` | 含义 |
| --- | --- |
| `task.issued.v1` | 首次下发 |
| `task.reprioritized.v1` | 优先级/排序修订 |
| `task.due_date_revised.v1` | 截止时间修订 |
| `task.content_revision_available.v1` | 非语义展示内容修订 |
| `task.withdrawn.v1` | 撤回任务 |

所有事件都传当前完整的「教师安全任务快照」，不做局部 PATCH，避免两端合并逻辑不一致。

### 3.2 请求结构

```json
{
  "event_schema_version": 1,
  "event_id": "evt_01J...",
  "event_type": "task.issued.v1",
  "occurred_at": "2026-07-17T08:30:00Z",
  "idempotency_key": "task_assignment:TASK-1001:r1",
  "trace_id": "trace_01J...",
  "correlation_id": "CAMP-1001",
  "causation_id": "signal_01J...",
  "producer": "TASK_TRIGGER_CENTER",
  "task": {
    "task_id": "TASK-1001",
    "assignment_revision": 1,
    "execution_contract_version": 1,
    "teacher_id": "T-1001",
    "camp_enrollment_id": "CAMP-1001",
    "template_id": "NT-M05",
    "template_version": 1,
    "completion_method": "QUIZ",
    "priority": "P1",
    "due_at": "2026-07-20T08:30:00Z",
    "teacher_timezone": "Asia/Manila",
    "localized_content": {
      "title": "Platform Policy & Rules",
      "why": "This module helps you understand the required platform rules.",
      "how_to": "Review the material and complete the quiz.",
      "completion_standard": "Reach the published passing score.",
      "result_copy": "Your result has been recorded."
    },
    "action_schema_version": 1,
    "action_schema": {},
    "allowed_actions": ["VIEW_TASK", "START_TASK", "SUBMIT_TASK", "REQUEST_HELP"],
    "payload_hash": "sha256:<hash>"
  }
}
```

上例为了阅读仅展示关键字段，不能直接作为完整请求。`task` 必须按下列字段组发送：

- 标识与版本：`task_id / assignment_revision / execution_contract_version / obligation_id / teacher_id / camp_enrollment_id / template_id / template_version`。
- 任务属性：`output_type / task_category / audience / dimension / completion_method / verification_mode / is_required / is_rectification / stage_id`。
- 排序与时间：`priority / is_primary / display_rank / assigned_at / activated_at / original_due_at / due_at / expires_at / teacher_timezone`。
- 执行投影：`execution_status / due_status / display_status_code / runtime_sequence / allowed_actions / attempt_no / remaining_attempts`。
- 内容与动作：`localized_content / public_reason / action_schema_version / action_schema / dependencies / retry_policy_ref / help_capability / review_capability / reward_display`。
- 治理字段：`policy_version / updated_at / payload_hash`。

`action_schema` 必须通过 [teacher-task-action-schema-v1.json](./teacher-task-action-schema-v1.json)；不得包含投诉详情、学生原始信息、内部证据、内部罚则或验证阈值。

### 3.3 成功响应

对方必须在任务快照和 Inbox 已事务性落库后才返回 `200`：

```json
{
  "event_id": "ack_evt_01J...",
  "event_type": "task.dispatch_ack.v1",
  "idempotency_key": "ack:TASK-1001:r1",
  "task_id": "TASK-1001",
  "assignment_revision": 1,
  "execution_contract_version": 1,
  "accepted": true,
  "accepted_at": "2026-07-17T08:30:01Z",
  "runtime_task_ref": "teacher_runtime_TASK-1001",
  "error_code": null
}
```

处理规则：

- 首次下发后建立 `TaskExecution=AVAILABLE`、`runtime_sequence=0`。
- 相同 `task_id + assignment_revision + payload_hash` 重放时返回原 ACK。
- 更高 `assignment_revision` 覆盖当前展示投影；更低版本返回 `STALE_ASSIGNMENT_REVISION`。
- `execution_contract_version` 不得在同一 `task_id` 上静默变更。完成方式或验证标准变更时，我们撤回旧任务并下发新 `task_id`。
- 收到 `task.withdrawn.v1` 后，教师端进入 `CANCELLED_BY_WITHDRAWAL`，并再通过接口 B 回传运行事件。

## 4. 接口 B：教师端状态回传

**接口归属**：我们提供，雨熹侧调用。  
**Method / Path**：`POST /integration/v1/task-runtime-events`

教师页面不能直接调本接口。页面先向雨熹侧任务运行服务发动作命令，运行服务完成校验和落库后，再发出状态事件。

### 4.1 请求

```json
{
  "event_schema_version": 1,
  "event_id": "evt_runtime_01J...",
  "event_type": "task.runtime_event.v1",
  "idempotency_key": "runtime:TASK-1001:sequence_5",
  "trace_id": "trace_01J...",
  "correlation_id": "TASK-1001",
  "causation_id": "submission_01J...",
  "task_id": "TASK-1001",
  "execution_contract_version": 1,
  "runtime_sequence": 5,
  "runtime_event_code": "VERIFICATION_PASSED",
  "runtime_status": "COMPLETED",
  "verification_result": "PASSED",
  "actor_type": "TEACHER_TASK_RUNTIME",
  "actor_id": "teacher-runtime",
  "occurred_at": "2026-07-17T08:45:00Z",
  "payload": {
    "attempt_no": 1,
    "result_ref": "result_safe_01J...",
    "completed_at": "2026-07-17T08:45:00Z"
  }
}
```

`payload` 只传业务必需的安全结果摘要，不回传原始答案、文件本体、内部阈值或学生信息。`CONFIRMATION_RECORDED` 额外回传 `selected_option_code`；首课缺席确认只允许 `CAN_CONTINUE / CANNOT_CONTINUE`。

### 4.2 事件和状态映射

| `runtime_event_code` | 事件后 `runtime_status` | `verification_result` |
| --- | --- | --- |
| `TASK_VIEWED` | `VIEWED` | `null` |
| `TASK_STARTED` | `STARTED` | `null` |
| `TASK_SUBMITTED` | `SUBMITTED` 或 `VERIFYING` | `null` 或 `PENDING` |
| `VERIFICATION_STARTED` | `VERIFYING` | `PENDING` |
| `VERIFICATION_PASSED` | `COMPLETED` | `PASSED` |
| `VERIFICATION_RETRY_REQUIRED` | `RETRY_REQUIRED` | `RETRY_REQUIRED` |
| `VERIFICATION_REJECTED` | `FAILED_FINAL` | `REJECTED` |
| `EXTERNAL_COMPLETION_SYNCED` | 可信同步结果满足完成规则时为 `COMPLETED` | `PASSED` |
| `HUMAN_REVIEW_COMPLETED` | `COMPLETED / RETRY_REQUIRED / FAILED_FINAL` | 与人工结论一致 |
| `CONFIRMATION_RECORDED` | `COMPLETED` | `PASSED` |
| `HELP_REQUESTED / REVIEW_REQUESTED / WAIVER_REQUESTED` | 保持当前可执行状态 | 不得因请求本身变为 `PASSED` |
| `TASK_EXPIRED` | `EXPIRED` | `null` |
| `TASK_CANCELLED_BY_WITHDRAWAL` | `CANCELLED_BY_WITHDRAWAL` | `null` |

`CONFIRMATION_RECORDED + COMPLETED` 只表示结构化答复已记录。`CANNOT_CONTINUE` 由我们创建运营 Case，不代表课程已释放。

### 4.3 成功响应

```json
{
  "accepted": true,
  "event_id": "evt_runtime_01J...",
  "task_id": "TASK-1001",
  "runtime_sequence": 5,
  "received_at": "2026-07-17T08:45:01Z"
}
```

我们仅在事件与 Inbox 已落库、只读投影已更新后返回 `200`。积分、后续任务和出营逻辑由我们异步处理，不放在这个 HTTP 响应中。

### 4.4 顺序规则

- 首个运行事件从 `runtime_sequence=1` 开始，同一任务必须严格单调递增。
- 序号等于当前序号 + 1 时接收。
- 已接收的同一事件重放时幂等返回 `200`。
- 序号小于或等于当前序号且不是已知重放时，返回 `STALE_RUNTIME_SEQUENCE`。
- 序号大于当前序号 + 1 时，返回 `RUNTIME_SEQUENCE_GAP`；教师端从缺失序号开始重放，不用最新状态跳过历史。

## 5. 标准错误

HTTP 状态码：

- `400`：JSON / 字段结构错误。
- `401 / 403`：签名、时钟、nonce 或系统权限错误。
- `404`：教师或任务不存在。
- `409`：幂等冲突、版本冲突、旧序号或序号缺口。
- `422`：Action Schema、状态迁移或事件语义不合法。
- `429 / 500 / 503`：可重试的限流或临时故障。

响应体统一为：

```json
{
  "accepted": false,
  "error_code": "EXECUTION_CONTRACT_VERSION_MISMATCH",
  "field_path": "$.execution_contract_version",
  "retryable": false,
  "message_key": "task.error.refresh_and_retry",
  "details": {
    "current_execution_contract_version": 2,
    "current_runtime_sequence": 4
  }
}
```

必须支持的关键错误码：

- 任务写入：`UNKNOWN_TEACHER / UNSUPPORTED_COMPLETION_METHOD / INVALID_ACTION_SCHEMA / STALE_ASSIGNMENT_REVISION / EXECUTION_CONTRACT_VERSION_MISMATCH / CONTENT_VERSION_UNAVAILABLE`。
- 状态回传：`TASK_NOT_FOUND / STALE_RUNTIME_SEQUENCE / RUNTIME_SEQUENCE_GAP / INVALID_RUNTIME_TRANSITION / RUNTIME_EVENT_STATUS_MISMATCH`。
- 通用：`AUTHENTICATION_FAILED / DUPLICATE_CONFLICT / TEMPORARY_UNAVAILABLE`。

`429 / 500 / 503` 或 `retryable=true` 才自动重试；建议间隔 `5s → 30s → 2m → 10m → 30m`，之后每 30 分钟重试，最长 24 小时并触发告警。业务冲突不得盲目重试。

## 6. 最小联调验收

首条链路使用 Mock 老师 + `QUIZ`，按以下顺序验收：

1. 我们下发 `task.issued.v1`，雨熹侧落库并返回 ACK。
2. 老师端可查到任务，状态为 `AVAILABLE`。
3. 查看、开始、提交、验证通过依次回传，我们投影最终为 `COMPLETED + PASSED`。
4. 重复发送同一下发事件和同一运行事件，两端都不生成重复记录。
5. 人为制造版本冲突和 `runtime_sequence` 缺口，确认返回结构化错误且不覆盖旧状态。
6. 下发一次截止时间修订和一次撤回，雨熹侧按 revision 更新并 ACK。

这 6 项通过后，只能说「任务下发/状态回传联调通过」；站内通知、提醒、六类完成方式全量验收和上线检查仍是独立门禁。
