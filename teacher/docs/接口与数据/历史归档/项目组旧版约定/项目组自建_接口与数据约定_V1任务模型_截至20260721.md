## 1. 已确认的数据边界

| 事项 | 唯一责任方 | 数据流向 | 本系统处理 |
|---|---|---|---|
| 教师业务身份 | 世文 | 世文 → 本系统 | 建立公司邮箱、本系统账号、`teacher_id`、`camp_enrollment_id` 的稳定映射 |
| 任务分配与优先级 | 世文 | 世文 → 本系统 | 只接收和展示正式分配，不自行触发任务 |
| 任务内容、题目和完成规则 | 新师训练营 | 本地维护 | 按已发布任务版本执行，不由世文 payload 覆盖 |
| 任务过程与完成判定 | 新师训练营 | 本地保存 | 保存原始过程并形成标准运行事件 |
| 五维积分、总分和业务状态 | 世文 | 世文 → 本系统 | 只展示教师可见结果，不自行计算 |
| 逐课积分归因 | 世文 | 世文 → 本系统 | 展示教师安全课程、维度和积分事件 |
| 产能成长积分 | 世文 | 世文 → 本系统 | 世文根据有效供给数据计算，教师端最高展示 10 分及安全解释 |
| 个性化任务触发 | 世文 | 世文 → 本系统 | 任务不计分，只作为改善入口 |
| 站内消息 | 世文 | 世文 → 本系统 | 幂等保存、展示和失效处理 |
| 消息已读 | 新师训练营记录，世文接收 | 本系统 → 世文 | 老师首次主动点击打开后回传 |
| 原始过程数据和素材 | 新师训练营 | 不跨系统 | 不回传视频心跳、答案、清单明细、图片或文件 |
| 产品分析埋点 | 新师训练营 | 本系统内部 | 页面曝光、入口点击、步骤流失和技术异常仅用于产品分析，不自动形成世文回传事件 |

两套系统继续保持业务职责、数据所有权和唯一写入方独立。数据库接入分为以下两个阶段：

### 1.1 短期：世文本地 PostgreSQL 临时远程 CRUD（已确认）

| 项目 | 当前约定 |
|---|---|
| 用途 | 公司数据库流程完成前的开发和联调数据通道，不作为生产环境 |
| 连接方式 | 本系统后端或同步任务通过 Cloudflare Tunnel 连接世文本地 PostgreSQL；浏览器和移动端不得直连 |
| 数据库权限 | 临时账号对 `public` Schema 现有及未来业务表具备 `SELECT / INSERT / UPDATE / DELETE`；禁止 `CREATE / DROP / ALTER / GRANT` |
| 可用条件 | Ric 的 Mac、PostgreSQL 和 Cloudflare Tunnel 同时在线 |
| 凭据管理 | Tunnel 地址、数据库账号、密码和完整连接串不进入仓库、文档、日志或客户端；使用本地环境变量或批准的密钥管理方式，并支持轮换 |
| 系统依赖 | 远程数据库不可作为页面实时查询的唯一来源；本系统保存最近一次成功同步的数据、源版本、源更新时间和同步状态 |
| 业务授权 | 世文拥有的身份、积分、归因、任务关联和消息等业务源表默认只读；任务运行状态由本系统维护。CRUD 是账号技术权限，不代表可任意修改世文业务表 |

短期接入要求：

1. 远程连接仅由后端或独立同步任务持有，前端继续只调用本系统 API。
2. 世文侧数据先映射为本系统的标准领域结构，再供页面使用；不得把世文表结构直接暴露给前端。
3. 入站同步至少记录 `source_updated_at`、`synced_at`、`source_version`、`sync_status` 和最近一次错误；源表尚无版本字段时，需在联调时补充替代方案。
4. Tunnel 或本地数据库中断时使用超时、退避重试和告警，不清空本地有效数据，也不回滚老师已保存的任务结果。
5. 对世文拥有的业务源表执行 `INSERT / UPDATE / DELETE` 前，必须先冻结目标表、字段、幂等键、版本／并发控制、审计要求和唯一写入方；当前默认只读取。任务运行状态写入本系统拥有的状态表，并按正式接口回传。
6. 临时数据库中的现有字段仍是候选实现依据；只有写入本文件并经双方确认的映射才成为项目数据合同。

### 1.2 长期：公司 PostgreSQL 共库隔离（暂定）

长期暂定共用公司 PostgreSQL，并优先采用独立 Schema、独立数据库角色和最小权限：

```text
公司 PostgreSQL
├── shiwen_schema        世文拥有并写入
├── tide_schema          新师训练营拥有并写入
└── integration_schema   双方约定的交换表或只读视图
```

- 双方默认只写自己拥有的 Schema；跨域读取和写入通过明确授权的视图、交换表或接口完成。
- 共享数据库不改变任务分配、积分计算、任务执行和原始素材的责任边界。
- 标准事件契约继续保留，用于幂等、审计、重试和未来拆库，不把跨 Schema SQL 当成唯一集成方式。
- 该方案尚未冻结；数据库实例、Schema 划分、角色权限、迁移窗口、回退方案和生产运维责任待公司流程完成后再次确认。

### 1.3 当前集成分工（已确认）

- 任务分配：世文通过《教师端任务下发与状态回传接口 V1》下发，本系统持久化并 ACK。
- 任务运行状态：查看、开始、提交、验证和完成状态由本系统维护并作为权威状态，成功变更后通过正式接口回传世文。
- 其他业务数据：教师身份、积分、逐课归因、个性化任务关联和消息等，短期通过读取世文数据库获得；实际结构见[世文数据库字段与业务映射（2026-07-21 实读版）](世文数据库字段与业务映射_20260721.md)。
- 世文接口文档中引用但当前未提供的 V1.2、Action Schema 和 Submission Schema 不作为本轮文档整理的阻塞项；具体任务结构以本系统任务级 PRD 和已确认字段为准。

## 2. 通用事件结构

跨系统事件统一包含：

```text
event_schema_version
event_id
event_type
occurred_at
idempotency_key
trace_id
correlation_id
causation_id
producer
payload
```

通用要求：

- `event_id` 全局唯一。
- 相同幂等键和相同 payload 返回首次处理结果，不重复写入。
- 相同幂等键但 payload 不同返回 `DUPLICATE_CONFLICT`。
- 时间使用 RFC 3339 UTC。
- ID 使用不透明字符串，最长 128 位。
- 每个环境使用独立鉴权配置。

## 3. 接口 A：世文下发任务分配

### 3.1 基本定义

| 项目 | 约定 |
|---|---|
| 接口提供方 | 新师训练营 |
| 调用方 | 世文／任务触发中心 |
| Method / Path | `POST /integration/v1/task-assignment-events` |
| 投递方式 | 至少一次；本系统使用 Inbox 或等价机制幂等消费 |

支持事件：

| `event_type` | 含义 |
|---|---|
| `task.issued.v1` | 首次下发任务 |
| `task.reprioritized.v1` | 修改优先级或展示顺序 |
| `task.due_date_revised.v1` | 修改截止时间 |
| `task.withdrawn.v1` | 撤回任务 |

`task.content_revision_available.v1` 不作为一期内容更新主流程；一期任务内容由本系统维护。

### 3.2 分配快照字段

分配事件使用完整快照，不使用局部 PATCH。

| 字段组 | 字段 | 维护方与规则 |
|---|---|---|
| 分配标识 | `task_id / assignment_revision / obligation_id / teacher_id / camp_enrollment_id` | 世文下发 |
| 本地版本 | `template_id / template_version / execution_contract_version` | 本系统发布并同步目录；世文只能分配已发布版本 |
| 分配属性 | `task_category / is_required / is_optional / stage_id / priority / is_primary / display_rank` | 世文下发 |
| 时间 | `assigned_at / activated_at / original_due_at / due_at / expires_at / teacher_timezone` | 世文下发；一期逾期仍可完成 |
| 教师安全原因 | `public_reason / trigger_summary / expected_benefit / next_step_hint / public_dimension / public_lesson_ref` | 世文下发；只允许教师可见安全内容 |
| 治理 | `policy_version / updated_at / payload_hash` | 世文下发，定义待联调冻结 |

不得下发：

- 投诉详情、学生信息、内部证据、风险等级、处罚规则和内部阈值；
- 本系统的视频、题目、答案、清单和任务执行规则；
- 暗示个性化任务可获得积分的 `reward_display` 或积分奖励字段。

个性化触发任务与供给类选修任务使用同一 `task_category`。正式枚举待双方冻结。

### 3.3 版本规则

| 字段 | 维护方 | 规则 |
|---|---|---|
| `assignment_revision` | 世文 | 分配属性变化时递增；本系统只接受更高版本 |
| `template_version` | 新师训练营 | 内容、题目或教师文案发布新版本时递增；已下发任务固定使用原版本 |
| `execution_contract_version` | 新师训练营 | 完成方式、验证标准或执行结构实质变化时发布新版本；旧任务撤回后以新 `task_id` 下发 |
| `policy_version` | 世文 | 记录分配和触发策略版本，不覆盖本地任务规则 |

本系统只能接管已发布的 `template_id + template_version + execution_contract_version`。未知版本返回结构化错误，不自动回退到其他版本。

### 3.4 成功、幂等与撤回

1. 分配快照和 Inbox 事务性落库后才返回 ACK。
2. 首次下发后创建本地执行记录，初始状态为 `AVAILABLE`、`runtime_sequence=0`。
3. 相同 `task_id + assignment_revision + payload_hash` 重放时返回首次 ACK。
4. 更低版本返回 `STALE_ASSIGNMENT_REVISION`。
5. 同一任务不得静默改变本地任务版本。
6. ACK 只代表已持久化和接管，不代表老师已查看。

撤回处理：

| 撤回时状态 | 教师端处理 | 数据处理 |
|---|---|---|
| `AVAILABLE` 且未查看 | 从任务列表隐藏 | 保留审计，进入取消状态并回传 |
| `VIEWED / STARTED / RETRY_REQUIRED` | 显示“任务已取消，无需继续” | 保留进度，关闭继续和提交 |
| `SUBMITTED / VERIFYING` | 显示取消结果并停止后续验证 | 保留提交和素材 |
| `COMPLETED` | 保留已完成历史 | 不回滚、不重复回传取消 |
| 其他终态 | 保留原终态 | 只记录撤回审计 |

ACK 至少包含：

```text
event_id
event_type=task.dispatch_ack.v1
idempotency_key
task_id
assignment_revision
execution_contract_version
accepted
accepted_at
runtime_task_ref
error_code
```

## 4. 接口 B：本系统回传任务运行事件

### 4.1 基本定义

| 项目 | 约定 |
|---|---|
| 接口提供方 | 世文／任务触发中心 |
| 调用方 | 新师训练营后端 |
| Method / Path | `POST /integration/v1/task-runtime-events` |
| 投递方式 | 本系统使用 Outbox 或等价机制发送，失败自动重试 |

教师页面不能直接调用跨系统接口。页面先调用本系统后端，本系统校验、保存并完成本地状态变更后再发送事件。

### 4.2 运行事件字段

```text
event_schema_version
event_id
event_type=task.runtime_event.v1
idempotency_key
trace_id
correlation_id
causation_id
task_id
execution_contract_version
runtime_sequence
runtime_event_code
runtime_status
verification_result
actor_type
actor_id
occurred_at
payload
```

### 4.3 标准事件

| `runtime_event_code` | 事件后状态 | 一期规则 |
|---|---|---|
| `TASK_VIEWED` | `VIEWED` | 回传查看，不带停留明细 |
| `TASK_STARTED` | `STARTED` | 回传开始 |
| `TASK_SUBMITTED` | `SUBMITTED / VERIFYING` | 回传提交，不带答案或素材 |
| `VERIFICATION_STARTED` | `VERIFYING` | 回传验证开始 |
| `VERIFICATION_PASSED` | `COMPLETED` | 回传完成 |
| `VERIFICATION_RETRY_REQUIRED` | `RETRY_REQUIRED` | 允许再次尝试 |
| `VERIFICATION_REJECTED` | `FAILED_FINAL` | 仅在不能继续时使用 |
| `HUMAN_REVIEW_COMPLETED` | 按人工结果 | 只回传安全结论 |
| `HELP_REQUESTED / REVIEW_REQUESTED / WAIVER_REQUESTED` | 保持当前状态 | 请求本身不改变完成结果 |
| `WAIVER_APPROVED` | `WAIVED` | 不等于通过，不触发计分 |
| `TASK_CANCELLED_BY_WITHDRAWAL` | `CANCELLED_BY_WITHDRAWAL` | 已完成任务不回滚 |

`EXTERNAL_COMPLETION_SYNCED` 和 `TASK_EXPIRED` 仅保留枚举，一期不作为设备检测、培训或逾期任务的主流程。

### 4.4 数据最小化

允许回传标准任务标识、版本、序号、状态、时间、`attempt_no` 等必要安全摘要和非个人化系统主体标识。

禁止回传：

- 视频心跳、观看区间、续播位置；
- 题目、答案、标准答案、解析；
- 清单逐项选择；
- 图片、文件、地址和内容；
- 学生信息、内部证据、审核意见和触发阈值。

任务卡曝光、页面停留、入口点击、步骤流失、播放卡顿、上传失败等内部产品分析埋点不属于本接口的标准运行事件，不占用 `runtime_sequence`，不得因新增内部埋点扩大跨系统 payload。提交、验证和任务状态仍以后端业务记录为准。

个性化任务的查看、开始、提交、验证和完成事件只用于任务闭环，不得触发任何积分计算。固定必修任务完成后，世文可按正式计分版本更新维度 5。

## 5. 积分、课程与业务结果数据库读取口径

以下内容是读取世文数据库时必须满足的业务需求清单；真实表、字段、数据量、教师安全范围和当前缺口见[数据库字段与业务映射](世文数据库字段与业务映射_20260721.md)。

### 5.1 结果快照

```text
teacher_id
camp_enrollment_id
result_version
score_as_of
visible_total_score
available_score
pending_score
dimension_scores
graduation_status
probation_status
gold_status
gold_condition_results
```

规则：

- `visible_total_score` 即页面中的“当前积分”，是已经确认并计入总分的教师可见积分，最高为 200；世文不向本系统暴露内部超出部分。
- `available_score` 只包含当前已明确、尚未完成且具有确定额度的事项，一期主要为固定必修任务；不得包含个性化任务或预测未来课程分。
- `pending_score` 是行为已发生但仍等待延迟数据或复核确认的分数，不计入当前总分。
- 五维、总分、三类积分和业务状态必须属于同一 `result_version`。
- 出营／通过试用期和金牌状态由世文明确返回，本系统不得自行推断。

### 5.2 维度数据

| 维度 | 必需数据 |
|---|---|
| 用户反馈 | 当前分、好评、收藏、15 天复约、样本量、统计周期、延迟状态和教师安全说明 |
| 可靠性 | 当前分、准时完课、Peak 完课、迟到／早退／缺席的教师安全事实、统计周期和说明 |
| 课堂质量 | 当前分、无质量问题课程、设备网络和课堂质量的教师安全结果、统计周期和说明 |
| 产能成长 | 当前分、上限 10、开放 slots、重点／TTP slots、有效完课、活跃天数和正式计分说明 |
| 固定必修成长任务 | 当前分、上限 30、正式任务数、计分版本、单项暂定分值和任务完成结果 |

固定必修任务正式分值未确认前，世文按同一计分版本将 30 分平均分配给正式任务清单；前端只展示返回值。产能成长 10 分由世文根据供给数据计算，不由前端根据任务状态、时段数量或课程数量推算。

### 5.3 积分事件与逐课归因

最小字段建议：

```text
score_event_id
result_version
event_at
dimension
source_type
source_ref
lesson_public_ref
metric_name
score_delta
score_before
score_after
status
score_as_of
public_reason
improvement_task_id
```

约束：

- `source_type` 至少需要区分课程、有效供给积分事件和固定必修任务；正式枚举由世文 Schema 冻结。
- 个性化任务只能通过 `improvement_task_id` 关联为改善入口，不能作为 `source_type`。
- 延迟到达的好评、收藏和复约需要保留原课程归因。
- 投诉详情、学生信息、内部证据和阈值不得进入教师可见投影。
- 教师端达到 200 后，世文不再向本系统提供需要展示的新积分增长事件。

## 6. 站内消息数据库读取与已读回传

消息主体短期从世文数据库读取，实际表和字段待读库后重写；业务上至少需要覆盖：

```text
message_id
message_revision
teacher_id
camp_enrollment_id
message_type
title
body
issued_at
expires_at
read_status
related_task_id
idempotency_key
public_safety_level
```

消息类型包括 `TEXT` 纯文字提醒和 `TASK` 带任务提醒。带任务提醒必须关联当前老师的有效任务。

已读回传事件建议为 `message.read.v1`，至少包含：

```text
event_id
message_id
teacher_id
opened_at
open_action
idempotency_key
```

规则：

- 教师端消息列表只查询当前老师、当前 `camp_enrollment_id` 的消息，默认按 `issued_at` 倒序返回，并支持全部和未读筛选。
- 消息过期或关联任务失效后仍可在当前训练营历史中查看，但不得返回可用的任务操作入口。
- 列表曝光、角标展示和进入可视区域不生成已读事件。
- 老师首次点击消息正文或任务入口时生成已读事件。
- 同一消息重复打开不产生重复已读记录。
- 本地已读成功后即更新页面；世文暂不可用时通过 Outbox 重试，不回滚本地状态。

## 7. 协议、鉴权与防重放

| 项目 | 当前约定 |
|---|---|
| 协议 | HTTPS + UTF-8 JSON |
| 时间 | RFC 3339 UTC |
| 幂等 | `event_id` 全局唯一；相同幂等键重放返回首次结果 |
| 鉴权 | 每个环境使用独立 HMAC-SHA256 密钥 |
| 时钟防护 | 拒绝超过 5 分钟的时间偏差 |
| nonce | 10 分钟内拒绝重复 nonce；多实例共享记录 |

请求头：

```http
Content-Type: application/json
Idempotency-Key: <与 body.idempotency_key 一致>
X-TIT-Key-Id: <key_id>
X-TIT-Timestamp: <RFC3339 UTC>
X-TIT-Nonce: <一次性随机串>
X-TIT-Signature: <lowercase hex HMAC-SHA256>
```

签名原文：

```text
HTTP_METHOD + "\n" + REQUEST_PATH + "\n" + X-TIT-Timestamp + "\n" + X-TIT-Nonce + "\n" + SHA256_HEX(raw_body)
```

密钥发放与轮换、旧密钥过渡、响应签名、代理路径和服务端时间同步要求仍待确认。

## 8. 顺序、错误与重试

### 8.1 运行事件顺序

同一任务的跨系统标准运行事件从 `runtime_sequence=1` 开始连续递增。本地视频心跳、答题和上传过程不占用序号。

- 等于当前序号＋1：接收；
- 已知事件重放：幂等返回；
- 小于或等于当前序号且不是已知重放：`STALE_RUNTIME_SEQUENCE`；
- 大于当前序号＋1：`RUNTIME_SEQUENCE_GAP`，发送方从缺失序号重放。

### 8.2 错误码

| HTTP 状态 | 含义 |
|---|---|
| `400` | JSON 或字段错误 |
| `401 / 403` | 鉴权、时钟、nonce 或权限错误 |
| `404` | 教师或任务不存在 |
| `409` | 幂等、版本或序号冲突 |
| `422` | 状态迁移或事件语义错误 |
| `429 / 500 / 503` | 临时故障，可以重试 |

关键错误码：`UNKNOWN_TEACHER / STALE_ASSIGNMENT_REVISION / EXECUTION_CONTRACT_VERSION_MISMATCH / CONTENT_VERSION_UNAVAILABLE / TASK_NOT_FOUND / STALE_RUNTIME_SEQUENCE / RUNTIME_SEQUENCE_GAP / INVALID_RUNTIME_TRANSITION / RUNTIME_EVENT_STATUS_MISMATCH / AUTHENTICATION_FAILED / DUPLICATE_CONFLICT / TEMPORARY_UNAVAILABLE`。

### 8.3 重试

只有 `429 / 500 / 503` 或 `retryable=true` 自动重试。建议间隔：

```text
5s → 30s → 2m → 10m → 30m → 每 30 分钟一次，最长 24 小时
```

版本、状态、权限和幂等冲突不得盲目重试。超过 24 小时后的死信、人工补偿、对账和告警责任人待生产方案补充。

## 9. 最小联调验收

1. 世文下发任务，本系统事务性落库并返回 ACK。
2. 重复任务事件不生成重复实例。
3. 查看、开始、提交、验证和完成事件按连续序号回传。
4. 版本冲突、序号缺口和未知老师返回结构化错误且不覆盖旧数据。
5. 任务撤回覆盖未查看、进行中、待复核和已完成场景。
6. 世文不可用时，本地状态不回滚，Outbox 自动重试。
7. 跨系统事件不包含答案、清单明细、图片、文件、学生信息和内部阈值。
8. 世文返回统一版本的五维、三类积分、总分、出营／试用期和金牌结果。
9. 固定必修任务暂按正式任务数平均分配 30 分，合计准确；个性化任务所有运行事件均不产生积分。
10. 逐课积分事件可以关联课程和维度；个性化任务只作为改善入口。
11. 纯文字和带任务消息可以幂等接收、更新和失效。
12. 消息曝光不标记已读，首次点击打开后才幂等回传已读。

## 11. 文档联动规则

- 产品范围、页面、积分含义或验收变化：先改 PRD，再检查本接口文档的数据字段和联调用例。
- 字段、事件或状态变化：先改本接口文档，再检查 PRD 的产品表现和验收是否受影响。
- 即使另一份不需要改业务内容，也要更新其联动口径版本，表示已经完成检查。
- 两份文档的联动口径版本必须一致。
- 提交前运行 `check_prd_interface_sync.sh`；检查失败时不得视为文档同步完成。
