# 新师训练营与世文数据交互对齐清单

| 项目 | 内容 |
|---|---|
| 文档用途 | 与世文逐项确认双方需要交换的数据、字段范围和接口责任 |
| 当前状态 | 临时本地 PostgreSQL 远程 CRUD 链路已确认；表级映射和长期生产方案待确认 |
| 依据 | 主 PRD、世文《任务触发中心：任务体系与下发／回流契约 V1》、项目组接口与数据约定 |
| 基本边界 | 两套系统业务职责和数据所有权独立；短期通过 Cloudflare Tunnel 远程访问世文本地 PostgreSQL，长期暂定共用公司 PostgreSQL 并按 Schema 隔离 |

## 1. 对齐状态说明

| 标记 | 含义 |
|---|---|
| 已有 V1 | 世文 V1 已提供方向、事件或示例，但仍需冻结完整字段定义 |
| 待世文提供 | 当前缺少世文正式 Schema 或数据接口 |
| 待双方确认 | 当前项目口径已提出，但需要双方共同确认 |
| 已确认边界 | 当前 PRD 已明确的数据责任或禁止项 |

### 1.1 数据库接入阶段结论

| 阶段 | 已确认／暂定方案 | 仍需确认 |
|---|---|---|
| 公司数据库流程完成前 | 已确认使用 Cloudflare Tunnel 远程访问世文本地 PostgreSQL；临时账号具备 `public` Schema 现有及未来业务表 CRUD，禁止 DDL 和授权操作；仅后端或同步任务连接 | 逐表读写范围、字段映射、唯一写入方、同步频率、幂等和冲突处理 |
| 公司数据库流程完成后 | 暂定共用公司 PostgreSQL，世文、本系统和集成数据按独立 Schema／角色隔离 | 最终实例结构、Schema 命名、权限矩阵、迁移和回退方案 |

临时账号的 CRUD 权限仅代表技术能力。未完成表级确认前，不得将其理解为可以任意修改世文全部业务表。Tunnel 地址、数据库账号、密码和完整连接串不写入本清单或代码仓库。

### 1.2 复核结论

经主 PRD、项目组接口约定和世文 V1 交叉检查，世文提供给本系统的数据应完整覆盖六类：

1. 教师身份与训练营周期；
2. 正式任务分配、调整与撤回；
3. 积分、五维和业务状态结果；
4. 教师可见课程表现、积分事件与逐课归因；
5. 教师可行动的改善建议及与个性化任务的关联；
6. 站内消息。

其中第 3—6 类尚未取得世文正式 Schema；世文 V1 目前主要覆盖任务下发和运行结果回流框架。

## 2. 世文需要提供给新师训练营的数据

### 2.1 教师身份与训练营身份

用途：把本系统账号、任务、积分和消息稳定关联到同一名教师及同一期训练营。

| 数据 | 建议字段 | 需要确认的问题 | 当前状态 |
|---|---|---|---|
| 教师唯一身份 | `teacher_id` | 是否永久不变；教师重新入职时是否复用 | 待世文提供 |
| 教师展示信息 | `teacher_display_name` | 账号页需要展示姓名；确认由世文提供还是本系统注册时采集 | 数据来源待确认 |
| 公司邮箱映射 | `company_email` | 邮箱变更、重复邮箱和未激活邮箱怎么处理 | 待世文提供 |
| 训练营实例 | `camp_enrollment_id` | 一名教师多次入营时如何区分 | 待世文提供 |
| 训练营批次 | `cohort_id`、`cohort_name` | 是否需要展示；同一批次与个人入营实例如何关联 | 数据来源待确认 |
| 入营与周期 | `camp_enrolled_at`、`launch_at`、`camp_end_at` | Day X／30、Launch 起算时间和教师本地自然日如何计算 | 待双方确认 |
| 教师时区 | `teacher_timezone` | 身份接口统一提供，还是每次任务下发携带 | 已有 V1，待冻结 |
| 默认语言 | `preferred_locale` | 由世文提供初始值，还是本系统由教师选择并保存 | 数据来源待确认 |
| 训练营状态 | `camp_status`、`status_updated_at` | 状态枚举、退出、暂停、重新入营规则 | 待世文提供 |
| 身份数据版本 | `identity_revision`、`updated_at` | 更新、乱序、重复同步如何处理 | 待双方确认 |

需要世文同时提供：身份新增、修改、失效的同步方式，测试账号，以及“任务先到、身份后到”时的补偿规则。

### 2.2 任务分配、调整与撤回

用途：世文决定给谁分配什么任务、优先级、顺序和截止时间；本系统接收正式分配后才创建执行实例。

支持的上游事件：

| 事件 | 含义 | 当前状态 |
|---|---|---|
| `task.issued.v1` | 首次下发任务 | 已有 V1，待冻结字段 |
| `task.reprioritized.v1` | 修改优先级或展示顺序 | 已有 V1，待冻结字段 |
| `task.due_date_revised.v1` | 修改截止时间 | 已有 V1，待冻结字段 |
| `task.withdrawn.v1` | 撤回任务 | 已有 V1，待冻结字段 |

每次任务分配建议使用完整快照，至少包含：

| 字段组 | 建议字段 | 维护方 | 当前状态 |
|---|---|---|---|
| 分配标识 | `task_id`、`assignment_revision`、`obligation_id` | 世文 | 已有 V1，待冻结 |
| 教师标识 | `teacher_id`、`camp_enrollment_id` | 世文 | 已有 V1，待冻结 |
| 路由安全 | `output_type`、`audience` | 世文 | 确认该接口是否只允许 `TEACHER_TASK + TEACHER`；如是可固定而不逐条传 |
| 本地任务版本引用 | `template_id`、`template_version`、`execution_contract_version` | 本系统发布目录，世文引用 | 待双方确认 |
| 任务分类 | `task_category`、`is_required`、`is_optional` | 世文 | 正式枚举待确认 |
| 阶段与排序 | `stage_id`、`priority`、`is_primary`、`display_rank` | 世文 | 正式枚举和排序规则待确认 |
| 时间 | `assigned_at`、`activated_at`、`original_due_at`、`due_at`、`expires_at`、`teacher_timezone` | 世文 | 字段必填性待确认 |
| 教师安全原因 | `public_reason`、`trigger_summary`、`expected_benefit`、`next_step_hint` | 世文 | 文案结构和安全白名单待确认 |
| 关联数据 | `public_dimension`、`public_metric`、`public_lesson_ref` | 世文 | 个性化任务关联字段待提供 |
| 治理信息 | `policy_version`、`updated_at`、`payload_hash` | 世文 | 计算和版本规则待确认 |

必须先解决的责任冲突：

- 世文 V1 将任务模板和模板版本归任务触发中心维护。
- 当前项目口径将任务内容、题目、素材和完成规则归新师训练营本地维护。
- 双方需要确认最终唯一写入方，以及任务目录和版本如何同步；否则 `template_id`、数据库结构和发布流程无法冻结。

### 2.3 积分与业务结果快照

用途：My TIT 展示当前积分、五维结果和出营／试用期／金牌状态。本系统只展示，不自行推算。

| 数据 | 建议字段 | 需要确认的问题 | 当前状态 |
|---|---|---|---|
| 结果归属 | `teacher_id`、`camp_enrollment_id` | 是否每期训练营独立结算 | 待世文提供 |
| 结果版本 | `result_version`、`score_as_of` | 五维、总分和状态必须属于同一版本 | 待世文提供 |
| 当前积分 | `visible_total_score` | 教师端最高展示 200 | 业务口径已确认，Schema 待提供 |
| 可获得积分 | `available_score` | 只包含已明确、未完成且额度确定的固定必修任务 | Schema 待提供 |
| 待确认积分 | `pending_score` | 不计入当前总分，何时转为已确认 | Schema 待提供 |
| 可获得积分明细 | `available_score_items[]`：`source_type`、`source_ref`、`score_amount`、`status` | 说明具体来自哪个未完成固定必修任务 | Schema 待提供 |
| 待确认积分明细 | `pending_score_items[]`：`source_type`、`source_ref`、`score_amount`、`status`、`estimated_update_at` | 必须说明来源、状态和预计更新时间 | Schema 待提供 |
| 五维积分 | `dimension_scores` | 五个维度的对象结构、上限、解释和统计周期 | 待世文提供 |
| 出营状态 | `graduation_status` | 不得仅根据 100 分自行推断 | 待世文提供 |
| 试用期状态 | `probation_status` | 状态枚举和更新时间 | 待世文提供 |
| 金牌状态 | `gold_status`、`gold_condition_results` | 复合条件的教师可见结果结构 | 待世文提供 |
| 成长标签 | `earned_tags`、`pending_tags` | 标签编码、文案、获得时间和失效规则 | 待世文提供 |
| 样本保护 | `sample_protection_status` | “前 10 个在岗日”等保护规则是否启用 | 待双方确认 |

需要世文分别提供五个维度的教师可见数据：

| 维度 | 至少需要的数据 |
|---|---|
| 用户反馈 | 当前分、好评、收藏、15 天复约、样本量、统计周期、延迟状态、教师安全说明 |
| 可靠性 | 当前分、准时完课、Peak 完课、迟到／早退／缺席的教师安全事实、统计周期、说明 |
| 课堂质量 | 当前分、无质量问题课程、设备网络和课堂质量的教师安全结果、统计周期、说明 |
| 产能成长 | 当前分、上限 10、开放 slots、重点／TTP slots、有效完课、活跃天数、正式计分说明 |
| 固定必修成长任务 | 当前分、上限 30、正式任务数、计分版本、单项分值、任务完成结果 |

每个维度还需统一返回累计分、近期积分变化、更新时间、数据截至时间、统计周期、样本量或数据状态；否则五维卡片无法区分“暂无数据”“等待延迟数据”和“本期无变化”。

需要重点确认：世文 V1 旧任务积分方案与当前“固定必修任务合计 30 分”的口径不一致，应以双方最终冻结的计分版本为准。

### 2.4 教师可见课程表现

用途：展示课程时间、指标表现和改善建议。它不能完全由积分事件替代，因为无积分变化的课程仍需展示；教师总分达到 200 后停止展示新增积分，但后续课程表现仍需继续展示。

| 建议字段 | 含义 | 当前状态 |
|---|---|---|
| `lesson_public_ref` | 教师可见且脱敏的课程标识 | 待世文提供 |
| `lesson_at`、`teacher_timezone` | 课程时间及展示时区 | 待世文提供 |
| `result_version`、`data_as_of` | 所属结果版本和数据截止时间 | 待世文提供 |
| `dimension`、`metric_name` | 该课程关联的维度和细分指标 | 正式枚举待确认 |
| `metric_result`、`data_status` | 教师可见指标结果及已确认／待确认／暂无数据状态 | 待世文提供 |
| `score_delta`、`score_status` | 该指标对应的可见积分变化或无变化状态 | 待世文提供 |
| `public_reason`、`next_step_hint` | 教师安全解释和可行动建议 | 安全白名单待确认 |
| `improvement_task_id` | 已正式下发时关联同一改善任务实例 | 可空；不得因此把任务作为积分来源 |

### 2.5 积分事件与逐课归因

用途：向教师解释“哪一节课、哪个供给事件或哪个固定必修任务带来了多少积分变化”。

| 建议字段 | 含义 | 当前状态 |
|---|---|---|
| `score_event_id` | 积分事件唯一标识 | 待世文提供 |
| `result_version` | 所属结果版本 | 待世文提供 |
| `event_at`、`score_as_of` | 事件时间和数据截止时间 | 待世文提供 |
| `dimension`、`metric_name` | 所属维度和细分指标 | 正式枚举待确认 |
| `source_type`、`source_ref` | 课程、供给事件或固定必修任务来源 | 正式枚举待确认 |
| `lesson_public_ref` | 教师可见课程标识 | 脱敏规则待确认 |
| `score_delta`、`score_before`、`score_after` | 本次变化及变化前后积分 | 待世文提供 |
| `status` | 已确认、待确认、无变化等状态 | 正式枚举待确认 |
| `public_reason` | 教师可见解释 | 安全白名单待确认 |
| `improvement_task_id` | 关联个性化改善任务 | 只能作为改善入口，不能作为积分来源 |

需要确认延迟到达的好评、收藏和复约如何保留原课程归因，以及教师端达到 200 后是否停止下发新的可见积分增长事件。

### 2.6 改善建议与个性化任务关联

用途：My TIT 在没有正式个性化任务时仍需要展示教师可以采取的下一步；有任务时进入同一任务实例。

| 建议字段 | 含义 | 当前状态 |
|---|---|---|
| `suggestion_id`、`suggestion_version` | 建议唯一标识和版本 | 正式 Schema 待世文提供 |
| `teacher_id`、`camp_enrollment_id` | 建议所属教师和训练营 | 待世文提供 |
| `public_dimension`、`public_metric`、`public_lesson_ref` | 教师可见关联维度、指标和课程 | 待世文提供 |
| `title`、`public_reason`、`next_step_hint` | 教师安全建议内容 | 内容结构和安全白名单待确认 |
| `data_as_of`、`expires_at` | 数据截止时间和建议有效期 | 待世文提供 |
| `related_task_id` | 世文已正式下发个性化任务时关联任务 | 可空；不能仅凭建议创建任务 |

需要确认：世文是直接提供最终教师文案，还是只提供安全原因代码和参数，由本系统按已审核文案模板渲染。

### 2.7 帮助、复核、豁免或人工审核处理结果

当前系统会向世文回传帮助、复核和豁免请求，但“谁处理、处理结果怎样回到教师端”尚未冻结。

如果由世文或世文侧运营处理，需要世文返回：

| 建议字段 | 含义 |
|---|---|
| `request_id`、`request_type` | 原帮助／复核／豁免请求 |
| `task_id`、`teacher_id`、`camp_enrollment_id` | 关联任务和教师 |
| `decision`、`result_status` | 已受理、通过、驳回、补充材料等教师可见结果 |
| `public_reason`、`next_step_hint` | 教师安全说明和下一步 |
| `decided_at`、`result_revision` | 处理时间和结果版本 |

如果由新师训练营项目组处理，则需明确本地处理入口和权限；一期不建设运营后台，不能默认本系统已经具备该能力。

### 2.8 站内消息

用途：接收世文发送的纯文字提醒和带任务提醒。

| 建议字段 | 含义 | 当前状态 |
|---|---|---|
| `message_id`、`message_revision` | 消息标识和更新版本 | 待世文提供 |
| `teacher_id`、`camp_enrollment_id` | 接收人和训练营实例 | 待世文提供 |
| `message_type` | `TEXT` 或 `TASK` | 待双方确认 |
| `title`、`body` | 教师可见内容 | 字段长度和安全规则待确认 |
| `issued_at`、`expires_at` | 发布时间和失效时间 | 待世文提供 |
| `related_task_id` | 关联的有效任务 | 带任务消息必需 |
| `public_safety_level` | 教师可见安全等级或策略 | 是否需要该字段待确认 |

还需冻结消息更新、失效、历史保留，以及关联任务撤回后的展示规则。

### 2.9 当前不要求世文单独返回的数据

以下数据可以由本系统根据正式分配和本地配置生成，不需要世文再提供一份投影：

- `current_tasks`：由已接收任务、当前状态、优先级和展示顺序查询得到。
- 任务执行状态、进度、`attempt_no`、剩余尝试次数和允许按钮：由本地任务运行记录及任务规则计算。
- 任务标题、Why、How、步骤、素材、题目和完成标准：按当前 PRD 由本系统已发布任务版本提供。
- 未正式分配的 `task_roadmap` 预览任务：当前 PRD 要求只有收到世文正式分配后才展示，一期暂不接收未下发预览任务。

## 3. 新师训练营需要回传给世文的数据

### 3.1 任务接收结果 ACK

用途：告诉世文任务是否已经被本系统持久化并接管。ACK 不代表教师已经查看。

| 建议字段 | 含义 | 当前状态 |
|---|---|---|
| `event_id` | ACK 事件唯一标识 | 已有 V1，待冻结 |
| `event_type` | 建议为 `task.dispatch_ack.v1` | 待双方确认 |
| `idempotency_key` | ACK 幂等标识 | 已有 V1，待冻结 |
| `task_id` | 世文任务标识 | 已有 V1 |
| `assignment_revision` | 已接收的分配版本 | 已有 V1 |
| `execution_contract_version` | 本系统接管的执行规则版本 | 待双方确认 |
| `accepted`、`accepted_at` | 是否接收及接收时间 | 已有 V1，待冻结 |
| `runtime_task_ref` | 本地执行实例的安全引用 | 是否回传及格式待确认 |
| `error_code` | 拒绝原因 | 正式错误码待确认 |

### 3.2 任务运行事件

用途：让世文形成任务执行投影，用于去重、后续触发、计分和效果回看。

一期建议回传：

| 事件代码 | 事件后状态 | 回传说明 |
|---|---|---|
| `TASK_VIEWED` | `VIEWED` | 教师真正打开任务；不带停留时长 |
| `TASK_STARTED` | `STARTED` | 教师开始执行 |
| `TASK_SUBMITTED` | `SUBMITTED`／`VERIFYING` | 已提交；不带答案、图片或文件 |
| `VERIFICATION_STARTED` | `VERIFYING` | 开始自动或人工验证 |
| `VERIFICATION_PASSED` | `COMPLETED` | 验证通过并完成 |
| `VERIFICATION_RETRY_REQUIRED` | `RETRY_REQUIRED` | 未达标但允许重试 |
| `VERIFICATION_REJECTED` | `FAILED_FINAL` | 最终不能继续 |
| `HUMAN_REVIEW_COMPLETED` | 按人工结果 | 只回传教师安全结论 |
| `HELP_REQUESTED` | 状态不变 | 教师请求帮助 |
| `REVIEW_REQUESTED` | 状态不变 | 教师请求复核 |
| `WAIVER_REQUESTED` | 状态不变 | 教师申请豁免 |
| `WAIVER_APPROVED` | `WAIVED` | 不等于通过，不触发计分 |
| `TASK_CANCELLED_BY_WITHDRAWAL` | `CANCELLED_BY_WITHDRAWAL` | 收到撤回后的关闭结果 |

每个任务运行事件至少包含：

```text
event_schema_version
```

### 3.3 消息已读事件

只有教师首次主动点击消息正文或任务入口时才回传；列表曝光、角标展示和进入可视区域不算已读。

| 建议字段 | 含义 | 当前状态 |
|---|---|---|
| `event_id` | 已读事件唯一标识 | 待双方确认 |
| `event_type` | 建议为 `message.read.v1` | 待双方确认 |
| `message_id` | 消息标识 | 待双方确认 |
| `teacher_id`、`camp_enrollment_id` | 教师和训练营实例 | `camp_enrollment_id` 是否必需待确认 |
| `opened_at` | 首次主动打开时间 | 待双方确认 |
| `open_action` | 打开正文或进入任务 | 正式枚举待确认 |
| `idempotency_key` | 防止重复已读 | 待双方确认 |

本地已读成功后立即更新页面；世文不可用时后台重试，不回滚本地已读状态。

## 4. 明确不回传给世文的数据

以下数据只保存在新师训练营系统内：

- 视频心跳、观看区间、续播位置、播放卡顿和首次完整观看明细。
- 题目、教师答案、标准答案和解析。
- 清单逐项选择和勾选明细。
- 图片、文件、文件地址和文件内容。
- 摄像头照片、设备检查原始材料。
- 页面曝光、入口点击、停留时长、步骤流失、上传失败等产品分析埋点。
- 学生信息、投诉详情、内部证据、审核意见、风险等级和触发阈值。
- 本系统账号密码、令牌、密钥和其他认证信息。

跨系统只回传任务标识、版本、状态、时间、尝试次数和必要的教师安全摘要。

## 5. 通用接口规则需要双方确认

| 事项 | 当前建议 | 需要冻结的内容 |
|---|---|---|
| 协议 | HTTPS + UTF-8 JSON | Content-Type、压缩和请求大小上限 |
| 时间 | RFC 3339 UTC | 精度、时钟同步和教师时区使用方式 |
| ID | 不透明字符串，最长 128 位 | 各字段具体长度和字符范围 |
| 幂等 | `event_id` 全局唯一；同幂等键同 payload 返回首次结果 | 幂等保存时长和冲突响应 |
| 内容哈希 | 使用 `payload_hash` | 序列化和哈希计算规范 |
| 鉴权 | 每个环境独立 HMAC-SHA256 密钥 | 密钥发放、轮换、旧密钥过渡和响应签名 |
| 防重放 | 时间偏差和 nonce 校验 | 时间窗口、nonce 保存时长和多实例共享方案 |
| 顺序 | 同一任务 `runtime_sequence` 连续递增 | 缺口重放和并发事件处理 |
| 错误 | HTTP 状态码 + 业务错误码 | 完整错误码、错误结构和 `retryable` 字段 |
| 重试 | 仅临时错误自动重试 | 间隔、最长时长、限流和超时 |
| 死信 | 超过重试窗口进入死信 | 人工补偿、对账、告警和双方负责人 |
| 环境 | 开发、测试、预发布、生产隔离 | 地址、白名单、账号、密钥和发布切换方式 |

## 6. 需要由新师训练营自行配置和维护的数据

以下内容不应等待世文逐条返回：

|---|---|---|

| 小测 | 题目、选项、答案、解析、通过分数、题库版本、重试次数 | 只回传提交／验证结果，不回传答案 |

| 上传与设备检查 | 文件类型／数量／大小、拍照与重拍规则、本地检测步骤、验证标准 | 不回传图片、文件和原始检测材料 |
| 阶段展示 | 阶段正式名称、天数、开放条件、固定必修任务在阶段内的配置顺序 | 世文负责正式分配；阶段口径仍需双方识别一致 |

## 8. 建议优先确认顺序

1. 先确认临时数据库逐表读写范围、字段映射和唯一写入方。
2. 再确认任务模板、内容和完成规则的唯一维护方。
3. 确认教师身份映射、任务目录和版本体系。
4. 冻结任务下发、ACK、运行事件和状态机。
5. 冻结积分结果、逐课归因、消息的正式 Schema。
6. 最后完成鉴权、环境、重试、对账和联调验收，并在公司数据库可用后复核长期共库方案。

未完成第 1—4 项前，可以进行内部架构、Mock 开发、结构检查和已授权读取，但不得对未确认的世文业务表执行写入，也不建议冻结生产数据库结构或对外接口合同。
