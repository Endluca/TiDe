## 1. 文档边界

本文档只记录教师端自有业务表，不重复定义世文权威表和两端共享任务表。

- 世文现有物理表以[数据库表结构](数据库表结构.md)为准。
- 共享 `task_templates / task_assignments` 以[教师端共享任务表契约](教师端共享任务表契约.md)为准。
- 任务执行的实际字段和约束以 `backend/database/migrations` 为准。本文档同步业务边界和核心表职责，不重复抄写全部 DDL。

### 2.1 `kuozhi_course_syncs`

- 每次正式刷新按 `account_id + idempotency_key / command_id` 双重幂等，保存映射版本、同步状态、完成结论和脱敏后的响应快照。
- 只关联当前账号拥有的 `task_assignment_id`；全条件达标时与 assignment 状态更新在同一事务提交。
- 应用账号只可 `SELECT / INSERT`，不能修改或删除历史；响应不保存阔知任务 URL、票证、密钥或 Cookie。
- `response_body.dataMode` 由数据库约束固定为 `REAL`，非正式课程结果无法写入。

### 2.2 `app_events`

`app_events` 只保存产品分析事件，不保存任务、积分或课程业务事实。完整事件名、触发条件和属性见[产品埋点事件字典](产品埋点事件字典.md)。

| 字段 | 类型／必填 | 含义 |
|---|---|---|
| `id` | uuid，PK，必填 | 数据库记录主键 |
| `teacher_binding_id` | uuid，可空 | 登录后教师绑定；登录前事件为空 |
| `anonymous_teacher_id` | varchar(64)，必填 | 后端生成的不可逆教师／会话匿名标识 |
| `event_name` | varchar，必填 | 事件字典中的稳定事件名 |
| `event_id` | varchar，必填 | 行为幂等标识 |
| `event_schema_version` | integer，必填 | 一期固定为 `1` |
| `event_source` | varchar，必填 | `CLIENT / BACKEND` |
| `session_id` | varchar(128)，必填 | 浏览器标签页会话或后端关联会话 |
| `task_assignment_id` | varchar，可空 | 任务事件关联的共享 assignment |
| `properties` | jsonb，必填 | 白名单扁平分析属性，最大 8 KB |
| `occurred_at` | timestamptz，必填 | 事件实际发生时间 |
| `received_at` | timestamptz，必填 | 数据库接收时间 |

约束：

- 登录事件按 `teacher_binding_id + event_id` 幂等；匿名事件按 `anonymous_teacher_id + event_id` 幂等。
- 任务事件写入前必须校验 assignment 属于当前教师；任务编码、类型、模板版本、执行规则版本、状态和尝试次数由后端覆盖。
- 客户端只允许事件白名单、属性白名单和扁平基础类型；敏感字段、超过 512 字符的字符串和超过 8 KB 的属性对象被拒绝。
- 后端权威事件为尽力写入；埋点失败不回滚已成功的业务事务。
- 本表不记录视频逐秒心跳，不写 `task_assignments`、积分或课程表。
- 前端对有效曝光及步骤首次开始／解锁／完成事件按标签页会话去重，刷新不重复上报；`408 / 429` 按退避策略重试，其他 4xx 直接丢弃。
- 已登录／匿名埋点接口分别限流为 300／30 次每分钟，限流范围不覆盖任务、积分或课程业务接口。
- 前端最多缓存 100 条事件，达到 20 条、等待 5 秒或页面隐藏时批量发送；后端单批最多接收 50 条，并使用一次归属查询和一次批量 INSERT。

一期索引：

| 索引 | 用途 |
|---|---|
| `(event_name, occurred_at DESC)` | 按事件和时间分析 |
| `(task_assignment_id, event_name, occurred_at DESC)` | 还原单任务旅程 |
| `(session_id, occurred_at)` | 会话分析 |
| `(properties->>'taskCode', properties->>'templateVersion', occurred_at DESC)` | 按任务和版本分析 |
| 匿名教师与 `event_id` 部分唯一索引 | 匿名事件幂等 |

当前任务语义分析使用 `analytics_actor_task_journey_v2 / analytics_task_assignment_funnel_v2 / analytics_task_funnel_v2`；`analytics_technical_quality_v1 / analytics_help_usage_v1` 继续承担技术质量和帮助使用分析。依赖旧教师快照的业务变化视图已由迁移 `0028_retire_task_business_change_view` 删除，被 v2 替代的 5 个 v1 视图已由 `0029_remove_unused_tide_objects` 删除。示例查询见 [product_analytics_queries.sql](../../backend/database/analytics/product_analytics_queries.sql)。

### 2.4 `job_leases`

| 字段 | 含义 |
|---|---|
| `job_key` | 调度任务稳定主键 |
| `owner_id` | 当前实例 ID |
| `lease_until` | 租约失效时间 |
| `updated_at` | 最近领取或续租时间 |

成长阶段提醒、个性化任务提醒、系统通知发布和工单图片清理启动前必须领取对应租约。业务幂等键和唯一约束仍是最终防重，不以租约替代业务幂等。

### 2.5 私有文件上传

- OSS 模式由后端生成固定 `objectKey`、类型、大小、有效期、私有 ACL 和 SHA-256 metadata 的短期 POST Policy；浏览器直传后由后端 HEAD 校验并标记 `READY`。
- 本地模式使用 `PUT /api/v1/files/{fileId}/content` 传输原始文件流；服务端边接收边计算大小和 SHA-256，并以临时文件原子落盘。
- 两种模式下载时都校验当前账号归属，不返回永久公开地址。

## 3. `system_notifications`

### 3.1 用途

`system_notifications` 只保存 TIDE 自身产生的个人系统通知，包括系统维护、服务异常／恢复、功能或政策更新、账号安全、人工公告、任务处理结果、新阶段开放，以及从共享 assignment 生成的个性化任务新分配／到期提醒。

它不保存：

- 世文产生的业务文字提醒；
- assignment 本身、任务过程或积分结果；
- FAQ 问答消息；
- 上传成功、保存成功等只需短暂出现的 Toast。

### 3.2 字段

| 字段 | 类型／必填 | 含义 |
|---|---|---|
| `system_notification_id` | uuid，PK，必填 | 系统通知唯一 ID |
| `teacher_id` | varchar，FK，必填 | 接收通知的教师，引用世文 `teachers.teacher_id` |
| `publication_id` | uuid，可空 | 配置发布来源；自动任务结果和个性化任务提醒为空 |
| `type_code` | varchar，必填 | 稳定类型码，如维护、服务恢复、任务处理结果、个性化任务分配／到期 |
| `title` | varchar，必填 | 安全纯文本标题；个性化任务优先使用安全 `display_title`，否则回退 `task_code` |
| `body` | text，必填 | 英文纯文本通知正文 |
| `action_type` | varchar，可空 | `TASK_DETAIL / MY_TIDE / TASKS / HELP / ACCOUNT`；无操作时为空 |
| `action_target` | text，可空 | 可选的系统内跳转目标；不保存带密钥的 URL |
| `issued_at` | timestamptz，必填 | 页面排序与展示使用的发布时间 |
| `read_at` | timestamptz，可空 | 教师首次主动打开通知的时间 |
| `clicked_at` | timestamptz，可空 | 教师首次点击通知操作的时间 |
| `expires_at` | timestamptz，可空 | 通知失效时间；空表示不设自动失效 |
| `cancelled_at` | timestamptz，可空 | 系统撤销通知的时间 |
| `dedupe_key` | varchar，唯一，必填 | 生成通知的幂等键，防止重复提示 |
| `payload` | jsonb，必填 | 最小扩展信息；个性化提醒只保存 assignment ID 和提醒类型，不保存 Why 或 evidence |
| `created_at` | timestamptz，必填 | 通知创建时间 |
| `updated_at` | timestamptz，必填 | 已读、点击或撤销状态最后更新时间 |

### 3.3 最小约束

- 一条通知只属于一名教师；教师只能读取和操作自己的通知。
- `dedupe_key` 全表唯一，同一业务事实重试不生成重复通知。
- `action_type` 和 `action_target` 必须同时为空或同时有值。
- 列表曝光、角标展示和滚动进入可视区域不写 `read_at`。
- 教师主动打开详情时幂等写入首次 `read_at`；点击操作时幂等写入首次 `clicked_at`。
- 已失效通知保留、继续计入未读，打开后可写 `read_at`，但不允许写点击或执行跳转。
- 已撤销通知不进入页面读模型。
- 已发布通知正文、受众和操作不可原地修改；应用账号只能更新个人通知的首次已读、点击和撤销，不能修改内容或删除。数据库 Owner 仅可在合规清理或隔离测试中维护数据。
- 个性化任务新分配／到期提醒分别使用 `personalized-task-assigned:{assignment_id}`、`personalized-task-due-24h:{assignment_id}`，并通过 `ON CONFLICT DO NOTHING` 防止并发与重启重复。
- 新阶段提醒使用 `growth-stage-available:{teacher_id}:{stage_number}`；首次启用只建立观察基线，不补发老师已经开放的历史阶段。

### 3.4 建议索引

| 索引 | 用途 |
|---|---|
| `(teacher_id, issued_at DESC, system_notification_id DESC)` | 教师消息游标分页 |
| `(teacher_id, read_at)` | 教师未读数量和未读筛选 |
| `UNIQUE (dedupe_key)` | 通知生成幂等 |

## 4. 展示合并边界

Messages 页可以在后端读模型中合并不同来源的消息，但不把外部消息复制到 `system_notifications`，也不把 TIDE 系统通知写入 `public.notifications`。

个性化任务提醒的创建只读取 `public.task_assignments` 的安全必要字段；不修改 assignment，不读取 `why / evidence_snapshot`，不写积分表。`system_notifications` 的已读、点击和撤销也只更新教师端自有表。

## 5. `system_notification_publications`

### 5.1 用途

保存一期项目侧 JSON 配置同步后的发布事实。它记录稳定 `config_key`、英文纯文本内容、受众规则、固定操作、北京时间计划、发布状态、收件人数和失败重试，不保存任意 SQL。

### 5.2 核心字段

| 字段 | 含义 |
|---|---|
| `publication_id / config_key` | 发布主键和配置幂等键 |
| `type_code / title / body` | 已冻结的通知类型与英文纯文本内容 |
| `audience` | 受控 JSON 条件：全部，或老师、批次、成长天数、账号、任务与状态 |
| `action_type / action_target` | 最多一个白名单系统内操作 |
| `scheduled_at / expires_at` | 计划发布和失效时间，配置入口要求 `+08:00` |
| `status` | `SCHEDULED / PUBLISHED / CANCELLED / FAILED` |
| `published_at / recipient_count` | 实际发布时间和一次性收件人快照数量 |
| `attempt_count / next_attempt_at / last_error` | 发布重试状态 |

发布事务内一次性解析收件人并批量写入 `system_notifications`。发布成功后内容与受众不可修改；更正采用撤销并使用新 `config_key` 重发。失败最多重试 10 次，同一发布对同一老师通过 `dedupe_key` 保证只生成一次。

## 6. `growth_stage_notification_states`

每名已有有效 TIDE 教师绑定的老师最多一条，保存 `teacher_id / highest_available_stage / initialized_at / updated_at`。

- 调度器首次看到老师时只写当前最高开放阶段，不创建历史通知。
- 后续最高开放阶段提升时，写入一条 `GROWTH_STAGE_AVAILABLE` 系统通知并同步更新状态。
- 新阶段通知在 `payload.stageNumber` 保存 `1–3` 阶段编号，持久化操作仍为 `TASKS -> /path`；教师端消息读模型仅对合法编号返回 `/path?stage={stageNumber}`，不修改表约束。
- 阶段开放仍由 `camp_day` 或上一阶段固定任务全部 `COMPLETED` 决定；本表只观察结果，不控制任务权限。
- 不修改或复制 `public.task_assignments`，不保存阶段任务明细。
