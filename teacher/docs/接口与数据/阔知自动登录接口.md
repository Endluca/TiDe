# 阔知系统自动登录接口

> 用途：TIDE 教师端打开阔知课程的免登录入口。
>
> 来源：阔知研发提供的《317 阔知系统自动登录》PDF。
>
> 安全说明：原 PDF 中包含明文 `secretKey` 和完整票证示例，本文不保留。密钥只能通过安全渠道注入 TIDE 后端，不得进入前端、Git、日志或业务数据。

## 1. 登录入口

```text
GET https://edu.51talk.com/login/ticket
```

TIDE 后端生成签名后的地址，教师浏览器访问该地址即可登录阔知，并通过 `to` 跳转到指定页面。

阔知原始 PDF 示例使用 `edu.51suyang.cn/login/ticket`；2026-08-04 联调确认该入口接受票证后会跳转到 `edu.51talk.com`，但登录 Cookie 无法跨站携带。TIDE 因此使用同站点 `edu.51talk.com/login/ticket`，并已用当前认证教师验证可免登进入课程页。

登录入口必须和 `to` 的课程页面保持同一站点。实测票证接口下发的是 host-only
`PHPSESSIDEDU` Cookie；若从 `edu.51suyang.cn` 登录后跳到 `edu.51talk.com`，浏览器不会携带该
Cookie，最终会重新落回登录页。

## 2. 参数

| 参数 | 必填 | 说明 | TIDE 取值 |
| --- | --- | --- | --- |
| `appkey` | 是 | 调用方业务标识 | 由阔知分配，按环境配置 |
| `type` | 是 | 用户类型：`admin`、`teacher` 或 `prs` | 固定为 `teacher` |
| `id` | 是 | 阔知识别的用户 ID | TIDE `teacher_id` |
| `to` | 否 | 登录成功后的跳转地址；为空时进入阔知首页 | `https://edu.51talk.com/course/{course_id}`；需要隐藏导航时在该地址内追加 `noheader=1` |
| `alt` | 是 | 按下方规则生成的登录票证 | 仅由 TIDE 后端生成 |

已确认：只要 TIDE 中的 `teacher_id` 存在，阔知侧就有对应账号，TIDE 不需要额外创建阔知账号。

## 3. 签名规则

1. 准备除 `alt` 外的全部请求参数。
2. 按参数名升序排序。
3. 按 `key1=value1&key2=value2` 形式进行 URL 编码并拼接。实现必须与 PHP `http_build_query` 的结果一致。
4. 使用阔知分配的 `secretKey` 对拼接结果计算 HMAC-SHA256。
5. 对 HMAC 结果进行 Base64 编码，得到 `alt`。
6. 将 `alt` 作为查询参数附加到登录入口；Base64 值本身也需要正确进行 URL 编码。

原文 PHP 示例：

```php
ksort($data);
$query = http_build_query($data);
return base64_encode(hash_hmac('sha256', $query, $secretKey));
```

PHP `hash_hmac` 在未传入第四个参数时返回十六进制字符串，因此 Node.js 实现必须先得到
`digest('hex')`，再对该字符串做 Base64；不能直接使用 `digest('base64')`。
若 `secretKey` 含 `#` 等 `.env` 特殊字符，配置值必须加引号，否则 `#` 后内容会被当作注释截断。

安全化示例：

```text
https://edu.51talk.com/login/ticket
  ?appkey=<由阔知分配>
  &type=teacher
  &id=<teacher_id>
  &to=<URL编码后的阔知课程页>
  &alt=<URL编码后的签名>
```

正式课程地址由版本化映射逐门生成，例如 G06：

```text
to=https://edu.51talk.com/course/520?noheader=1
```

`to` 的完整值参与签名，不能在生成 `alt` 后再追加 `noheader=1`。

## 4. TIDE 接入边界

- 签名必须在 TIDE 后端生成，前端不得持有 `secretKey`。
- 前端只获取短期免登地址，并按后端返回的 `courses[]` iframe 内嵌一门或多门课程；接口中的 `embedMode` 固定为 `IFRAME`，前端不提供新窗口或其他外跳入口。
- TIDE 使用 `teacher_id` 绑定阔知账号。
- 自动登录只负责打开课程；视频和考试结果通过《阔知课程详情接口》由后端查询，前端不得直连。
- 当前 G01、G05、G06、G07、G08 已配置课程入口；G01 使用课程 407、课程任务 2158、试卷 305；G09 的阔知课程、视频和考试任务 ID 尚未发布，保持内容待配置。
- G02 已退出阔知接入：旧课程 `499` 及其视频／考试映射不得再由当前 G02 调用；G02 使用 TIDE 原生版本化政策文档。
- 所有环境只允许当前认证教师进入正式映射课程；不存在示例账号、示例课程或切换开关。

## 5. POC 前仍需阔知确认

- `appkey` 和 `secretKey` 是否区分测试、生产环境，以及密钥轮换方式。
- 票证有效期、是否一次性使用、是否支持时间戳或 nonce 防重放。
- 阔知页面是否能提供满足第三方 iframe 的 Cookie（例如适当的 `SameSite`、`Secure`）以及域名白名单要求；TIDE 不保留新窗口降级模式。
- PC 和移动端 iframe 的正式支持范围；`noheader=1` 已随 `to` 正确传入，登录后的隐藏效果仍需在可免登环境验收。
- 若课程域名后续调整，登录票证入口也必须同步到相同站点，并重新验证 Cookie 域策略。
