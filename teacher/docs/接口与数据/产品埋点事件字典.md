# 产品埋点事件字典

状态：一期已实现

日期：2026-07-30

联动口径版本：TIDE-SHARED-DB-20260730-14

事件 Schema 版本：`1`

## 1. 边界

- 所有产品分析事件只写 `tide.app_events`。
- 客户端事件只表示用户行为；提交、验证、步骤完成和任务完成以后端事件及业务表为准。
- 埋点写入失败不阻塞注册、登录、任务执行、提交、积分或课程读取。
- 埋点不写 `task_assignments`、积分表、课程表或世文业务数据。
- 不记录邮箱、密码、令牌、完整问题／答案、清单明细、图片、文件名、文件地址、学生信息、内部证据或审核意见。
- 视频心跳仍写任务过程表；只有播放、暂停、续播、完播、跳播拦截、卡顿和失败等低频节点写 `app_events`。
- 一期只提供数据库视图与只读 SQL，不建设管理看板。

代码中的权威白名单为：

- 后端：[app-event.dictionary.ts](../../backend/src/app-events/app-event.dictionary.ts)
- 前端：[event-dictionary.js](../../frontend/src/analytics/event-dictionary.js)

## 2. 事件外层结构

| 字段 | 规则 |
|---|---|
| `event_id` | 8–128 字符；同一行为只生成一次；数据库幂等忽略重复写入 |
| `event_name` | 必须属于本字典白名单 |
| `event_schema_version` | 一期固定为 `1` |
| `occurred_at` | 客户端／后端实际发生时间；只接收 7 天内且不超过当前时间 5 分钟的事件 |
| `received_at` | 数据库接收时间 |
| `session_id` | 8–128 字符；浏览器按标签页保存，30 分钟无操作后新建会话 |
| `anonymous_teacher_id` | 后端生成的 64 位 SHA-256 标识，不保存明文邮箱或教师编号 |
| `event_source` | `CLIENT` 或 `BACKEND` |
| `teacher_binding_id` | 登录后由后端绑定；登录前为空 |
| `task_assignment_id` | 任务事件必填；后端校验属于当前老师 |
| `properties` | 最多 8 KB，只允许本字典中的扁平字符串、数字、布尔值或 `null` |

任务事件中的 `taskCode / taskType / templateVersion / executionContractVersion / taskStatus / attemptNo` 由后端查询当前 assignment、模板和执行版本后覆盖客户端值。

`app_events.properties.taskCode` 是事件发生时的原始证据，任务目录换码时不回写。当前任务语义统一读取 analytics v2：`task_code` 只通过
`task_assignment_id -> task_assignments.template_version_id -> task_templates.row_id`
解析，`raw_task_code / raw_task_codes` 保留原始编码供审计。缺少稳定 assignment／模板身份时，`task_code` 为空且
`task_code_resolution = 'UNRESOLVED'`，不得用 raw code 冒充当前语义。v1 视图仅保留用于原始口径核对和兼容，示例只读 SQL 默认使用 v2。

## 3. 公共属性

| 属性 | 含义 |
|---|---|
| `page` | 当前 Hash 路由页面 |
| `entrySource / displayPosition` | 入口来源与展示位置 |
| `sourcePage / targetPage` | 导航来源页与目标页 |
| `taskCode / taskType` | 任务编码与任务类别 |
| `templateVersion / executionContractVersion` | 共享模板版本与教师端执行规则版本 |
| `taskStatus / stepKey / stepType / attemptNo` | 当前任务、步骤和尝试信息 |
| `deviceType / os / browser / language` | `PC/MOBILE`、系统、浏览器和界面语言 |
| `clientVersion` | 前端版本或提交版本 |
| `result / errorCode / reasonCode` | 结果和稳定错误码 |
| `durationMs / effectiveDurationMs` | 总耗时与页面可见状态下的有效耗时 |
| `online / networkType` | 网络状态；不记录 IP |

其他白名单属性：`percent`、`completedCount`、`itemCount`、`questionCount`、`scoreBand`、`passed`、`chapterId`、`videoPositionSeconds`、`isResume`、`visibilityRatio`、`permission`、`retryNo`、`contentType`、`interaction`、`faqCategory`、`faqHit`、`feedbackResolved`、`notificationType`、`actionType`、`httpMethod`、`endpointGroup`、`statusCode`。

## 4. 账号事件

全部由后端产生，客户端不能伪造结果事件。

| 事件名 | 触发条件 |
|---|---|
| `ACCOUNT_REGISTER_STARTED` | 后端开始处理注册请求 |
| `ACCOUNT_REGISTER_SUCCEEDED` | 账号与教师绑定创建成功 |
| `ACCOUNT_REGISTER_FAILED` | 注册校验、绑定或服务处理失败 |
| `ACCOUNT_VERIFICATION_EMAIL_SENT` | 验证邮件投递尝试结束；以 `result` 区分成功／失败 |
| `ACCOUNT_VERIFICATION_SUCCEEDED` | 一次性验证令牌消费成功或此前已验证 |
| `ACCOUNT_LOGIN_SUCCEEDED` | 登录校验成功并创建会话 |
| `ACCOUNT_LOGIN_FAILED` | 密码错误、未验证或账号不可登录 |
| `ACCOUNT_PASSWORD_RESET_STARTED` | 后端开始处理重置申请 |
| `ACCOUNT_PASSWORD_RESET_SUCCEEDED` | 重置令牌消费成功且密码已更新 |
| `ACCOUNT_PASSWORD_RESET_FAILED` | 邮件投递失败或重置令牌无效 |

邮箱只用于业务处理，事件中只保存不可逆匿名标识和稳定错误码。

## 6. 任务执行漏斗事件

| 事件名 | 来源 | 触发条件 |
|---|---|---|
| `TASK_STARTED` | 后端 | 第一次有效操作触发合法 `start` 命令成功 |
| `TASK_STEP_STARTED` | 客户端 | 当前步骤第一次发生有效操作；同一会话、assignment、步骤只报一次 |
| `TASK_STEP_COMPLETED` | 后端 | 步骤保存后由后端判定为完成 |
| `TASK_STEP_FAILED` | 后端 | 步骤保存后由后端判定为失败 |
| `TASK_EXITED` | 客户端 | 未完成任务时离开详情；记录有效停留时间 |
| `TASK_PROGRESS_RESUMED` | 客户端 | 重新打开已有进度的任务 |
| `TASK_SUBMITTED` | 后端 | 提交事务成功 |
| `TASK_VALIDATION_STARTED` | 后端 | 提交后开始执行验证 |
| `TASK_VALIDATION_PASSED` | 后端 | 验证通过 |
| `TASK_VALIDATION_RETRY_REQUIRED` | 后端 | 验证未通过且当前执行版本允许重试 |
| `TASK_VALIDATION_FAILED` | 后端 | 验证未通过且不允许重试，或验证产生终止性错误；用 `result` 区分 |
| `TASK_COMPLETED` | 后端 | 合法完成记录与 assignment 完成状态已提交 |
| `TASK_RETRY_STARTED` | 后端 | 合法重试命令成功 |

后端权威事件使用业务命令标识生成稳定 `event_id`；命令重放不会产生第二条事件。

## 7. 专项内容事件

### 7.1 视频

| 事件名 | 来源 | 触发条件 |
|---|---|---|
| `VIDEO_PLAYED` | 客户端 | 本次播放器首次成功播放 |
| `VIDEO_PAUSED` | 客户端 | 老师主动暂停 |
| `VIDEO_RESUMED` | 客户端 | 暂停、续播点或后续章节恢复播放 |
| `VIDEO_COMPLETED` | 后端 | 视频步骤首次满足完整观看规则 |
| `VIDEO_SEEK_BLOCKED` | 客户端 | 首次完整观看前向前跳播被拦截；同播放器只报一次 |
| `VIDEO_STALLED` | 客户端 | 播放卡顿；同播放器 10 秒内最多一次 |
| `VIDEO_FAILED` | 客户端 | 元数据、媒体或播放失败 |

事件只记录 `stepKey / chapterId / videoPositionSeconds`，不逐秒写播放进度。

| `QUIZ_STARTED` | 客户端 | 第一次开始回答当前小测；同一会话、assignment、步骤只报一次 |
| `QUIZ_SUBMITTED` | 客户端 | 小测保存请求返回结果 |

## 9. 写入、去重与失败处理

- 前端队列最多保留 100 条，失败按 1 秒、5 秒、30 秒重试，最多重试 3 次；`429` 优先遵守服务端 `Retry-After`。
- 除 `408 / 429` 外的 4xx 校验失败直接丢弃，不重复发送无效或敏感事件。
- 有效曝光、步骤开始、文档开始／完成和小测解锁／开始的同会话去重键保存在当前标签页 `sessionStorage`，刷新不重复上报；30 分钟会话失效后自动重置。
- 已登录埋点接口每分钟最多接收 300 次，匿名接口每分钟最多 30 次；限流只作用于埋点接口，不改变任务业务接口。
- 分析接口自身失败不再生成 `API_FAILED`，避免递归。
- 登录前只允许页面、导航和技术异常事件，且不能携带 assignment。
- 登录后任务事件必须通过当前账号绑定和 assignment 所有权校验；不存在或不属于当前老师时返回统一 404。
- `properties` 同时经过前端过滤和后端白名单、类型、长度、大小与敏感字段校验。
- 后端 `captureSystem` 为尽力写入，任何埋点异常都被隔离，不回滚已成功的业务事务。
