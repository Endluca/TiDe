# 教师端共享任务表契约

状态：唯一当前契约
日期：2026-07-30
联动口径版本：TIDE-SHARED-DB-20260730-14

## 1. 合作结论

任务触发中心与教师端共用同一个 PostgreSQL，直接读写 `task_assignments`。不再建任务发布接口、任务状态回传接口或第二套任务副本。

共库不等于共享超级用户：

- 教师浏览器和运营浏览器都不能直连 PostgreSQL；
- 只有教师端后端和任务触发中心后端可写入；
- 两个服务使用不同的受限数据库账号，并由数据库约束/触发器守住字段所有权、状态机和终态；
- 分数、总分、毕业和金牌结论不写入 `task_assignments`，教师端无权修改积分表。

站内消息同样共库但不混表：世文业务提醒以 `public.notifications` 为权威，TIDE 系统通知以 `tide.system_notifications` 为权威，教师端后端只在读模型中合并。

### 1.1 站内消息共享边界

- `public.notifications` 只承载世文业务文字提醒，不负责个性化任务分配或到期提醒，也不保证携带 `task_id`；教师端不得依赖该字段发现或打开个性化任务。
- 教师端可以按当前 `teacher_id` 读取 `public.notifications`，并幂等更新首次 `read_at / clicked_at / status`、写入 `notification_events`；不得修改标题、正文、收件人或业务原因。
- TIDE 配置通知、任务处理结果和个性化任务分配／到期提醒写入自有 `tide.system_notifications`，不得复制或回写到 `public.notifications`。
- 页面按发布时间倒序合并两类来源，不向老师展示来源差异；底层来源 ID 仍用于正确回写。
- 个性化 assignment 仍由世文任务触发中心创建；TIDE 只读 `task_assignments`，自行生成一次性的新任务和 24 小时内到期提醒。

## 2. 当前任务边界

共享任务目录以当前编码为准，保留连续编号的 G01–G09 共 9 个固定成长任务，以及系统现有的个性化改善任务。G04 是合并后的“首课备课与设备网络检测”；重排前的退役任务以隐藏技术编码 G00 只读保留，不进入当前列表、积分或资格判断。个性化任务只根据真实业务数据为命中老师创建，不默认全量分配。

| 编码 | 任务 | 分值 |
|---|---|---:|
| G01 | 资料与资质完善 | 3 |
| G02 | 平台政策学习 | 2 |
| G03 | 不同类型学员应对 | 2 |
| G04 | 首课备课与设备网络检测 | 3 |
| G05 | TTP 入门 | 3 |
| G06 | ME 文化与 PARSNIP | 4 |
| G07 | 可靠性培训 | 3 |
| G08 | Cocos 课程培训 | 5 |
| G09 | SET 教学基础 | 5 |

共享积分结构合计 30 分，教师端可见固定任务为 9 个。G03 的教师端标题必须精确为 `How to handle different types of students`，G04 必须精确为 `Lesson Preparation&Device Network Check`；G01–G09 同时是教师端执行流程路由码。`free-trial-training` 仅保留为候选资料，不展示、不计数、不计分。当前教师端个性化任务范围为 13 类：课中质量问题、出席问题、出席（未填写 Lesson Memo）问题，课堂节奏、互动、纠错、语速、授课语言引导、教具使用、学员回应、发音、行为规范／职业态度九类反馈匹配学习，以及拉黑问题的教师安全复核。

当前分工：

- 任务触发中心在新教师首次进入 `teachers` 时幂等初始化 G01–G09 assignment，并读取合法完成状态幂等结分；初始化本身不创建通知、提醒或其他投递意图；
- 教师端不创建固定 assignment，只读取关联已发布模板的 G01–G09，过滤隐藏 G00 后按天数或上一可见阶段完成状态开放，并更新 9 个固定任务从查看到完成之间的状态；
- 任务触发中心只能从已发布的上述个性化模板中选择，根据真实设备、出勤、Lesson Memo 或教师安全反馈数据创建 `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER` assignment；
- 教师端只展示当前老师已分配的个性化 assignment，执行和保存进度，不自行触发、复制或为所有老师预置全部任务；
- 个性化任务不写入固定必修积分，也不承诺完成后立即产生业务指标改善。

## 3. 两端实际共享什么

### 3.1 `task_templates`

两端只读已发布的当前任务目录。教师端查询必须以 `task_assignments.template_version_id = task_templates.row_id` 关联，并限制 `task_templates.status = 'PUBLISHED'`；不能只按教师读取 assignment，否则会把隐藏历史任务重新展示。关键字段：

| 字段 | 含义 | 必要性 |
|---|---|---|
| `row_id` | assignment 引用的模板记录 ID | 冻结任务静态内容，避免后续调整改变历史任务 |
| `template_id` | 稳定任务编码 | 两端用同一编码识别固定任务或个性化模板 |
| `status` | 模板是否已发布 | assignment 只能引用已发布记录 |
| `external_task_template_code` | 教师端任务类型编码 | 让教师端稳定路由到对应执行页 |
| `integration_mode` | 当前 9 个固定任务为 `INBOUND_STATUS_ONLY`；个性化模板为 `OUTBOUND_MANAGED` | 区分全量固定任务和按业务触发的个性化任务；两者都直接使用共享表，不恢复 HTTP 发布接口 |
| `payload` | 标题、Why、How、完成标准、分值、截止规则等 | 静态内容只存一处，不在 assignment 重复 |

全部物理字段见 [数据库表结构](数据库表结构.md)。

教师端四个任务摘要区域只读取共享表，不得由本地目录、翻译表或执行步骤覆盖：

- Why：`task_assignments.why`，并继续展示 `evidence_snapshot` 的教师安全白名单投影；
- How：assignment 引用模板的 `payload.how_summary`；
- Completion standard：assignment 引用模板的 `payload.completion_standard`；
- What you’ll gain：assignment 引用模板的 `payload.benefit`。

本地 `tide.task_step_definitions` 只负责任务操作区和完成校验，不是上述四个摘要区域的文案来源。中英文均按世文共享字段原值展示；世文未提供对应语言时，教师端不得用本地固定文案替换。

### 3.2 `task_assignments`

这是两端共享的唯一任务事实。

| 字段 | 含义 | 创建后谁可修改 |
|---|---|---|
| `assignment_id` | 一次任务实例的唯一 ID | 数据库生成，不可修改 |
| `teacher_id` | 任务所属教师 | 不可修改 |
| `task_code` | 稳定任务编码 | 不可修改 |
| `template_version_id` | 引用 `task_templates.row_id` | 不可修改 |
| `task_kind` | `FIXED_GROWTH / PERSONALIZED_IMPROVEMENT` | 不可修改 |
| `creator_system` | `TEACHER_APP / TRIGGER_CENTER` | 不可修改 |
| `display_title` | 本次 assignment 的动态展示标题；空值时回退模板标题 | 创建方写入后不可修改 |
| `evidence_snapshot` | 触发课程、教师安全原因及内部证据的创建时快照 | 创建方写入后不可修改；教师端只读取安全白名单 |
| `status` | 当前执行状态 | 按第 5 节状态机更新 |
| `priority` | 教师端和运营排序优先级 | 当前数据库视为创建内容，创建后不由教师端修改 |
| `why` | 该教师为什么有这条任务 | 创建方写入后不可修改 |
| `due_at` 及三个时区字段 | `due_at` 是实际截止时间；`timezone_used / timezone_source / timezone_verified_at` 是截止时间的时区证据 | 当前在创建时冻结，TIDE 只读 |
| `status_reason_code` | 失败、过期、豁免或取消原因码 | 产生该状态的有权服务更新 |
| `source_mode` | 真实/Mock/代理数据标记 | 不可修改 |
| `dedupe_key` | 任务创建幂等键 | 不可修改 |
| `created_by` | 创建服务/账号 | 不可修改 |
| `updated_by` | 最后更新服务/账号 | 每次合法更新时写入 |
| `row_version` | 乐观锁序号 | 数据库自动递增；调用方用它防止旧状态覆盖新状态 |
| `assigned_at` | assignment 对教师端可读时间 | 数据库生成，不可修改 |
| `status_changed_at` | 当前状态业务生效时间 | 与状态在同一事务更新 |
| `completed_at` | 可信完成时间 | 进入 `COMPLETED` 时写入，之后不可改 |
| `created_at` | 实例创建时间 | 数据库生成，不可修改 |
| `updated_at` | 最后合法更新时间 | 数据库自动更新 |

`task_assignments` 不再包含另一套触发评估或结果副本。个性化任务的模板、动态标题、教师安全 Why、优先级、截止时间、`dedupe_key` 和 `evidence_snapshot` 在 assignment 创建时冻结；教师端任务页面只从批准的白名单生成安全投影，不读取内部 evidence。提醒调度器只读取 assignment 标识、教师、任务编码、动态标题、状态、`assigned_at`、`due_at` 和三个时区证据字段，不读取 `why / evidence_snapshot`。

## 4. 两端怎么写

### 4.1 任务触发中心创建当前 9 个固定任务

任务触发中心为每位适用老师幂等初始化 G01–G09：

- `task_code` 必须是 G01–G09 之一；
- `task_kind = FIXED_GROWTH`；
- `creator_system = TRIGGER_CENTER`；
- `status` 由数据库固定从 `ASSIGNED` 开始；
- `template_version_id` 必须指向同一 `task_code` 的已发布模板；
- `dedupe_key = fixed:{teacher_id}:{task_code}`。

初始化必须在同一事务中恰好建立 9 条共享任务事实，不创建通知或投递意图。目录不是恰好 9 项、模板引用无效或最终少于 9 条时失败关闭，并记录内部异常 `TASK_BASELINE_INCOMPLETE`。数据库会拒绝重复 G 任务、未发布模板、越权编码和非 `ASSIGNED` 初始状态；教师端受限角色没有创建固定任务的职责。

### 4.2 教师端更新执行状态

教师端服务一次事务内更新：

- `status`；
- `status_reason_code`（需要原因码的状态必填）；
- `status_changed_at`；
- `completed_at`（只有 `COMPLETED`）；
- `updated_by`。

更新条件必须同时带旧 `row_version`，例如：

```sql
UPDATE task_assignments
SET status = :new_status,
    status_reason_code = :reason_code,
    status_changed_at = :changed_at,
    completed_at = :completed_at,
    updated_by = :service_name
WHERE assignment_id = :assignment_id
  AND row_version = :expected_row_version;
```

影响行数为 0 时，先重读当前行，不得盲目重试覆盖。数据库会自动递增 `row_version`、更新 `updated_at`、写入审计，并在状态变化时写入 Outbox。

### 4.3 任务触发中心

- 幂等初始化 G01–G09 assignment，并读取合法 `COMPLETED`；
- 从 `task_templates.payload` 读取对应固定分值；
- 向 `score_entries` 写入唯一 `FIXED_TASK_AWARD`；
- 不更新或伪造 G01–G09 的教师完成状态。
- 任务触发中心创建 `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER` assignment；
- 只能使用已发布的个性化模板和确认的触发规则，并通过 `dedupe_key` 执行合并、去重和再次触发规则；
- 教师端只更新执行状态，不修改 Why、优先级、截止时间或模板引用；
- 个性化任务是改善行动，不冒充固定成长任务积分来源。

### 4.4 积分结算与教师端读取

- 教师端积分首页只读 `public.teacher_scorecard_current`，按当前会话绑定的 `teacher_id` 查询一行；总分、出营／金牌资格、五维分和子项均直接使用视图结果。
- 课程列表与单课明细只读 `public.teacher_lesson_score_current`，按当前 `teacher_id` 过滤，并使用 `lesson_sequence + LIMIT/OFFSET` 分页；教师端不再根据课程事实或积分规则计算课程分。
- 教师端后端不读取 `score_entries / lesson_dimension_scores / config_versions / tide_score_policy_versions_v1` 来重建教师可见积分，也不保留旧计算路径或本地兜底分。
- “基础分”只表示 `CAPACITY` 最高 10 分与 `NEW_TEACHER_TASK` 最高 30 分的实际已得分之和，不是无条件赠送的 40 分。
- “可获得积分”由未完成且未进入终态的 G01–G09 乘以对应 `NEW_TEACHER_TASK.components[].points_per_unit` 生成；隐藏 G00、个性化任务、未来课程和无上限维度不进入。合计为 0 时不返回展示块。
- 不再生成或展示“待确认积分”。短暂读取延迟通过刷新或重试处理，不虚构暂定分数。
- `business_facts` 只通过后端白名单输出；当前不返回差评详情、拉黑、投诉、缺席原因等负向或运营内部字段。
- 逐课课堂质量为 `SOURCE_MISSING` 时保持 0 分；教师端不得平均拆分、反推或用摄像头／CPU／网络事实代替 `perfect` 结果。
- 详细字段以[教师端积分与课程读取对照表](教师端积分与课程读取对照表.md)为唯一当前积分读取契约。

## 5. 状态机

状态集：

`ASSIGNED / VIEWED / IN_PROGRESS / SUBMITTED / UNDER_REVIEW / COMPLETED / FAILED / EXPIRED / WAIVED / CANCELLED`

核心规则：

- 新任务只能从 `ASSIGNED` 开始；
- `VIEWED / IN_PROGRESS / SUBMITTED` 必须来自教师真实动作，不能用任务创建时间推断；
- `COMPLETED / FAILED / EXPIRED` 必须由教师端可信服务按模板完成标准产生；
- `WAIVED / CANCELLED` 只能由有权运营或系统流程产生，教师端受限角色不能写；
- `COMPLETED / EXPIRED / WAIVED / CANCELLED` 为不可回退终态；
- `FAILED` 不是终态，可合法进入 `IN_PROGRESS / SUBMITTED / UNDER_REVIEW / COMPLETED`；
- 进入 `FAILED / EXPIRED / WAIVED / CANCELLED` 必须有 `status_reason_code`；
- 进入 `COMPLETED` 必须有 `completed_at`；
- assignment 不允许删除。误报完成不能直接回退或删行，必须走受控数据修正和审计流程。

## 6. 固定任务特别约束

- 固定必修任务不存在复营或跨营期回补；同一教师同一 G 任务终身只有一条 assignment。
- 任务触发中心必须补齐覆盖范围内“每位教师 × G01–G09”基线。少于 9 条属于内部 `TASK_BASELINE_INCOMPLETE`，不是“教师未完成”或外部 `SOURCE_MISSING`。
- 教师端按可见任务开放：G01–G04 从第 1 天开放；G05–G07 在第 8 天自动开放，或在前述 4 项全部为 `COMPLETED` 后提前开放；G08–G09 在第 15 天自动开放，或在 G05–G07 全部为 `COMPLETED` 后提前开放。历史阶段任务继续显示。
- 教师端不读取或计算 `BEFORE_FIRST_LESSON / BEFORE_FIRST_PUSH` 事件截止时间。
- 合法 `COMPLETED` 由积分结算进程生成唯一 `FIXED_TASK_AWARD`；教师端不写分值。
- `is_cpl_tesol` 和 `is_self_introduce` 位于 `teacher_metric_snapshots`，分别作为 G01 的 TESOL 与 Self-intro 外部状态。G01 只有在两项外部状态均通过、61 题达到发布配置通过线（当前 80%）、Essay 完成确认、完成证明提交五项全部满足后，才能进入 `COMPLETED`。
- G01 的 61 题答案、Essay 完成确认和完成证明过程数据由教师端 `tide` Schema 持有；教师端不保存 Self-intro 原视频或 TESOL Essay 原文。
- G02 为 Platform Policies，通过阔知课程 499 完成视频和考试；教师端后端查询并判定结果。
- G03 为 Student Types，正式内容未发布前保持不可完成的内容待配置状态；Free Trial 不进入当前固定必修。
- G04 为首课备课与设备网络检测合并任务；当前教师端实现包含备课确认、摄像头／麦克风／网络检测和首课画面检查，运营契约要求的电脑／扬声器等设备项仍须在生产接入前完成联调。隐藏 G00 不提供独立入口。
- G05 为 TTP；G06 为 ME Culture & PARSNIP；G07 为 Reliability Training；G08 为 Cocos。四项均使用阔知课程，G07 在正式考试任务 ID 补齐前关闭自动完成。
- G02、G05、G06、G07、G08 的课程查询和判定快照保存在 `tide.kuozhi_course_syncs`；共享表只保存 assignment 当前状态。视频完成线、课程任务 ID、考试满分和通过线来源由版本化映射提供，前端不得复制。示例联调模式不得写快照或共享状态。
- G09 在本系统内完成视频和小测；题库本体保存在教师端自有 `tide.task_quiz_banks`，共享表不保存题目或答案。

## 6.1 个性化任务特别约束

- 个性化任务的模板范围、触发条件、合并和再次触发规则以已发布配置为准；前端内置的示例教师、课程、日期和结果不是真实分配。
- 任务触发中心创建 assignment；教师端只读取当前教师的分配，并更新查看、开始、提交、复核、完成或重试状态。
- 已有未完成实例时，新的同类证据按模板配置追加或合并，不绕过 `dedupe_key` 重复建卡。
- 个性化任务只展示教师安全原因和必要的关联课程，不展示学员身份、投诉原文、内部阈值或风险标签。
- TIDE 提醒调度器默认关闭；首次启用必须配置明确的 `rollout_at`，建议每 5 分钟只读扫描 `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER` assignment。
- 新任务提醒以 `assigned_at` 判断，只处理 `assigned_at >= rollout_at` 的新 assignment；不补发现有历史任务。提醒幂等键为 `personalized-task-assigned:{assignment_id}`。
- 到期提醒以 `due_at` 为准：仅当 `due_at > 当前时间` 且不超过未来 24 小时，并且状态为 `ASSIGNED / VIEWED / IN_PROGRESS / FAILED` 时发送；`SUBMITTED / UNDER_REVIEW / COMPLETED / EXPIRED / WAIVED / CANCELLED` 均不催促。提醒幂等键为 `personalized-task-due-24h:{assignment_id}`。
- 两类提醒都写入 `tide.system_notifications`，接收人为 assignment 的 `teacher_id`，`action_type = TASK_DETAIL`，`action_target = /task/{assignment_id}`，`expires_at = due_at`；标题使用安全的 `display_title`，否则回退 `task_code`，正文使用固定鼓励式英文模板。
- 提醒写入使用 `ON CONFLICT DO NOTHING`；调度器不得修改 assignment、读取内部 evidence、写入 `public.notifications` 或积分表。
- 个性化任务完成只代表改善行动已完成，不直接加分，也不代表后续业务指标已改善。
- 拉黑量达到 2 及以上时，任务触发中心先向运营端创建确认任务，不直接创建教师 assignment。
- 只有运营确认教师确有问题并选择已发布任务后，任务触发中心才为该老师创建个性化 assignment；具体教师任务内容与完成规则待嘉荷发布配置。
- 运营确认过程不写入教师端共享 assignment；`task_assignments` 不保存教师对拉黑信号的原因说明。

## 7. 权限现状与生产验收

### 当前公司测试库已实现

- `tit_teacher_crud` 可读 `task_templates` 和 `task_assignments`；
- 公司测试库复用同一 `tit_teacher_crud`：G01 外部状态仍只读 `teacher_metric_snapshots`；积分与课程只读 `teacher_scorecard_current / teacher_lesson_score_current`。该角色不读取原始积分流水、逐课分表或积分配置；
- 该角色不创建 assignment，只能更新 `status / status_reason_code / status_changed_at / completed_at / updated_by`；
- 数据库触发器已强制状态机、终态、所有权、乐观锁递增、审计和 Outbox。
- 物理 Schema 与后端任务查询已支持 `PERSONALIZED_IMPROVEMENT + TRIGGER_CENTER`；公司测试库当前有 831 条该类 assignment。5 个已发布个性化任务码族的具体内容在嘉荷配置前保持 `PENDING`；后续模板和真实触发样例仍待世文、嘉荷补齐。
- 公司测试库当前有 527 条 `public.notifications`，均未携带 `task_id`；该表只按世文业务文字提醒读取，不作为 assignment 或截止时间事实。
