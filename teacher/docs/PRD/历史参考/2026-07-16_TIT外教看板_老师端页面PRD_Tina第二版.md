## 2. 背景与目标

New Teacher Camp 需要在老师端提供一个清晰、正向、可行动的 TIT 看板，让新老师知道自己当前处于试用期哪个阶段、已经完成了哪些准备、还需要做什么，以及如何通过任务继续获得成长积分和解锁下一步机会。

### 2.1 产品目标

| 目标 | 说明 |
|------|------|
| 建立成长心智 | 老师看到的是“继续赚分和成长”，不是被扣分或被处罚 |
| 降低新师迷茫 | 明确当前阶段、下一里程碑和今日最该完成的任务 |
| 提升任务完成率 | 通过今日任务、成长路径、Toki 提示和完成反馈推动老师行动 |
| 支持后续接入真实任务中心 | 页面先保留字段、状态和组件结构，当前阶段可使用 Mock 数据 |
| 保持老师端表达友好 | 对异常、争议、待确认场景使用中性、帮助式文案 |

## 4. 用户与使用场景

### 4.1 目标用户

| 用户 | 核心诉求 |
|------|----------|
| 上线 0-30 天的新外教 | 知道如何完成上线准备、首课准备和试用期任务，了解当前成长状态、今日任务和下一阶段目标 |

### 4.2 关键场景

| 场景 | 老师端应支持 |
|------|--------------|
| 老师刚进入试用期 | 展示 Day X/30、必修任务、下一里程碑 |

## 6. 页面需求

### 6.1 首页概览

目标：老师进入页面后，能立刻知道当前状态和下一步行动。

#### 模块字段

| 字段 | 说明 |
|------|------|
| 试用期阶段 | 如 Day 5/30、首课准备、稳定成长等 |
| 成长积分 / 成长进度 | 当前已获得积分或阶段进度；规则未确认时可用进度占位 |
| 下一里程碑 | 如“完成设备检测后可进入首课准备下一步” |
| 当前优先任务 | 取今日任务中的首要任务 |
| Toki 提示 | 正向鼓励和行动建议 |

#### 展示规则

- 不展示投诉、处罚、淘汰、黑名单、红线等字样。
- 如真实积分未确认，使用“成长进度”或“已完成 X / 10 项任务”替代正式分数。
- Toki 文案以鼓励式为主，例如：
  - “Nice progress. Complete your Device Check to keep your first class ready.”
  - “You have finished 3 preparation tasks. One more step to unlock the next stage.”

### 6.2 今日任务

目标：让老师清楚知道今天最该完成什么。

#### 模块结构

| 区域 | 说明 |
|------|------|
| 首要任务 | 当前最重要的 1 个任务，默认突出展示 |
| 次要任务 | 最多 2 个，避免信息过载 |
| 截止提示 | 使用友好表达，如 Due today / Due in 2 days |
| 完成收益 | 告诉老师完成后会带来什么正向结果 |
| 操作按钮 | Start / Continue / View result / Try again |

#### 任务卡字段

| 字段 | 示例 |
|------|------|
| task_name | Device & Network Check |
| task_type | 外部设备检测 |
| priority | High / Medium / Low |
| due_time | 2026-07-18 23:59 |
| status | Start / Continue / Under review / Done / Try again / Overdue |
| estimated_duration | 5 min |
| result_message | Your device check helps keep your class stable. |
| action_text | Start check |

### 6.3 My TIT / 成长看板

目标：让老师看到自己的整体成长状态，而不是只看任务列表。

#### 五项成长维度

| 维度 | 英文名称建议 | 展示重点 |
|------|--------------|----------|
| 可靠性 | Reliable Teaching | 准时、稳定、完整完成课程 |
| 课堂质量 | Class Quality | 设备、网络、摄像头、灯光、课堂准备 |
| 学员体验 | Student Experience | 好评、互动、学习体验趋势 |
| 产能成长 | Availability Growth | slots、重点时段、真实完课量 |
| 新师任务 | New Teacher Tasks | 培训、账号、证书、资料、规则学习 |

#### 状态表达

| 状态 | 使用场景 |
|------|----------|
| 已完成 | 该维度当前任务已完成 |
| 进行中 | 老师正在完成相关任务 |
| 可继续提升 | 有可选提升任务 |
| 建议关注 | 有建议完成的任务或提醒 |
| 观察中 | 样本较少或仍在观察期 |
| 需要确认 | 结果尚未确认，老师可查看帮助或等待反馈 |

### 6.4 成长路径

目标：让老师知道试用期成长路线和任务解锁关系。

#### 阶段结构

| 阶段 | 说明 | 任务示例 |
|------|------|----------|
| Day 1-7 / 首课准备 | 完成基础资料、设备和平台规则 | Profile & Credentials、Device Check、Platform Policies、Lesson Preparation |
| Day 8-14 / 稳定成长 | 完成文化、规则、可靠性和体验课训练 | TTP Orientation、ME Culture & PARSNIP、Reliability Training、Free Trial Training |
| Day 15-30 / 毕业准备 | 完成课程体系和进阶教学训练 | Cocos Course Training、SET Teaching Fundamentals |

#### 展示要求

- 已完成任务显示完成标记。
- 当前任务显示高亮。
- 未解锁任务显示预览，不给老师造成压力。
- 支持阶段点亮、勋章或轻量庆祝反馈。
- 阶段名未正式确认前，页面需标注为 Mock 或配置项。

### 6.5 通用任务详情页

目标：用同一套详情框架承载不同任务类型。

#### 固定结构

| 区域 | 内容 |
|------|------|
| 任务头部 | 任务名称、阶段、状态、预计用时 |
| Why | 为什么收到这个任务，用老师能理解的语言说明 |
| How | 老师需要怎么做，步骤清晰 |
| Result | 完成后会发生什么，强调正向收益 |
| 完成标准 | 告诉老师什么算完成 |
| 操作容器 | 根据任务类型切换 |
| 帮助入口 | Help / Contact support / Request review |
| Toki 提示 | 当前状态下的鼓励或引导 |

#### 五类任务操作容器

| 任务类型 | 页面能力 |
|----------|----------|
| 学习小测 | 查看素材、开始小测、提交、通过/重试 |
| 学习清单 | 查看步骤、逐项确认、完成 |
| 上传审核 | 查看要求、上传文件、提交、审核中、需要更新 |
| 外部设备检测 | 查看说明、跳转检测、返回结果、重新检测 |
| 外部培训 / 标签回传 | 查看培训说明、前往平台、等待同步、展示完成状态 |

## 7. 状态与文案规则

### 7.1 老师端状态

| 状态 | 英文展示 | 说明 |
|------|----------|------|
| 待完成 | Start | 老师尚未开始 |
| 进行中 | Continue | 老师已开始但未完成 |
| 已提交 / 审核中 | Under review | 等待系统或人工确认 |
| 已完成 | Done | 任务完成 |
| 未通过 / 需要更新 | Try again / Update required | 需要老师重新操作或补充 |
| 逾期 | Overdue | 超过截止时间，仍提供行动入口 |

### 7.2 不展示的内部状态

| 内部状态 | 老师端处理 |
|----------|------------|
| 待触发 | 不展示 |
| 系统校验 | 可合并展示为 Under review |
| 人工复核 | 可合并展示为 Under review 或 Need confirmation |
| 已豁免 | 不直接展示，可转为 Done 或 Not required |
| 投诉 valid / invalid / pending | 不展示 |
| 处罚建议 | 不展示 |

### 7.3 文案原则

- 使用行动导向：Start check、Upload file、Continue learning。
- 使用成长导向：Improve、Prepare、Unlock、Keep going。
- 避免惩罚导向：Penalty、Blacklist、Serious complaint、Elimination。
- 对争议结果使用中性表达：Need confirmation、Request review、Try again。

## 9. MVP 验收标准

| 验收项 | 标准 |
|--------|------|
| 首页概览 | 能展示当前阶段、成长进度、下一里程碑和 Toki 提示 |
| 今日任务 | 能展示 1 个首要任务和最多 2 个次要任务 |
| 成长路径 | 能展示三阶段任务地图、完成状态和当前任务 |
| My TIT | 能展示五项成长维度和正向状态 |
| 通用任务详情 | 五类任务均可进入详情页并展示对应操作容器 |
| 状态变化 | Start、Continue、Under review、Done、Try again、Overdue 均有样例 |
| 完成反馈 | 任务完成后首页、今日任务、成长路径、My TIT 同步变化 |
| 正向表达 | 页面不展示投诉等级、处罚、黑名单、淘汰、内部复核细节 |
| 帮助入口 | 设备检测、上传审核、争议场景均有帮助或重试入口 |
| 中英文 | 核心页面、任务按钮、状态文案支持中英文切换 |
| 响应式 | PC 和 390px 移动端无横向溢出、遮挡或关键操作不可见 |

## 10. 待确认问题

| 问题 | 影响 |
|------|------|
| 老师端首版展示具体积分，还是只展示成长进度 | 影响首页和 My TIT 视觉设计 |
| 五项成长维度英文名称是否采用本文建议 | 影响中英文文案 |
| Day 1-7 / Day 8-14 / Day 15-30 是否为正式阶段名 | 影响成长路径 |
| Self-intro / TESOL 是否为毕业必要条件 | 影响任务优先级 |
| Platform Policies 首个主路径素材和小测题是否已确认 | 影响 MVP 主演示路径 |
| 设备检测失败后的正式帮助文案和重测入口 | 影响失败恢复体验 |
| 投诉或重大反馈经内部确认后，老师端是否只展示专项提升任务 | 影响任务边界和申诉入口 |
| 勋章、奖励、优秀新师机会是否本期展示 | 影响正向激励模块 |
