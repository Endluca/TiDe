# 阔知培训插件接入方案 PRD（初稿）

> 状态：待 TIDE、阔知产品及研发共同评审
>
> 更新日期：2026-07-30

## 1. 背景与目标

TIDE 不再自建视频播放和测试能力。所有“视频＋测试类任务”统一使用阔知课程，通过 iframe 嵌入 TIDE。

目标：

- 老师从 TIDE 进入任务后，无需再次登录阔知。
- 视频播放、学习进度、测试作答和测试判定均由阔知负责。
- TIDE 获取可信的任务结果，用于展示任务状态并衔接现有结分流程。
- 视频继续使用阔知存储和播放流量，不迁移到 TIDE OSS。

## 2. 产品边界

### 阔知负责

- 课程、视频和测试内容。
- 视频播放、续播及完播记录。
- 测试作答、评分、通过判定及重考。
- 保存老师在阔知内的学习结果。
- 提供结果查询能力，并通过 Firehose 将结果变化推送至 TIDE。

### TIDE 负责

- 任务入口、任务说明、阶段开放和老师侧状态展示。
- TIDE 老师与阔知账号的身份映射。
- TIDE 任务与阔知课程／课程任务的映射。
- 接收或查询阔知结果，更新共享 `task_assignments` 的合法状态字段。
- 沿用现有幂等结分流程；TIDE 不直接写积分表。

### 当前不需要

- TIDE 不保留本地播放器、视频心跳和续播逻辑。
- TIDE 不保留本地测试页面、题库、答案、评分和重试逻辑。
- TIDE 不向阔知回传任务状态。视频与测试均在阔知完成，阔知已经持有原始结果。
- 本期不包含上传作业、勾选清单、人工审核等额外完成步骤。未来如增加，按“复合任务”另行设计。

## 3. 当前已确认

根据 2026-07-30 与阔知研发张鹤的初步沟通：

- 阔知没有 Web 播放器 SDK，需要打开阔知播放页面。
- 需要自动登录，具体方式和文档待阔知提供。
- iframe 初步可行，并可隐藏阔知导航；仍需实际 POC。
- TIDE 需要配置阔知 `course_id`。
- 可根据 `course_id` 查询课程任务信息，包括任务 ID、任务名称和视频名称、时长等。
- 当前一个视频对应一个阔知课程任务。
- 阔知可提供具体视频任务的播放进度，但没有暂停、退出事件。
- 阔知使用 Firehose 监听具体库表事件，并可推送至 TIDE 业务接口。
- Firehose 账号、地址和环境信息待与小龙确认。

测试结果能力尚未与阔知确认，是本次评审的重点。

## 4. 用户流程

1. 老师在 TIDE 打开视频＋测试类任务。
2. TIDE 根据老师和任务映射，生成阔知自动登录地址。
3. TIDE 在任务页面内通过 iframe 打开对应阔知课程页。
4. 老师在阔知内完成视频学习和测试。
5. 阔知通过 Firehose 将视频或测试结果变化推送至 TIDE。
6. 推送延迟或失败时，TIDE 调用阔知查询接口补偿。
7. TIDE 根据映射后的阔知结果更新任务状态：
   - 视频或测试未完成：保持进行中。
   - 测试未通过：保持未完成，可继续进入阔知重考。
   - 阔知要求的视频全部完成且测试通过：更新为 `COMPLETED`。
8. 世文任务触发中心读取合法 `COMPLETED`，按现有规则幂等结分。

若 iframe 实测不可用，则降级为免登录跳转阔知；状态同步方式不变。

## 5. TIDE 改造范围

### 前端

- 增加阔知课程 iframe 容器，不再分别渲染本地视频和本地测试。
- 支持加载中、登录失效、页面不可用、结果同步中和重新进入。
- 适配 PC 和 390px 手机端。
- 不提供“手动完成”入口。

### 后端

- 对接阔知自动登录。
- 维护老师、TIDE 任务和阔知课程的映射。
- 提供 Firehose 回调接口，校验来源并幂等处理。
- 对接阔知学习和测试结果查询接口，进行补偿与人工重查。
- 将阔知结果转换为 TIDE 任务状态。
- 不在前端暴露阔知账号密码或长期有效凭证。

### 数据

至少需要保存：

- 身份映射：`teacher_id`、阔知用户 ID／账号。
- 内容映射：TIDE `task_code`、模板版本、阔知 `course_id`、课程任务 ID、任务类型、顺序。
- 视频结果快照：进度、已观看时长、总时长、是否完播、更新时间。
- 测试结果快照：考试／尝试 ID、分数、是否通过、尝试次数、完成时间、更新时间。
- 同步记录：事件 ID、事件类型、发生时间、接收时间、处理结果、失败原因。

过程数据只保存在 TIDE 自有 Schema，不写入共享 `task_assignments`。

## 6. 双方需要提供的能力

### 阔知提供

- 自动登录接口或免登录地址生成规则。
- iframe 页面地址规则、隐藏导航方式和域名白名单要求。
- 用户查询／创建能力，或双方统一的账号映射规则。
- 课程及课程任务查询接口。
- 视频进度和完播结果查询接口。
- 测试结果查询接口。
- Firehose 可监听的视频及测试结果事件。
- 测试环境、测试账号和联调联系人。

### TIDE 提供

- Firehose 回调地址。
- 回调鉴权、签名校验和网络白名单要求。
- 老师标识及任务映射配置。
- 事件幂等、失败记录和补偿查询能力。

## 7. 接口最小字段

### 课程任务

- `course_id`
- `course_task_id`
- `task_type`：视频／测试
- `task_name`
- `sort_order`
- 视频名称及总时长

### 视频结果

- 阔知用户 ID
- `course_id`
- `course_task_id`
- 已观看时长／进度百分比
- 是否完播
- 结果更新时间

### 测试结果

- 阔知用户 ID
- `course_id`
- `course_task_id`
- 考试／尝试 ID
- 分数
- 是否通过
- 尝试次数
- 完成时间
- 结果更新时间

### Firehose 事件

- 唯一事件 ID
- 事件类型
- 业务主键
- 变更后的完整结果
- 事件发生时间
- 数据版本

最终字段名以阔知接口文档为准。

## 8. POC 验收

选择一个真实“视频＋测试”课程验证：

- 从 TIDE 进入后无需再次输入阔知账号密码。
- iframe 可正常打开，并隐藏无关导航。
- PC 和手机端可完成视频和测试。
- 视频未完成、测试未通过、测试通过和重考均能正确同步。
- TIDE 可收到 Firehose 推送，漏推时可通过查询接口恢复。
- 重复、乱序事件不会导致任务状态回退或重复结分。
- 老师再次进入时可继续学习或重考。
- 阔知完成结果能正确更新 TIDE 任务状态。

## 9. 待阔知评审确认

- 自动登录方式、凭证有效期及账号不存在时的处理。
- iframe 的正式支持范围、Cookie 限制和域名白名单。
- 测试是否作为课程任务返回，以及测试结果字段。
- 测试分数取最近一次还是最高一次；通过后能否再次作答。
- 视频进度字段、更新延迟、关闭页面后的保存时机。
- 是否支持固定 1 倍速及首次完播前禁止拖动。
- Firehose 监听的视频／测试数据表、推送字段、签名、重试和顺序保证。
- 查询接口的调用限制、分页和批量查询能力。

## 10. 与现行文档的冲突

现行总 PRD 和接口文档仍规定视频、小测及过程数据由 TIDE 持有。本方案改为：

- 阔知负责视频和测试执行及原始结果。
- TIDE 只保存必要结果快照，并更新任务状态。
- 不再使用 TIDE 本地题库、答案和视频心跳。

本初稿不直接修改共享任务表契约和数据库结构。阔知评审及 POC 通过后，需要同步更新：

- `新师训练营_教师端系统_PRD.md`
- `教师端共享任务表契约.md`
- `数据库表结构.md`
