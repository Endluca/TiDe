# 阔知培训插件接入方案 PRD（第一阶段）

> 状态：课程免登、iframe 和详情查询口径已确认；Firehose 和生产联调待完成
>
> 更新日期：2026-08-05

## 1. 背景与目标

TIDE 不再自建视频播放和测试能力。视频＋测试类任务统一使用阔知课程，并且只在任务页 iframe 内嵌；不提供跳转阔知的新窗口按钮。

第一阶段目标：

- 老师从 TIDE 进入任务后，无需再次登录阔知。
- 视频播放、学习进度、测试作答和原始得分由阔知负责。
- TIDE 后端查询当前老师的阔知课程详情，按 TIDE 已发布任务配置判定是否达到完成标准。
- TIDE 保存必要的查询与判定证据，合法更新共享 `task_assignments` 状态，并衔接现有幂等结分流程。
- 视频继续使用阔知存储和播放流量，不迁移到 TIDE OSS。

## 2. 产品边界

### 阔知负责

- 课程、视频和测试内容。
- 视频播放、续播及完播记录。
- 测试作答、原始评分及重考。
- 保存老师在阔知内的学习结果。
- 提供课程详情查询能力；后续通过 Firehose 将结果变化推送至 TIDE。

### TIDE 负责

- 任务入口、任务说明、阶段开放和老师侧状态展示。
- 使用当前 TIDE `teacher_id` 作为阔知详情接口的 `t_id`，不建立第二套人工账号映射。
- 维护 TIDE 任务与阔知课程、必修课程任务及考试通过线的版本化映射。
- 只从后端查询阔知结果，归一化视频进度与考试分数，并判断 TIDE 任务是否完成。
- 只更新共享 `task_assignments` 契约允许的状态字段；不写积分表、总分或资格。

### 当前不需要

- TIDE 不保留本地播放器、视频心跳和续播逻辑。
- TIDE 不保留本地测试页面、题目、答案、作答和重试逻辑；仅保留任务发布版本的通过线及分数量纲配置，用于解释阔知返回结果。
- TIDE 不向阔知回传任务状态。
- 本期不包含上传作业、勾选清单、人工审核等额外完成步骤。未来如增加，按“复合任务”另行设计。

## 3. 当前已确认

### 3.1 课程打开方式

- 阔知没有 Web 播放器 SDK，需要打开阔知课程页面。
- 自动登录入口为 `https://edu.51talk.com/login/ticket`，课程页为 `https://edu.51talk.com/course/{course_id}`；两者必须保持同站点，避免 host-only Cookie 丢失。
- 隐藏导航参数为课程页内的 `noheader=1`；TIDE 已确认参数随签名后的 `to` 正确传入，登录后的隐藏效果待可免登环境验收。
- G06 `ME Culture & PARSNIP` 当前映射为 `course_id=520`、视频任务编号 `2791`。
- 2026-08-03 POC 已证明免登票证可直接打开课程 520。2026-08-05 起正式任务与示例联调统一使用 iframe，后端不再保留可配置的新窗口模式，前端不提供外跳降级入口。

### 3.2 课程详情查询接口

```http
GET http://edu.51talk.me/api/me/TeacherCourseDetail
Accept: application/vnd.edusoho.v2+json

course_id=<阔知课程 ID>
t_id=<当前登录账号绑定的 teacher_id>
```

- `t_id` 已确认为教师 ID；正式业务请求必须从后端当前认证账号的绑定关系取得，前端不得提交或覆盖任意老师 ID。
- 接口只允许 TIDE 后端调用，浏览器不得直连。
- 当前内部域名需要解析为 `172.16.0.54`。现阶段只在部署 TIDE 后端的 Mac mini 配置 `KUOZHI_DETAIL_HOST_IP=172.16.0.54`；后端客户端保留原域名并覆盖 DNS 解析。迁移到公司服务器后复制该后端配置，不在前端站点或老师设备配置。
- 当前测试环境缺少 TIDE 测试老师的对应课程数据，因此业务账号返回空数据不视为接口故障。
- 后端联调冒烟样例暂用 `t_id=360107609、course_id=131`；该样例只用于开发和联调验证，不得写入正式老师运行路径、业务数据库或前端。

### 3.3 已确认的完成规则

- 视频课程任务以 `percent = 100` 判定完播；接口的字符串和数字形式都必须安全归一化为数值后再判断。
- 考试使用阔知返回的 `score`，并与该 TIDE 任务发布版本配置的考试通过线比较。
- TIDE 当前题库通过线是百分制。若阔知 `score` 为原始得分，必须先根据该阔知试卷配置的满分归一化为百分比：`score_percent = score / full_score × 100`；若阔知后续确认 `score` 已是百分制，则直接使用。
- 分数量纲与 `full_score` 必须配置在具体阔知考试任务映射中，不能由前端猜测，也不能仅根据一次返回值推断。
- 只有 TIDE 映射中配置的全部必修视频均完播、全部必修考试均达到各自通过线时，才允许把对应 TIDE 任务更新为 `COMPLETED`。
- 阔知返回的 `isOptional` 只作为来源证据；哪些课程任务必修以 TIDE 的版本化映射为准。
- `test_times` 只用于展示和审计，不直接影响通过判断。
- 空课程对象、`task_list = null`、缺少必修课程任务、字段无法解析或接口暂时不可用时，都不得判定完成，也不得回退已经完成的终态。

### 3.4 后续同步能力

- 第一阶段使用后端查询接口：进入任务、从阔知返回 TIDE 或老师主动刷新时查询一次。
- 阔知后续使用 Firehose 推送视频和测试结果变化；Firehose 到位后作为主同步通道，详情查询作为漏推补偿与人工重查通道。
- Firehose 账号、地址、鉴权和环境信息待与小龙确认。

## 4. 用户流程

1. 老师在 TIDE 打开阔知类任务。
2. TIDE 后端校验当前账号拥有该 assignment，并读取任务发布版本对应的阔知课程映射。
3. TIDE 后端使用当前绑定的 `teacher_id` 生成阔知免登地址。
4. TIDE 在任务页 iframe 内加载阔知课程，不提供新窗口跳转按钮。
5. 老师在阔知完成视频与考试，然后返回 TIDE 或点击刷新进度。
6. TIDE 后端使用当前绑定的 `teacher_id` 和映射的 `course_id` 查询课程详情；仅 `SAMPLE_DRY_RUN` 使用显式隔离的样例查询老师，免登身份仍是当前认证教师。
7. TIDE 后端按映射筛选必修课程任务、归一化进度与分数，并形成一次可追溯判定：
   - 没有课程数据：显示“暂未同步到课程数据”，保持当前状态；
   - 有学习进度但条件未全部满足：保持或进入 `IN_PROGRESS`；
   - 视频全部完播且考试全部达到通过线：合法更新为 `COMPLETED`；
   - 阔知暂时不可用：显示可重试状态，不把技术故障解释为老师未完成。
8. 世文任务触发中心读取合法 `COMPLETED`，按现有规则幂等结分。

Firehose 接入后，第 5～7 步由事件同步主动触发，页面查询继续承担补偿作用。

## 5. TIDE 改造范围

### 5.1 前端

- 正式映射与示例联调都只展示阔知 iframe；课程头部保留标题和课程 ID，不展示任何阔知外跳按钮。
- 展示“未开始／同步中／进行中／考试未通过／已完成／暂未同步到数据／同步失败可重试”等状态。
- 提供“刷新学习进度”入口；刷新请求只携带 TIDE `taskInstanceId`，不携带 `teacher_id` 或任意 `course_id`。
- 展示后端返回的已归一化进度和判定结果，不在前端复制完成规则。
- 不提供“手动完成”入口。

### 5.2 后端

- 新增阔知课程详情客户端，固定请求头，配置连接超时、响应超时和有限重试。
- 通过任务实例所有权校验取得当前 `teacher_id`，通过版本化映射取得 `course_id` 和必修课程任务规则。
- 严格解析阔知响应；兼容 `task_list` 为对象或空值、数值字段为字符串或数字的现状。
- 对视频进度、考试得分和 TIDE 发布通过线进行服务端归一化与判定。
- 保存最小结果快照与判定证据，使用幂等键更新任务状态，遵守终态不可回退规则。
- 第一阶段提供认证后的进度查询／刷新接口；后续提供 Firehose 回调与补偿任务。
- 不向前端暴露内部课程详情接口地址、任意老师查询能力或后端网络配置。

### 5.3 配置与数据

课程映射至少包含：

- TIDE `task_code` 与模板版本；
- 阔知 `course_id`；
- 必修课程任务列表：`course_task_id`、`type`、顺序；
- 视频完成线，当前固定为 `100`；
- 考试分数量纲：`PERCENT` 或 `RAW_POINTS`；
- 原始分制下的 `full_score`；
- 对应 TIDE 发布版本的 `pass_score` 来源；
- 页面打开方式、`noheader` 等非计分配置。

TIDE 自有 Schema 至少保存：

- 课程查询快照：老师、任务实例、课程、查询时间、结果状态；
- 必修课程任务结果：类型、原始进度／分数、归一化值、是否达标；
- 任务判定快照：使用的映射版本、通过线、最终结论和原因；
- Firehose 到位后的事件 ID、发生时间、接收时间、处理结果和失败原因。

过程数据只保存在 TIDE 自有 Schema；共享 `task_assignments` 只保存契约允许的任务当前状态字段。

## 6. 阔知课程详情响应契约

当前接口返回 HTTP 200 JSON，核心结构如下：

| 字段 | 当前类型 | TIDE 用途 |
| --- | --- | --- |
| `id` | `string \| null` | 实际课程 ID；空值表示没有课程数据 |
| `title` | `string \| null` | 课程名称 |
| `duration` | `string` | 课程总时长参考值，不参与完成判断 |
| `percent` | `string/number` | 课程汇总进度，仅展示，不替代逐任务判定 |
| `task_list` | `object \| null` | 以课程任务 ID 为键的视频／考试结果 |
| `cover` | `string` | 课程封面 |

视频任务当前包含：

- `id`、`title`、`isOptional`、`type=video`；
- `percent`、`time`、`watchTime`、`url`。

考试任务当前包含：

- `id`、`title`、`isOptional`、`type=testpaper`；
- `percent`、`score`、`test_times`、`url`。

当前接口没有稳定提供 `passed`、考试满分、通过线、结果更新时间或事件版本，因此这些信息不能由一次响应臆测：考试满分和通过线由 TIDE 版本化配置补足，时间与事件语义等待 Firehose 契约。

空数据当前同样返回 HTTP 200，例如 `id/title/task_list` 为 `null`。后端必须依据响应内容区分“成功返回空数据”和“有课程结果”，不能只判断 HTTP 状态码。

## 7. 异常与状态规则

| 场景 | 教师端表现 | 后端处理 |
| --- | --- | --- |
| 查询返回空课程 | 暂未同步到课程数据，可稍后刷新 | 不改完成状态，记录空结果 |
| 缺少映射中的必修课程任务 | 数据仍在同步，可稍后刷新 | 失败关闭，不判完成，记录缺项 |
| 视频 `percent < 100` | 展示当前进度 | 保持进行中 |
| 考试低于通过线 | 展示未通过并允许重新进入课程 | 保持进行中，不手工改分 |
| 字段类型或分数量纲不可解析 | 暂时无法同步，可重试 | 失败关闭并记录契约错误 |
| 阔知超时或 5xx | 同步失败，可重试 | 不修改老师业务结论，有限重试 |
| 重复刷新或重复事件 | 展示同一结果 | 幂等处理，不重复完成或结分 |
| 已完成任务后收到旧数据 | 保持已完成 | 终态不可回退 |

## 8. 部署与安全

- Mac mini 当前只在后端运行环境配置 `KUOZHI_DETAIL_HOST_IP=172.16.0.54`，不依赖系统 `/etc/hosts`。
- 迁移到公司服务器时，在公司服务器重新配置并验证解析、路由、超时和访问白名单；不依赖开发者电脑上的 hosts。
- 前端站点不直连 `edu.51talk.me`，也不接收可以查询任意老师的代理参数。
- 后端日志不得记录完整免登票证、密钥、Cookie 或阔知返回的可直接登录 URL。
- 课程详情请求必须由已认证账号的任务实例触发，并再次校验 assignment 所有权，防止越权查询其他老师。

## 9. 分阶段验收

### 9.1 第一阶段：查询与判定 POC

- 使用 `t_id=360107609、course_id=131` 的测试样例验证内部域名解析、请求头、响应解析和视频／考试任务识别。
- 样例 ID 只存在于显式隔离的 `sampleProfile`，默认关闭；正式运行路径只读取 `tasks` 映射。单元测试使用固定响应，不依赖内网接口。
- 空课程、空 `task_list`、视频未完播、考试未通过、考试通过、字段异常和接口超时都有自动化测试。
- 前端可以刷新进度，且只接收后端归一化结果。

### 9.2 第二阶段：TIDE 业务课程联调

- 阔知测试环境加入一名现有 TIDE 老师及对应业务课程后，以真实 `teacher_id + course_id` 验证。
- 老师完成视频与考试后，TIDE 能正确更新任务状态；重复刷新不重复完成。
- 从 TIDE 进入阔知无需再次输入账号密码，返回后能刷新到最新结果。

### 9.3 第三阶段：Firehose 与生产准备

- TIDE 可校验并幂等接收 Firehose 推送，重复、乱序和漏推不会导致状态回退。
- 查询接口可恢复漏推结果，并提供受控的人工重查能力。
- 公司服务器完成内部域名解析、网络白名单、监控、告警和回滚演练。

## 10. 仍待确认

- 阔知 `score` 是百分制还是原始得分，以及原始得分对应的稳定满分字段或规则。
- 接口返回的 `score` 是最近一次、最高一次还是已通过尝试结果；通过后能否再次作答。
- 视频进度更新延迟和关闭页面后的保存时机。
- 详情接口的调用限制、超时建议、分页／批量能力及正式错误码。
- iframe 的正式支持范围、Cookie 限制、域名白名单和 `noheader=1` 上线时间。
- Firehose 监听表、推送字段、签名、重试、顺序保证、事件时间和数据版本。

以上待确认项不阻塞第一阶段适配器和纯函数判定开发；分数量纲未确认前，不允许在真实业务老师路径自动写入 `COMPLETED`。

## 11. 与现行文档的冲突与同步范围

- 不再使用 TIDE 本地题库、答案和视频心跳作为阔知类任务的正式完成证据。

本方案已进入实现，新增教师端自有表 `tide.kuozhi_course_syncs`，不增加共享表字段。同步更新范围：

- `新师训练营_教师端系统_PRD.md`；
- 受影响的 G02、G05、G06、G07、G08 任务级 PRD；
- `教师端共享任务表契约.md`；
- `数据库表结构.md`；
- 新增“阔知课程详情接口”文档，并与现有自动登录接口文档建立引用。
