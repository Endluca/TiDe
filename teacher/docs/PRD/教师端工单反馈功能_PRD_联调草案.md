## 0. 文档信息

| 项目 | 内容 |
|---|---|
| 功能名称 | 教师端工单反馈 |
| 文档版本 | V0.4 |

## 1. 背景与目标

当前 Help 入口直接进入 AI FAQ。AI 只能依据已审核 FAQ 回答，无法解决教师的个别业务问题、数据问题或产品异常。

本功能增加人工工单闭环：

```text
教师提交工单
→ 世文运营看板读取
→ 运营回复
→ 教师端刷新时读取最新回复并显示未读红点
→ 教师确认已解决或继续补充
→ TIDE 关闭工单并清理全部 OSS 图片
```

目标：

- AI 无法解决时，教师可以直接提交工单。
- 尽量自动补充系统已有信息，减少教师填写。
- 教师与运营围绕同一工单持续追加消息。
- 教师刷新页面后，可以在“我提交的工单”中看到运营回复和未读红点。
- 工单关闭和图片清理由 TIDE 统一负责。

## 2. 产品范围

### 2.1 本期包含

- Help 二级入口。
- 教师创建工单、上传截图和补充消息。
- 世文运营看板读取工单、追加运营回复和运营图片。
- Messages 页面查看工单及未读回复。
- 教师确认“已解决”或“未解决”。
- 运营回复后 48 小时无教师反馈自动关闭。
- 工单关闭后删除教师和运营上传的全部 OSS 图片。

### 2.2 本期不包含

- TIDE 侧运营管理后台。
- 工单优先级、转派、催办、评价或服务时效考核。
- 教师修改或撤回已经发送的历史消息。
- 已关闭工单重新打开；仍有问题时重新创建工单。
- 把运营内部处理记录、判责或备注直接展示给教师。

## 3. 入口与页面

### 3.1 Help 入口

教师点击顶部 Help 或任务页帮助入口后，先进入帮助中心：

1. **问问 TIDE AI**：进入现有 AI FAQ。
2. **提交工单**：进入工单填写页。

AI 明确未命中时，增加：

> 仍未解决？提交工单

从 AI 进入时，可以预填教师刚才的问题，但必须让教师确认或修改后再提交。

### 3.2 Messages 页面

Messages 页面增加切换：

- **系统消息**
- **我提交的工单**

“我提交的工单”列表展示：

- 二级问题类型；
- 提交时间；
- 当前状态；
- 最近更新时间；
- 是否有未读运营回复。

未读红点展示在：

- Messages 导航入口；
- “我提交的工单”切换按钮；
- 对应工单列表项。

教师打开对应工单后，清除该工单的未读状态；如果仍有其他未读系统消息或工单回复，Messages 入口继续显示红点。

点击工单后进入详情，以对话形式展示教师和运营的全部消息。

### 3.3 运营回复后的教师操作

运营追加回复后：

1. 教师刷新页面、重新进入 Messages 或重新登录时，TIDE 读取共享表中的最新数据。
2. 如果存在尚未读过的运营回复，“我提交的工单”和 Messages 入口显示未读红点。
3. 教师进入对应工单后看到运营回复。
4. 底部提供“已解决”和“未解决”。

处理规则：

- 点击“已解决”：TIDE 关闭工单。
- 点击“未解决”：展开新的填写窗口；教师提交后，消息继续追加到原工单，重新等待运营回复。
- 本功能不为运营回复额外创建 `system_notifications` 站内提醒。

## 4. 提交内容

### 4.1 教师填写

| 字段 | 必填 | 说明 |
|---|---|---|
| 二级问题类型 | 是 | 一级类型由系统自动映射 |
| 关联对象 | 条件必填 | 任务问题选择关联任务；课程问题选择关联课次；找不到时可选择对应兜底项 |
| 问题描述 | 是 | 说明现象、期望结果和已尝试操作 |
| 截图 | 否 | 最多 3 张；报错类问题建议提供“截图或完整错误提示”至少一项 |
| 完整错误提示 | 否 | 系统无法自动获取时由教师补充 |

选择规则：

- 选择“任务内容或完成规则”后显示“关联任务”，只列出当前教师真实存在的任务。
- 选择“课程安排或课程信息”后显示“关联课次”，展示课程日期、时间和 Lesson ID。
- 从对应任务页面进入时自动选中当前任务，但教师可以切换。
- 找不到对应项时允许选择“找不到对应任务／课次”，不阻止教师提交。
- “关联对象”属于问题上下文，不是新的第三级问题类型。

### 4.2 系统自动补充

- `teacher_id`；
- 当前页面及入口来源；
- 教师选择或页面自动选中的任务名称、任务编码、assignment ID；
- 教师选择或页面自动选中的课程日期、时间和 `lesson_id`；
- My TIDE 当前展示的 Last updated；
- 设备类型、操作系统、浏览器、界面语言和客户端版本；
- 系统已经获取到的标准错误码、教师可见错误提示和请求 ID；
- 提交时间。

只补充当前场景中真实存在的信息；不存在时保持为空，不使用 Mock 补齐。

## 5. 问题分类

教师选择二级问题类型；一级问题类型由服务端按固定映射写入。任务和课程类型出现的“关联对象”只补充上下文，不参与一级／二级分类映射。

| 二级问题类型 | 一级问题类型 |
|---|---|
| 任务内容或完成规则 | 运营类 |
| 课程安排或课程信息 | 运营类 |
| 积分、审核或业务结果 | 运营类 |
| 页面或功能异常 | 产品类 |
| 登录或账号问题 | 产品类 |
| 视频、上传、摄像头问题 | 产品类 |
| 其他问题 | 其他类 |

前后端和世文运营看板必须使用同一组稳定枚举，不根据自由文本重新判断一级类型。

## 6. 共享数据设计

### 6.1 共享表

建议新增：

`public.teacher_support_tickets`

该表是唯一权威工单记录，不在两套系统中复制工单。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `ticket_id` | uuid，PK | 工单唯一 ID |
| `teacher_id` | varchar，必填 | 工单所属教师 |
| `primary_category` | varchar，必填 | 一级问题类型 |
| `secondary_category` | varchar，必填 | 二级问题类型 |
| `problem_location` | varchar，必填 | `MY_TIDE / TASK / LESSON / MESSAGES / ACCOUNT / HELP / OTHER` |
| `problem_context` | jsonb，必填 | 页面、任务、课程、Last updated、设备、浏览器和错误上下文 |
| `messages` | jsonb，必填 | 教师和运营的完整消息数组 |
| `status` | varchar，必填 | 当前工单状态，由 TIDE 维护 |
| `last_operator_reply_at` | timestamptz，可空 | 运营最后回复时间 |
| `teacher_reply_deadline_at` | timestamptz，可空 | 教师反馈截止时间 |
| `last_read_operator_message_id` | uuid，可空 | 教师最后读到的运营消息 ID |
| `teacher_last_read_at` | timestamptz，可空 | 教师最后打开该工单的时间 |
| `close_reason` | varchar，可空 | `RESOLVED / NO_RESPONSE_TIMEOUT` |
| `closed_at` | timestamptz，可空 | 关闭时间 |
| `image_cleanup_status` | varchar，必填 | `NOT_REQUIRED / PENDING / SUCCEEDED / FAILED` |
| `images_deleted_at` | timestamptz，可空 | 全部图片完成删除时间 |
| `row_version` | bigint，必填 | 双方并发追加消息时的乐观锁版本 |
| `created_at` | timestamptz，必填 | 创建时间 |
| `updated_at` | timestamptz，必填 | 最后更新时间 |

### 6.2 消息 JSON

```json
[
  {
    "message_id": "f9a9974d-f9bd-4377-9223-84acf822ef58",
    "sender": "TEACHER",
    "content": "My TIDE 页面一直显示未更新。",
    "images": [
      {
        "file_id": "42f589da-b9f3-42ea-b01e-0b49e6a95c38",
        "object_key": "support-tickets/ticket-id/message-id/file-id.png",
        "filename": "error.png",
        "mime_type": "image/png",
        "size": 102400,
        "storage_provider": "OSS",
        "deleted_at": null
      }
    ],
    "created_at": "2026-07-28T10:00:00Z"
  }
]
```

约束：

- `sender` 只允许 `TEACHER / OPERATOR`。
- 每条消息必须有唯一 `message_id`，用于幂等写入和未读判断。
- 历史消息只能追加，不能修改正文或整体替换。
- 教师端统一将运营发送者展示为“运营支持”，不展示内部账号信息。
- 消息 JSON 不保存永久公开的 OSS 地址。

### 6.3 双方写入边界

| 操作 | TIDE | 世文 |
|---|---:|---:|
| 创建工单 | 是 | 否 |
| 追加教师消息 | 是 | 否 |
| 追加运营消息 | 否 | 是 |
| 更新工单状态 | 是 | 否 |
| 设置或清除教师反馈截止时间 | 是 | 否 |
| 关闭工单 | 是 | 否 |
| 删除 OSS 图片并回写清理状态 | 是 | 否 |
| 读取工单 | 按当前教师读取本人记录 | 运营看板按授权读取 |

双方都具有完成各自操作所需的编辑权限，但不允许直接整体覆盖 `messages`。数据库提供受控的原子追加方法，并校验 `message_id + row_version`，避免教师与运营同时发送消息时互相覆盖。

## 7. 状态流转

| 当前状态 | 触发动作 | 下一状态 | 状态修改方 |
|---|---|---|---|
| 新建 | 教师首次提交 | `WAITING_OPERATOR` | TIDE |
| `WAITING_OPERATOR` | 运营追加回复，教师端刷新同步 | `WAITING_TEACHER` | TIDE |
| `WAITING_TEACHER` | 教师点击“未解决”并追加消息 | `WAITING_OPERATOR` | TIDE |
| `WAITING_TEACHER` | 教师点击“已解决” | `CLOSED` | TIDE |
| `WAITING_TEACHER` | 运营最后回复后 48 小时无教师反馈 | `CLOSED` | TIDE |

规则：

- 世文只追加运营消息，不直接更新 `status`。
- TIDE 不后台轮询运营回复。教师刷新页面、进入 Messages 或重新登录时，TIDE 读取共享表并同步最新运营消息。
- 读取到新的运营消息后，TIDE 更新为 `WAITING_TEACHER`，并将截止时间设为运营最后回复时间后 48 小时。
- 同一工单出现新的运营回复时，48 小时从最新回复重新计算。
- 自动关闭前必须再次确认没有更新的教师消息，避免超时任务与教师提交同时发生时误关闭。
- `CLOSED` 后不再接受任何新消息。

## 8. 刷新同步与未读状态

本功能不为运营回复创建独立站内提醒，也不把工单回复写入 `tide.system_notifications`。

教师端在以下时机读取共享工单表：

- 页面刷新；
- 重新登录；
- 进入 Messages；
- 在 Messages 内切换到“我提交的工单”。

未读规则：

- 最新 `OPERATOR` 消息的 `message_id` 不等于 `last_read_operator_message_id` 时，该工单为未读。
- 任意工单存在未读运营回复时，Messages 导航入口和“我提交的工单”切换按钮显示红点。
- 教师打开工单后，TIDE 将当前最新运营消息写入 `last_read_operator_message_id`，并更新 `teacher_last_read_at`。
- 工单回复不额外生成一条系统消息，避免同一回复在两个列表重复出现。
- 工单因 48 小时无反馈自动关闭时，不自动视为已读；教师刷新后仍可看到未读红点和运营回复，但需要继续沟通时应新建工单。

运营内部备注不得进入教师可见消息。

48 小时自动关闭仍由 TIDE 负责，并与前端未读同步分开处理。到期任务只判断“最新待处理消息是否为运营回复、该回复是否已超过 48 小时、期间是否没有更新的教师消息”，满足条件后由 TIDE 关闭工单并清理图片。该任务不生成未读状态或提醒。

## 9. OSS 图片

### 9.1 存储位置

所有工单图片统一使用独立目录：

```text
support-tickets/{ticket_id}/{message_id}/{file_id}.{ext}
```

要求：

- 不与任务图片、摄像头图片、课程素材或其他业务图片混放。
- 路径中不使用明文 `teacher_id`。
- 教师和运营图片都必须通过 TIDE 提供的受控上传能力写入该目录。
- 不接受无法由 TIDE 删除的外部图片 URL。
- 数据库保存文件 ID、对象键和必要元数据；教师端通过登录鉴权接口读取，不暴露永久公开地址。

### 9.2 清理规则

以下任一情况发生时，由 TIDE 发起全部图片清理：

- 教师点击“已解决”；
- 运营回复后 48 小时教师无反馈，TIDE 自动关闭。

清理范围包括教师和运营在该工单中上传的全部图片。

处理顺序：

1. TIDE 将工单更新为 `CLOSED`。
2. 将 `image_cleanup_status` 更新为 `PENDING`。
3. 删除 `support-tickets/{ticket_id}/` 下全部对象。
4. 删除成功后标记消息中的图片 `deleted_at`，并更新为 `SUCCEEDED`。
5. 删除失败时更新为 `FAILED` 并自动重试，不重新打开工单。

关闭后的工单仍保留文字消息，但图片位置展示为“图片已清理”。

## 10. 双方开发分工

### 10.1 TIDE 负责

- Help 和“我提交的工单”页面；
- 教师工单创建、消息追加和截图上传；
- 自动补充教师、任务、课程和技术上下文；
- 工单状态流转；
- 教师端刷新时同步运营回复；
- 工单未读状态和 Messages 红点；
- 48 小时自动关闭；
- 教师和运营全部 OSS 图片删除；
- 教师数据权限和图片访问控制。

### 10.2 世文负责

- 运营看板读取共享工单；
- 运营消息编辑与提交；
- 运营图片通过 TIDE 受控上传能力上传；
- 只向 `messages` 追加 `OPERATOR` 消息；
- 不修改工单关闭状态、教师消息或原始问题上下文。

## 11. 验收标准

- [ ] Help 不再直接进入 AI，而是先展示 AI 和提交工单两个入口。
- [ ] AI 未命中后可以进入工单，并保留教师确认后的问题描述。
- [ ] 教师不需要手动填写 `teacher_id`、设备、浏览器和已存在的任务／课程信息。
- [ ] 一级类型按已确认映射自动生成。
- [ ] 任务问题必须选择关联任务或“找不到对应任务”；提交后上下文包含真实 assignment ID、任务编码和名称。
- [ ] 课程问题必须选择关联课次或“找不到对应课次”；提交后上下文包含真实课程日期、时间和 Lesson ID。
- [ ] 其他问题类型不出现关联对象选择框。
- [ ] 教师和运营同时追加消息不会互相覆盖或产生重复消息。
- [ ] 世文不能修改工单关闭状态。
- [ ] 运营回复后不额外生成系统消息。
- [ ] 教师刷新或进入 Messages 后可以读取最新运营回复。
- [ ] 未读回复会在 Messages、“我提交的工单”和对应工单列表项显示红点。
- [ ] 教师打开工单后只清除该工单的未读状态。
- [ ] 教师点击“未解决”后可以继续追加文字和图片。
- [ ] 教师点击“已解决”后工单由 TIDE 关闭。
