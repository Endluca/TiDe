## 1. 任务目标与边界

老师在首课前完成三个部分：

1. **课件准备确认**：老师确认已浏览全部课件并完成本节课备课，不要求上传截图；
2. **设备与网络检测**：在站内检测摄像头、麦克风和网络；
3. **授课环境照片检查**：在真实授课位置拍摄一张 16:9 横向照片，逐项检查光线、人物入镜、机位与状态、授课耳麦、着装、背景和照片清晰度 7 项标准。

7 项画面检测来自同一张摄像头预览图，不要求分别拍摄。页面不提供上传相册图片作为替代入口。

拍照入口使用 Self-intro 标准说明和合格正面参考图。检测未通过时展示具体未通过项和调整建议；参考图只用于拍照前对照，不作为老师需要上传的证明材料。

照片检查不能替代设备与网络检测，因此三项设备网络结果和照片 7 项检查必须分别通过。当前教师端实现只校验摄像头、麦克风和网络；运营权威目录同时要求电脑、扬声器与摄像头等设备项，二者完成条件对齐前不得把本 PRD 视为生产验收已通过。

资源包中课程 400 与 500 的题目属于历史资料，不进入当前 G04 完成步骤。

三个部分在同一个首课准备工作台内完成，不拆成独立 G 任务。

### 1.1 首课时间与任务内提醒

- 只在首课准备任务详情页内部展示首课开始时间和实时倒计时；
- 临近首课时，倒计时提示使用更明显但紧凑的颜色，不使用全屏弹窗、全局顶部通栏或额外优先级标签；
- 不修改首页、任务列表或其他任务页面；
- 摄像头画面检测通过且课件准备已确认后，任务内部的倒计时提示停止展示；
- Mock 阶段默认把首课设为当前时间后 3 小时，便于直接验收临近首课的提示状态。

## 2. 教师侧流程

```text
查看首课时间与倒计时
  → 确认已浏览全部课件并完成备课
  → 检测摄像头、麦克风和网络
  → 打开摄像头并调整当前授课画面
  → 拍摄一张摄像头预览图
  → 同一张图检测 7 项授课准备标准
  → 任一项未通过：自动展开对应示例，按提示调整后重新拍摄
  → 7 项全部通过：保存检测证据并完成画面检查
  → 备课确认、设备网络检测、照片检查全部通过
  → COMPLETED
```

授课环境照片检测标准：

1. 光线清楚；
2. 人物完整入镜；
3. 机位与授课状态合适；
4. 清楚佩戴授课耳麦；
5. 着装适合正式授课；
6. 背景整洁稳定；
7. 照片清晰且可检测。

课件准备确认文案：

> I have reviewed all the slides and finished preparing for this lesson.

当前阶段由老师主动勾选确认。后续如果系统能够可靠回传课件浏览和备课行为，可用系统状态替代或补充主动确认，但不得要求老师提交截图。

## 3. 完成判定

- 已确认浏览全部课件并完成本节课备课；
- 摄像头、麦克风和网络三项检测全部通过；
- 已通过浏览器摄像头拍摄当前授课环境；
- 同一张照片的 7 项标准全部通过；
- 页面将任务状态更新为 `COMPLETED`，并保存教师当前进度。

图片检测结果、图片保存策略和回传接口以后端结果为最终事实源。后台可以对通过后的图片进行存储优化，但教师端不把美颜处理作为任务步骤或完成条件。

### 3.1 需要的产品字段

当前资料尚未提供后端真实物理字段 ID，下面仅定义必须表达的业务字段，不作为已存在字段：

| 模块 | 必须记录的字段含义 |
| --- | --- |
| 公共关联 | `teacher_id`、任务实例 ID、任务模板 ID |
| 首课排期 | 首课 ID、首课开始时间、任务内提醒等级和提醒阈值 |
| 设备网络检测 | 摄像头、麦克风、网络结果，检测时间和规则版本 |
| 授课环境照片检查 | 原始图片 ID、检测状态、7 项检测结果、规则版本、拍摄时间、检测时间、最终图片资源 ID |
| 课件准备确认 | 确认状态、确认时间；未来可扩展课件浏览和备课行为回传 |
| 总任务 | 画面检测状态、课件确认状态、总任务状态、完成时间 |

> 原型中的 `readinessPhoto`、`readinessAnalysis`、`readinessChecks`、`readinessCheckedAt` 等前端状态不是后端正式字段 ID。
