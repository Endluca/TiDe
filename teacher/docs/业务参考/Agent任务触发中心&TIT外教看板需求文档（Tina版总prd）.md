# Agent任务触发中心&TIT外教看板需求文档

### 1.1 项目背景与目标

当前New Teacher Camp已经沉淀了TIT（Teacher Improvement Tool）、任务中心和运营监控看板的初步方向和需求。现需要补齐的是中间的“任务触发中心”：系统如何从新老师成百上千甚至上万节课程数据中，自动识别问题、生成任务、推动老师完成成长动作，并让运营知道哪些老师需要优先干预。

本模块不是单纯展示数据，也不是把所有异常都推给运营人工判断，而是把课程数据、出席数据、设备网络数据、学员反馈、投诉记录、资料完整度、培训完成情况和产能数据，统一转化为可解释、可追踪、可复核的外教成长任务。

业务目标：

| 目标 | 说明 | 需要支持的能力 |
| --- | --- | --- |
| 提升新师试用期通过率 | 让老师知道毕业标准、当前差距和下一步动作 | TIT看板、成长进度、任务推荐 |
| 提升有效供给 | 识别能稳定开课、稳定履约、被学生接受的新师 | 产能指标、可靠性指标、风险分层 |
| 降低运营人力消耗 | 从逐个盯人转为系统识别高风险老师 | 任务触发、优先级、运营待办 |
| 提升课堂体验 | 对设备、网络、课堂准备、反馈异常做及时干预 | 课程数据检测、个性化任务、整改闭环 |
| 建立可复制的新师培养机制 | 把培训从“统一推送”变成“标准任务 + 数据驱动任务” | 必修任务包、个性化任务、效果回看 |

### 1.2 定义

Agent任务触发中心是连接“数据指标”和“老师任务”的规则引擎与任务编排模块。

核心定位：

1.  数据输入层：接入课程、出席、设备网络、学员反馈、投诉、资料、培训、产能等数据。
    
2.  规则判断层：按新师试用期标准识别异常、风险、短板和成长机会。
    
3.  任务生成层：生成必修成长任务、个性化触发任务、人工确认任务。
    
4.  展示与执行层：把任务和风险同步到外教端 TIT 看板、任务中心和运营管理看板。
    
5.  闭环复核层：根据老师完成结果、后续课程表现和人工复核结果，关闭任务或升级风险。
    

与现有模块的关系：

| 模块 | 作用 | 与Agent任务触发中心的关系 |
| --- | --- | --- |
| TIT外教端看板 | 老师查看试用期进度、风险和成长任务 | 展示任务触发中心输出给老师的结果 |
| 任务中心 | 承载老师具体任务、截止时间和完成状态 | 接收任务触发中心生成的任务 |
| 运营管理看板 | 运营查看风险老师、任务进度和干预名单 | 展示任务触发中心的风险判断与处理状态 |
| 数据平台/课堂日志 | 提供课程、设备、反馈、出席等数据 | 作为任务触发中心的主要输入 |
| 培训内容库 | 提供培训、教材、规则学习和整改内容 | 作为任务触发后的内容来源 |

本期不涵盖范围：

*   不替代人工质检；系统先识别和推荐，重大投诉、拉黑、争议问题仍需人工 validate。
    
*   不直接决定淘汰；任务触发中心只提供风险分层、证据和建议动作，最终转正/淘汰由运营规则确认。
    
*   不因单节课低样本直接强处罚；新师前期数据样本不足时，系统应以提醒、观察和轻任务为主。
    
*   阈值由业务、数据和培训团队基于历史数据共同校准。
    

### 1.3 用户角色与使用场景

| 角色 | 核心问题 | 需要看到什么 | 需要完成什么动作 |
| --- | --- | --- | --- |
| 新师 | 我怎样才能通过试用期？当前还差什么？ | 试用期进度、毕业状态、优秀状态、风险提醒、当前任务、成长路径 | 完成资料、培训、整改、开课、设备检测等任务 |
| 外教运营 | 哪些老师最危险？为什么危险？先跟进哪些老师？ | 红黄绿分层、风险原因、任务状态、待人工确认事项 | 跟进高风险老师、审核投诉、关闭/升级任务 |
| 培训负责人 | 哪些培训被频繁触发？培训有没有改善指标？ | 培训触发次数、完成率、完成后指标变化 | 补充培训内容、优化任务素材 |
| AI/数据 | 数据怎么进来？规则怎么判断？任务怎么发？ | 数据源、字段、规则、任务状态流转、日志 | 建设规则引擎、任务服务、看板和监控 |
| 管理层 | 新师培养机制是否有效？ | 新师漏斗、通过率、优秀率、有效供给、风险分布 | 判断机制效果和资源投入 |

### 1.4 任务体系设计

任务体系分为三层：必修成长体系任务、个性化触发任务、人工确认任务。

#### 1.4.1 必修成长体系任务

必修成长体系任务面向所有新师触发，目标是确保老师具备上线和试用期毕业的基本条件。该类任务不依赖异常课程数据，通常在入职、激活、首课前、试用期前7天、试用期中段等节点自动生成。

| 任务类别 | 任务示例 | 触发时机 | 完成标准 | 校验方式 | 内容负责人 |
| --- | --- | --- | --- | --- | --- |
| 资料完整度 | 上传自我介绍视频 | 入职后自动触发 | 视频已提交且审核通过 | 系统校验 + 人工审核 | 外教运营 |
| 资料完整度 | 上传TESOL/教学资质证明 | 入职后自动触发 | 文件已上传且有效期符合要求 | 系统校验 | 系统自动化 |
| 平台规则 | Policy、Rules | 入职后自动触发 | 完成学习并通过小测 | 任务中心状态 | TS&Wilson |
| 文化与合规 | ME Culture/<br>PARSNIP培训 | 入职后自动触发 | 完成学习 | 任务中心状态 | Sophia /Anna待确认 |
| 教学基础 | Lesson Preparation | 首课前自动触发 | 完成课程准备任务 | 任务中心状态 | Sophia / Anna待确认 |
| 设备自检 | 设备、网络、摄像头、麦克风检查 | 登录AC自动触发 | 检测结果达标 | 系统检测 | 海璇 |
| Cocos教材产品 | 教材/课程体系培训<br>Level 0-2 | 首课前或获得排课资格前 | 获得对应教材标签 | 培训系统标签 | Sophia |
| SET<br>教学能力 | SET基础训练 | 试用期内自动触发 | 完成训练并获得标签 | 培训系统标签 | Sophia/ Anna待确认 |

待Sophia /Anna确认事项：

*   新师必修教学培训清单。
    
*   Trial、SET、Cocos、教材、ME Culture、PARSNIP等内容是否均为新师必修。
    
*   每项培训的英文任务名、任务说明、素材链接、测试方式、截止时间。
    
*   哪些任务作为“毕业必要条件”，哪些作为“优秀老师加分项”。
    

#### 1.4.2 个性化触发任务

个性化任务由课程数据、行为数据或反馈异常触发。目标是让老师不是看到抽象扣分，而是收到可执行的提升动作。

| 触发维度 | 异常信号 | 自动生成任务 | 任务目的 | 复核/关闭方式 |
| --- | --- | --- | --- | --- |
| 个人资料 | 未提交自我介绍视频/TESOL/未获标签 | 补充资料或培训任务 | 现有的引导链接和标准介绍 | 系统状态达标后关闭 |
| 可靠性 | 缺席、迟到、早退、假早退、睡觉 | Reliability规则复训 + 运营提醒 | 降低履约风险 | 后续连续N节无异常后关闭，N待数据确认 |
| 设备网络 | CPU/RAM/网络/延迟/带宽不达标 | 设备检测与网络优化任务 | 保证课堂流畅 | 新检测结果达标后关闭 |
| 课堂环境 | 摄像头关闭、灯光差、背景差、噪音明显 | Lights, Camera, Activate 标准培训+整改提醒 | 提升课堂专业感 | 系统识别达标或人工审核通过 |
| 课堂准备 | 课件查看不足、备课率低 | 课前准备任务 | 提升课堂准备度 | 后续备课率达标后关闭 |
| 产能 | Peak/LN slots不足、活跃天数不足 | 补开高峰时段任务 | 提升有效供给 | 开放slots或完成目标课量后关闭 |
| 学员反馈 | 差评率高、好评率低 | 教学提升培训任务 | 改善课堂体验 | 后续评价改善后关闭 |
| 复约/收藏 | 复约低、收藏低 | 课堂准备度 + 课后引导话术任务 | 提升学生再次预约意愿 | 后续复约/收藏改善后关闭 |
| 投诉/拉黑 | 投诉、拉黑、重大负向反馈 | 人工确认任务；valid后触发专项整改 | 防止重大体验风险 | 运营validate后关闭或升级 |

#### 1.4.3 人工确认任务

以下场景不建议系统直接判定老师责任，需要先进入运营 validate：

| 场景 | 原因 | 处理方式 |
| --- | --- | --- |
| 学员投诉 | 多次投诉可能涉及学生、课程、系统、家长预期等多方因素 | 生成“待运营确认”任务，确认valid后再触发专项任务 |
| 拉黑 | 可能来自单个学生偏好，不一定代表普遍教学问题 | 结合课程样本和反馈记录判断 |
| 设备/网络争议 | 可能由平台、地区网络或设备检测误差导致 | 支持重新检测和人工豁免 |
| 重大差评 | 单节课低样本不能直接强处罚 | 样本不足时进入观察，样本充足后触发训练 |
| 假早退/睡觉等高风险行为 | 涉及事实判断和申诉 | 保留证据，运营复核后处理 |

### 1.5 任务状态流转

任务需要具备完整生命周期，避免“发了任务但没人知道是否解决”。

| 状态 | 定义 | 进入条件 | 下一步 |
| --- | --- | --- | --- |
| 待触发 | 规则已定义，但当前老师未命中 | 规则存在，未满足触发条件 | 命中规则后进入已触发 |
| 已触发 | 系统识别到任务应生成 | 数据命中规则或运营手动触发 | 生成老师任务 |
| 待完成 | 老师可在任务中心看到并执行 | 任务已下发 | 老师提交或系统自动完成 |
| 已提交 | 老师完成提交动作，但未校验 | 老师上传材料、完成学习或重新检测 | 进入系统校验/人工复核 |
| 系统校验 | 系统根据数据判断是否达标 | 可自动判断的任务 | 达标则完成，不达标则未通过 |
| 人工复核 | 需要运营或培训负责人判断 | 投诉、资质、视频、争议类任务 | 通过、驳回或豁免 |
| 已完成 | 任务完成且通过校验 | 系统达标或人工通过 | 同步看板，更新成长进度 |
| 未通过 | 老师提交但不达标 | 校验失败或人工驳回 | 重新打开任务或生成新任务 |
| 逾期 | 超过截止时间未完成 | 到期未完成 | 提升优先级，进入运营待办 |
| 已豁免 | 经人工判断无需完成 | 特殊情况或误触发 | 记录原因，不再重复触发 |

任务属性建议：

| 字段 | 说明 |
| --- | --- |
| task\_id | 任务唯一ID |
| teacher\_id | 老师ID |
| task\_type | 必修成长/个性化触发/人工确认 |
| trigger\_source | 入职节点、课程数据、反馈数据、运营手动等 |
| trigger\_rule\_id | 命中的规则ID |
| trigger\_reason | 老师可理解的触发原因 |
| evidence | 关联课程、反馈、投诉、设备检测等证据 |
| priority | P0/P1/P2/P3 |
| due\_time | 截止时间 |
| status | 当前任务状态 |
| verify\_method | 系统校验/人工复核/标签校验 |
| close\_condition | 关闭条件 |
| owner | 老师、运营、培训、系统 |
| override\_reason | 人工豁免或调整原因 |

### 1.6 触发规则设计

触发规则分为“必修节点触发”和“数据异常触发”。

#### 1.6.1 必修节点触发

| 触发节点 | 触发任务 | 说明 |
| --- | --- | --- |
| 入职完成后 | 资料完整度任务、平台规则任务、设备自检任务 | 保证老师具备基础上线条件 |
| 首课前 | 课前准备任务、可靠性规则任务、课程教材任务 | 保证首课体验 |
| 试用期第1-7天 | Cocos/教学基础任务/SET | 建立基础教学能力 |
| 试用期中段 | 未完成任务提醒、风险复盘任务 | 避免临近毕业才发现问题 |
| 试用期结束前 | 毕业条件确认、优秀条件确认 | 输出毕业/优秀状态 |

#### 1.6.2 数据异常触发

阈值本期先作为“待配置项”，由数据团队基于历史新师样本校准。

| 维度 | 指标 | 触发逻辑 | 任务动作 |
| --- | --- | --- | --- |
| 可靠性 | 缺席、迟到、早退、假早退、睡觉 | 出现异常或累计异常超过阈值；Sudden booking需排除或单独处理 | 可靠性复训、运营提醒 |
| 设备 | CPU Score、CPU Model、RAM、内存占用、CPU占用 | 低于上线标准或课堂中频繁异常 | 设备升级建议、重新检测 |
| 网络 | 延迟、带宽、卡顿、掉线、频繁进出教室 | 超过异常阈值或连续多节异常 | 网络优化任务、设备检测 |
| 课堂环境 | 摄像头、灯光、背景、噪音、仪容仪表 | AI识别异常或课堂日志异常 | 环境整改任务 |
| 课堂准备 | 备课率、课件查看、课前准备行为 | 低于阈值 | 课前准备任务 |
| 产能 | Peak slots、LN slots、真实完课量、活跃天数 | 供给不足或重点时段不足 | 补开slots任务 |
| 学员反馈 | 好评率、差评率、评价率 | 样本量达到保护线后判断 | 教学提升任务 |
| 复约收藏 | 复约、收藏、拉黑 | 复约低或拉黑出现 | 课后引导/人工确认 |
| 投诉 | 投诉数量、投诉类型、valid结果 | 严重投诉先进入人工确认 | valid后触发专项整改 |
| 培训标签 | Cocos、教材、SET等标签 | 未获得必要标签 | 推送对应培训 |

样本量保护原则：

*   试用期前10天不建议过度依赖复约率、好评率、差评率等低样本指标。
    
*   单节课异常优先触发提醒或观察，不直接触发强处罚。
    
*   多次重复异常可升级任务优先级，并进入运营待办。
    
*   所有扣分和任务触发必须可解释：哪节课、哪个指标、为什么触发、如何完成、是否可申诉。
    

### 1.7 看板需求

#### 1.7.1 外教端 TIT 看板

外教端看板目标是让老师清楚知道：当前进度、是否能毕业、哪里有风险、今天要做什么。

| 模块 | 字段 | 展示说明 |
| --- | --- | --- |
| 试用期进度 | 第X天/30天、剩余天数 | 告诉老师当前试用期位置 |
| 毕业状态 | 已达成/待完成/高风险 | 展示是否满足毕业条件 |
| 优秀状态 | 已达成/待完成 | 展示是否满足优秀老师标准 |
| 当前分层 | 绿色/黄色/红色 | 简化老师对风险的理解 |
| 指标差距 | 标准值、当前值、差距 | 展示关键短板 |
| 当前任务 | 任务名、截止时间、优先级、状态 | 让老师知道本周必须完成什么 |
| 风险提醒 | 最影响毕业的1-3个问题 | 避免展示过多后台指标 |
| 成长路径 | 当前阶段、下一阶段要求、推荐培训 | 让老师知道如何进阶 |
| 已获得标签 | Cocos教材、SET等 | 展示能力资产 |
| 申诉/帮助 | 任务说明、整改指引、申诉入口 | 处理争议和误触发 |

外教端展示原则：

*   不展示过多后台数据，只展示老师能理解、能行动的内容。
    
*   每个任务必须有“为什么收到这个任务”和“完成后有什么变化”。
    
*   **高风险提醒要克制，避免把老师体验做成惩罚感过强的扣分系统,采用加分制度进行。**
    
*   对设备、网络、投诉等争议场景提供重新检测、查看规则或申诉入口。
    

#### 1.7.2 运营端管理看板

运营端看板目标是帮助运营快速判断：谁最需要跟进、为什么、现在处理到哪一步。

| 模块 | 字段 | 用途 |
| --- | --- | --- |
| 新师漏斗 | 入职人数、激活人数、首课人数、培训完成人数、毕业人数、优秀人数 | 看整体转化 |
| 风险分层 | 红黄绿人数、名单、占比、趋势 | 快速定位高风险老师 |
| 风险原因 | 可靠性、设备网络、课堂质量、产能、反馈、培训未完成 | 判断风险来源 |
| 任务完成 | 任务触发数、完成数、逾期数、未通过数 | 看任务执行效率 |
| 待人工确认 | 投诉、拉黑、重大差评、设备争议 | 运营优先处理 |
| 培训管理 | 培训触发次数、完成率、标签获取率 | 看培训供给是否有效 |
| 产能管理 | Peak/LN开课量、活跃外教数、供给不足名单 | 保障有效供给 |
| 效果回看 | 任务完成前后指标变化 | 判断任务是否真正改善问题 |

运营端支持动作：

*   按风险等级、任务逾期、投诉待确认、毕业临近等条件筛选老师。
    
*   查看老师被触发任务的证据链，包括课程、设备检测、反馈或投诉记录。
    
*   手动触发任务、调整优先级、延期、关闭、豁免或升级。
    
*   对人工确认类任务填写 validate 结果和处理备注。

#### 1.8.2 系统数据流

1.  数据平台汇总老师维度与课程维度数据。
    
2.  Agent任务触发中心按老师、试用期阶段、课程样本、规则配置进行判断。
    
3.  命中规则后生成任务，写入任务中心。
    
4.  TIT外教端看板读取任务、进度、风险和成长路径。
    
5.  运营端看板读取风险分层、待确认事项、任务完成和效果数据。
    
6.  老师完成任务后，系统校验或人工复核。
    
7.  任务结果回写触发中心，用于关闭任务、继续观察或升级风险。

### 1.9 验收标准

MVP验收需要覆盖以下场景：

| 验收场景 | 输入样例 | 预期输出 |
| --- | --- | --- |
| 资料未完成但课堂正常 | 老师未提交自我介绍视频/TESOL，课程无异常 | 触发资料补充必修任务，不触发课堂风险 |
| 出席异常明显 | 多次迟到/缺席/早退 | 触发可靠性复训任务，运营端进入黄色或红色名单 |
| 设备网络异常明显 | 多节课卡顿、延迟高、摄像头/麦克风异常 | 触发设备检测和网络优化任务 |
| 低评价/投诉/复约低 | 评价差、复约低或出现投诉 | 样本量不足先观察；投诉进入人工确认 |
| 各项优秀无风险 | 资料完整、培训完成、课程稳定、反馈好 | 外教端展示毕业/优秀进度良好，不生成额外风险任务 |

功能验收：

*   能为单个新师生成完整的必修任务列表。
    
*   能基于异常课程数据触发对应个性化任务。
    
*   能把任务展示到外教端 TIT 看板，并显示原因、截止时间、完成方式。
    
*   能在运营端展示风险老师名单、触发原因、任务状态和处理进度。
    
*   能将投诉、拉黑、重大差评等任务进入人工确认，而不是直接系统判定。
    
*   能支持任务完成后的关闭、未通过、逾期、豁免和再次触发。
    
*   能标注待Sophia & Anna补充的培训内容，不阻塞产研先建设任务框架。

### 1.11 建议一期范围

一期建议先完成“可触发、可展示、可闭环”的最小闭环，不追求所有规则一步到位。

一期范围：

1.  必修成长任务：资料完整度、设备自检、平台规则、Reliability、Trial准备、教材/SET/Cocos标签任务。
    
2.  个性化任务：可靠性、设备网络、课堂环境、产能不足、培训标签缺失。
    
3.  人工确认任务：投诉、拉黑、重大差评。
    
4.  外教端 TIT 看板：试用期进度、毕业状态、当前任务、风险提醒、成长路径。
    
5.  运营端看板：红黄绿名单、任务完成、逾期、待人工确认。
    
6.  规则配置：至少支持阈值、任务模板、截止时间、重复触发冷却期、关闭条件。
